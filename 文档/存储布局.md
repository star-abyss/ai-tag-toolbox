# 存储布局

## 目录约定

程序代码与随版本发布的内置资源位于仓库和交付包的 `程序/`。Danbooru 标签基础库位于 `程序/内置资源/标签/`，随 GitHub 源码与交付包发布；首次启动时复制到个人数据根的 `标签/`，之后标签模块只读写个人数据副本。用户模型位于启动入口 `启动.cmd` 同层的 `模型/`：

```text
工具箱/
├─ 启动.cmd
├─ 程序/
├─ 模型/
│  ├─ 识图/
│  │  └─ wd-eva02/       WD EVA02 模型文件与标签词表
│  └─ 翻译/
│     └─ opus-mt/        opus-mt-en-zh/ 与 opus-mt-zh-en/
└─ 文档/
```

把模型放到相应子目录下即可。WD EVA02 通过 `wd-eva02*.onnx` 与 `tags-canary.json` 识别；opus-mt 通过两种方向目录里的配置、分词器与词表文件识别。两者不需要额外的 `模型.json`。扫描目录和文件要求见 `程序/对接层/模型引擎/目录.js`。

## 个人数据

位置设置文件固定在 `%LOCALAPPDATA%\工具箱\位置.json`。首次启动默认个人数据根为 `%LOCALAPPDATA%\工具箱\`。数据根包含 `设置.json`、API 服务商与密钥、会话和消息附件、图库、标签用户数据、主 AI 预设、世界书、ComfyUI 工作流及其他用户配置。

用户可在界面更改数据根目录；新位置从下次启动开始生效。更改位置只更新 `位置.json`，程序不会自动复制或搬动文件。需要保留原数据时，用户自行复制整个数据根，再切换位置。`设置.json` 保存界面设置与当前识图、翻译模型选择。

识图与翻译模型根固定为 `启动.cmd` 所在目录的 `模型/`，不随个人数据根目录变化。更新时覆盖原程序文件夹应保留根目录 `模型/`；若改用新的程序文件夹，应把原来的 `模型/` 一并复制过去。

## GitHub 与交付包

GitHub 收录源码、文档与模型放置说明。根目录 `模型/` 下只跟踪 Markdown 说明，用户权重、词表、模型配置均由 `.gitignore` 排除。打包脚本默认创建 `模型/识图/` 和 `模型/翻译/` 并放入说明文档，不复制模型文件；`-IncludeModels` 会包含这些模型目录中的文件。脚本输出是否包含模型，便于确认包内模型状态。

桌面交付包包含运行代码、内置标签种子、生产依赖以及 `文档/桌面版/` 中的正式说明。打包脚本离线安装锁定依赖，使用无链接的目录布局，并移除包含本机构建路径的包管理器元数据；生成后可移动整个程序目录。交付包排除个人数据、旧版存档、旧 `程序/tag模块/data/` 运行数据、API 配置、测试、探针、旧设计、开发验收记录、Git 元数据和临时文件。桌面版的项目说明和模块架构介绍保留。

## 决策记录

1. 个人数据的位置独立于程序包；位置文件固定存放，修改数据目录从下次启动生效。
2. 模型位于启动入口同层，识图和翻译分别扫描中文子目录；程序不搜索其他模型位置。
3. 内置标签种子只作为首次初始化来源，用户标签读写发生在个人数据目录。
4. 交付包与 GitHub 排除个人存档、模型权重和临时探针；本机检查包可显式包含模型。

## 验证入口

`node 程序/对接层/test/存储位置.js` 验证跨程序目录保存数据与运行中新增模型。

`node 程序/对接层/界面/试/存储设置.js` 验证真实 HTTP 设置与重启后的目录切换。

`node 程序/对接层/界面/试/存储界面.js` 验证浏览器中的目录、模型选择与首选项。

`node 程序/对接层/test/存储交付.mjs <交付包的程序目录>` 验证包内真实模型推理与设置、图库、工作流持久化，需要识图和翻译模型已经放好。
