# 一、执行摘要

## 1.1 这一层是什么

**它是一个本地服务加一个浏览器页面。** 服务住在 `程序/对接层/界面/`，与调试台（`程序/对接层/tools/动作浏览器/`）平级；
页面是原生 ES module + 一个 CSS，**没有构建步骤**。

它做四件事：

| # | 做什么 |
|---|---|
| 1 | 把八份动作表要到手，照着它们画十二块面板 |
| 2 | 把面板的动作调用转给模块（与工具走的是同一条路） |
| 3 | 把字节与缩略图开成两条 GET（原图、现缩的缩略图） |
| 4 | 把出图这类长活挂在任务表上，用 SSE 把状态推给页面 |

**另外还管一页**：API 配置页（§六）——它填的链路与"这个模型能不能看图"都落在本机存档里，
问的对象是**服务商本人**（`GET /models` 与一次带图的请求），不是模块。

## 1.2 一句话

> **界面不是控制器，是观察窗。** 它做的每一件事，都必须是模型用同一个工具、
> 同一份参数能做的——它没有自己的动作，不替用户填，不替模块拦。

## 1.3 三条定性

| # | 定性 | 体现 |
|---|---|---|
| 1 | **界面不写第二份清单** | 动作名、参数名、可选性、说明、错误码全部从宿主读；界面上没有一处写死"有哪些动作" |
| 2 | **约束看得见** | 一次只能飞一个、只读默认、草稿没存、`按深度`只落最浅一档、一次调用走了哪条链路——都在界面上 |
| 3 | **够看清就行** | 一个 CSS 文件、一种脾气；不引入组件库、不加构建步骤。**长相只有两处来源**（`页/页.css` 的令牌 + `页/组件.css` 的零件），十二块面板一处都不各写 |

# 二、目标与非目标

## 2.1 目标

| # | 目标 | 判据（可验） |
|---|---|---|
| G1 | 七个能力模块 + 主 AI 的每个动作都能在界面上做 | 84 个动作在"全部动作"那块里逐个可执行 |
| G2 | 最常用的几件事有专门的块，不用手写 JSON | 标签查词、图库浏览、出图、预设编辑都有面板 |
| G3 | 图看得见、看得快 | 原图逐字节相同；缩略图现缩；`<img>` 走缓存 |
| G4 | 长任务不因关页面而丢 | 出图挂在任务表上，回来还能看回执 |
| G5 | 坏了能查 | 任何回执都能原样看到；失败给 `码: 人话` |

## 2.2 非目标（明确不做）

| 不做 | 为什么 |
|---|---|
| 前端框架 / 组件库 / 构建步骤 | 与"无构建步骤 · 轻量化"冲突；界面是列表加表单 |
| 在界面里改 `cordis.patch.yml` | 那份配置带 `!!js`，里面还有密钥引用；改它要动 YAML 语法 |
| 界面上自己算一份"能不能用" | 能力在谁那儿、工具就在谁那儿：模块拒了就是拒了，界面照原样显示理由 |
| 替用户补默认值 / 校验参数 | 留空就是不传；必填留空照传，拒绝是模块的事 |
| 画假进度条 | 模块只报状态切换，没有百分比。造一个假的比不画更坏 |
| 多级回落 / 兼容层 | 规则 8、规则 10 |
| 把大图塞进 JSON | 一张 1.2 MB 的 PNG 过 JSON 要膨胀成约 160 万字符；所以有 `/字节` 与 `/缩略图` |

# 三、术语

| 词 | 意思 |
|---|---|
| **桌** | 宿主交给页面的那一份交付面：`{ 项目根, 版本, 动作表, 装不上, 模型 }` |
| **交付面** | `动作表` 里的一条：`{ 模块, 动作, 摘要, 参数:[{名,可选,说明,界面,类型}] }` |
| **界面字段** | 一个参数怎么画：`{ 控件, 选项?, 字段? }`。控件种类：`text·textarea·number·boolean·select·ref·context` |
| **上下文参数** | 不给人填的参数（`引用` / `作用域` / `产出` / 识图那三个）：由面板从上下文里挑好再递 |
| **面板** | 一块界面。形状 `{ 名, 标题, 副题, 要的模块, 画(容器, 上下文) }` |
| **交接** | 面板之间递的那一件东西：图片的引用（`页/交接.js`，一格内存位） |
| **任务** | 与一次 HTTP 请求解耦的长活：`{ id, 什么, 状态, 回执, 事件[] }` |
| **字节路** | `/字节` 与 `/缩略图` 两条 GET：原图与现缩的图 |
| **链路** | API 配置页上的一行：`{ id, 地址, 模型, 上下文窗口, 密钥 }`。行序 = 优先级 |
| **服务商那一面** | `程序/对接层/界面/服务商.js`：填的链路住本机存档，"有哪些模型""吃不吃图"问服务商本人 |
| **本机存档** | `%APPDATA%\工具箱\API\`：`链路.json`（用户填的）+ `模型表.json`（问回来的）。**不在软件目录里** |

# 四、分层：第四层落在哪

```
① 模块层    七个能力模块 + 主 AI。互不认识，也不认识界面
      ↓ 被使用（不是被包裹）
② 门面层    请求表 · API 池与路由 · 提示词装配 · 工具注册 · 动作表
      ↓ 两条使用者，平级
③ 执行层    工具那一条：模型填参数 → 模块 → 回执进上下文
            界面那一条：**面板填参数 → 模块 → 回执画出来**
```

**界面与模型是同一个门面层的两个使用者**，谁都不比谁多一样东西。由此得到三条：

| # | 规矩 | 违反的后果 |
|---|---|---|
| 1 | **模块动作只走 `POST /toolbox/调` 这一条**，别的路一个不加 | 界面会长出模块没有的能力 |
| 2 | 界面上的每一样都要能追到交付面（动作名 / 参数名 / 说明 / 控件） | 出现"必须和别处保持一致的清单"（规则 7） |
| 3 | 模块报什么就显示什么，界面不翻译 | 看不到模块真正说了什么 |

**规矩 1 说的是模块动作。** 另外两样东西不是模块动作，各有自己那一条路（§六、[接口.md](../程序/对接层/界面/接口.md) §2.4）：
**链路表**（界面自己那份配置）与**服务商**（"这家有哪些模型""吃不吃图"都得问它本人，模块里没有这个东西）。

**界面这一层与 `tools/` 下那些脚本是一类东西**，区别只在一条：那些走进程内直调，
界面走浏览器 → HTTP → 宿主 → 门面。所以它补的正是别人验不到的那一段。

# 五、十二块面板

| 面板 | 版式 | 一句话 | 主要用到哪几个动作 |
|---|---|---|---|
| **标签** | 甲 | 一个选择器：分类栏 · 卡片墙 · 已选栏 · 查库 | `query` `record.*` `position.*` `note.*` `hidden.*` `modified.*` `identity.*` `status` |
| **收藏** | 甲 | 自己攒的那几格：挑词 · 移出去 · 建页建类 | `position.list` `position.members` `position.attach/detach` `position.createPage/createClass` `record.batch` |
| **标签组** | 甲 | 自己建的那些组（两张身份表都不认的），按成员多少分档 | `record.groups` `record.batch` `position.*` |
| **角色库** | 甲 | 角色组按作品分（**作品就是页「角色组」底下的类**，一个作品一个类）· 复制角色词或角色词+特征 | `position.list` `position.members` `render.pageMap` `render.words` |
| **图片** | 甲 | 三个存放地 · 上传 · 看一张 · 收藏与分类 | `列` `取详情` `存` `改` `删` `清空` `维护.报告` `表.收藏` `表.分类` |
| **识图** | 乙 | 本地打标 · 读元数据 · 交给模型看图（结果按类别分组，**另给一块按渲染顺序排好的**） | `看模型` `认图` `读元数据` `看图` + 标签模块的 `render.sort` |
| **装订 / 翻译** | 乙 | 切成一格一格 · 两路译法 · 原文译文对照 | `切分` `装订` `看模型` `本地译` |
| **翻译** | 乙 | 本地模型翻译 · 范围表双向对照 | `看模型` `本地译` `切分` |
| **世界书** | 丙 | 挂哪几本 · 条目 · 落点 · 草稿与存档 · 命中预览 | `表` `读` `执行` `测` `书` `条目` `存` `丢` `重读` `状态` |
| **comfyUI** | 丙 | 连不连得上 · 工作流 · 出图 · 取回图 | `探活` `看队列` `看节点定义` `存/取/清工作流` `认` `出图` `取图` |
| **主 AI** | 丙 | 预设：身份 · 流程 · 工具表 · 世界书 · 模型 | `表` `读` `执行` `测` `预设` `工具` `存` `丢` `状态` |
| **全部动作** | 甲 | 宿主交来的每一个动作，点着执行、回执原样看 | 全部（就是调试台那一块） |

**版式那三个字**：甲=左栏+主体+已选栏 · 乙=左进右出两栏 · 丙=分节表单。
每一块的四个区各放什么、几个钮，看 [对接层/界面/布局.md](../程序/对接层/界面/布局.md) §九（施工图）。

**面板与模块不是一对一。** 装订与翻译两块各一个文件，因为它们的切分是同一份、只有"谁来译"不同；
标签组与角色库共用 `页/面板/组.js` 的取数，因为读的是同一份 `record.groups`、只是看的东西不同
（标签组看用户自己建的，角色库看角色组、按系列组分的作品）。

翻译页使用模块回执中的原文范围与译文范围建立对应，不另写切分器，不从译文按词名或顺序猜配。tag 按项高亮，句子按整单元高亮；混合语言单元由本地模型适配器只翻译来源语言片段，已有目标语言文字及格式保留。页面按一次在执行和一个最新待处理输入协调自动翻译，停止输入约 500 ms 后发起；过期响应丢弃，失败可重试。翻译结果不做页面缓存，模型加载缓存保留。复制取当前有效回执中的完整译文。

**"全部动作"那块永远留着**：某块面板还没做，从这儿先用；某块面板做坏了，从这儿对照看模块真正交出来什么。

**长相只有一处来源**：令牌在 `页/页.css`，零件（按钮 · 输入 · 卡片 · 分段 · 浮层）在 `页/组件.css`，
版式（三个公共区 · 三种身子排法）与"哪块面板用哪一式"在 [对接层/界面/布局.md](../程序/对接层/界面/布局.md)，
零件清单与"什么场合用哪个"在 [对接层/界面/组件.md](../程序/对接层/界面/组件.md)。
**面板里出现一个模板外的类名，就等于把长相拆成了十二份**——自检有一条专门盯它
（源码级扫 `造()` 用到的类名，对那两份样式的类名表核一遍），验收标准见组件.md §四。

# 六、AI 页上那两块（API 配置页 · 提示词页）

**它们是界面上唯一两处"填东西给 AI 用"的地方**：`/` 那一屏的「AI 页 → API 页 / 提示词页」。
两块都跟十二块面板不是一类东西 —— **面板调的是模块动作**；API 页**问的是服务商本人**，
提示词页改的是**主 AI 预设**。

## 6.1 API 配置页：一行 = 一条链路

行序 = 优先级。三件事：

| 做什么 | 怎么走 |
|---|---|
| 填链路（地址 · Key · 模型 · 上下文窗口） | `POST /toolbox/链路`（`{}` 读 / `{存:[…]}` 写） |
| 模型那一格**点一下就取清单** | `POST /toolbox/服务商 {做什么:'列模型'}` → `GET <地址>/models` |
| 「👁 探测」与「测试连接」 | `POST /toolbox/服务商 {做什么:'探图' \| '试一条'}` |

**模型那一格是"自由输入 + 一份现取的候选"**（§十三 决定 34）：

- **型号永远填得进去** —— 服务商没提供的型号也存得住、也照发；
- 候选里**只有这家真的提供的模型** —— 清单就是上一次 `GET /models` 取回来的那份（落 `模型表.json`）；
- **候选是页面自己画的一块**（`.link-model-list`），不是浏览器原生的 `<datalist>`：
  原生那一份弹出的时机不在我们手上，而候选是异步取回来的 —— 取回来那一刻重画一次，
  原生弹出就被顶掉，用户看见的是"弹出来又没了"。自己画就没有这个问题：
  **点这一格摊开**（或按「取列表」）、**点一条就填进那一格**、**点别处 / Esc 收起**、取回来重画也不关掉它。
- 取不到就如实写在提示行上，输入框照旧可用。

## 6.2 "能不能看图"只有一个来源：服务商本人

| 结论 | 从哪来 | 谁显示 |
|---|---|---|
| `👁` / `🚫` | **声明**：`/models` 里那条自己写了 `input_modalities` / `modalities` / `capabilities.vision` 这类 | 候选那一行 + 行徽标 |
| `👁` / `🚫` | **探测**：真发一张 1×1 的图，服务商收下了算能、明确拒了算不能 | 行徽标 |
| `👁?` | 还没结论（没声明，也没探过） | 行徽标 |

**探测结论优先于声明**（真问过一次比它自己写的更算数）。**表里没有结论的，界面顺手探一次**
（一行一次，同一对（地址 · 模型）不重复问）；**服务商没给结论的（连不上、钥匙不对、没这个模型）
一律不下结论**，也不写进表——"没声明"不等于"不能"。

**模型名字一个字都不算依据**：`deepseek-vl` 与 `gpt-4o` 这种名字既不能证明能看图，也不能证明不能。

## 6.3 三样东西三个家（与上层设计 §七 同一条）

| 东西 | 住哪 | 谁写 |
|---|---|---|
| 链路（地址 · 模型 · 上下文窗口 · **密钥**） | `%APPDATA%\工具箱\API\链路.json`（C 盘，**不在软件目录里**） | 这一页 |
| 这家提供哪些模型、各自声明了什么；每个（地址 · 模型）的图片能力结论 | `%APPDATA%\工具箱\API\模型表.json` | 服务商那一面 |
| 哪个请求走哪条路由 | `程序/对接层/cordis.patch.yml`（`!!js`），**界面只读** | 用户手改 |

**密钥只进不出**：存下去之后页面拿不到它（`getSettings()` 交的是 `keyConfigured`），
要问服务商时由服务商那一面按 `id` 配钥匙。**它是明文写的**，页面上一句话写清了真路径
（`#linkStorePath` 现问宿主要，界面不拼第二份）。

## 6.4 提示词页：预设与世界书工作区（V1.5.1）

工作区采用酒馆世界书的通栏版式。顶部左侧是已启用书的多选标签框，右侧是折叠的「启用与预设设置」；下面一行选择当前编辑的世界书并放置新建、导入、复制、导出、改名、删除图标，再往下是搜索工具栏与紧凑条目列表。没有左侧目录和按请求排列的启用卡片。编辑选择是页面状态，启用列表来自模块存档，两者互相独立。模块动作仍只走 `/toolbox/调`。

多选框集中显示主 AI 和三个基础请求已启用的世界书，标签携带所属请求信息，可逐本移除。点「＋」展开多选列表，勾选作用于折叠设置中选定的请求；查看其他预设不会改变实际启用列表。主 AI 始终读取并写入实际执行预设的世界书引用。翻译、识图、文生图各自默认启用对应基础书；对应关系仍由装配层注入。用户明确停用后，刷新或重启不重新开启。默认主 AI 预设的引用列表仍只读，三个基础请求的启用设置不受主 AI 只读影响。

编辑选择器列出全部世界书与预设编辑入口，初始显示文生图基础世界书。切换编辑对象、复制书或保存正文均不修改启用列表；启停只重画顶部，保留编辑对象、未保存正文与关键词。预设查看选择器、新建与导入收在右侧折叠设置中，原有预设和工具编辑能力保留。基础提示词不自动挂入主聊天预设，主 AI 工具仍由工具表提供。

世界书条目收起时即显示可编辑标题、触发方式、插入位置、深度和角色；行首开关与这些字段均直接保存局部修改，保留正文与关键词的未保存编辑。插入位置与角色选项来自宿主「条目」参数的界面字段。正文展开后显式保存，条件 JSON 仅编辑 `keys`；其余字段由行内控件负责，不重复编辑。搜索覆盖标题、正文及关键词，展开/收起只作用于搜索结果。默认内容只读，复制后编辑。酒馆的排序权重、触发概率没有本项目执行能力，不增加无效列。预设里的身份、流程、模型、工具、程序附加和发送预览继续使用折叠分段。

| 页面内容 | 唯一来源与行为 |
|---|---|
| 身份、流程 | 主 AI 预设；分别在系统提示词 order 0、5100 |
| 工具注册表 | 预设的工具表；展示名字、开关、参数与说明。默认表仍从模块动作现算，运行登记复用 `登记工具` |
| 文生图、画师品质、识图、翻译等正文 | 世界书模块的条目，保留常驻、关键词、落点与启用状态；三份默认均可查看 |
| 主 AI 挂书 | 顶部修改实际使用预设的 `worldbook`；本次通过世界书 `执行({启用})` 取命中，不另存请求订阅 |
| 识图、翻译、文生图请求挂书 | 世界书模块的请求启用列表；正文始终只存世界书 |
| 模型 | 预设的 `model`，存链路标识与模型名；空链路使用 API 表第一条，指定不存在的链路明确失败 |
| 发送预览 | 读取当前请求存档的预设与本轮文本命中；工具表作为 tools 字段展示，不伪装成一段正文 |

默认预设与默认世界书只读，编辑先创建副本。新建预设后在同一个操作内切换当前请求到新预设；复制与导入只新增，预设按「设为当前」启用，世界书在顶部启用列表中加入。运行读取启用列表中的第一套预设，界面明确显示这一点。

正文编辑按保存落盘；预设保存、工具保存、条目保存各对应自己的修改与 `存`。改名、删、启用、复制、导入也立即 `存`。预设导出含身份、流程、工具、世界书引用与模型，直接走模块的完整导出。

### 6.4.1 独立启动助手

双击启动只需界面服务。会话由 `程序/会话模块/index.js` 管理，每会话住 `程序/工具箱数据/会话/<会话ID>.json`，当前选择属于页面 preferences；启动至少提供一条空会话，输入框据此开放。每轮读主 AI 存档、登记同一份工具表、取预设引用的世界书，使用 API 链路表发送。工具回执再次交给模型，直到模型返回最终回复或用户停止，不另设循环次数上限。

会话动作仍用 `/对话/*`，变化通过 SSE 推送。前端按服务端版本接收状态，避免发消息的旧回执覆盖已经完成的状态；切换会话时重连对应流。模型回复整条接收，工具进度和会话状态通过 SSE 更新。运行中的会话拒绝重复发送，并把理由交回输入区；本版不提供队列与插队。

DSH 插件仍使用 DSH 的会话与循环，独立界面不查桥的发现文件，也不作桥失效后的回退。

旧方案原文保存在 [提示词页两字段旧设计](旧设计/_旧设计_提示词页两字段_已被界面设计V1.5.1取代.md)。

# 七、参数怎么变成控件

**两张表合起来才是一个参数的全部说明**，它们住同一个文件（`程序/对接层/模块清单.js`）：

| 表 | 回答什么 | 谁读 |
|---|---|---|
| `参数类型` | 这东西在模型那一侧是什么类型（JSON Schema） | 工具定义 |
| `界面字段` | 界面上用什么控件、对象里有哪些字段 | 交付面 |

**查不到的参数**：说得出的按标量走（`array`→标识、`boolean`→开关、`number`→数字），说不出的当文本框；
`引用` / `作用域` / `产出` 这三样界面不认识就给 `context`——**由哪个面板去填由那个面板自己决定**。

**两条硬规矩**：

1. **不给校验、不给默认值、不给必填**。留空就是不传；必填留空照传，模块自己拒绝并给码。
   （界面加一条"这个必填"，就等于模块之外多了一个约束来源。）
2. **`context` 那类参数不给人填**。它由面板从上下文里挑好再递：图库挑中的那一张、
   刚出的那个产出、从上一个面板交接过来的引用。

**参数值的读法只有一条**：先按 JSON 解，解不出来就是字符串——**这一条只对对象形状的参数生效**，
其余按原字走。原因与调试台那一条相同：界面不去猜类型，猜错了就是"界面替用户决定事情"。

**拦阻画在面板里，不弹窗**：一句"先挑一张图"应该是面板里的一行提示。
弹窗遮住整页、也留不下痕迹。

## 6.1 动作名用哪一套（这一条踩过坑）

| 名字 | 长什么样 | 谁用 |
|---|---|---|
| **模块侧**（模块自己那层） | `query` · `认图` · `出图` | **界面用它**——`门.run()` 认的就是它 |
| **模型侧** | `query` · `detect` · `generate` | 工具注册表（`<模块键>_<动作名>` 的后半段，只含 ASCII） |

交付面上 `动作` 是模块侧、`模型侧` 是另一套，两条都交出来就是为了让人看得见这个差别。
**面板里调动作一律写模块侧那一套**：写错了不会当场炸，要等用户点下去才报
`HOST_NO_SUCH_ACTION`——所以自检里有一条专门盯它（§十一）。

两边都认：宿主那一层收到模型侧的名字会查一次反表翻过去（HTTP 那一面因此对 curl 也宽容），
浏览器那一侧的 `宿主.调` 也索引了两种名字。但**面板自己写的那一套只准是模块侧**。

# 八、字节怎么走

**JSON 里不带图。** 一张 1.2 MB 的 PNG 过一趟 JSON 要变成约 160 万字符，图库里排几十张就是把几百 MB 塞进页面。

| 路 | 收 | 回 | 谁用 |
|---|---|---|---|
| `GET /字节?存放地=&条目ID=&变体=` | 引用 | 原图字节 | 看大图、识图、出图的输入 |
| `GET /缩略图?存放地=&条目ID=&边长=` | 引用 | 现缩的图 | 图库格子（一次几十张） |
| `POST /存图` | `{ 字节, 文件名, … }` | 模块的 `存` 回执 | 上传、出图取回 |

**缩略图不落盘，现读原图现缩。** 三条理由：

1. 图片模块的派生变体要给装配层递一个"处理图片"才生成——现在没给，所以 `preview` / `thumbnail` 本来就不存在；
2. 一份缩略图在盘上就是第二份真相：格子用哪一档，凭什么要存进条目里；
3. 现缩只在第一次付代价，之后按 `条目ID|边长` 记在内存里（267 条封顶）。

**两条 GET 靠 Cookie 认令牌**：`<img>` 发不了自定义头，所以页面那一次响应会下一个 `HttpOnly; SameSite=Strict` 的 Cookie。
三条 POST 仍然要 `x-toolbox-token` 头。

**缓存**：两条 GET 都带 `ETag` 与 `Cache-Control: private, max-age=31536000, immutable`。
条目 ID 是每次存图新生成的，所以同一串地址的内容不会变——`304` 那条路是通的（实测）。

**缩不出来就给原图**：`sharp` 不在、或者这张不是它认得的格式，`/缩略图` 照原样把原图交回去。
界面永远拿得到一张能画的图，代价只是这一次大一点。

# 九、长任务：出图

**出图能跑 30 分钟**（模块的 `上限毫秒` 默认就是这个量级），而一条 HTTP 连接可能先断。所以它走任务那条路：

```
页面  POST /toolbox/任务 { 什么:'出图', 参数 }     → { id }
页面  EventSource /toolbox/任务/流?id=…            ← 模块报的状态一条条推
页面  POST /toolbox/任务/看 { id, 从 }             ← 断线了随时补
```

| 设计点 | 怎么办 |
|---|---|
| 模块的事件 | 出图那条路支持 `onEvent`。HTTP 递不了函数，**由服务这一侧造一个**递进去，收一条记一条 |
| 进度 | 模块只报**状态切换**（已提交 · 状态 · 完成），**没有百分比**。界面只画状态与已等时间 |
| 断线 | 任务挂在内存表里（最多 50 条、做完留 6 小时）；页面回来按 `?从=N` 接着要 |
| 取消 | 这一版不给取消按钮：模块要一个 `AbortSignal`，而那条信号也过不了 JSON |

**这一条是"约束看得见"的正例**：界面上一句"模块只报状态切换，没有百分比"，
比一个动来动去的假进度条诚实，也让人知道该等多久。

# 十、面板与宿主之间

```
页/壳.js          外壳：侧栏 · 顶条 · 切面板 · 模型条 · 重读动作表
      ↓ 造面板们(上下文)              上下文 = { 宿主, 模子, 交出去, 接过来, 盯着 }
页/面板/*.js      十二块面板：只有"这个动作怎么调、这个回执怎么画"
      ↓ 宿主.调(模块, 动作, 参数)
页/宿主.js        宿主接口 · 浏览器这一侧。**面板不直接 fetch**
      ↓ fetch
服务.js           路由 · 令牌 · 字节 · 任务
      ↓ 宿主.js（服务那一侧）
模块
```

**`页/宿主.js` 是唯一一处 fetch。** 它存在只为一件事：将来把界面搬进别的壳里
（挂在 DSH 的 Web 界面上、或者改成进程内直调），换的只是这一个文件。

**回执一律原样画**：成功给 `data` 本身，失败给 `{ ok:false, reason, code }`——两种都原样交回。
一处例外是为了看得见：回执里带的原始字节画成图（JSON 里换成一句"多少字节"）。

```bash
node 程序/对接层/界面/试/无头.js        # 123 条：十二块面板（假 DOM）
node 程序/对接层/界面/试/皮实测.js      # 117 条：旧版那层皮（真浏览器 CDP）
```

**`无头.js` 真起服务**（真装配、真模块、真数据），把外壳与十二块面板在一个够小的假 DOM 上真画一遍。抓四样：

| 抓什么 | 怎么抓 |
|---|---|
| 语法错、名字打错、方法不存在 | 一画就露：十二块面板逐个点开、真跑 |
| 画的时候抛异常 | 面板里那句"这块面板画不出来"不该出现 |
| 面板契约破了 | 导航九项齐；交付面上每条动作都带齐 模块/动作/摘要/参数/控件 |
| **面板自造类名** | 源码级：把每份面板 `造()` 用到的类名捞出来，对 `页.css` 与 `组件.css` 的类名表核一遍 |

**`皮实测.js` 起真服务 + 真浏览器**，把旧版那层皮按屏幕点一遍；其中两块（API 配置页 27 条 ·
提示词页旧方案 13 条；现行另见 AI 页专用回归）落在**我们自己造的东西**上，所以不需要真 key、也不碰用户的数据：

| 判据 | 怎么验 |
|---|---|
| 链路真存得住 | 加一行 → 存档文件里真多一条；地址与型号写下去就在 |
| **点模型那一格真去服务商那边取** | 候选逐条对得上假服务商给的那几个；**服务商没提供的不出现** |
| **候选点得中**（用户报的那条） | 点一下摊开 → 停住不消失 → 点一条填进那一格 → 收起；点别处 / 再点也开得回来 |
| 候选上带服务商的声明 | 声明写了 image 的带 👁、只有 text 的带 🚫、没声明的只给一个点 |
| **型号自己填也存得住** | 填一个服务商没有的型号 → 存档里就是它；它不进候选 |
| **没结论的顺手探一次** | 假服务商收下的那个变成 👁、拒掉的那个变成 🚫；结论按（地址 · 模型）进 `模型表.json` |

| 测试连接真发请求 | 吐司说得出这次走的是哪条链路 |
| **提示词页真接上了主 AI 预设** | 默认那份的人设与流程真显示在框里；只读默认那一份时两格只读、写钮灰着、说清出路 |
| **「还原默认」/「清空」真回到该有的样子**（用户报的那条） | 改一段 → 盘上就是它；点「还原默认」→ 框里与盘上都回默认那份；点「清空」→ 两处都空 |
| V1.5.1 提示词展示 | 工具表与全部世界书入口可见，默认只读、用户副本可编辑 |
| 提示词组 = 预设 | 新增一组 → 盘上真多一份（照着默认抄的）、框能改了；切换 → 显示的是那一份 |

**假服务商**：`/v1/models` 交四个模型（两个在声明里写了图片能力、两个没写）；
`/v1/chat/completions` 对带图的请求一个收下一个拒掉。**存档指向一个临时 `--数据目录`**，
提示词页那份 `程序/工具箱数据/主AI/预设.json` **跑完放回原样**（原本没有就删掉）。

另外几条判据在同一个脚本里：令牌注进页面 · 不带令牌取字节被挡 · 取不存在的条目如实给码 ·
认不出的任务被拒 · `页面那条路走不出页目录` · 没这条路就 404 · 识图那三个按钮真调到模块 ·
识图工作区写完仍是单张 · **标签面板那一路真点一遍**（分类栏读出来 · 卡片墙铺出来 ·
点卡片已选栏跟着说 · 按 Enter 真调 `query`）。

**为什么不用 jsdom**：本仓库运行时零依赖，不自带它。自检那份假 DOM 只实现面板真正用到的那几样
（造元素 · 类名 · 事件 · `cloneNode` · `hashchange`），**它不断言长相**——长得对不对只能人看。

**自检不查什么**：功能对不对、好不好看。那只能真人用。**真服务商**（真 key、真地址）也没进自检：
那一趟要么花用户的钱，要么得往自检里塞一把钥匙。人自己填一次就知道。

# 十三、决定记录

| # | 决定 | 由来说 |
|---|---|---|
| 1 | **界面住 `程序/对接层/界面/`，是一个本地服务加一个浏览器页面** | 与调试台平级；动作浏览器已经证明这条路能跑通（浏览器 → HTTP → 宿主 → 门面） |
| 2 | **零构建**：原生 ES module + 一个 CSS | 与"无构建步骤 · 轻量化"同源 |
| 3 | **界面只调 `POST /toolbox/调`** | 它跟模型一样只是门面层的一个使用者；多一条路就多一种能力 |
| 4 | **面板不直接 fetch**，走 `页/宿主.js` | 将来搬进别的壳，换的只是这一个文件 |

## V1.5.5 绘图开关修复

聊天区与 ComfyUI 设置页的「启用绘图」共用模块的 `绘图开关({启用?})`，通过 `/toolbox/调` 读写。`comfyOn` 是界面适配字段，实际值只保存在现有 ComfyUI 工作流存档的顶层 `启用`；导入、替换或清除工作流不改变它。连接和工作流就绪情况由异步探活与认口刷新，开关在离线或没有工作流时仍然可点。

`出图` 在操作开始和提交前检查开关，关闭时返回 `COMFY_DISABLED`，不向 ComfyUI 提交。关闭不等于中断已提交的任务。模型工具仍按预设清单提供，统一由模块执行这项用户选择。

回归入口：`node 程序/对接层/界面/试/绘图开关.js`。它使用真实宿主、真实浏览器、隔离存档及模拟的 ComfyUI/模型服务，覆盖两个勾选框、离线切换、失败回滚、页面刷新、服务重启和 AI 工具执行；不会触发本机真实绘图。

## V1.5.4 聊天展示设计

### 展示与数据

| 区域 | 来源 | 展示与交互 |
|---|---|---|
| 用户输入 | user 消息的 id、parts、createdAt | 一条消息一个气泡；原文换行、图片和复制操作保留。 |
| 本轮过程 | Turn 及所属 assistant 消息的 reasoning、toolCalls | 用户输入之后放一份过程摘要，显示真实状态、耗时、工具次数。思考、工具和中间说明放在可展开区域；完成后默认收起，用户展开后刷新同一记录保持选择。 |
| 工具详情 | 工具声明及 ToolCall 的 args、result、status | 名称取宿主动作表，不另存工具名清单。参数和回执可以展开查看、复制；对象和数组按通用结构展示，完整原文保留。 |
| 最终结果 | 本轮最后一份有正文的助手消息，以及图片块 | 正文独立于过程区；支持段落、标题、列表、引用、表格、链接、行内代码和代码块。表格与代码在区域内横向滚动，代码可单独复制。图片沿用会话引用与现有预览链路。 |
| 失败与停止 | Turn.status、Turn.error | 失败原因原样显示在折叠区外；失败、停止、中断不画成完成。已产生的正文与工具回执保留。 |
| 回复信息 | assistant.model、createdAt | 正文下方保留一次复制、时间与实际服务商/模型信息。 |
| 输入与保存状态 | 会话运行位、草稿、未保存错误 | 沿用现有发送、停止、附件和草稿门面；提交或保存失败仍有可见说明。 |

Markdown 解析器随页面本地分发，无浏览器 CDN 依赖。原始文字始终是复制与持久化的来源；渲染结果不写回消息。链接和图片按 Markdown 数据呈现，不从普通文字推测模块动作。公式、专用图表及新的用户确认协议在有实际数据契约时另行设计。

### 接口与职责

`view-bridge.js` 从现有会话记录生成轮次投影；`dsh-chat.js` 负责消息、过程、结果与状态的唯一渲染；`chat-markdown.js` 负责文字到 DOM；`dsh-mount.js` 连接会话状态和宿主动作声明。`app-view.js` 保留输入及保存错误，不再重复展示已由轮次负责的完成状态。业务动作仍经 `/toolbox/调`。

`#talkConv` 是唯一纵向滚动区。仍在跟随底部时，新回复自动进入视野；用户向上翻看历史后，后续更新保持阅读位置。工具详情在用户展开时创建结构视图，参数原始字串单独保留供复制；工具状态更新后沿用本次展开选择。原来的独立过程派生脚本与底部完成状态已移除。

草稿保存会通知会话订阅者，聊天区也会收到新的会话快照。`dsh-chat.js` 按消息段复用 DOM：文字、文件与图片使用界面可见字段作为指纹，图片按标识识别；工具段保留参数与回执对象身份，因此同一调用的回执变化仍会刷新。工具段与结果图片段分开缓存，打字只更新草稿时图片节点继续使用原节点。未知块按对象身份更新；复用判定不遍历或序列化大回执，详情仍按展开状态懒加载。

默认主 AI 预设只增加表达说明：先给当前结果，按内容采用简洁 Markdown，标签与代码便于复制。它不规定工具调用步骤、不隐藏推理、不添加调用次数与输出长度上限；用户预设保持原样。
