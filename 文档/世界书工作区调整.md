# 世界书工作区调整与验收

## 目标与设计（2026-10-17）

以用户标注的截图为准：左侧选择请求模块，右侧整体展示该模块的世界书工作区。上方是当前模块启用的多本书，中间选择正在编辑的一本书，下方编辑该书条目。主 AI、文生图、翻译、识图拥有独立书籍范围。

现状有三处差异：顶部汇总所有请求的启用书；书库共享而无请求归属；关键词通过 JSON 编辑，触发方式切换与关键词内容未形成直接的表单操作。

## 调整计划

1. 世界书模块为用户书存储 `scope`，表行通过 `请求` 回答归属。默认书归属由装配层已注入的默认映射计算。按请求读书表、设置启用及执行时都使用该归属。无归属旧书原文件保留，不猜测、不迁移。
2. 左侧以宿主返回的请求默认映射生成入口，并加入主 AI。右侧整块随请求切换；编辑选择及本页未保存内容按请求和书分别保留。
3. 顶部只显示当前请求的真实启用列表，可启用零至多本；编辑书的下拉只显示当前请求的书。主 AI 启用列表继续来自实际使用预设的世界书引用，默认预设只读，可显式复制并启用后编辑。
4. 世界书的新建、导入、复制归入当前请求，均不自动启用；导出只输出当前编辑的一本。没有书时提供新建、导入入口。主 AI 身份、流程、工具及请求模型设置保留独立的预设入口，不混入书籍选择。
5. 条目提供启用开关、常驻/关键词方式、每行一个关键词的输入及正文编辑。编辑正文和条件后显式保存；开关、落点等行内设置保存时保留尚未保存的文字。
6. 更新界面和模块契约、决定记录及补丁版本；运行模块、装配和真浏览器回归，进行视觉检查，再打包到桌面并验证交付副本。

## 实现细节

- 主 AI 的启用书仍引用实际执行预设，正文只存世界书模块一处；副请求从世界书模块读取各自启用存档。DSH 装配与独立界面采用相同来源。
- 用户书标识使用 UUID，删除后不复用；宿主在书籍删除成功保存后清理用户预设引用。书保存失败不先清引用；引用清理失败明确报告“世界书已保存”，保留重试标识，再次保存可重试，重读不会取消已经落盘删除的引用清理。
- 切换读取期间整个右侧工作区不可操作，导航显示禁用，避免异步读取期间把旧模块操作写入新模块。读取失败显示错误和重试入口。
- 未保存字段按模块、书及条目标识暂存在本页内存；保存条目只清掉该条目的草稿，其他条目继续保留。页面刷新仍以已保存内容为准。
- 显式选择关键词触发但关键词为空时不命中；填写任意关键词后按匹配参与，选择常驻后清除已保存关键词。

## 最终效果验收

| 用户操作 | 应有结果 |
|---|---|
| 点击左侧模块 | 右侧标题、启用列表、编辑选择、条目及预览全部跟随模块，其他模块的书不出现 |
| 一个模块启用两本书 | 两本均参与该请求执行，其他模块保持原启用状态 |
| 移除全部启用书并刷新/重启 | 该模块持续为空，不重新启用默认书 |
| 启用 A、编辑未启用的 B | B 的编辑不改变 A 的启用，也不让 B 进入模型请求 |
| 在不同模块导入同名书并修改其中一本 | 两本归属和正文独立，不能通过跨模块引用参与另一个请求 |
| 编辑正文/关键词后切书或切模块再回来 | 未保存内容、触发方式和展开状态保留；顶部启停操作也不清掉这些内容 |
| 关键词触发条目 | 命中任一关键词才参与，未命中不参与；停用后始终不参与；常驻条目不依赖关键词 |
| 导入/导出 | 每次仅一本；导入归当前模块且不自动启用；导出再导入后正文与条件相同 |
| 编辑默认书 | 默认正文只读；复制后在当前模块内编辑用户副本 |
| 主 AI 实际发送 | 使用实际预设引用的主 AI 书，不混入翻译、识图、文生图书；发送预览与真实报文一致 |
| 宽窄窗口、浅深色 | 侧栏和编辑区域清楚，控件可达，无页面横向溢出 |
| 桌面交付副本 | 版本正确，可从交付目录启动并显示新工作区，运行资源来自交付副本 |
