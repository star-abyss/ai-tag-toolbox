# 一、这个项目是什么

**一个本地运行的 AI 绘画工具箱。** 它由 Node.js 服务和系统浏览器页面组成；Windows 双击入口会在 cmd 控制台前台运行 Node 服务，服务准备好后打开系统浏览器。界面提供 Danbooru 标签选择、ComfyUI 出图与 AI 对话调度。

**这是重写版。** 旧目录（同级的 `工具箱/`）里的实现、文档、数据**一律不作参考**，
也不拿来对照。需要什么，按本仓库的架构重新写。

## 1.1 三条定位

| # | 定位 | 它的意思 |
|---|---|---|
| 1 | **本地** | 不上服务器。跑在用户自己的机器上 |
| 2 | **小型化 · 个人项目** | 一个用户、一台机器。不付多人协作与多写者的复杂度 |
| 3 | **轻量化** | 无构建步骤；`node` 能直接 `require` 整棵树 |

## 1.2 实现策略

**以实现功能为优先目标。** 不随意加安全性、验证性、规范性、防范性的内容；
保证输入输出规范即可视为达标。**可加可不加的东西不加，约束性的东西不加。**

推论：

- **不加兜底机制。** 卡死了用户自己会按停止按钮。
- **不加隐藏上限。** 任何对 AI 的约束都必须能在界面上看到。
- **格式由程序负责，内容由 AI 负责。**
- **流程只写在提示词里**，而且由用户自己写；代码里不预置流程。

## 1.3 三条判据

改任何与 AI 相关的代码之前，用这三条过一遍：

```
① 工具不替 AI 决定任何事情。
② 工具提供的约束必须能在界面上看到。
③ 工具只提供格式封装和必要的格式说明。
```

**违反任一条即视为缺陷。**

# 二、技术选型与理由

| 选了什么 | 为什么 | 换掉它的代价 |
|---|---|---|
| **无构建步骤**（CommonJS，直接 `require`） | 交付包能在 node 里直接装配整个应用，于是能在没有 Electron 的情况下跑全部自检 | 失去秒级验证 |
| **六边形**（核心 + 端口 + 两个适配器） | 核心不认识盘，所以内存适配器能跑通同一套判据 | 端口封不住就成了说法 |
| **依赖从装配层递进来** | 模块自己不找、不猜、不探测路径 | 模块会开始认识别的东西 |
| **一个模块一个目录、对外只有 `index.js`** | 边界可见：谁调谁一眼看得出 | 内部件被递出去，边界就没了 |
| **中文动作名 + 中文回执字段** | 写出来的东西能直接读 | 读代码要先做一次翻译 |
| **失败一律 `{ ok:false, reason, code }`** | 调用方能分辨失败原因 | 失败被吞掉或变成一个 `null` |

**没选什么**：TypeScript（多人协作且类型错误成为主要 bug 来源时才谈）、前端框架（界面是列表加表单）、
数据库（文件就是数据库）、包管理器工作区（模块各自独立，没有共享依赖）。

# 五、每个模块长什么样

**有盘的三个模块结构是同一个形状，看一个就懂另外两个。**

```
<模块名>模块/
├── index.js             门面。**对外只有这一个文件**（出口 Object.freeze）
├── core.js              核心。纯逻辑，**不 require fs / path**
├── port.js              端口契约
├── adapter-file.js      文件适配器。**唯一 require fs / path 的地方**
├── adapter-memory.js    内存适配器。用来证明核心不依赖盘
├── test/                自检
├── tools/               探针、演示、验收脚本
├── README.md            给 AI 的上手指南
├── <模块名>设计.md        设计规范：范围 / 需求 / 架构 / 数据 / 接口 / 错误 / 不做什么 / 验证 / 决策记录
├── 接口 那份             契约：字段名、类型、必填、错误码
└── package.json
```

**装订模块没有盘**，所以形状是同一个、少了存储那两件：

```
装订模块/
├── index.js             门面
├── core.js              核心。纯逻辑，不 require 任何别的模块
├── port.js              端口契约（两个递进来的函数）
├── adapter-fake.js      自包含的实现，用来跑自检
├── adapter-real.js      真实链路的实现
├── test/ · README.md · 装订模块设计.md · 接口.md · 调用示例.md · package.json
```

**comfyUI 模块也不碰盘**，但要发请求：形状同一个，把存储那两件换成通信那两件。

```
comfyUI模块/
├── index.js             门面 + 动作表（十个动作）
├── core.js              核心：连接 / 存档 / 认口 / 出图编排
├── graph.js             图：两种形态互转 · 认口 · 填口（纯函数）
├── port.js              端口契约（七个方法）
├── adapter-http.js      真实链路的实现。**唯一发请求的地方**
├── adapter-memory.js    自包含的实现，用来跑自检
├── test/ · tools/ · README.md · comfyUI模块设计.md · 接口.md · 调用示例.md · package.json
```

**翻译与识图两个模块也不碰盘**：它们的"外部世界"（切分 / 查词 / 模型 / 位图 / AI 链路）**全是递进来的函数**。

```
翻译模块/                          识图模块/
├── index.js  门面（三个动作）      ├── index.js  门面（四个动作）
├── core.js   编排，纯逻辑          ├── core.js   四条路的编排
├── port.js   端口（切分/查词/译）   ├── port.js   端口（取图字节/查词/tagger/看图/读元数据）
├── adapter-fake.js / adapter-real.js
├── test/ · README.md · 设计.md · 接口.md · 调用示例.md · package.json
```

**识图模块另外多一个纯函数文件** `元数据.js`（PNG 文字块解析），它不 `require fs`，只吃字节。

## 5.2 调用链方向永远一致

```
装配层 → index.js（门面） → core.js（纯逻辑） → port → adapter-file.js（盘）
```

**反向引用 0 处。** 核心不许 `require fs / path`；它只说"读存档 / 写存档"这类话，由适配器翻成真实路径。

# 六、三层架构

```
① 模块层    提供能力。互不认识，也不认识模型、界面、Agent 框架。
      ↓ 被使用（不是被包裹）
② 门面层    对外的全部。模型和界面都只跟这一层打交道。
      工具清单（给模型）· 通用面板（给人）
      **一个工具可以用多个模块**——工具的数量不由模块数量决定
      ↓ 由谁执行
③ 执行层    那一段顺序：归一化参数 → 向模块要东西 → 调模块 → 整形结果
```

| # | 要点 |
|---|---|
| 1 | **模块不进清单。** 模型根本不知道有哪些模块 |
| 2 | **工具不是"模块的壳"。** 一个工具可以用多个模块 |
| 3 | **工具的数量由"要给模型几件事做"决定**，不由模块数量决定 |
| 4 | **执行层不属于任何模块。** 跨模块的那段顺序，只能落在调用方 |
| 5 | **共用逻辑放在装配层**，它不是模块，也不是工具 |

**三条边界规则**（每个模块都要守，全表在 [AGENTS.md](../AGENTS.md)）：

| # | 规则 | 检验法 |
|---|---|---|
| 1 | 一个模块**只交出一份清单** | 宿主与界面读取模块清单；模型从装配层的单份绘画业务定义取得工具，不从模块全量动作直接生成，没有模块双份清单 |
| 2 | **对外的参数永远是标识** | 看 `describe()` 的参数名有没有路径 / 地址 |
| 3 | **不解析不属于自己的东西** | 要解析别的模块的数据结构 = 字段定义放错了地方 |

# 八、新增一个模块要做什么

**照着做。任何一步的产物都要能在自检里体现。**

1. **建目录** `<模块名>模块/`
2. **写代码**：`index.js` / `core.js` / `port.js` / 适配器 / `package.json`
   （有盘的模块是 `adapter-file.js` + `adapter-memory.js`；没盘的模块按它的端口写自己的适配器，见装订模块）
3. **写四份文档，顺序不能乱**：
   - `README.md` —— 给 AI：索引 + 东西在哪 / 怎么调 / 哪条不能动 / 改完怎么验（照 [图片模块/README.md](../程序/图片模块/README.md) 的十节骨架）
   - `<模块名>设计.md` —— 设计规范，**自包含**，不引用别的模块的设计
   - `接口.md` —— 契约。**改实现之前先改它**
   - `调用示例.md` —— 调用示例与错误表
4. **写自检** `test/run.js`：加一条能力就加一条判据
5. **在本文件 §四 的模块清单里加一行**，在 [README.md](../README.md) 的模块表里加一行，
   在 [AGENTS.md](../AGENTS.md) 的模块清单里加一行，在 [AI导览.md](AI导览.md) 补入口，
   在 [项目目录.md](项目目录.md) §二 加那一行文件说明
6. **跑自检**

**模块之间平级**：目录结构同一个形状，互不依赖。

**加一个模块到对接层**（那个模块本身不算装配层，接线是装配层的活）：

1. 在 `程序/对接层/模块清单.js` 里加一行：**英文模块键** · 门面路径 · 工厂名 · 装配选项
2. 若它的动作名不是 ASCII，在同一条里补 `动作名` 对照（模块自己那层的中文名不动）
3. 在 `程序/对接层/接口.md` §三 的模块键表里加一行
4. 跑 `cd 程序/对接层 && node test/run.js`；工具条数那条会自动跟着变
