  翻译模块 · 设计规范

> **自包含。** 不引用别的模块的设计。整栋楼的三层结构与边界规则在根 [AGENTS.md](../../AGENTS.md)。
> 上手指南在 [README.md](README.md)；字段名与错误码在 [接口.md](接口.md)。

**一句话**：**一段文本切成一格一格，库里查得到的给中文名，查不到的交给本地模型，再按原样拼回来。**

---

   一、范围

    1.1 它做

|   | 做什么 |
|---|---|
| 1 | 切分：调**递进来的**切分函数，把文本变成一格一格 |
| 2 | 查词：把每格的「词」交给递进来的查词函数 |
| 3 | 挑剩下的：库里查不到、又不是目标语言的格，才准备交出去 |
| 4 | 组报文：原文 + 待译词表 + 方向，交给递进来的本地模型 |
| 5 | 拼回：库译名优先、其次模型译文、再其次原词 |
| 6 | 一次只跑一次：同时在飞的只有一个（闸门走 `finally`） |

    1.2 它不做

| 不做 | 归谁 |
|---|---|
| 不认识标签库、不解析它的字段 | 查词函数（装配层递进来） |
| 不认识模型、不读盘、不探测路径 | 本地模型引擎（装配层递进来） |
| **不拥有切分** | 装订模块那一套；装配层递同一份进来 |
| 不认识 AI、不发请求、不管链路 / 密钥 / 超时 / 重试 | AI 那条路是**装订模块**；本模块只管本地那条 |
| 不解释权重 / 括号 / 转义的**语义** | 程序只把它们当壳移动，不当意思读 |
| 不解析模型返回的语义 | 只挑自己发出去的那些词，其余不看 |
| 不落盘、不保存任何东西 | 无存储 |
| 不做兼容层、不留回退开关 | 要回退用 git |

    1.3 它跟装订模块的分工（本模块存在的理由）

**两条路，用户自己挑：**

```
装订模块   查不到的词 → AI        要钱、要网、通顺句子也行
翻译模块   查不到的词 → 本地模型   离线、免费、只擅长度短的词与短语
```

**为什么不让一条路自己切两种模式**：两条路的失败表现、等待时间、能不能离线都不一样；
"用哪条"是用户的选择，按判据②必须在界面上看得见——**做成两个工具，就是让它看得见**。

**为什么切分只有一份**：切分是"这段文本长什么样"的判断，两条路必须得出**同一结果**，
否则同一个词在两条路上的分格都不一样。两处各写一套就是"必须和别处保持一致的清单"（规则 7）。

---

   二、术语

| 词 | 意思 |
|---|---|
| **单元** | 切出来的一格：`{ 前, 词, 后 }` |
| **壳** | `前` 与 `后` 合起来，装括号与权重 |
| **格** | 有内容的单元（`词` 非空） |
| **报文** | 交给本地模型的那份东西：`{ source, words, from, to, 模型? }` |
| **键值对** | 模型回来的东西：`{ 词: 译文 }` |
| **三路来源** | `库` · `模型` · `原词` |
| **方向** | `en-zh` · `zh-en` · `auto`（按字数猜） |
| **在飞** | 闸门。一次译在跑时它立着，跑完就放下 |

---

   三、约束

|   | 约束 |
|---|---|
| 1 | 对外的参数只有「文本」「方向」「模型」；**没有路径 / 地址** |
| 2 | 核心不 `require fs` / `path`，不 `require` 别的模块 |
| 3 | 一个模块只交出一份清单：`describe()` 就是那一份 |
| 4 | 失败一律 `{ ok:false, reason, code }`，走 `本地译` 的带 `原文`；**不抛错**（装配阶段除外） |
| 5 | 出口 `Object.freeze`，不递内部件 |

---

   四、需求

| 编号 | 需求 |
|---|---|
| R-1 | 能把一段文本按递进来的切分函数切成一格一格 |
| R-2 | 每一格先查库；查到就用库译名，且**不问模型** |
| R-3 | 库里没有的才交给模型；一次只发一批 |
| R-4 | 模型没给的词**照抄原词**，不许丢格、不许串格 |
| R-5 | 方向三种：`auto` / `en-zh` / `zh-en`；写别的明确失败 |
| R-6 | 目标语言是中文时，已经是中文的格不必交出去 |
| R-7 | 壳与空格原样保留，程序不做任何"整理" |
| R-8 | 同时在飞的只有一次；进行中再调给 `TEXT_LOCAL_BUSY` |
| R-9 | 任何失败都带 `原文`（走 `本地译` 的那几条） |
| R-10 | 模型回错键、回空串、回非对象：一律当"没译出来"，不串格 |

---

   五、架构

```
装配层
  ├── 切分（装订模块那一套）
  ├── 查词（标签模块的 认词）
  └── 译  （本地模型引擎）
        ↓ 三个函数
index.js（门面：动作表 · 直呼式 · describe）
        ↓
core.js（编排：切分 → 查词 → 挑剩下的 → 交给模型 → 拼回）
        ↓
port.js（三个函数的形状）
```

**核心是纯逻辑**：它只调那三个函数，不认识盘、不认识模型、不认识别的模块。

---

   六、一次本地译的编排

```
① 取原文快照
② 定方向（auto → 猜；明说 → 用明说的；写错 → 失败）
③ 切分（递进来的）
④ 查词（递进来的）→ 库译名[]
⑤ 挑剩下的：库译名 为空 且（方向是 zh-en 或 词里没有中文）
⑥ 有要译的才发一批（没有要译的 ⇒ 一次都不发）
⑦ 归位：只认自己发出去的那些键
⑧ 拼回：库译名 → 模型译文 → 原词
```

   九、决策记录

|   | 决定 | 由来说 |
|---|---|---|
| 1 | **本地翻译是独立的一个模块，不是装订模块的一个模式** | 两条路的失败表现、等待时间、离线能力都不同；"用哪条"是用户的选择，做成两个工具才看得见（判据②） |
| 2 | **切分不复制，由装配层递装订模块那一份** | 切分是"这段文本长什么样"的判断，两条路必须同一结果；两处各写一套就是坏清单（规则 7） |
| 3 | **查词与装订模块共用同一个函数**（标签模块的 `认词`） | 同一个词在两处不能给出两个中文名 |
| 4 | **三个端口都从外面递，模块不拥有任何一个** | 模块自己不找、不猜、不探测路径（规则 9） |
| 5 | **"已经是目标语言"按方向判，不按'是不是中文'判** | 中译英时中文格正是要译的；按后者判会把要译的东西吃掉 |
| 6 | **模型没给的词照抄原词，不丢格** | 失败的表现就是原文（跨模块判据）；界面永远有东西可显示 |
| 7 | **一次只发一批，同时在飞的只有一个** | 与装订模块同一条：有副作用的操作要挡住重入 |
