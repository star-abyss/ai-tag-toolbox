# 对话管理设计

## 组成与边界

正常的对话管理需要五部分：会话身份与当前选择；消息记录与模型上下文；发送、运行、停止及失败；本地存档与导入导出；向界面发布状态。这些由同一个模块负责，界面只展示快照并提交动作。

模块不认识 HTTP、DOM、服务商地址、主 AI 预设或业务工具。文件存储和本轮执行作为两个端口传入。`对接层/界面/助手.js` 负责装配预设、世界书、服务商和工具循环；`服务.js` 负责 HTTP 与 SSE；`页/对话管理.js` 负责浏览器状态投影与平铺会话列表；`dsh-mount.js` 负责挂载列表、DSH 消息区与输入卡。

## 消息和生命周期

`messages` 是消息内容的唯一存档。模型的 `history` 从消息、参考正文与工具轨迹生成，不另存一份消息正文。模块与执行器之间传副本，发布时只收消息记录；执行器无法改动会话标题或当前选择。

受理发送先占用本会话的运行位并保存用户消息，再启动执行。运行中再次发送、删除或清空该会话返回 `CHAT_BUSY`。停止通过 AbortSignal 交给执行端口，模块在 `finally` 中保存结果并释放运行位。切换或重命名可以发生在运行期间，回复始终回到开始执行的那条会话。

管理动作与存储写入分别按提交顺序执行。管理写入失败时还原此次管理操作涉及的字段，保留在途消息所属对象；发送保存失败时交回失败，撤销本次用户消息。每次成功的状态变更增加版本，SSE 与 HTTP 响应共用这一份版本。

## 验收

- 一次 Enter：一个可见用户消息、一个存档用户消息、一个携带该输入的模型请求。
- 左侧操作：新建、点击切换、改名、删除与空白会话管理正常；刷新保留当前选择。
- 管理页导出按钮下载可解析的 JSON，文件输入可导回；导入生成新 ID；清空后上下文也清空。
- 运行中的会话有停止能力和重入提示；操作失败不丢原内容，也不让在途回复失去会话。
- 所有读出口给副本；文件和内存适配器可替换；工具、预设与世界书仍通过原宿主执行。

## 决定记录

| # | 决定 | 原因 |
|---|---|---|
| 1 | 对话管理独立成应用状态模块 | 会话、消息与生命周期原来混在界面助手和页面适配中，改名没有实现，切换只有页面缓存 |
| 2 | 当前会话选择落盘 | 刷新或重启应回到用户正在看的对话；删除其他对话不应改变它 |
| 3 | 消息正文只存 `messages`，模型上下文现生成 | 展示记录和模型历史不能成为需要手动对齐的两张消息表 |
| 4 | 聊天区只由 DSH 消息组件渲染，侧栏只由平铺会话组件渲染，移除回退开关 | 浏览器复现了两套渲染器把同一用户消息显示两次；旧侧栏重绘还会删除新挂载点。继承的工作区浏览器隐藏非当前的空白会话，标题与控件也挤在窄栏里，因此侧栏改成直接列出所有会话 |
| 5 | 沿用 `/对话/*` 作为应用状态入口 | 这是既有会话通道，不是七个业务模块的 AI 工具；业务模块仍只有 `/toolbox/调` |
| 6 | 保留存档会话的身份与消息，导入另建新身份 | 本次封装不重建用户会话；显式导入是追加新对话，无兼容分支或迁移工具 |
