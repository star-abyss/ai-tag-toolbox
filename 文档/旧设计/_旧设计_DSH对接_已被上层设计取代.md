# 一、先说结论

**模块层不用动。** 本项目 §六 那三层，与 DSH 的插件模型是同一个形状：

| 本项目 | DSH | 落在哪 |
|---|---|---|
| ① 模块层（五个模块） | 普通 Node 包，插件 `require` 进来 | 五个模块目录，不动 |
| ② 门面层（工具清单） | `ctx.tools.register(defineTool(...))` | 新增：对接层 |
| ③ 执行层（那段顺序） | `execute(args, exec)` | 新增：对接层 |

**要做的只有一件：补一个对接层。** 它是本项目的**装配层**，同时也是 DSH 的 **Host 插件**。

**对接层不放进任何一个模块目录**，它自成一个包（§四）。放进去就等于从模块层反向伸手去够模块层。

**为什么模块层能不动**：本项目的三条跨模块禁令，正好就是 DSH 插件本来就要求的东西——

| 本项目禁令 | DSH 那边 |
|---|---|
| 核心不许 `require fs` / `path` | 不冲突：插件是 Host 侧代码，本来就有盘 |
| 对外参数只能是标识，不许出现路径 / 地址 | 工具 `parameters` 是模型填的，本来就该只有标识 |
| 一个模块对外只有 `index.js`，出口 `Object.freeze` | 插件只碰门面，本来就是唯一入口 |

**唯一动不了的那条是它**：本项目的"对外"是**给人写的程序**调的，DSH 的"对外"是**给模型**调的。同一个 `index.js`，面对的是两种调用方，所以对接层必须存在，而且必须薄。

# 二、五个模块现在的对外形状

| 模块 | 装配参数 | 动作数 | 直呼式失败给 | 有盘 |
|---|---|---:|---|---|
| **标签** `tag模块/` | `{ port }` / `{ data: '…/data' }` | 31 | `null`，`run()` 给 `{ok,reason,code}` | 是 |
| **图片** `图片模块/` | `{ port }` / `{ 根目录: '…' }` | 12 | `null`，`run()` 给 `{ok,reason,code}` | 是 |
| **世界书** `世界书模块/` | `{ port }` / `{ 根目录, 默认目录 }` | 10 | 同上 | 是 |
| **装订** `装订模块/` | `{ 查词, AI翻译, 分隔符? }` | 2 | `{ok:false,code,reason,原文}` | 否 |
| **comfyUI** `comfyUI模块/` | `{ port }` / `{ 地址, 存档, … }` | 10 | `null`，`run()` 给 `{ok,reason,code}` | 否（发请求） |

**共同点**：`{ port }` 与"直接给位置"两条装配路都收——所以对接层走哪条都行。
**共同点**：**失败信封五个模块已经统一**成 `{ ok:false, reason, code }`（标签那一条是这一轮补的）。
**共同点**：`describe()` 给 `[{动作, 摘要, 参数, 说明}]`，中文键。**给人看的一页索引，运行时不读它**，字段的完整形状以各自 `接口.md` 为准。
**共同点**：门面的 `run(动作, 参数)` 是唯一统一的入口。

**还剩两处不齐，对接层要逐模块处理，不能"一把梭"：**

| 不齐的地方 | 谁不一样 | 对接层怎么办 |
|---|---|---|
| **`run()` 的返回不是 `{ok,data}`** | 装订的 `装订` 直接给回执 `{ok,译文,原文}`；`切分` 才给 `{ok,data}` | 两个工具分开写，各按各的形状剥；**这是设计要的**（失败的表现就是原文），别去统一 |
| **门面漏出内部件** | 标签的 `index.js` 还导出 `PORT`（整个 `port.js`）与 `KEYS` | **对接层只用 `createTagModule`**，另外两个不碰 |

# 三、对不上 DSH 标准的地方（差距表）

**按"要不要改模块层"分三类。**

## 3.1 对接层自己解决（模块层不动）★ 多数在这里

| # | 差距 | 本项目现在 | DSH 要什么 | 对接层怎么办 |
|---|---|---|---|---|
| 1 | **入口形状** | `module.exports = { createXxxModule }`（CommonJS） | `export function apply(ctx, config)`（ESM） | 插件里用 `createRequire` 把门面 require 进来，装配在 `apply` 里做 |
| 2 | **清单格式** | `describe()` 给中文键的 `{动作,摘要,参数,说明}` | `defineTool({ name, description, parameters, output })` | 手工把动作映成工具（表在 §五）。**`describe()` 是给人看的一页索引**：它不声明程序接口才用的参数（`信号` / `onEvent`），字段的完整形状以各自 `接口.md` 为准——这条已写进模块的决策记录 |
| 3 | **失败是返回值，不是抛错** | 五个模块一律返回 `{ ok:false, reason, code }` | 要么抛 `Error`，要么按 `output.schema` 给值 | 拿到 `ok:false` 就**抛**，抛出的话用模块给的那句人话。**信封已在模块层统一**（§3.4），所以这一段可以共用 |
| 4 | **字段名** | 动作用中文（`探活` · `存`）或英文（`query`） | 工具名要与已有的不撞（`read` / `write` / `grep` / `todo_write` …） | 工具名统一 `工具箱_<域>_<动作>`；**参数名与回执字段保留中文**（本项目命名规矩） |
| 5 | **参数里的路径 / 地址** | 装配参数里有 `data` / `根目录` / `地址` | 工具 `parameters` 里绝不能有 | 路径与地址**只从插件 `config` 来**，落进装配那一步，永不进工具参数 |
| 6 | **回执形状** | `{ ok:true, data }` 信封 | `output.schema` 声明的那个值 | 对接层负责剥信封、贴回执字段 |
| 7 | **同步 / 异步** | 标签同步、图片一半一半、其余异步 | `execute` 一律 Promise | 对接层 `async` 包一层，模块层不动 |
| 8 | **字节** | `图片模块.存` 收 `Buffer` | 工具收不到字节 | **`存` 与 `取内容` 都不做成工具**（理由见 §3.3 第 2 条） |
| 9 | **大产出** | `看节点定义` 真机回 2564 个节点类 | 回执要**有界** | 对接层只回节点名与数量，字段清单另开一个工具按名字取 |
| 10 | **长任务** | `出图` 默认上限 30 分钟 | `timeoutMs` 到了就落 `TOOL_TIMEOUT` | 工具声明 `timeoutMs`；见 §6 |
| 11 | **人不看见的约束** | —— | 判据②：约束必须能在界面上看到 | 地址 / 根目录 / 模型 / 上限，一律写成插件 `config` 的字段（§四.3） |
| 12 | **装配参数有别名** | 标签 `data \|\| root`、图片 `根目录 \|\| root \|\| data` | 一个位置只有一个名字 | **已在模块层删掉**（见 §4.2）；提示词与 comfyUI 本来就没有 |

## 3.2 模块层要加一点点（两处，都是"多加一个参数"）

| # | 差距 | 位置 | 加什么 |
|---|---|---|---|
| 1 | **取消传不进去** | `comfyUI模块/core.js` 的 `走出图` | 它已经收 `信号`，但门面 `出图` 没有这条路，`装订模块/core.js` 的 `装订` 连端口都不带信号 | 给 `装订` 的端口补一个可选 `信号`，`装订(文本, 信号)`；`comfyUI` 的门面把 `信号` 透下去 |
| 2 | **草稿不跨调用** | `世界书模块/core.js` | 草稿活在内存，插件重载就丢 | **不加**：`存` / `丢` 两个动作已经把这个边界交给调用方了，对接层串起来就行 |

**这两处要不要动，见 §七 的 D-2。** 不动也行：插件层自己短轮询，模块层还是一个字不改。

## 3.4 已经在模块层统一掉的（本轮）

**这三件事是"对接 DSH 之前"就该一致的，已在模块层做完，对接层不必再逐模块特殊处理：**

| # | 什么 | 原来 | 现在 | 判据 |
|---|---|---|---|---|
| 1 | **标签的失败没有 `code`** | `{ok:false, reason}` —— 它是唯一没有错误模型的模块，调用方只能 `switch` 一句中文短语 | `{ok:false, reason, code}`，16 个码定义在 `tag模块/error.js`，`reason` 原文一个字没改 | 标签 66 条（新加 2 条：失败信封、码表自洽） |
| 2 | **装配参数的路径别名** | 标签 `data \|\| root`、图片 `根目录 \|\| root \|\| data` | 各只有一个名字，给别的当场抛 | 标签 66 条、图片 40 条各新加 1 条 |
| 3 | **`describe()` 的身份** | 看着像"运行时的契约"，于是跟实现比就"少报了参数" | 明确为**给人看的一页索引**，字段完整形状以 `接口.md` 为准（标签决策 117） | 不加"逐字相等"的判据——那正是规矩⑦说的坏清单 |

**有一条特意没统一**：装订的 `装订` 成功时给的是回执 `{ok,译文,原文,兜底?}`，不是 `{ok,data}`。这不是不齐，是设计要的（决定 15：「一次装订失败的表现就是『显示原文』」；模块总判据「失败的表现就是原文」）。**别去"修"它。**

## 3.5 结构性的：有几样**不能**当作工具给模型

| # | 什么 | 为什么不能 | 怎么办 |
|---|---|---|---|
| 1 | 图片模块的 `存` | 它要 `字节`。工具只换文本，模型交不出字节 | 出图 → 存图这条链**在一次工具调用内部走完**，模型只看见引用 |
| 2 | 图片模块的 `取内容` | 回的是字节，一张 1.2 MB PNG 塞进回执就是灾难 | 要字节的只有程序；模型要的是"这张图存下来了，引用是 X" |
| 3 | 图片模块的 `取地址` | **它的参数是标识，但它的回执是本机绝对路径**（`port.全路径` 给的） | 契约里本来就写明"只给界面与模块之间"，对接层不许把它塞进任何工具回执 |
| 4 | 提示词的书 / 条目**整份读写** | 世界书是长文本，整份进出会吃掉上下文 | 拆成"看目录"与"改一条"两步，每次只碰一条 |
| 5 | 标签模块的 `reload` | 这是给程序在外部改过库之后调的 | 不进清单；要重读就给一个显式的工具，见 §五 的待定 |

# 四、对接层长什么样

## 4.1 放在哪

**自成一个目录，放在项目根旁边，与五个模块平级。** 不要塞进任何一个模块目录，也不要塞进 `工具箱（重写）/` 里面当第六个"模块"。

```
工具箱（重写）/           ← 五个模块，一个字不动
dsh-工具箱/               ← 新增：DSH 插件包（对接层 = 装配层）
```

**理由**：本项目 §六 说"模块不进清单"，DSH 说"插件不进模块"。两边都要求这一层独立存在，那它就该有个自己的目录。

## 4.2 包骨架

```json
{
  "name": "dsh-toolbox",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "exports": { ".": "./index.js" },
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

```yaml
# cordis.patch.yml —— 一个模块一行，可以单独开关
- insert:
    - id: toolbox-tag
      name: 'dsh-toolbox'
      config:
        项目根: '<放这个仓库的目录>'
        标签: { 数据目录: 'tag模块/data' }
    - id: toolbox-image
      name: 'dsh-toolbox'
      config:
        项目根: '<放这个仓库的目录>'
        图片: { 根目录: '图片模块/.data' }
    - id: toolbox-world
      name: 'dsh-toolbox'
      config:
        项目根: '<放这个仓库的目录>'
        世界书: { 根目录: '世界书模块/.data', 默认目录: '世界书模块/assets/世界书' }
    - id: toolbox-comfy
      name: 'dsh-toolbox'
      config:
        项目根: '<放这个仓库的目录>'
        comfyUI: { 地址: 'http://127.0.0.1:8188', 存档: 'comfyUI模块/.data/工作流.json' }
```

**一个模块一行**：开关、停用、换配置各自独立，不用重启整个工具箱。

**配置里的路径一律是相对于 `项目根` 的**，所以换个机器只改 `项目根` 一处。配置只给本文件与 [项目说明.md](../项目说明.md) §五 里写着的那**一个**名字——**不给别名**。规矩⑧说多级兜底来源是缺陷，配置这一层就不该去踩它。

**别名已经在模块层删掉了**（这一条动过模块层）：

| 模块 | 原来 | 现在 |
|---|---|---|
| 标签 | `options.data \|\| options.root` | 只有 `data`；给别的名字当场抛 |
| 图片 | `选项.根目录 \|\| 选项.root \|\| 选项.data` | 只有 `根目录`；给别的名字当场抛 |
| 世界书 · comfyUI | 本来就只有 `根目录` / `地址` | 不动 |

两个模块各加了一条判据把它钉住（标签 64 条、图片 40 条，全绿）。**对接层从配置给路径时，五个模块各只有一个名字可用。**

## 4.3 配置就是"能看见的约束"

判据②要求"工具提供的约束必须能在界面上看到"。本项目里，那些约束现在藏在装配参数里；到了 DSH，它们必须变成插件 `config` 的字段——**一个工具参数都不许涨**。

| 配置字段 | 喂给谁 | 界面上看得见的是什么 |
|---|---|---|
| `项目根` | `createRequire` 的解析起点 | 这些模块装在哪 |
| `标签.数据目录` | `createTagModule({ data })` | 标签库在哪 |
| `图片.根目录` | `createImageModule({ 根目录 })` | 图存在哪 |
| `世界书.根目录` · `世界书.默认目录` | `createWorldbookModule({ 根目录, 默认目录 })` | 用户那份世界书与四份只读默认在哪 |
| `comfyUI.地址` | `createComfyModule({ 地址 })` | 连的是哪台 ComfyUI |
| `comfyUI.存档` | 同上 | 工作流存在哪个文件 |
| `出图.上限毫秒` | 同上 | 盯多久算超时 |
| `装订.翻译`（若选 D-1 的甲案） | 装订的 `AI翻译` 端口 | 用哪个 provider / model 翻译 |

## 4.4 装配那一步

```js
import { createRequire } from 'node:module';
export const inject = ['tools'];
export const name = 'toolbox';

export function apply(ctx, config) {
  const require = createRequire(import.meta.url);
  const 根 = config.项目根;
  const 模块 = (名) => require(`${根}/${名}/index.js`);   // 只用门面

  // ① 装配：模块要什么就从配置给什么。这一步之后，模块里再也没有路径
  const 标签 = 模块('tag模块').createTagModule({ data: join(根, config.标签.数据目录) });
  // …其余四个同理

  // ② 登记：一个工具一个 defineTool，全部走 ctx.tools.register
  ctx.tools.register(defineTool({ /* 表在 §五 */ }));
  // …
}
```

**`ctx.effect` 不用手写**：`ctx.tools.register` 返回的就是那个精确的 disposer，`ctx.effect` 包一层即可。

## 4.5 信封归一：一段共用的执行层代码

模块的失败一律**返回**而不是抛，DSH 要的是**抛**。五个模块的信封现在一致（§3.4），所以这段只写一遍：

```js
/** 拿模块的 `{ok, data|reason, code}` 说话：成功给 data，失败抛出去。 */
function 取(结果) {
  if (!结果) throw new Error('模块没给结果');
  if (结果.ok) return 结果.data;
  const 错 = new Error(结果.reason || 结果.code || '模块失败');   // reason 是给人看的那句
  错.code = 结果.code;                                          // code 给程序分辨
  throw 错;
}

/** 同上，等 Promise：图片的写、装订、comfyUI 全部。 */
async function 取异步(等着的) {
  return 取(await 等着的);
}
```

**一个例外要单独接**：

| 谁 | 为什么 | 怎么接 |
|---|---|---|
| 装订的 `装订` | 成功给的是**回执** `{ok,译文,原文,兜底?}`，不是 `{ok,data}` | 那个工具直接读回执，不套 `取`；它的 `切分` 才用 `取` |

# 五、工具表（第一版 16 个）

**工具数不由模块数决定，由"要给模型几件事做"决定。** 65 个动作压成 16 个工具：**同族、同形状的合成一个，用动作参数分**。

| 工具名 | 模块 | 用的动作 | 参数 | 回执 |
|---|---|---|---|---|
| `工具箱_标签_查词` | 标签 | `query` | `词串` · `上限?` | 候选（记录 / 档 / 命中）+ `还有更多` + `合计` |
| `工具箱_标签_认词` | 标签 | `recognize` | `词`（一个或一批） | 一一对应的中文名 |
| `工具箱_标签_记录` | 标签 | `record.get` / `batch` / `create` / `edit` / `delete` / `groups` | `动作` · `标识?` · `标识列表?` · `名称?` · `中文名?` · `成员?` | 那条记录 |
| `工具箱_标签_位置` | 标签 | `position.*`（10 个） | `动作` · `位置` · `页?` · `类?` · `标识?` · `成员?` · `名?` · `配色?` · `位置序?` | 位置表 |

**这张表里三处是执行层的活**（模块层没有这条动作，或者要跨模块）：

1. **`工具箱_标签_查词` 与 `工具箱_标签_认词` 分成两个工具**：模块里它们是两个动作，但模型分不清"查库"和"认词"什么时候用哪个。分成两个工具、各写各的 description，模型才选得对。参数里的 `?` 表示可省；带 `动作` 那几个，`动作` 是必填。
2. **`工具箱_comfy_出图` 用了两个模块**：出图 → 取回字节 → 存进图片模块 → 回引用。**一次调用走完**，模型永远不碰字节。这就是本项目 §六 说的"一个工具可以用多个模块"。
3. **`工具箱_图片_收` 收 `来源路径?`**：DSH 的模型能填路径（`read` / `write` 就是这样）。但本项目禁令②说"对外参数不许出现路径"。**这两条并不冲突**：DSH 的路径由 `file_path` 这类参数进，由沙箱管；本项目的禁令管的是**模块自己的对外**。所以 `来源路径` 只出现在对接层的工具参数里，**不进 `图片模块.存`**——对接层读成字节再给模块。**要在 `接口.md` 里写清这条界线。**

# 六、长任务与取消

**问题**：`出图` 要盯几分钟到半小时；DSH 的 `timeoutMs` 一到就落 `TOOL_TIMEOUT`，而工具声明了 `timeoutMs` 就必须**真的**honor `exec.signal`。

| 工具 | `timeoutMs` | 怎么honor取消 |
|---|---|---|
| `工具箱_comfy_出图` | `出图.上限毫秒`（配置，默认 30 分钟） | `exec.signal` 透到 comfyUI 的 `出图` 参数 `信号`（它本来就有） |
| `工具箱_装订_译文` | 按模型而定 | 要看 §七 D-2 怎么定 |
| 其余 14 个 | 用默认 | 都是短操作，`exec.signal` 透下去即可 |

**模块层要加的那一处**（§3.2 第 1 条）：`装订模块/core.js` 的 `装订` 现在收不到信号，它内部 `await AI翻译(报文)` 会一直等。若选 D-2 的乙案（插件自己调模型），`AI翻译` 的闭包能拿到 `exec.signal`，模块层就不用改。

# 八、怎么落地

1. **建 `dsh-工具箱/`**：`package.json` · `cordis.patch.yml` · `index.js`
2. **`index.js` 里分五段**：一段一个模块。每段只有三件事——`createRequire` 拿门面、按 `config` 装配、`ctx.tools.register` 登记工具
3. **先只做标签模块这一段**，跑通"装上去 → 模型能调 → 回执对"，再照抄另外四段
4. **写工具 description**：一句话说清这个工具**做什么**、**什么时候用**。**照 `接口.md` 与动作表写，不要照抄 `describe()`**——它是给人看的一页索引，参数不全是有意的（§3.4 第 3 条）
5. **跑一遍模块自检**：`cd tag模块 && node test/run.js`（现在 66 条）——**模块层没动，自检必须全绿**。这是"对接层没伸手进去"的证据
6. **装上**：`plugin_manager` 的 `install_bundle`，`target` 给 `dsh-工具箱/` 的绝对路径
7. **验**：`cordis_inspect_query` 取 `Tool.listTools`，确认 16 个工具在；再让模型真调一个（先调不需要真机的，比如 `工具箱_标签_查词`）
8. **补文档**：本文档在 §九 补实测记录；[项目说明.md](../项目说明.md) §四"还没做的"里划掉"门面层 · 执行层"

**第 5 步不能省，第 7 步不能拿"装上了"代替。** 装上只说明插件激活了，不说明工具能调、更不说明回执对。
