  翻译模块 · 接口

> 2026-10-17：装配改用 `{文本处理,查词?,译?,默认方向?,默认模型?}`，文本处理由装配层传入装订门面的同名端口（切分、拼装、猜方向、需翻译）。模型报文改为 `{source,units:[{id,text}],from,to,模型?}`，回 `{模型?,units:[{id,text}]}`；不再交付第二份整段译文或原词键值表。表含标识、原文范围、词范围和同次拼装生成的译文范围（UTF-16 左闭右开）。en-zh 词库优先；zh-en 不使用中文名作英文结果；混合文字按来源语言判定。待译项缺失或空结果明确失败并带原文。本段取代以下旧报文及缺失结果照抄成功的约定。

> **这是契约。改实现之前先改它；改完跑 `node test/run.js`。**
> 设计理由在 [翻译模块设计.md](翻译模块设计.md)；上手指南在 [README.md](README.md)。

**一句话**：**一段文本切成一格一格，库里查得到的给中文名，查不到的交给本地模型，再按原样拼回来。**

**它跟装订模块的分工**：装订模块那条路把查不到的词交给 **AI**；本模块那条路把查不到的词交给 **本地模型**。两条路的切分、查词、拼回是同一套（都由装配层递同一份进来），**只有"谁来译"那一步不同**。用户在工具表里自己挑走哪条。

---

   一、对外操作

    1.0 被多个操作共用的形状

```
单元 = {
  前  必串    原样前缀。括号与权重，如 '('  '(([' ——没有就是空串
  词  必串    给查词与模型的那一串，纯词。空单元时是空串
  后  必串    原样后缀，如 ':1.3)'  '))'  ']' ——没有就是空串
}

报文 = {
  source  必串    完整原文，只供理解语境
  words   必数组  要它译的词，按出现顺序
  from    必串    来源语言：英文 / 中文
  to      必串    目标语言：中文 / 英文
  模型     选串    用哪一格模型；不给就用装配层定的那一格
}

键值对 = { <原文的词>: <译文> }
```

**约束（不是建议）：**

|   | 约束 | 违反时 |
|---|---|---|
| 1 | 参数里只有「文本」「方向」「模型」，**不许出现路径 / 地址** | 缺陷，不是错误码 |
| 2 | 单元的三字段都是字符串，空单元是三字段都空的那个 | —— |
| 3 | **切分与查词不是本模块的东西**：切分由装配层递（与装订模块同一份），查词是标签模块的 `认词` | 递不进来就少那一路能力 |

    1.1 `本地译`

```
入  { 文本 必串, 方向 选串, 模型 选串 }
出  { ok:true, data:{ 译文, 原文, 方向, 模型, 表, 统计 } }
    | { ok:false, code, reason, 原文? }
```

| 项 | 规定 |
|---|---|
| 必做 | 切分 → 查词 → 挑剩下的 → 交给模型 → 拼回 |
| 三路来源 | **库译名优先，其次模型译文，再其次原词**；每一格的出处记在 `表[].出处`（`库` / `模型` / `原词` / `空`） |
| 交给谁 | 只交**库里查不到**的格；目标语言是中文时，已经是中文的格也跳过（那是目标语言，不必再译） |
| 方向 | `auto`（缺省，按字数猜）· `en-zh` · `zh-en`。写别的 → `TEXT_LOCAL_BAD_DIRECTION` |
| 原文快照 | 进函数时取一次；跑的过程中外面改了界面不影响这一次 |
| 一进一出 | **同时在飞的只有一次**；进行中再调 ⇒ `TEXT_LOCAL_BUSY`（闸门走 `finally`） |
| 异步 | **是**（要等模型） |
| 抛错 | 不抛。模型抛错由本模块接住，换成失败回执 |
| `表` | 逐格一行：`{ 前, 词, 后, 译文, 库译名, 模型译文, 出处 }`；空单元也在表里（`出处:'空'`） |
| `统计` | `{ 格, 有内容, 库里查到, 模型译出, 照抄原词 }` |

    1.2 `看模型`

```
入  {}
出  { ok:true, data:{ 可用 必真伪, 缺 必数组, 模型, 有查词 必真伪 } }
```

| 项 | 规定 |
|---|---|
| 必做 | 只说**端口齐不齐**（缺哪个），不去探测盘上有没有模型文件 |
| 为什么 | 模块不找路径；"这一格模型在不在"是装配层与界面的事 |

    1.3 `切分`

```
入  { 文本 必串 }
出  { ok:true, data: 单元列表 }
```

**它就是把递进来的切分函数转一次**，不是本模块另写一套；没递切分就 `TEXT_LOCAL_NO_SPLIT`（构造时已经拦了）。

    1.4 直呼与动作表

| 门面成员 | 说明 |
|---|---|
| `本地译(文本, { 方向?, 模型? })` | 回执本身（异步） |
| `译文(文本, { 方向? })` | 只要译文：成功给串，失败给 `null` |
| `猜方向(文本)` | `'en-zh'` 或 `'zh-en'` |
| `run(动作, 参数)` | 走动作表 |
| `actions` | `['看模型', '本地译', '切分']`（冻住） |
| `describe()` | `[{ 动作, 摘要, 参数, 说明 }]` |
| `ERR` · `SAY` · `端口` | 错误码 · 码 → 人话 · 三项端口的名字与形状（都冻住） |

**出口冻住**：门面 `Object.freeze`，不递 `core` / `port` / 适配器。

---

   二、端口（装配层递什么进来）

| 名 | 形状 | 必给 | 不给会怎样 |
|---|---|---|---|
| `切分` | `(输入) → { 文本, 单元 }` | **是** | 构造就抛错 |
| `查词` | `(词列表) → 中文名 或 null 的数组` | 否 | 少了"查库"那一路，全交给模型 |
| `译` | `(报文) → { 译文, 模型?, 键值? }` | 否 | `本地译` 报 `TEXT_LOCAL_NO_ENGINE` |

**"没给"是合法状态，不是坏配置**：不给查词就没有库译名，不给译就没有本地模型——两条都给不出来时，只有 `切分` 还能用。

装配：

```js
const 翻译 = require('./翻译模块/index.js').createTranslateModule({
  切分: 装订.切分,                  // 与装订模块同一份
  查词: (词们) => 标签.recognize(词们),
  译: 模型引擎.译,                  // 装配层造的，见 对接层/模型引擎.js
});
```

   三、错误码

| 码 | 什么时候 | 给人的意思 |
|---|---|---|
| `TEXT_LOCAL_BUSY` | 上一次还没回来 | 等它回来 |
| `TEXT_LOCAL_NO_ENGINE` | 要用本地模型而没递进来 | 本地翻译不可用，显示原文 |
| `TEXT_LOCAL_NO_SPLIT` | 没递切分 | 装配错了 |
| `TEXT_LOCAL_FAILED` | 模型抛错 | 显示原文；看引擎报的那句 |
| `TEXT_LOCAL_BAD_DIRECTION` | 方向写错 | 只认 auto / en-zh / zh-en |
| `TEXT_LOCAL_BAD_ARGUMENT` | 动作名不对，或动作自己抛错 | 改代码 |

**走 `本地译` 的失败都带 `原文`**，界面永远有东西可显示。
