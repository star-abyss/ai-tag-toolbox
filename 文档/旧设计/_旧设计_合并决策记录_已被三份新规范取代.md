# 以下是旧版原文，一字未改

**一句话**：**几个固定子模块，各挂一份世界书；来一个请求，就把那份世界书筛一筛、拼成一段文本。**

---

# 一、范围

## 1.1 它做

| # | 做什么 |
|---|---|
| 1 | 管世界书：三份只读默认 + 用户自己那份（新建 / 导入 / 改名 / 删 / 切换） |
| 2 | 管条目：加 / 改 / 删 / 移 / 停用 / 条件 |
| 3 | 按这次调用的输入筛出命中的条目 |
| 4 | 把命中的条目拼成一段提示词交出去 |
| 5 | 导入酒馆世界书（只读顺序、启用情况、启用条件） |
| 6 | 草稿与手动保存：改条目即时生效，落下要按保存 |

## 1.2 它不做

| 不做 | 归谁 |
|---|---|
| **不对模型说话**：不建连接、不发请求、不收回答 | AI 调用 |
| 不认识主 AI | **主 AI 另行设计**，两者互不认识 |
| **不拥有系统生成的提示词** | 各个域模块自己算（R-19） |
| 不解析返回内容 | 提问的那个模块 |
| 不管用哪条链路、哪个模型、密钥、超时、重试 | AI 调用 |
| **不存参数**（温度、惩罚、输出上限） | AI 调用（R-14） |
| 不管上下文、历史 | 提示词模块没有上下文 |
| 不做宏替换 | 我们根本没有那个概念（R-24） |
| 不管界面怎么画 | 界面是通用面板的事 |
| 不认识对话、图片、标签 | 它只认识自己的世界书 |
| 不做兼容层、不留回退开关 | 要回退用 git（R-28） |
| 不做酒馆**对话预设**导入 | 那是主 AI 那边的事（R-23） |

# 二、术语

| 词 | 意思 |
|---|---|
| **子模块** | 一件提示词 干的事。固定三个，ID 是字母 + 序号 |
| **世界书** | 一个子模块挂的那份东西：`{ name, entries[] }` |
| **条目** | 世界书里的一段：`{ id, label, text, always, keys, enabled }` |
| **只读默认** | 随程序走的那份世界书，一份一个文件，不能改不能删 |
| **用户那份** | 存在端口里的世界书，随便建改删 |
| **标识** | 对外的引用：用户那份是 `wb1`，只读默认是 `$default:a1` |
| **草稿** | 内存里那份，读与全部改动都作用在它上面 |
| **存档** | 端口里那份，**执行只用它** |

# 三、约束

## 3.1 继承自框架的边界规则

| # | 规则 | 本模块怎么体现 |
|---|---|---|
| 1 | 一个模块只交出一份清单 | 门面只有 `index.js`；界面侧与模型侧读同一份 |
| 2 | 能力在谁那儿，工具就在谁那儿 | 装载即存在；没有"可用性判断" |
| 3 | **对外的参数永远是标识** | 参数只有 `用途` / `书` / `标识` / `输入`；检验法：看 `describe()` 的参数名 |
| 4 | 决定要在做出这个决定的操作里执行 | 筛选在 `执行` 里做，不靠调用方先滤一遍 |
| 5 | "能不能来"用"东西有没有传进来"表达 | 端口没递默认目录 = 没有默认世界书 |
| 6 | 不解析不属于自己的东西 | 返回内容不解析；酒馆的字段不原样留着 |
| 7 | "必须和别处保持一致的清单"都不该存在 | 用途名就是子模块 ID，不需要第二张表 |
| 8 | 多级兜底来源是缺陷 | 不给"没默认就找别处"这种退路 |
| 9 | 依赖由装配层传进来 | 端口与位置都由装配层递；核心不 require fs/path |
| 10 | 不做兼容层，不留回退开关 | 不兼容旧提示词数据 |

## 3.2 本模块自己的硬约束

| # | 约束 |
|---|---|
| 1 | **只读默认没有任何写路径**（R-5） |
| 2 | **`执行` 只读存档**，不读草稿（R-16） |
| 3 | 条目顺序就是数组顺序（R-11） |
| 4 | `always` 只有一个来源（R-13） |
| 5 | 筛选只有关键词子串命中（R-12） |
| 6 | 拼装只有一处（R-20） |
| 7 | 参数不许进本模块的数据（R-14） |
| 8 | "读不懂"不许当成"没有"（R-29） |
| 9 | `always` 与 `keys` 互斥（R-15） |

# 四、架构

## 4.1 形状

```
提示词 模块
├─ 子模块表      三个：a1 翻译 / a2 识图 / a3 文生图
├─ 世界书        每个子模块一份：只读默认 或 用户那份
├─ 筛选与拼装    按输入挑条目 → 一段文本
└─ 草稿 / 存档   读与改在草稿，执行在存档
```

## 4.2 一次执行

```
调用方：提示词.执行({ 用途:'a1', 输入:'请把这段翻成中文' })
  ① 按用途找子模块           找不到 → 报出来（不兜底、不猜）
  ② 取它当前的世界书          有存档用存档，没有用只读默认
  ③ 按输入筛条目              见 §6
  ④ 拼成一段文本              见 §6
  ⑤ 交出去
```

**返回的文本不解析**——要哪些字段是提问那个模块的事。

## 4.3 对外只有一份清单

门面（`index.js`）既给界面用，也给调用点用，**不写第二遍**。
模型侧能不能看见本模块，由门面层决定（本模块不决定）。

## 4.4 依赖方向

```
域模块（翻译 / 识图 / 出图）
      │  只递 { 用途, 输入 }
      ↓
提示词 模块 ──→ 端口（存档 + 只读默认）
      │
      └─→ 提示词交给调用方 → AI 调用 → 发出去
```

**没有环。** 本模块不认识任何域模块，也不认识 AI 调用。

# 五、需求

## 5.1 子模块

| # | 需求 |
|---|---|
| R-1 | 子模块**三个**：`a1` 翻译 / `a2` 识图 / `a3` 文生图 |
| R-2 | ID 形状是**字母 + 序号**；字母段标明它属于提示词 模块 |
| R-3 | 用户**加不出新子模块**；清单由开发者增行（同"模块清单由开发者新增"） |
| R-4 | 子模块的显示名只给人看；程序只认 ID |

## 5.2 世界书

| # | 需求 |
|---|---|
| R-5 | 默认内容 = **只读世界书**，一个子模块一份文件；**不能改、不能删** |
| R-6 | **按文件分门别类**：打开一个世界书不读其他几个 |
| R-7 | 用户那份**存在端口里**，可增删改；一个文件装全部子模块 |
| R-8 | `active` 一个可空字段指向默认或用户那份；**没有第三态** |
| R-9 | 世界书的名字就是列表里显示的东西，**不分组、按名字排序** |

## 5.3 条目

| # | 需求 |
|---|---|
| R-10 | 条目 = `{ id, label, text, always, keys, enabled }`；`id` 由程序分配，世界书内唯一 |
| R-11 | 条目**顺序就是数组顺序**；不另存 `order`。顺序由用户改：`移` 支持 `方向:上/下` 与 `到:序号` |
| R-12 | 条目可停用（`enabled:false`）；可带**启用条件**（`keys`），空即恒常 |
| R-13 | **`always` 只有一个来源**：显式 `always`、来源里的 `constant`、或"没有关键词"三种说法归一成它 |
| R-14 | 条目里**不许有参数**（温度、惩罚、上限） |
| R-15 | **`always` 与 `keys` 互斥，不许同时成立**；写的时候按给进来的那一项定，另一项跟着归一 |

## 5.4 对外

| # | 需求 |
|---|---|
| R-16 | 对外只有**一个动作**：`执行({ 用途, 输入? }) → 提示词`。**只读存档**，不读草稿 |
| R-17 | 调用点只写**用途 + 这次的内容**；不写路径、不写地址 |
| R-18 | **返回内容不解析**；要哪些字段是提问那个模块的事 |
| R-19 | **不拥有系统生成的提示词**；本模块交出的只有"用户那份 + 默认那份"拼出来的东西 |
| R-20 | **拼装只有一处**：段与段之间空一行，每段去首尾空白，空的跳过 |

## 5.5 导入

| # | 需求 |
|---|---|
| R-21 | 能导入一份世界书 JSON（自己的形状或酒馆的形状） |
| R-22 | 酒馆世界书**只读顺序、启用情况、启用条件**；插入位置那类字段一概不读 |
| R-23 | **不做酒馆对话预设导入** —— 那是主 AI 那边的事 |
| R-24 | **不做宏替换**；导入进来的 `{{…}}` 就是普通文字 |

## 5.6 草稿与保存

| # | 需求 |
|---|---|
| R-25 | 改条目**即时生效**在草稿上；**写进端口要按 `存`** |
| R-26 | **导入 / 新建世界书立即出现在草稿里并切过去**；落下仍由 `存` |
| R-27 | 切走子模块或切走世界书时若草稿脏，界面要提醒；模块提供 `读`（带 `脏`）与 `丢` |

## 5.7 出错

| # | 需求 |
|---|---|
| R-28 | 失败一律 `{ ok:false, reason, code }`；**reason 的写法是 `码: 人话`** |
| R-29 | **读的三态**：有 / 确实没有 / 读不懂；**读不懂时冻结写** |
| R-30 | 默认文件缺失 → 那个子模块如实报出来，不是凭空消失；**读不懂与不存在分开报**（R-29 的"读不懂"在只读默认上同样成立） |

# 六、筛选与拼装

```
输入 = 调用方给的那段文本（没有则视为空串）

参与 = enabled === true
     且 text 去空白后非空
     且 （ always === true  或  keys 里任一项命中 ）

命中 = 输入.toLowerCase() 里出现 关键词.toLowerCase()

拼装 = 参与条目的 text 各自去掉首尾空白，按数组顺序用 "\n\n" 连接
```

| 规则 | |
|---|---|
| 匹配只有一条 | 关键词子串命中；**不做正则** |
| 大小写 | 两边都折小写（中文日文不受影响） |
| 没有输入 | 只有恒常条目参与 |
| 全不参与 | 提示词是**空串**，不是 `null` |
| **不做** | 概率抽取 · 次级关键词逻辑 · 分组权重 · 递归扫描 · 向量匹配 · 上下文深度判定 · 匹配位置 |

# 七、数据

## 7.0 界面该看见什么（两条状态的呈现）

`always` 与 `keys` 合起来只有**两条**真正不同的状态，界面必须让用户一眼看出来：

| 状态 | 数据 | 列表里显示 | 含义 |
|---|---|---|---|
| **每次参与**（恒常） | `always:true, keys:[]` | `每次` | 只要开着就一定进提示词 |
| **关键词触发** | `always:false, keys:['龙','dragon']` | `触发：龙 / dragon` | 输入里出现任一个词才进 |

**还有一条"走不到"的状态**：`always:false, keys:[]`（不恒常、又没词）——它**永不参与**。
这个组合由 R-15 的互斥规则挡在一处：只说 `always:false` 时会出现，但**清空关键词**会被算成"每次参与"，
所以它只在"用户正在打字、词还没填"的中途存在。界面照实显示为`未设条件（不会进入）`即可。

**界面上的落法**：

```
触发条件  ● 每次参与          ○ 关键词触发  [ 龙, dragon ]
                                          ↑ 在框里打字 → 自动切到"关键词触发"
                                            把框清空   → 自动切回"每次参与"
```

**一行到位，不需要"确认条件"这类按钮。** 判据 V-39 验的是模块侧：
不论走哪个入口，`always` 与 `keys` 都不会同时成立。

## 7.1 盘上的形状

```
<根目录>/世界书.json                用户那份（一个文件装全部子模块）
<默认目录>/a1.json a2.json a3.json  三份只读默认
```

用户那份：

```jsonc
{
  "format": "worldbook", "version": 1,   // format 只是标记，不参与判定；version 不是 1 才算读不懂
  "subs": {
    "a1": { "active": "wb1", "books": [ { "id": "wb1", "name": "我的翻译", "entries": [ … ] } ] },
    "a2": { "active": null, "books": [] },
    "a3": { "active": null, "books": [] }
  }
}
```

## 7.2 世界书

```jsonc
{
  "name": "翻译默认提示词",
  "entries": [
    { "id": "e1", "label": "常驻", "text": "…", "always": true,  "keys": [], "enabled": true },
    { "id": "e2", "label": "中文", "text": "…", "always": false, "keys": ["中文", "zh"], "enabled": true }
  ]
}
```

## 7.3 两个状态

```
存档（端口里）  ← 执行只用它
   ↑ 存 / ↓ 丢
草稿（内存里）  ← 读与全部改动都作用在它上面
```

**判脏不做字段**：草稿与存档各序列化一次，比字符串。没有版本号、没有时间戳、没有逐条标记。

## 7.4 两条不变量

| 不变量 | 后果 |
|---|---|
| **一处字段值只存一处** | `always` 只有一个来源；顺序只有数组顺序 |
| **出口一律给副本** | 读出来的条目、表、世界书都是副本；端口给的值进来时也拷一份 |

# 十、酒馆兼容

## 10.1 读哪三样

**只读三样、明确不读其余。**

| 读 | 从哪读 |
|---|---|
| 条目**顺序** | 对象形状按 key 的先后；数组形状按数组顺序 |
| **启用情况** | `disable` **取反**成 `enabled` |
| **启用条件** | `key` → `keys` |
| 正文 / 显示名 / 恒常 | `content` → `text`；`comment` → `label`；`constant` → `always` |
| 世界书的名字 | 顶层 `name` → `originalData.name` → 兜底"未命名世界书" |

> **`originalData.name` 不是可有可无的**：酒馆自己写盘时顶层**没有** `name`，
> 名字在 `originalData.name` 里（实测 11 份真实世界书全部如此）。只看顶层会把每本书都读成"未命名世界书"。

## 10.2 不读哪些（逐条理由）

| 不读 | 一行理由 |
|---|---|
| `position` / `depth` / `role` / `outletName` | **我们没有对话可插** —— 发出去的是一份提示词，没有位置、没有身份 |
| `order` | 顺序由数组位置决定，不需要第二套排序 |
| `probability` / `useProbability` | 参与与否必须是确定的 |
| `keysecondary` / `selectiveLogic` / `selective` | 次级关键词与四种布尔组合，超出"读条件"的范围 |
| `group` / `groupOverride` / `groupWeight` / `useGroupScoring` | 同上，权重抽取 |
| 递归四件（`excludeRecursion` 等） | 我们没有递归扫描 |
| `sticky` / `cooldown` / `delay` | 那是"在对话里待多久" |
| `vectorized` / `scanDepth` | 需要嵌入模型 / 扫描深度 |
| `matchPersonaDescription` 等六个 | 那些内容我们没有 |
| `triggers` / `ignoreBudget` / `automationId` / `addMemo` / `characterFilter*` | 不是内容 |
| `extensions` / `uuid` / 世界书自身的 `id` | 不是内容 |
| **正则关键词** | 我们只做字面关键词 |
| `caseSensitive` / `matchWholeWords` 的显式真值 | 空时与酒馆一致；显式真时我们更宽松 |

**判据一句话**：凡是回答"**放哪儿 / 什么时候 / 以什么身份 / 以什么概率**"的字段，一律不要；
凡是回答"**是什么内容 / 什么时候算命中**"的，才搬。

## 10.3 兼容范围

| 目标 | 酒馆兼容 |
|---|---|
| 提示词（本模块） | ✅ **要** —— 世界书 |

## 12.1 拿真实世界书验过的

用 11 份真实酒馆世界书（V1.2…V2.4，31 KB–77 KB）实测：

| 验的 | 结果 |
|---|---|
| 导入 | **11/11 成功**；条目数与停用位逐个与文件对上 |
| 名字 | 11 份都取到 `originalData.name`（世界书自己带的名字）——**正是这一步暴露了名字回退的缺陷** |
| 形状 | `entries` 是**对象**（uid → 条目），42 个字段；顶层还有 `originalData` |
| 调度 | V2.4 九条：不给输入命中 5 条 → 19392 字；各段字数之和 **逐字对上** |
| 往返 | 开一条停用条（+382 字 = 正文 380 + 分隔 2）· 加自建（+17 = 15 + 2）· 加条件后按输入进出 · 切回默认 · 再切回来 |

**实测发现的一件事**：这批世界书**一条关键词条件都不用**——V1.2 只有 1 条带 `key`，
V1.5 之后全为空。它们靠**停用位 + 注释里的"（选开）"** 做用户单选。
所以"命中 5/9 恒常"是对的行为：**导入保真地把作者的意图搬了过来**，
用户按需要开哪条就开哪条。

## 12.2 只读默认拦不拦得住

`node tools/防改.js`（**16 条**，用**真 assets 目录**跑，每一步之后比文件哈希）：

| 试的入口 | 结果 |
|---|---|
| 改名 · 删除 · 加条目 · 改条目正文 · 删条目 · 移条目（六个） | `PROMPT_READONLY_BOOK` |
| 导入覆盖默认 | `PROMPT_NO_SUCH_BOOK`（"不能覆盖这本书"） |
| 三个子模块各删一次 | 全部 `PROMPT_READONLY_BOOK` |
| 把 `a2` 的默认换给 `a3` | `PROMPT_NO_SUCH_BOOK` |
| 读它 / 执行它 / 切回它 | **全部正常**（893 / 339 / 6230 字） |
| 三个文件哈希 | **一字未变** |

**边界（如实记）**：模块只挡住"**通过它自己**"的写。进程里直接用 `fs` 写那个目录**能改、能删**
（这个工具第五节验的就是这件事，**对着一份拷到系统临时目录的副本**做，真文件不沾 —— 早先它直写真文件、靠 `finally` 还原，
进程半路死掉就会留下脏文件）。这一层**靠约定，不靠机制** ——
程序里没有任何一条路径去写默认目录，这是代码纪律，不是运行时锁。
要更硬就得在装配层做（打包进 asar、或启动时校验哈希），**本模块不做**。

# 附：本模块的决策记录

> **作废的留原文不删。** 拍板过程见 `work/` 下的讨论记录。

| # | 决策 | 出处 |
|---|---|---|
| 1 | 提示词模块是**"实现特定功能的一段程序"**，与主 AI 不是一套玩意；主 AI 另行设计 | 两者的取用方式与配置形态都不同 |
| 2 | 架构只有三样：**子模块表 · 世界书 · 一个动作** | 没有为管理而存在的机制 |
| 3 | 子模块 **三个**（`a1` 翻译 / `a2` 识图 / `a3` 文生图），**ID 是字母 + 序号** | 字母段标明来源；标题生成不需要子模块 |
| 4 | 用户**加不出新子模块** | 同"模块清单由开发者新增" |
| 5 | 默认内容 = **只读世界书**，一个子模块一份文件 | 它本身就是可用的东西，不需要"导入副本" |
| 6 | **按文件分门别类**，打开一个世界书不读其他几个 | 用户与程序都只看得到当前那一份 |
| 7 | **不允许删默认世界书** | 它随程序走，用户碰不到 |
| 8 | 用户世界书**存在端口里**，一个文件装全部；可增删改 | 一次保存一次原子写 |
| 9 | **`active` 一个可空字段**指向默认或用户那份 | 两种世界书，没有第三态 |
| 10 | **切回默认和切换世界书是同一个动作**；**不提供任何"回出厂"按钮** | 默认从没被改过，所以没有"还"这个动作 |
| 11 | 下拉**不分两组，按名字排序**；默认靠名字自明 | 程序不给默认加特例 |
| 12 | 条目带**可选启用条件**（`keys`），空 = 恒常 | 与世界书同构 |
| 13 | `constant` 与"没有关键词"**归一成一个 `always`** | 两个字段说同一件事，就会出现"到底谁说话" |
| 14 | 筛选**只做关键词子串命中**；不做正则 / 概率 / 次级逻辑 / 权重 / 递归 / 向量 | 参与与否必须确定；其余需要我们没有的东西 |
| 15 | 对外只有一个动作：**`执行({ 用途, 输入? }) → 提示词`** | 调用点只写用途 |
| 16 | **返回不解析** | 有哪些字段是提问那个模块的事 |
| 17 | **不拥有系统生成的提示词** | 那是各个域模块自己算的，提示词里没有这个东西 |
| 18 | **参数（温度、惩罚、上限）一律不存、不传、不读** | 归 AI 调用；读进来就是替别人保管字段 |
| 19 | **不碰主 AI** | 两者互不认识 |
| 20 | 兼容酒馆世界书：**只读顺序、启用情况、启用条件；不读插入位置** | 我们没有对话可插 |
| 21 | 兼容**只在提示词**；酒馆对话预设是主 AI 那边的事 | 两者的机制不同 |
| 22 | **没有"恢复默认"这个概念** | 用户从没改到过默认，所以不存在"还原" |
| 23 | 改条目即时生效、**落下按保存**；**导入立即生效**；切走若有未保存改动要提醒 | 两种改动改的不是同一样东西 |
| 24 | 出错**照项目既有形状**（`ok/data/error`），不抛给用户也不静默 | 调用点要能分辨"用途不对"和"没发出去" |
| 25 | **不做宏替换** | 我们根本没有那个概念 |
| 26 | **不做兼容层**，不兼容旧提示词数据 | 要回退用 git |
| 27 | 条目 **`id` 只由程序发**：一处发号（`worldbook.js` 的 `归一条`），从 `e1` 起跳过已占用的号；`加`、导入、读存档、读默认四条进路都走它；给进来的 `id` 一律不采信，`改` 也不许改 `id` | 原先发号的去重起点写成"这本书现有条目数"，传进来的 `e1` 就撞上已有的 `e1`；给进来的 `id` 照收则和"程序分配"直接矛盾。**发行号必须是唯一的进路**：只改一半（比如只改 `加` 那条）会让读回来的条目 `id` 全空，这一版踩到过 |
| 28 | `读` 给了 `书` 而非空、标识又找不到 → 报 `PROMPT_NO_SUCH_BOOK`，**不回落到"当前那本"** | 静默换一本，界面会以为它就是你要的那本；契约写的是"给了 `书` 就按它" |
| 29 | 文件适配器的 `listDefaults` **收全**：读不懂的那份也进清单，标 `state:'unreadable'`，核心照"读不懂"报 | 丢掉它就等于把"读不懂"说成"没有这份"，核心里所有 `unreadable` 分支在文件适配器下永远走不到 |
| 30 | **冻结只挡写盘的那几个入口**（`书` / `条目` / `存`）；`丢` / `重读` 不写盘，冻结时照用 | 冻结是"别把读不懂的存档盖掉"，不是把整个模块锁死 |
| 31 | `tools/防改.js` 里"绕开模块直写 / 直删"改成**对着系统临时目录里的副本**做，跑完删掉 | 早先直写真文件、靠 `finally` 还原，进程半途死掉就把默认文件留成脏的 |

| 33 | 装配的 `根目录` **只认这一个名字**，没有 `root` / `data` 之类的别名 | 多级兜底是缺陷（框架规则 8）；契约里也只写了 `{ 根目录, 默认目录 }` |

| 35 | `tools/看默认.js` / `tools/防改.js` 不再手抄 `['a1','a2','a3']`，走适配器的 `listDefaults()` | 手抄的清单必然跟真目录漂移；测试里那份"要验这三份"的判据仍保留 |
| 36 | 存档顶层的 **`format` 只是标记**，不参与判定；`version !== 1` 才是"读不懂" | `format` 写了从不校验，等于契约里多了一个假字段；两条路选"写明它是标记" |
