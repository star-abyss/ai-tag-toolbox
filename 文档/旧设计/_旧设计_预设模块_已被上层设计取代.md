# 一、范围

## 1.1 它做

| # | 做什么 |
|---|---|
| 1 | 管预设：只读默认 + 用户自己那份（新建 / 导入 / 改名 / 删 / 切换） |
| 2 | 管段：加 / 改 / 删 / 移 / 停用 |
| 3 | **管顺序**：这次按什么次序把段接起来 |
| 4 | 答"这次用哪几套预设、有哪些段、按什么顺序" |
| 5 | 导入酒馆预设的**提示词拼接**那半 |

## 1.2 它不做

| 不做 | 归谁 |
|---|---|
| **不拼装**：不把段接成一段话 | **上层**——它手里同时有世界书的条目 |
| **不填槽**：不把世界书的条目放进槽里 | 上层 |
| **不调模型** | 上层（模型调用那一小块） |
| **不读模型的设定**（温度 · 上下文 · 惩罚） | provider。酒馆那半明确不读（U-12） |
| **不读对话格式开关**（`wrap_in_quotes` / `names_behavior`） | harness 的消息格式是定死的 |
| 不读角色卡 · 正则 · 扩展脚本 | 各有各的归属，不在本轮 |
| 不认识世界书、不认识标签、不认识图片 | 它只认识自己的预设 |
| 不管界面怎么画 | 界面是通用面板的事 |
| 不做兼容层、不留回退开关 | 要回退用 git |

# 二、术语

| 词 | 意思 |
|---|---|
| **预设** | 一套骨架：一串有顺序的段 |
| **段** | 一条：`{ 名字, 角色, 注入位置?, 注入深度?, 内容, 启用 }` |
| **顺序** | 这次按什么次序接。**一张具名槽位表** |
| **槽** | 顺序表里的一个位置。分两类：**段占的槽**与**给别人投的槽** |
| **投槽** | 给别人投的槽：`世界书前` / `世界书后` / `对话`。**我们自己不放内容，只留位置** |
| **槽位表** | 一次请求的最终次序：段与投槽混在一起的一张有序表 |
| **只读默认** | 随程序走的预设，住在 `assets/预设/`。**没有任何写路径** |
| **草稿 / 存档** | 同世界书模块：草稿在内存，落下按保存 |

# 三、约束

## 3.1 继承自框架的边界规则

| # | 规则 | 本模块怎么体现 |
|---|---|---|
| 1 | 一个模块只交出一份清单 | 门面只有 `index.js`；出口冻住 |
| 2 | 能力在谁那儿，工具就在谁那儿 | 端口没递默认目录 = 没有只读默认 |
| 3 | **对外的参数永远是标识** | 参数只有 `请求` / `预设` / `标识` / `段`；检验法：看 `describe()` |
| 4 | 决定要在做出这个决定的操作里执行 | 顺序在 `执行` 里算出来，不靠调用方先拼一遍 |
| 5 | "能不能来"用"东西有没有传进来"表达 | 端口没递默认目录 = 没有默认预设 |
| 6 | 不解析不属于自己的东西 | 返回内容不解析；酒馆里我们用不上的字段不搬进来 |
| 7 | "必须和别处保持一致的清单"都不该存在 | **有哪几套预设由目录回答**，代码里没有清单 |
| 8 | 多级兜底来源是缺陷 | 不给"没默认就找别处"这种退路 |
| 9 | 依赖由装配层传进来 | 位置由装配层递；核心不 require fs/path |
| 10 | 不做兼容层，不留回退开关 | 不兼容旧预设数据 |

## 3.2 本模块自己的硬约束

| # | 约束 |
|---|---|
| 1 | **只读默认没有任何写路径** |
| 2 | **`执行` 只读存档**，不读草稿 |
| 3 | **不拼装、不填槽、不做取舍** |
| 4 | **槽位表是有序的**，顺序就是它的意义 |
| 5 | **投槽里我们自己不放内容**——只留位置 |
| 6 | **一处字段值只存一处**：顺序表里不许出现第二份段的内容 |
| 7 | 停用的段不参与，但留在预设里 |
| 8 | 参数不许进本模块的数据 |

# 四、架构

## 4.1 形状

```
预设模块（六边形）
├─ 门面 index.js     动作表
├─ 核心 core.js      预设 · 段 · 顺序 · 草稿/存档
├─ preset.js         解析 · 归一化 · 顺序展开（纯函数）
├─ port.js           端口：readState / writeState / listDefaults / readDefault
├─ adapter-file.js   文件适配器。唯一 require fs / path 的地方
├─ adapter-memory.js 内存适配器
└─ assets/预设/       只读默认：主AI.json
```

**与世界书模块同构**：同样有盘、同样两态、同样只读默认。差别只在**内容与规矩**（段 vs 条目、顺序 vs 条件）。

## 4.2 一次执行

```
执行({ 请求 })
  ① 按请求取启用列表      —— 哪几套
  ② 逐套读它当前那份      —— 读存档，不读草稿
  ③ 展开顺序表            —— 逐槽：是段就取它的内容，是投槽就留个位
  ④ 交出去：{ 请求, 预设, 段, 槽位 }
```

**就这四步。** 不接成一段话、不填槽、不决定世界书的条目放哪。

## 4.3 对外只有一份清单

门面既给界面用，也给调用点用，**不写第二遍**。

## 4.4 依赖方向

```
装配层
  └─ 预设模块（谁都不认识）
        ↑ 位置与端口都由装配层递
```

**没有环。** 本模块不认识世界书模块，也不认识上层——**它只留一个空位**，谁往里填是上层的事。

# 五、需求

## 5.1 预设

| 项 | 规定 |
|---|---|
| 名字 | 一个串，由调用方给（跟世界书模块同一把钥匙：**请求的名字**） |
| 几套同时用 | **0 到多套**。一套都没有 ⇒ 交回空 |
| 只读默认 | `assets/预设/<请求>.json`。不能删、不能改 |
| 用户那份 | 端口里一个文件装全部；可增删改 |
| 不认识的名字 | **不报错**，按空处理——有哪几套由目录回答（R-7） |

## 5.2 段

| 项 | 规定 |
|---|---|
| 形状 | `{ 名字, 角色, 注入位置?, 注入深度?, 内容, 启用 }` |
| `角色` | `系统` / `用户` / `助手`。默认 `系统` |
| `注入位置` | 缺省 = **按顺序表**（普通段）；给了就是"插进对话的第几条" |
| `注入深度` | 只在给了 `注入位置` 时有意义；默认 4 |
| `标识` | 程序发。段在预设内有稳定标识，供顺序表引用 |
| 顺序 | **由顺序表决定**，不由数组顺序决定（与世界书条目不同） |

## 5.3 顺序与槽

**顺序表就是一张有序的槽位表**，逐项要么指向一个段，要么是一个投槽：

| 槽 | 谁往里投 |
|---|---|
| 段自己 | 该段的内容 |
| `世界书前` | 落点是 `前` 的世界书条目 |
| `世界书后` | 落点是 `后` 的世界书条目 |
| `对话` | 正式的对话（harness 的会话） |

| # | 规定 |
|---|---|
| 1 | **顺序表的次序就是最终次序**，本模块不再重排 |
| 2 | 停用的项跳过，但留在表里 |
| 3 | **投槽里我们自己不放内容**——它是给别人的位置 |
| 4 | 一个投槽可以在表里出现**多次**（分几处投），按次数如实交出 |
| 5 | 名字与槽的对应**不做兜底**：顺序表提到一个不存在的段 ⇒ `PROMPT_NO_SUCH_SEGMENT` |

## 5.4 与世界书那一半的接口（本模块只留位）

**这是两个模块之间唯一的关系，而且它不是调用关系**：

```
预设模块  交出一张有序的槽位表，里面有"世界书前 / 世界书后"这样的空位
世界书模块 交出带落点的条目
上层      把条目的落点对上槽的名字，填进去
```

| # | 规定 |
|---|---|
| 1 | **本模块不知道世界书模块的存在**，也不知道条目长什么样 |
| 2 | 它只知道"有这么几个槽，别人会往里投" |
| 3 | 槽的名字由本模块定；世界书那边的落点由它自己定；**两张表由上层对上** |

## 5.5 导入酒馆预设

**只读提示词拼接那半。**

| 酒馆的 | 我们 | 备注 |
|---|---|---|
| `prompts[].name` | 段的 `名字` | |
| `prompts[].content` | 段的 `内容` | 一字不改 |
| `prompts[].role` | 段的 `角色` | `system` / `user` / `assistant` → 中文 |
| `prompts[].injection_position` | 段的 `注入位置` | 缺省 = 按顺序表 |
| `prompts[].injection_depth` | 段的 `注入深度` | 默认 4 |
| `prompts[].identifier` | 段的 `标识` | 用原值（它本来就稳定） |
| `prompt_order[].order[]` | **顺序表** | 逐项：`identifier` + `enabled` |
| `worldInfoBefore` / `worldInfoAfter` / `chatHistory` 三项 | **投槽** | 它们不是段，是位置 |
| `prompt_order[].character_id` | **不读** | 那是"按角色各一份顺序"；我们只有一份 |

**不读的**：`temperature` · `frequency_penalty` · `presence_penalty` · `top_p` · `top_k` · `top_a` · `min_p` · `repetition_penalty` · `openai_max_context` · `openai_max_tokens` · `seed` · `n` · `wrap_in_quotes` · `names_behavior` · `send_if_empty` · `jailbreak_system` · `impersonation_prompt` · `new_chat_prompt` 那一组 · `bias_preset_selected` · `wi_format` / `scenario_format` / `personality_format` · 各种 `*_model` 与 `*_url` · `stream_openai` · `image_inlining` · `squash_system_messages` · `assistant_prefill` · …

**一句话**：**只留"有哪些段、内容是什么、按什么顺序"，别的一律不要。**

| # | 规定 |
|---|---|
| 1 | 导入校验：JSON 语法错 / 没有 `prompts` / 没有 `prompt_order` ⇒ `PROMPT_BAD_PRESET`，**不动状态** |
| 2 | 段的 `标识` 用原值；重名 ⇒ 后到的加后缀，**不静默覆盖** |
| 3 | 顺序表里提到一个不存在的 `identifier` ⇒ **跳过它**，不为它造一个空段 |

## 5.6 草稿与保存

同世界书模块：改段即时生效（作用在草稿上），落下按 `存`；`丢` / `重读` 不写盘，冻结时照常可用。

## 5.7 出错

一切失败都可分辨（`code` + `reason`）。码表见 §八。

# 六、交出什么

## 6.1 形状

```js
执行({ 请求 })
  → {
      请求,                                    // 原样带回
      预设: [{ 标识, 名字 }],                   // 这次启用了哪几套，按启用顺序
      段:   [{ 标识, 角色, 内容, 注入位置?, 注入深度?, 预设 }],
      槽位: [ … ]                              // 有序；每一项要么是段的标识，要么是投槽名
    }
```

| 字段 | 为什么有 |
|---|---|
| `请求` | 调用方要按它把结果发回去 |
| `预设` | 界面上要能说出"这次用了哪几套" |
| `段[].预设` | 多套同时用时，"这段是谁的"必须看得出来 |
| `段[].内容` | 上层要拼 |
| `段[].角色` · `段[].注入位置` · `段[].注入深度` | 上层要按它们决定放哪 |
| **`槽位`** | **顺序就是它的意义**；上层按它把段与别人投进来的东西排成一列 |

## 6.2 三条边界

| # | 规定 |
|---|---|
| 1 | **交回的不是"一段提示词"**，是一组有序的段加槽位。拼装归上层 |
| 2 | **没有 `文本` 这个回程字段**——调用方自己发问，不必回一份 |
| 3 | **一套都不启用 ⇒ 交回空**，不是失败 |

# 七、数据

## 7.1 盘上的形状

```
<根目录>/预设.json                      用户那份（一个文件装全部）
<默认目录>/主AI.json                     只读默认，一套一个文件
```

**文件名就是请求名**（与世界书模块同一条）。

## 7.2 用户那份

```jsonc
{
  "format": "preset", "version": 1,
  "subs": { "主AI": { "启用": ["主AI"] } },
  "presets": {
    "p1": {
      "name": "我导入的",
      "槽位": ["main", "worldInfoBefore", "chatHistory", "jailbreak"],
      "segments": [
        { "标识": "main", "名字": "Main Prompt", "角色": "系统", "内容": "…", "启用": true },
        { "标识": "jailbreak", "名字": "Jailbreak", "角色": "系统", "内容": "…", "启用": true,
          "注入位置": "按深度", "注入深度": 0 }
      ]
    }
  }
}
```

**`槽位` 是一串标识或投槽名**——它引用段，不重复段的内容（约束 6）。

## 7.3 两个状态

| 状态 | 住哪 | 谁作用在它上面 |
|---|---|---|
| **存档** | 端口里那份 | **`执行` 只用它** |
| **草稿** | 内存里那份 | `读` 与全部改动 |

## 7.4 两条不变量

| # | 不变量 |
|---|---|
| 1 | 存档读不懂 ⇒ 写被冻结，但默认预设照常可用 |
| 2 | 只读默认一个字节都不会被本模块改动 |

# 八、错误码

| 码 | 什么时候 |
|---|---|
| `PROMPT_NO_SUCH_PRESET` | 标识指的预设不在 |
| `PROMPT_READONLY_PRESET` | 想改名 / 删 / 加段 / 改段，而目标是只读默认 |
| `PROMPT_NO_SUCH_SEGMENT` | 标识指的段不在那套预设里；或顺序表提到一个不存在的段 |
| `PROMPT_BAD_PRESET` | 导入的内容 JSON 坏 / 没有 `prompts` / 没有 `prompt_order` |
| `PROMPT_STATE_UNREADABLE` | 存档读不懂，写被冻结 |
| `PROMPT_WRITE_FAILED` | 写不进去 |
| `PROMPT_BAD_ARGUMENT` | 参数不对 / 没有这个动作 |

| # | 决定 | 由来说 |
|---|---|---|
| 1 | **任务是分开的两个模块：世界书与预设** | 住的东西不同（条目 vs 骨架）、进出条件不同（按条件 vs 永远在）、用户的用法不同（挂很多本 vs 选一套）。这是酒馆自己的分法 |
| 2 | **本模块管骨架**：任务身份 + 工作流程 | harness 与酒馆都提供这两样，我们换成自己的 |
| 3 | **只读入酒馆预设的提示词拼接那半** | 模型设定归 harness 的 provider；对话格式开关归 harness 的消息格式 |
| 4 | **不拼装、不填槽** | 骨架与世界书条目都由上层合并；**上层是唯一同时握着两样的地方** |
| 5 | **顺序表是一把有序的槽位表，里面含投槽** | 酒馆的 `prompt_order` 就是这个形状：段与 `worldInfoBefore` / `chatHistory` 这些位置混在一张有序表里 |
| 6 | **投槽里我们自己不放内容** | 它是给别人的位置。放内容就等于把世界书那半搬进来了 |
| 7 | **与世界书模块不是调用关系** | 本模块只留空位；两张表由上层对上。**两个模块互不认识** |
| 8 | **与世界书模块同构** | 同样有盘、两态、只读默认；差别只在内容与规矩。这样用户学一遍就懂两个 |
| 9 | **`character_id` 不读** | 那是"按角色各一份顺序"；我们只有一份 |
| 10 | **顺序表提到不存在的段 ⇒ 跳过，不造空段** | 造空段等于替别人编内容 |
