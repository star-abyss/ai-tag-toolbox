# 装订模块 · 接口契约

> 2026-10-17：切分增加标识、原文范围、词范围（UTF-16 左闭右开）；装订增加可选方向 auto/en-zh/zh-en，默认 en-zh，成功回执交付方向、表、统计及同一次拼装生成的译文范围。保留原始格式、分隔符及空项，不再接收装配分隔符；中译英不使用中文词库输出。门面文本处理是装配层递给本地翻译的共用纯文本端口。本段取代下文旧的规整原文、收掉空项、统一分隔符约定。

> **一份能独立于实现存在的契约。** 字段名、类型、必填、约束、错误码都写死在这里。

> 改实现之前先改这里。
>
> 三组接口，边界各不相同：
> - **对外操作**（§一）：门面交出去的那两个。**参数只有文本。**
> - **端口**（§二）：核心要求装配层提供什么。**两个函数，都可以不给。**
> - **装配**（§三）：装配层递什么进来。

## 〇、约定

| 记号 | 意思 |
|---|---|
| `必` | 必填 |
| `选` | 可选 |
| `?` | 可能没有（`null`／`undefined`） |
| `串` / `数` / `真伪` / `对象` / `数组` | `string` / `number` / `boolean` / `object` / `Array` |
| `→` | 返回值 |

**两套命名，不许混：**

- **中文键 = 给人的**（动作名、回执字段、参数名）
- **英文键 = 给程序的**（报文里的 `source` / `words` / `from` / `to`）

**失败一律 `{ ok:false, reason, code }`**，`reason` 的写法是 `码: 人话`。
直呼式（`装订.切分(...)`）成功给数据、失败给 `null`。**模块不抛错**（装配阶段除外）。

## 一、对外操作

### 1.0 被两个操作共用的形状

```
单元 = {
  前  必串    原样前缀。括号与权重，如 '('  '(([' ——没有就是空串
  词  必串    给查词与 AI 的那一串，纯词。空单元时是空串
  后  必串    原样后缀，如 ':1.3)'  '))'  ']' ——没有就是空串
}

报文 = {
  source  必串    完整原文（规整后），只供理解语境
  words   必数组  要它译的词，按出现顺序；**不带值**
  from    必串    来源语言：'英文'
  to      必串    目标语言：'中文'
}

回执 = { ok:true, 译文 必串, 原文 必串, 兜底 选串 }
      | { ok:false, code 必串, reason 必串, 原文 必串, 原因 选串 }
```

`兜底` 只在编排自己接住抛错时出现（那时 `译文` 就是 `原文`），值是抛错原因；正常走完六步的回执里没有这个字段。

**约束（不是建议）：**

| # | 约束 | 违反时 |
|---|---|---|
| 1 | 参数里只有「文本」，**不许出现路径 / 地址 / 标识** | 缺陷，不是错误码 |
| 2 | 单元的三字段都是字符串，空单元是三字段都空的那个 | —— |
| 3 | 报文里的 `words` 不带值 | —— |
| 4 | 失败回执里的 `原文` 是**这次装订快照**的那份 | —— |

### 1.1 `切分`

```
入  { 文本 必串 }
出  数组[单元]
```

| 项 | 规定 |
|---|---|
| 必做 | 按四条规则切；每格剥出壳与词 |
| 空单元 | **保留**，形状是三字段都空 |
| 规整 | CRLF / CR → LF；全角标点折半角。大小写与空白不动 |
| 退化 | 括号交错或不平衡 ⇒ **整段一个单元**，`前` / `后` 为空 |
| 抛错 | 不抛 |

### 1.2 `装订`

```
入  文本
出  回执
```

| 项 | 规定 |
|---|---|
| 必做 | 切分 → 查词 → 投影 → 发送 → 归位 → 拼回 |
| 必做 | 一进一出：**同时在飞的只有一次**；进行中再调 ⇒ `TEXT_BUSY` |
| 必做 | 全查到时**一次都不发** |
| 必做 | 失败时 `原文` 给出来，界面拿它显示 |
| 原文快照 | 进函数时取一次；飞行中用户改了界面上的文本，不影响这次 |
| 异步 | **是**（要等 AI 翻译） |
| 抛错 | 不抛。执行器抛错由本模块接住，换成失败回执 |

### 1.3 直呼与动作表

| 门面成员 | 说明 |
|---|---|
| `切分({ 文本 })` | 直呼式：成功给单元数组，失败给 `null` |
| `装订(文本)` | 成功给 `{ ok:true, 译文, 原文 }`；失败给 `{ ok:false, … }` |
| `译文(文本)` | 异步。只要译文：成功给文本，失败给 `null` |
| `有内容的格(单元数组)` | **只留可译的那些格**。原文与译文两边都过一遍，序号才一一对应 |
| `run(动作, 参数)` | 走动作表。两条路两种形状：`切分` 给 `{ ok:true, data }`、`装订` 给 `{ ok:true, 译文, 原文, 兜底? }`；动作名不对或动作抛错给 `{ ok:false, reason, code }` |
| `actions` | `['切分', '装订']`（冻住） |
| `describe()` | `[{ 动作, 摘要, 参数, 说明 }]` |
| `ERR` | 错误码字典（冻住） |
| `SAY` | 码 → 人话（冻住） |
| `端口` | 两项端口的名字与形状（冻住） |

**出口冻住**：门面 `Object.freeze`，不递 `core` / `port` / `adapter`。

### 1.4 高亮怎么配（调用方的用法）

```
原文格 = 装订.有内容的格(装订.切分({ 文本: 原文 }))
译文格 = 装订.有内容的格(装订.切分({ 文本: 译文 }))
        ⇒ 两边格数相同、序号一一对应；第 i 格对第 i 格
```

**两边都要过 `有内容的格`。** 原文里的空单元（`a,,b` 中间那一格）在译文里没有对应的东西——
只过一边，两边格数就不等，高亮会从那里开始整体错位。

## 二、端口

本模块**没有盘**，所以端口不是存储，是两个递进来的函数。**两个都可以不给。**

### 2.1 `查词`

```
查词(词列表 必数组) → 数组[中文名 或 null]
```

| # | 规定 |
|---|---|
| 1 | 入参是一批**原样词**（切分产出的「词」），不是归一化后的键 |
| 2 | 出参长度与入参一一对应：命中给中文名（串），未命中给 `null` |
| 3 | 归一化在函数内部做；本模块不碰 |
| 4 | 抛错 ⇒ 整次失败（`TEXT_LOOKUP_FAILED`） |
| 5 | 不给 ⇒ 没有库可对，所有词都进 `words`（**不是失败**） |
| 6 | 返回不是数组 ⇒ 当作全都没查到 |

### 2.2 `AI翻译`

```
AI翻译(报文 必对象) → 键值对
```

| # | 规定 |
|---|---|
| 1 | 入参是本模块组装好的报文；函数自己取提示词、自己发请求 |
| 2 | 出参可以是一个对象，或一段**文本**（文本里含 JSON 对象也行）；也可以返回 Promise |
| 3 | 出参不是对象 / 解析不出对象 ⇒ `TEXT_BAD_ANSWER` |
| 4 | 抛错（含超时）⇒ `TEXT_TRANSLATOR_FAILED` |
| 5 | 不给 ⇒ 用到它时那一次失败（`TEXT_NO_TRANSLATOR`） |
| 6 | **本模块不重试**：一次装订只调它一次 |

## 三、装配

```js
createBindingModule({
  查词 选函数,
  AI翻译 选函数,
  分隔符 选串,        // 拼回时行与行之间那一格，默认 ', '
})
```

| 项 | 规定 |
|---|---|
| 两个函数都不给 | **合法**。查词不给 ⇒ 全交给 AI；AI 翻译不给 ⇒ 用到时那次失败 |
| 给了但不是函数 | **构造即抛错**（装配阶段允许抛） |
| 出口 | `Object.freeze`；只交操作面，不递内部件 |

### 3.1 现成的真实适配器 `adapter-real.js`

不想自己写那两个函数，就把**下面三个函数**递给它，它造出一对端口：

```js
const { createRealAdapter } = require('./装订模块/adapter-real.js');

const 端口 = createRealAdapter({
  认词,      选函数
  取提示词,  选函数
  发请求,    选函数
  用途,      选串，默认 '翻译'
});
createBindingModule(端口);
```

| 参数 | 形状 | 规定 |
|---|---|---|
| `认词` | `(词列表 必数组) → 数组[中文名 或 null]` | 就是端口 `查词` 要的那一支，原样转交 |
| `取提示词` | `(报文 必对象) → 串` | 拿这一次的报文，给那一段系统提示词。不给 ⇒ `system` 是空串 |
| `发请求` | `({ 用途, system, user }) → 正文` | 唯一发请求的地方。`用途` 与 `system` 是本适配器填的，`user` 是报文序列化成的一段话。给回应是正文（串），或 Promise |
| `用途` | `串` | 提示词表里选哪一条用途。默认 `'翻译'` |

| # | 规定 |
|---|---|
| 1 | `认词` 不是函数 ⇒ 调 `查词` 时抛错；`发请求` 不是函数 ⇒ 调 `AI翻译` 时抛错 |
| 2 | 本适配器只 require 递进来的东西，不 require 别的模块 |
| 3 | 出口是 `{ 查词, AI翻译 }`，正好能整个递给 `createBindingModule` |

接线例子见 [调用示例.md](调用示例.md) §一。

## 四、错误码

| 码 | 什么时候 | 给人的意思 |
|---|---|---|
| `TEXT_BUSY` | 上一次还没回来 | 等它回来 |
| `TEXT_NO_TRANSLATOR` | 要用 AI 翻译而没递进来 | 翻译功能不可用，显示原文 |
| `TEXT_TRANSLATOR_FAILED` | 执行器抛错（含超时） | 发不出去，显示原文 |
| `TEXT_BAD_ANSWER` | 返回解析不出键值对 | 显示原文；想改去改提示词 |
| `TEXT_LOOKUP_FAILED` | 查词函数抛错 | 显示原文 |
| `BIND_BAD_ARGUMENT` | 没有这个动作 | 改代码 |
| `BIND_FAILED` | 动作自己出错 | 改代码 |

**一句话：能分辨才叫失败。** 走 `装订` 那条路的每一条失败都带 `原文`，界面永远有东西可显示；
走 `run` 那条路而动作名不对 / 动作自己抛错的（`BIND_BAD_ARGUMENT` / `BIND_FAILED`），只有 `{ ok:false, reason, code }`，不保证带 `原文`。

## 五、这份契约怎么被校验

`test/run.js` 拿这份文档里写死的字段名与形状去问实现：

| 校验 | 判据 |
|---|---|
| 对外恰好两个动作 | `actions` 恰好是 `['切分','装订']` |
| 出参字段名与契约一致 | 单元的三字段、回执的字段逐个比对 |
| 对外参数里没有路径 / URL | 参数名不许匹配 `/路径\|地址\|path\|url/i` |
| 尖括号 / 花括号的边界 | V-16 |
| 端口给了不是函数要抛错 | V-84 |
| 装配给的空串分隔符要照用 | V-86 |
| 编排接住抛错时的 `兜底` | V-87 |
| 出口冻住、不递内部件 | V-80 |
| 失败一律可分辨 | V-61 … V-65、V-83 |

**改实现之前先改这份契约；改完契约，跑 `node test/run.js`。**
