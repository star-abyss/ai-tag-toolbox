# 装订模块 · 设计规范

> 本文档是重写项目的模块设计之一。框架（三层结构与边界规则）在根 [AGENTS.md](../../AGENTS.md)，本文档只写本模块自己。
> **不引用别的模块的实现与内部结构**；提到提示词时，只说它住在哪一份文件里（§十一），不把那边的设计搬进来。

**一句话**：**把一段文本切开，查得到的词换成库里的中文名，查不到的交给 AI，再按原样拼回去。**

---

# 一、范围

## 1.1 它做

| # | 做什么 |
|---|---|
| 1 | 切分：一段文本 → 单元列表（每格记 `前 / 词 / 后`） |
| 2 | 查词：把每格的「词」交给递进来的查词函数 |
| 3 | 投影：原文原样 + 一张待译词表，交给递进来的 AI 翻译 |
| 4 | 归位：把 AI 回的键值对填回它自己那一格 |
| 5 | 拼回：库译名优先、其次 AI 译文、再其次原词；空单元收掉 |
| 6 | 一次装订只跑一次：同时在飞的只有一个 |

## 1.2 它不做

| 不做 | 归谁 |
|---|---|
| 不认识标签库、不解析它的字段 | 查词函数（装配层递进来） |
| 不认识提示词、不认识 AI 调用 | AI 翻译（装配层递进来） |
| 不拥有归一化 | 查词函数内部做；本模块只交原样词 |
| 不管理提示词 | 世界书模块的 `翻译` 世界书（§十一）；本模块一个字的提示词都没有 |
| 不发送请求、不管链路 / 密钥 / 超时 / 重试 | AI 调用与装配层 |
| 不解释权重 / 括号 / 转义的**语义** | 程序只把它们当壳移动，不当意思读 |
| 不认任何软件的方言 | 认识那个格式的模块（`<lora:x>` 剥成 `前<` / 词 `lora:x` / 后 `>`，本模块不解释 `lora:x` 是什么） |
| 不解析 AI 返回的**语义** | 只挑自己发出去的那些词，其余不看 |
| 不做本地翻译 | 本地档整段进、整段出，与识图的本地档同形，不经过本模块 |
| 不管界面怎么画 | 通用面板的事 |
| 不做"该不该翻译"的判断 | 调用方 |
| 不重试 | 用户自己点 |
| 不落盘、不保存任何东西 | 无存储 |
| 不做兼容层、不留回退开关 | 要回退用 git |

# 二、术语

| 词 | 意思 |
|---|---|
| **单元** | 切分出来的一格：`{ 前, 词, 后 }` |
| **壳** | `前` 与 `后` 合起来，装括号与权重 |
| **词** | 交给查词函数与 AI 的那一串，纯词 |
| **空单元** | 三个字段都空的单元。`a,,b` 中间那一格 |
| **表** | 一次装订里的那张表：一行一格，四列（壳 / 词 / 库译名 / AI译文） |
| **报文** | 交给 AI 翻译的那份东西：`{ source, words, from, to }` |
| **键值对** | AI 回来的东西：`{ 词: 译文 }` |
| **进行中** | 闸门。一次装订在跑时它立着，跑完就放下 |

# 三、约束

## 3.1 继承自框架的边界规则

| # | 规则 | 本模块怎么体现 |
|---|---|---|
| 1 | 一个模块只交出一份清单 | 门面只有 `index.js`；出口冻住 |
| 2 | 能力在谁那儿，工具就在谁那儿 | 查词与 AI 翻译是递进来的函数；没递 = 那个能力不存在 |
| 3 | **对外的参数永远是标识** | 对外只有两个动作，参数只有「文本」；检验法：看 `describe()` |
| 4 | 决定要在做出这个决定的操作里执行 | 筛选哪些词要发，在装订里做，不靠调用方先滤一遍 |
| 5 | "能不能来"用"东西有没有传进来"表达 | 没递查词 ⇒ 所有词都交给 AI；没递 AI 翻译 ⇒ 用到时那一次失败 |
| 6 | 不解析不属于自己的东西 | AI 回来的是不是键值对只管形状；里面是什么内容不看 |
| 7 | "必须和别处保持一致的清单"都不该存在 | 表就是切分的产物，不另存第二份 |
| 8 | 多级兜底来源是缺陷 | 查词抛错就是失败，不退回"不查库" |
| 9 | 依赖由装配层传进来 | 两个函数都由装配层递；核心不 require 任何别的模块 |
| 10 | 不做兼容层，不留回退开关 | —— |

## 3.2 本模块自己的硬约束

| # | 约束 |
|---|---|
| 1 | **表只活在一次装订里。** 不进端口、不跨调用保存 |
| 2 | **一次装订同时在飞的只有一个。** 进行中再调 ⇒ 拒绝（`TEXT_BUSY`） |
| 3 | **闸门一定会开。** 成功、失败、抛错，都走 `finally` |
| 4 | **报文里没有程序造的符号。** 只有原文与那张词表 |
| 5 | **查到的词根本不发出去。** 模型碰都碰不到 |
| 6 | **AI 不许看壳、库译名、空行。** 报文只投影「词」这一列 |
| 7 | **拼回顺序：库译名 → AI译文 → 原词。** |
| 8 | **空单元不查、不发、拼回时收掉。** |
| 9 | **失败的表现就是原文。** 回执里的 `原文` 是这次装订快照的那份 |
| 10 | 一切失败都可分辨（`code` + `reason`） |

# 四、架构

## 4.1 形状

```
装订模块（六边形）
├─ 门面 index.js     切分 · 装订 · 译文 · 有内容的格
├─ 核心 core.js      六步，全是纯函数 + 一次装订的编排
├─ 端口 port.js      查词 · AI翻译
└─ 适配器             adapter-fake.js（自包含）· adapter-real.js（接真实链路）
```

**本模块没有盘**，所以端口不是存储，是两个递进来的函数。核心不 require 任何别的模块。

## 4.2 一次装订

```
装订(文本)
  进行中 ⇒ 拒（TEXT_BUSY）
  进行中 = true
  try {
    原文 = 规整(文本)
    ① 切分      原文 → 表（行 = 格）
    ② 查词      表.词 → 表.库译名        只把「词」交出去
    ③ 投影      表 → 报文                只取「词」这一列，不带值
    ④ 发送      报文 → 键值对
    ⑤ 归位      键值对 → 表.AI译文        逐行按键取值
    ⑥ 拼回      表 → 译文                库译名优先；空行跳过
  } catch { 译文 = 原文，回执另附 兜底 = 抛错原因 }
  finally { 进行中 = false }
```

**一张表走完全程。** 中间没有第二个结构，也没有"反向拼接"这一步。

**没有要译的词就一次都不发**——全查到的时候，AI 那边零请求。

## 4.3 对外只有一份清单

门面既给界面用，也给调用点用，**不写第二遍**。模型侧能不能看见本模块，由门面层决定。

## 4.4 依赖方向

```
装配层
  ├─ 标签模块 → recognize  ──┐
  ├─ 提示词    → 提示词       ─┤ 包成两个函数
  └─ AI 调用  → 发请求       ─┘
                             ↓
                    装订模块（谁都不认识）
```

**没有环。** 本模块不认识标签、不认识提示词、不认识 AI 调用。

# 五、需求

## 5.1 切分（四条规则）

| # | 规则 |
|---|---|
| 1 | **按逗号切**，也认 `、` `;` `|` 换行 |
| 2 | **括号深度内的逗号不算**：`(` `)` `[` `]` `{` `}` `<` `>` |
| 3 | **反斜杠转义**：`\(` `\)` `\\` 是字面字符，不参与嵌套 |
| 4 | **切不出来就退**：交错 / 不平衡 ⇒ 整段当一个单元，不猜 |

规整（进切分之前）：CRLF 与 CR 折成 LF；全角 `，；｜（）［］｛｝` 折成半角。
**全角分隔符靠 `规整` 折半角才命中**——切分那张分隔符表里只有半角 `,` `、` `;` `|` 与换行，
`；` `｜` `，` 是先进 `规整` 变成 `;` `|` `,` 的。
**只折标点，不折大小写、不去空白、不做别的归一化**——那是查词那边的事。

首尾空白：每个单元切出来时去掉首尾空白。

## 5.2 一个单元装什么

```
单元 = { 前, 词, 后 }
```

| 字段 | 装什么 |
|---|---|
| `词` | 给查词与 AI 的，纯词 |
| `前` | 原样前缀，如 `(`、`((`、`[` |
| `后` | 原样后缀，如 `:1.3)`、`))`、`]` |

**只有一对配平的括号才算壳**：

| 输入 | 前 | 词 | 后 |
|---|---|---|---|
| `(x:1.3)` | `(` | `x` | `:1.3)` |
| `dark grey skin (dark grey skin:1.3)` | | `dark grey skin (dark grey skin:1.3)` | |
| `((smug, smug face):1.5)` | | `((smug, smug face):1.5)` | |
| `(smug, smug face)` | `(` | `smug, smug face` | `)` |
| `(flat_breasts)` | `(` | `flat_breasts` | `)` |
| `x:1.3` | | `x` | `:1.3` |
| `\(x\)` | | `\(x\)` | |
| `(a)(b)` | | `(a)(b)` | |
| `<lora:x>` | `<` | `lora:x` | `>` |
| `<lora:x:1>` | | `<lora:x:1>` | |
| `(nsfw:1.2, 1girl)` | | `(nsfw:1.2, 1girl)` | |

四条边界：

- **转义的括号剥不掉**——`\(x\)` 整段是词。这正是规则 ③ 的价值。
- **框里装不下这一格就不剥**——`(a)(b)`、`dark grey skin (dark grey skin:1.3)` 整段当词；
  外层括号里还套着括号的 `((smug, smug face):1.5)` 也是整段一格。
- **尖括号与花括号里不认权重**——`<lora:x:1>` 里有 `:数字`，那就不是壳，整段当词；
  只是冒号而不带 `:数字` 的 `<lora:x>`、`{lora:abc}` 照常剥成 `前` `<` / `词` `lora:x` / `后` `>`。
- **词段与后缀段不许重叠**——`(nsfw:1.2, 1girl)` 整段当词：后缀要成为后缀，就不能把词里已经用掉的那一段再算一遍。

## 5.3 查词

**只把「词」交出去**，一次交一批，拿回一一对应的一批。

| # | 规定 |
|---|---|
| 1 | 入参是切分产出的原样词，不是归一化后的键 |
| 2 | 归一化在查词函数内部做，本模块不碰 |
| 3 | 命中者填进 `库译名`；`null` / 空串 / 不是字符串 ⇒ 留 `null` |
| 4 | 词为空的格子不查、不占位 |
| 5 | 抛错 ⇒ 整次失败（`TEXT_LOOKUP_FAILED`），不退回"不查库" |
| 6 | 没递查词函数 ⇒ 不是失败，所有词都进 `words` |

## 5.4 报文

```
{
  source  必串    完整原文，只供理解语境
  words   必数组  要它译的词，按出现顺序；**不带值**
  from    必串    来源语言：'英文'
  to      必串    目标语言：'中文'
}
```

| # | 规定 |
|---|---|
| 1 | `source` 是**规整后**的原文，一字不改 |
| 2 | `words` **只放查不到的**；查到的根本不发 |
| 3 | `words` **不带值**——`null` 会让模型把 `null` 当答案抄回来 |
| 4 | 同一个词出现多次 ⇒ `words` 里就出现多次（按格不按词） |
| 5 | 壳、库译名、空行——一列都不进报文 |

## 5.5 归位与拼回

```
每一行：  有库译名 → 用库的
          否则有 AI 译文 → 用 AI 的
          否则 → 用原词
拼回：    前 + 上面那一个 + 后；空行跳过；行与行之间一个规范分隔符
```

| # | 规定 |
|---|---|
| 1 | 归位是**逐行按键取值**，不按顺序配 |
| 2 | 缺键 / 值是 `null` / 数字 / 对象 / 数组 ⇒ 那一行留 `null`，退原词 |
| 3 | 不认识的键丢掉 |
| 4 | 规范分隔符：`, `（一个逗号 + 一个空格）。装配层给了 `分隔符` 就用给的那个 |
| 5 | 段内的一个字节都不改；被规范的只有段与段之间那一格 |
| 6 | 空单元不产词、不产分隔符——首尾的空单元因此被收掉 |
| 7 | **格数不等于行数**：行数由切分决定，分隔符个数由非空行决定 |
| 8 | 默认值**只有一处**：在 `core.js` 装配时定；给了空串也算给了，不退回 `, ` |

## 5.6 对齐：怎么让原文与译文一一对上

译文里有几格，原文里就有几格——**但只有把两边都过一遍同一个筛选**才成立：

```
原文格 = 有内容的格(切分(原文))
译文格 = 有内容的格(切分(译文))
       ⇒ 两边格数相同、序号一一对应；第 i 格对第 i 格
```

| # | 规定 |
|---|---|
| 1 | **两边都要过 `有内容的格`**。原文里的空单元在译文里没有对应的东西 |
| 2 | 只过一边 ⇒ 从那个空单元起整体错位。这是静默错位，不报错 |
| 3 | `有内容的格` 是门面成员，调用方不必自己写这个筛选 |

## 5.7 AI 返回的形状（只碰语法）

```
① 直接解析
② 扒掉 ``` 围栏 → 再解析
③ 从最外层的每个 { 起，找与它配平的那一段 → 再解析
```

| # | 规定 |
|---|---|
| 1 | 三条随便宽容——弄错了也只是解析不出来，**不会解析出一个错的对应关系** |
| 2 | 整段解析不出来，或解出来不是对象 ⇒ 整次失败（`TEXT_BAD_ANSWER`） |
| 3 | 数组不是键值对；**嵌在数组里的对象也不算** |
| 4 | "按顺序硬配"这种碰语义的事，一条都不做 |
| 5 | 第三条**扫到文本末尾才停**，没有"试几个 `{` 就放弃"的个数上限 |

# 六、横切：鲁棒性

**四件事全是同一条：一次装订就是一个边界。**

| 事 | 怎么办 | 靠什么 |
|---|---|---|
| 表怎么维护 | **不维护**。一次装订一份，用完就地扔掉 | 表是局部变量 |
| 用户连续点击 | 拒绝第二次，报 `TEXT_BUSY` | 进行中守卫 |
| AI 没回复 | 超时归 AI 调用；执行器抛错 ⇒ 整次退原文 ⇒ 开闸 | `finally` |
| AI 格式不对 | 语法层宽容解析；解不出整次退原文；单行缺键只退那一行 | 两层判定 |
| AI 回的是上一次 | **不可能**——同一时刻只有一次在飞 | 同一条守卫 |
| 飞行中用户改了文本 | **照旧套用**，不比对、不提示、不报错 | 不做"文本变了"的判断 |

**界面那份原文用"这次翻译的那份"**（回执里的 `原文`），不是界面上现在那份。

# 七、错误

**任何一环出问题，最差的结果也是"用户自己的原文"。**

| 码 | 什么时候 | 界面 |
|---|---|---|
| `TEXT_BUSY` | 上一次还没回来 | 等它回来，或什么都不做 |
| `TEXT_NO_TRANSLATOR` | 用到 AI 翻译而没递进来 | 显示原文 |
| `TEXT_TRANSLATOR_FAILED` | 执行器抛错（含超时） | 显示原文 |
| `TEXT_BAD_ANSWER` | 返回解析不出键值对 | 显示原文 |
| `TEXT_LOOKUP_FAILED` | 查词函数抛错 | 显示原文 |
| `BIND_BAD_ARGUMENT` | 动作名不对 | 改代码 |
| `BIND_FAILED` | 动作自己出错 | 改代码 |

回执形状：`{ ok:false, code, reason, 原文, 原因? }`。`reason` 的写法是 `码: 人话`。
**失败时也把原文给出来**——调用方拿它显示，不必自己去记这次翻的是哪段文本。
走 `run` 而动作名不对 / 动作自己抛错的（`BIND_BAD_ARGUMENT` / `BIND_FAILED`）只有 `{ ok:false, reason, code }`。
编排自己接住抛错时反而算成功：`{ ok:true, 译文: 原文, 原文, 兜底 }`（§4.2）。

# 八、对外

**两个动作。** 出口 `Object.freeze`，不递内部件。

| 动作 | 输入 | 输出 | 同步 |
|---|---|---|---|
| `切分` | 文本 | `[{ 前, 词, 后 }]` | 是 |
| `装订` | 文本 | `{ ok:true, 译文, 原文, 兜底? }` / `{ ok:false, code, reason, 原文, 原因? }` | **异步** |

另有两个直呼成员：`译文(文本)`（只要译文，失败给 `null`）、`有内容的格(单元)`（对齐用）。

**为什么两个都对外**：切分要单独用得着——凡是要"原文与译文对齐"的地方（高亮）都用它。交出去才不会长出第二份实现。

# 十一、实测

**13 条真实提示词、654 个单元**跑过切分与剥壳：共 8 条带壳、10 处词里含裸括号、4 处含反斜杠、4 处含冒号。**没有一条退化。**

**8 轮端到端**（6 条例子的报文交给真模型再收回来）：

| 例·轮 | 要发 | 回 | 缺键 | 原文格 / 译文格 | 对齐 |
|---|---:|---:|---:|---|---|
| 例2·1 | 24 | 18 | **6** | 114 / 114 | ✓ |
| 例2·2 | 24 | 24 | 0 | 114 / 114 | ✓ |
| 例2·3 | 24 | 24 | 0 | 114 / 114 | ✓ |
| 例7·2 | 16 | 16 | 0 | 49 / 49 | ✓ |
| 例8·4 | 13 | 13 | 0 | 36 / 36 | ✓ |
| 例11·2 | 14 | 14 | 0 | 54 / 54 | ✓ |
| 例13·1 | 17 | 17 | 0 | 50 / 50 | ✓ |
| 例5·1 | 14 | 14 | 0 | 36 / 36 | ✓ |

- **八轮全部装订成功、全部格数一一对应。**
- 唯一的缺键出现在第一轮（提示词还没补"每个词都要出现"那条之前）。
- 同一个报文跑三次，模型给出三种形态（丢键 / 键=值 / 译出来）——**三种都被接住，都落在"那一格退原词"**。
- 拿真报文配 19 种坏回复，逐条落在设计的位置上。**这些记录目前没有落库**（本仓没有 `work/` 目录）。

**提示词住在** [世界书模块/assets/世界书/翻译.json](../世界书模块/assets/世界书/翻译.json) 的 `e1`，本模块里一个字的提示词都没有。

# 附：本模块的决策记录

| # | 决策 | 出处 |
|---|---|---|
| 1 | 装订模块与翻译模块、识图模块平级；本地档不经过它 | 讨论定 |
| 2 | 一张表走完全程，没有第二张表、没有反向拼接 | 讨论定 |
| 3 | 表只活在一次装订里，不进端口、不跨调用保存 | 讨论定 |
| 4 | 进行中守卫 + `finally` 开闸；界面禁用只是体验 | 讨论定 |
| 5 | 超时归 AI 调用；本模块不知道 60 秒这个数 | 讨论定 |
| 6 | 飞行中用户改了文本 ⇒ 照旧套用，不比对、不提示 | 用户原话：对应不上拉到，不报错就行 |
| 7 | 空单元 = 三字段都空；不查、不发、拼回时收掉 | 讨论定 |
| 8 | 报文只投影「词」一列，不带值、不带壳、不带空行 | 用户原话：模型只该看到原文和要它翻译的词 |
| 9 | 键用原词，不用编号——报文里没有程序造的符号 | 用户原话：标记不该给模型 |
| 10 | 单行缺键只退那一行；整段解不出才整次退原文 | 讨论定 |
| 11 | 解析只碰语法；吞掉旁边的东西可以，读内容不行 | 讨论定 |
| 12 | 切分与拼回互为逆；同一份文本切出来的格数与拼回去的格数相等 | 讨论定 |
| 13 | 权重只认圆括号与方括号；尖括号、花括号里带 `:数字` 就不是壳 | 实测例5 `<lora:x:1>` |
| 14 | 一切失败都给原文，回执里带这次装订快照的那份原文 | 讨论定 |
| 15 | 一次装订失败的表现就是"显示原文"，不做重试、不做降级 | 架构 |
