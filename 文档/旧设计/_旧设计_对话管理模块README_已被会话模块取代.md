# 对话管理模块

管理会话、当前选择、消息记录、发送与停止、存档和变化通知。入口只有 `index.js`，无外部包依赖。

它是应用状态模块，不属于七个 AI 能力模块，也不登记为模型工具。界面沿用 `/对话/*` 操作它；标签、图片等能力动作仍走 `/toolbox/调`。模型、预设、世界书和工具循环由装配层传入，本模块不决定 AI 的流程。

```js
const { createConversationModule, createFileAdapter } = require('./index');
const chat = createConversationModule({
  port: createFileAdapter({ 目录: '/由装配层传入的存档目录' }),
  执行: async ({ 会话, 话, 信号, 更新 }) => {
    // 会话是本轮副本，history 从消息记录生成。
    会话.messages.push({ id: '本轮消息标识', role: 'assistant', text: '回复', status: 'complete', toolCalls: [] });
    更新(会话);
  },
});
await chat.ready;
const id = chat.状态().当前;
await chat.调('发', { 会话: id, 话: '你好' });
```

## 接口

`状态()` 同步返回副本；`调(动作, 参数)` 返回 Promise。写操作按提交顺序执行，同一会话同时只有一轮模型执行。不同会话的执行互不串消息。

| 动作 | 参数 | 行为 |
|---|---|---|
| 状态 | 无 | 会话列表、当前选择、运行状态 |
| 新 | 无 | 新建并选中 |
| 换 | `会话` | 切换并保存当前选择 |
| 改名 | `会话?`、`标题` | 保存标题 |
| 删 | `会话?` | 删除；删除其他会话保留当前选择，删除当前会话选相邻一条，删除最后一条创建新会话 |
| 清空 | `会话?` | 清空该会话的消息与模型上下文 |
| 发 | `会话?`、`话` | 保存用户消息后开始执行；立即返回受理结果与 `会话号` |
| 停 | `会话?` | 取消这条会话的执行信号；执行结束后释放运行状态 |
| 导出 | 无 | `{ok:true, 内容}`，内容是 `{会话:[…]}` 的 JSON |
| 导入 | `内容` | 追加导出的会话，重新生成会话与消息 ID，并选中最后一条；未完成工具记录标为停止，带对应回执 |

未指定目标会话时使用当前选择。`subscribe(callback)` 返回退订函数；`停()` 取消所有在途执行，供宿主关闭时调用。

状态：`{ok:true, 版本, 当前, 会话:[{id,title,titleManual?,messages,updatedAt,running}], 在跑}`。`titleManual` 标记用户手动设置的标题，首次发送不会覆盖它。失败：`{ok:false, code, reason}`，`reason` 为 `码: 人话`；码集中在 `ERR`。

## 存储端口与执行端口

- `port.read()` 同步返回 `{sessions, currentId}` 的副本。
- `port.write({sessions,currentId})` 返回 Promise；失败抛错。
- 文件适配器将会话写入 `会话.json`，当前会话 ID 写入 `当前.json`。目录由装配层提供；内存适配器遵守同一契约。
- `执行({会话,话,信号,更新})` 接收会话副本。副本的 `messages` 是展示记录，`history` 是本轮按模型协议生成的上下文。执行期间通过 `更新(会话)` 发布消息进展；`history` 不作为另一张存档表保存。
- 每条用户消息可带 `context`，表示插在该消息前面的模型参考正文；每条助手消息的 `toolCalls` 保存 `id,name,args,status,result`。模型上下文按消息顺序生成工具声明和回执。
- 程序生成的错误、停止提示带 `model:false`，只供界面展示。
