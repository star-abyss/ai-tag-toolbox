# 一、范围

## 1.1 它做

| # | 做什么 |
|---|---|
| 1 | 管书：只读默认 + 用户自己那份（新建 / 导入 / 改名 / 删 / 切换） |
| 2 | 管条目：加 / 改 / 删 / 移 / 停用 / 条件 / **落点** |
| 3 | 答"这个请求这次启用了哪几本" |
| 4 | 按这次调用的文本筛出命中的条目 |
| 5 | 把命中条目连同**它的落点**交出去 |
| 6 | 导入酒馆世界书（顺序 · 启用情况 · 启用条件 · 落点 · 深度 · 角色） |
| 7 | 草稿与手动保存：改条目即时生效，落下要按保存 |

## 1.2 它不做

| 不做 | 归谁 |
|---|---|
| **不拼装**：不把命中条目接成一段话 | **上层**——它手里有骨架，模块手里只有条目 |
| **不排序**：不决定条目之间的先后 | 上层按落点分堆 |
| **不做取舍**：不决定哪本优先、哪条压哪条 | 上层 |
| **不发请求**：不建连接、不收回答 | 上层（模型调用那一小块） |
| 不拥有骨架（任务身份 · 工作流程） | 预设 |
| 不认识主 AI、不认识副 AI | 它只认"请求"这个名字 |
| 不解析返回内容 | 提问的那个模块 |
| 不管用哪条链路、哪个模型、密钥、超时、重试 | API 路由与上层 |
| **不存参数**（温度、惩罚、输出上限） | 上层与 provider（R-14） |
| 不管上下文、历史 | 本模块没有上下文 |
| 不做宏替换 | 我们根本没有那个概念（R-24） |
| 不管界面怎么画 | 界面是通用面板的事 |
| 不认识对话、图片、标签 | 它只认识自己的世界书 |
| 不做兼容层、不留回退开关 | 要回退用 git（R-28） |
| 不做酒馆**对话预设**导入 | 那是预设模块的事（R-23） |

# 二、术语

| 词 | 意思 |
|---|---|
| **请求** | 调用方交进来的名字（`翻译` / `识图` / `主AI` …）。**一个任务一套书** |
| **书** | 一份世界书：一个名字 + 一串条目 |
| **条目** | 一条：`{ id, label, text, always, keys, enabled, 落点, 深度?, 角色? }` |
| **启用列表** | 这个请求这次用哪几本。**可以几本** |
| **只读默认** | 随程序走的书，住在 `assets/世界书/`。**没有任何写路径** |
| **用户那份** | 用户的书，住端口里。可增删改 |
| **命中** | 这次参与的一条条目，连同它的落点 |
| **落点** | 这条要放在哪：`前` / `后` / `顶部` / `底部` / `按深度` |
| **深度** | 落点是 `按深度` 时才有：距对话末尾第几条 |
| **角色** | 落点是 `按深度` 时才有：`系统` / `用户` / `助手` |
| **草稿 / 存档** | 草稿在内存，改动作用在它上面；存下来才进端口 |
| **冻结** | 存档读不懂时，只挡写盘的那几个入口 |

# 三、约束

## 3.1 继承自框架的边界规则

| # | 规则 | 本模块怎么体现 |
|---|---|---|
| 1 | 一个模块只交出一份清单 | 门面只有 `index.js`；出口冻住 |
| 2 | 能力在谁那儿，工具就在谁那儿 | 端口没递默认目录 = 没有只读默认 |
| 3 | **对外的参数永远是标识** | 参数只有 `请求` / `文本` / `书` / `标识` / `条目`；检验法：看 `describe()` |
| 4 | 决定要在做出这个决定的操作里执行 | 筛选在 `执行` 里做，不靠调用方先滤一遍 |
| 5 | "能不能来"用"东西有没有传进来"表达 | 端口没递默认目录 = 没有默认书 |
| 6 | 不解析不属于自己的东西 | 返回内容不解析；酒馆里我们用不上的字段原样留着、不解释 |
| 7 | "必须和别处保持一致的清单"都不该存在 | **有哪几本书由目录回答**，代码里没有清单 |
| 8 | 多级兜底来源是缺陷 | 不给"没默认就找别处"这种退路 |
| 9 | 依赖由装配层传进来 | 端口与位置都由装配层递；核心不 require fs/path |
| 10 | 不做兼容层，不留回退开关 | 不兼容旧提示词数据 |

## 3.2 本模块自己的硬约束

| # | 约束 |
|---|---|
| 1 | **只读默认没有任何写路径**（R-5） |
| 2 | **`执行` 只读存档**，不读草稿（R-16） |
| 3 | **条目顺序就是数组顺序**（R-11） |
| 4 | `always` 只有一个来源（R-13） |
| 5 | 筛选只有关键词子串命中（R-12） |
| 6 | **不拼装、不排序、不做取舍**（本轮新增） |
| 7 | 参数不许进本模块的数据（R-14） |
| 8 | "读不懂"不许当成"没有"（R-29） |
| 9 | `always` 与 `keys` 互斥（R-15） |
| 10 | **落点只做三种**：`前` / `后` / `按深度`（本轮定） |

# 四、架构

## 4.1 形状

```
世界书模块（六边形）
├─ 门面 index.js     十个动作
├─ 核心 core.js      书 · 条目 · 启用列表 · 草稿/存档
├─ worldbook.js      解析 · 归一化 · 筛选（纯函数）
├─ port.js           端口：readState / writeState / listDefaults / readDefault
├─ adapter-file.js   文件适配器。唯一 require fs / path 的地方
├─ adapter-memory.js 内存适配器
└─ assets/世界书/     只读默认：主AI · 翻译 · 识图 · 文生图
```

## 4.2 一次执行

```
执行({ 请求, 文本 })
  ① 按请求取启用列表      —— 哪几本
  ② 逐本读它当前那份      —— 读存档，不读草稿
  ③ 逐本筛条目            —— always 恒进；keys 命中才进
  ④ 交出去：{ 请求, 书, 命中 }
```

**就这四步，没有第五步。** 不接成一段话、不排先后、不决定谁压谁。

## 4.3 对外只有一份清单

门面既给界面用，也给调用点用，**不写第二遍**。模型侧能不能看见本模块，由门面层决定。

## 4.4 依赖方向

```
装配层
  └─ 世界书模块（谁都不认识）
        ↑ 位置与端口都由装配层递
```

**没有环。** 本模块不认识任何一个别的模块，也不认识上层。

# 五、需求

## 5.1 请求

| 项 | 规定 |
|---|---|
| 形状 | 一个串，如 `'翻译'` / `'识图'` / `'主AI'` |
| 名字从哪来 | **调用方定的**。它就是"这件事"的名字 |
| 不认识的名字 | **不报"没有这个用途"**——按空启用处理，交回 `书: []`、`命中: []`。**有哪几本书由目录回答**（R-7） |
| 请求与书的对应 | **不建对照表**。书的名字就是请求的名字（R-7） |

## 5.2 书

| 项 | 规定 |
|---|---|
| 两份来源 | 只读默认（`assets/世界书/<请求>.json`）· 用户那份（端口里一个文件装全部） |
| 启用几本 | **0 到多本**。一本都没有 ⇒ 交回空 |
| 只读默认能不能删 | **不能**。它随程序走，用户碰不到 |
| 只读默认能不能改 | **不能**。要改就导出 → 导入 → 启用副本（见上层设计「只读的含义」） |
| 用户那份 | 可增删改；一本一本书，各自有名 |
| 冻结 | 存档读不懂 ⇒ **冻结这个键的写**；默认书照常可用 |

## 5.3 条目

| 项 | 规定 |
|---|---|
| 形状 | `{ id, label, text, always, keys, enabled, 落点, 深度?, 角色? }` |
| `id` 谁发 | **只由程序发**：从 `e1` 起顺着找第一个没被这本书占用的号（V-40）。给进来的 `id` 不采信 |
| `always` / `keys` | 互斥。`always:true` ⇒ 清空 `keys`；给 `keys` ⇒ 按"词空不空"定 `always`（空 ⇒ `always:true`） |
| 顺序 | **数组顺序就是参与顺序** |
| `enabled` | 停用的条目不参与，但留在书里 |
| 参数 | **一律不存**。温度那类东西本模块一个字段都没有（R-14） |

## 5.4 落点

| 落点 | 意思 | 酒馆对应 |
|---|---|---|
| `前` | 投进"前"槽 | `position: 0` |
| `后` | 投进"后"槽 | `position: 1` |
| `顶部` | 投进"顶部"槽 | `position: 2` |
| `底部` | 投进"底部"槽 | `position: 3` |
| `按深度` | 按 `深度` 插在距对话末尾第几条 | `position: 4` |

| # | 规定 |
|---|---|
| 1 | **本模块只交落点，不解释它**。放哪、怎么排是上层的事 |
| 2 | `顶部` / `底部` **存下、原样带出去，本轮不实现**（U-13） |
| 3 | 落点是 `按深度` 时 `深度` 才有意义；默认 4 |
| 4 | 落点是 `按深度` 时 `角色` 才有意义；默认 `系统` |
| 5 | 落点缺省 = `前` |

**为什么本模块不管"按深度"怎么算**：那要数对话，对话在上层。**本模块只把 `深度` 这个数原样交出去**，有对话的那一方自己数（U-14）。

## 5.5 筛选

| # | 规定 |
|---|---|
| 1 | **`always:true` ⇒ 恒进**，不看文本 |
| 2 | **`keys` 非空 ⇒ 文本里出现任一个 key 才进**（子串命中） |
| 3 | 文本从哪来 | 调用方给的 `文本` |
| 4 | 不做正则 / 概率 / 次级逻辑 / 权重 / 递归 / 向量（R-12） |
| 5 | 参与与否**必须确定** |

## 5.6 导入酒馆世界书

| 项 | 规定 |
|---|---|
| 读哪些 | 顺序 · 启用情况（`disable`）· 启用条件（`key`）· 落点（`position`）· 深度（`depth`）· 角色（`role`） |
| 不读哪些 | `probability` · `keysecondary` · `selectiveLogic` · 递归那几项 · `group` 那一组 · `scanDepth` · `caseSensitive` · `matchWholeWords` · `sticky` / `cooldown` / `delay` · `automationId` · `vectorized` · `addMemo` |
| 只读默认哪些位置 | `position: 5` / `6` / `7` **存下、原样带出去，不参与拼装**（U-13） |
| 校验 | JSON 语法错 / 没有 `entries` ⇒ `PROMPT_BAD_WORLDBOOK`，**两种情况都不动状态** |
| `id` | 由程序重发（V-41），原 `uid` 不沿用 |

## 5.7 草稿与保存

| 项 | 规定 |
|---|---|
| 改条目 | **即时生效**（作用在草稿上） |
| 落下 | 按 `存` |
| `丢` | 草稿丢回存档 |
| `重读` | 重读端口 |
| 冻结只挡什么 | **只挡写盘的那几个入口**（`书` / `条目` / `存`）；`丢` / `重读` 不写盘，冻结时照常可用 |

## 5.8 出错

一切失败都可分辨（`code` + `reason`）。码表见 §十一。

# 六、交出什么

## 6.1 形状

```js
执行({ 请求, 文本 })
  → {
      请求,                                  // 原样带回，调用方按它原路发回去
      书:   [{ 标识, 名字 }],                 // 这次启用了哪几本，按启用顺序
      命中: [{ 文本, 落点, 深度?, 角色?, 书 }]  // 逐条；`书` 是它来自哪一本
    }
```

| 字段 | 为什么有 |
|---|---|
| `请求` | 调用方要按它把结果发回去 |
| `书` | 界面上要能说出"这次用了哪几本" |
| `命中[].书` | 多本同时启用时，"这条是谁的"必须看得出来 |
| `命中[].文本` | 上层要拼 |
| `命中[].落点` | 上层要按它分堆 |

## 6.2 三条边界

| # | 规定 |
|---|---|
| 1 | **交回的不是"一段提示词"**，是一组带落点的条目。拼装归上层（U-10） |
| 2 | **没有 `文本` 这个回程字段**——调用方自己就是发问的那一方，它手里有；回一份就是同一份数据两处存 |
| 3 | **一本书都不启用 ⇒ 交回空**，不是失败 |

## 6.3 上限

| 项 | 规定 |
|---|---|
| 条数 | **不设上限**（R-14 的精神：可加可不加的限制不加） |
| 单条长度 | **不设上限** |
| 总量 | 超了由上层处理；本模块不截断、不警告 |

# 七、数据

## 7.1 盘上的形状

```
<根目录>/世界书.json                   用户那份（一个文件装全部）
<默认目录>/主AI.json 翻译.json …         只读默认，一本书一个文件
```

**文件名就是请求名**，这样"有哪几本书"由目录回答，代码里没有清单（R-7）。

## 7.2 用户那份

```jsonc
{
  "format": "worldbook", "version": 1,   // format 只是标记；version 不是 1 才算读不懂
  "subs": {
    "翻译": { "启用": ["翻译", "wb1"] },
    "主AI": { "启用": ["主AI"] },
    "识图": { "启用": ["识图"] }
  },
  "books": {
    "wb1": { "name": "我的翻译", "entries": [ … ] }
  }
}
```

**一处改动**：`active`（一本）→ **`启用`（一串）**。主副同构，只是启用列表里有几个元素不同（U-9）。

## 7.3 世界书

```jsonc
{
  "name": "翻译默认",
  "entries": [
    { "id": "e1", "label": "常驻",   "text": "…", "always": true,  "keys": [],           "enabled": true, "落点": "前" },
    { "id": "e2", "label": "中文",   "text": "…", "always": false, "keys": ["中文","zh"], "enabled": true, "落点": "按深度", "深度": 2, "角色": "系统" }
  ]
}
```

## 7.4 两个状态

| 状态 | 住哪 | 谁作用在它上面 |
|---|---|---|
| **存档** | 端口里那份 | **`执行` 只用它** |
| **草稿** | 内存里那份 | `读` 与全部改动 |

## 7.5 两条不变量

| # | 不变量 |
|---|---|
| 1 | 存档读不懂 ⇒ 写被冻结，但默认书照常可用 |
| 2 | 只读默认一个字节都不会被本模块改动 |

# 十、酒馆兼容

## 10.1 读哪几样

顺序 · 启用情况（`disable`）· 启用条件（`key`）· 落点（`position`）· 深度（`depth`）· 角色（`role`）。

## 10.2 不读哪些（逐条理由）

| 不读 | 为什么 |
|---|---|
| `probability` / `useProbability` | 参与与否必须确定（R-12） |
| `keysecondary` / `selectiveLogic` | 次级逻辑，同上 |
| 递归那几项（`excludeRecursion` / `preventRecursion` / `delayUntilRecursion`） | 同上 |
| `group` / `groupWeight` / `groupOverride` / `useGroupScoring` | 同上 |
| `scanDepth` | 扫多深由上层定 |
| `caseSensitive` / `matchWholeWords` | 我们的命中口径是确定的子串 |
| `sticky` / `cooldown` / `delay` | 时间机制，我们没有 |
| `automationId` / `vectorized` / `addMemo` | 酒馆内部的东西 |
| `displayIndex` | 显示顺序由数组顺序回答 |
| 世界书级 `extensions` / 书自身的 `id` | 不是内容 |

**留在条目上但不动**：上面这些字段导入时**不搬进来**；而 `position: 5/6/7` 三种**搬进来但不实现**（U-13）。

## 10.3 兼容的判据

```
导入一份带 position / depth / role 的酒馆世界书  →  导出  →  语义相同
```

**有真实数据可依**：酒馆导出的世界书与预设 JSON 就是这一种，拿真文件试。

# 十一、出错

| 码 | 什么时候 | 界面 |
|---|---|---|
| `PROMPT_NO_SUCH_BOOK` | 标识指的书不在 | 刷新表再选 |
| `PROMPT_READONLY_BOOK` | 想改名 / 删 / 加条目 / 改条目，而目标是只读默认 | 提示"默认是只读的"，让他导出再导入 |
| `PROMPT_NO_SUCH_ENTRY` | 条目 id 不在那本书里 | 别用缓存的旧 id |
| `PROMPT_BAD_WORLDBOOK` | 导入的内容 JSON 坏 / 没有 `entries` | 提示"这不是一份世界书"。**状态没动** |
| `PROMPT_STATE_UNREADABLE` | 存档读不懂，写被冻结 | 显示横幅；**默认照常能用** |
| `PROMPT_WRITE_FAILED` | 写不进去（磁盘满 / 权限 / 被占用） | 显示端口交回的原因；草稿还在 |
| `PROMPT_BAD_ARGUMENT` | 参数不对 / 没有这个动作 / 移越界 | 检查参数名 |

**本轮改了两条**：

| 原来 | 现在 | 为什么 |
|---|---|---|
| `SUB_AI_` 前缀 | `PROMPT_` 前缀 | 名字里带着旧概念（U-39） |
| `NO_SUCH_SUB`（用途不在三个里） | **删掉** | 有哪几本书由目录回答，模块不再有"只许三个"这条规矩（R-7） |

# 十二、验证

**判据与本文档的 `V-*` 一一对应，且必须能在不读源码的情况下判真假。**

| 组 | 判据 |
|---|---|
| 请求与书 | V-1 … V-8（不认识的名字交回空、一本书都不启用交回空、文件名即请求名） |
| 条目 | V-9 … V-22（发号、`always`/`keys` 互斥、停用、顺序、参数不进） |
| 落点 | **V-23 … V-30（新增）**：五种落点存得下、三种参与拼装、缺省是 `前`、`深度` 与 `角色` 只在 `按深度` 时有意义 |
| 筛选 | V-31 … V-36（恒进、子串命中、确定） |
| 导入 | V-37 … V-43（顺序、启用位、条件、三种落点、坏文件不动状态、`id` 重发） |
| 往返 | **V-44 … V-46（新增）**：导入 → 导出 → 语义相同 |
| 装配 | V-47 … V-52（端口不合格拦住、`根目录` 只认一个名字、两个都不给抛错） |
| 草稿 | V-53 … V-58（即时生效、`存`/`丢`/`重读`、冻结只挡写） |
| 门面 | V-59 … V-62（出口冻住、不递内部件） |

**本轮验证上的两处变化**：

| | 变化 |
|---|---|
| 多 | 落点与往返两组是新的，**而且有真实数据可依**（本机有真酒馆世界书） |
| 少 | "用户加不出新子模块"那条判据**删掉**——模块不再有"只许三个"这条规矩 |

# 十四、决定记录

> **作废的留原文不删。** 编号顺延。前 37 条见本文档旧版与 `work/` 下的讨论记录。

| # | 决定 | 由来说 |
|---|---|---|
| 38 | **改名叫「世界书模块」**（原名「提示词模块」，更早叫「副 AI 模块」） | 它只管世界书：挑条目、交出去。**拼装已经归上层**，叫"提示词模块"名不副实 |
| 39 | 错误码前缀 `SUB_AI_` → `PROMPT_`；装配函数 → `createPromptModule`；包名 → `prompt-module` | 名字里带着旧概念 |
| 40 | **温度那一类参数本来就不在** | 定 R-14 时就没往里放。这次是**把说法与事实对上**，不是删代码 |
| 41 | **`执行` 不再拼装**：交回的是带落点的条目，不是一段话 | 骨架住在预设，**只有上层同时握着骨架和条目**；模块拼出来的是半个提示词 |
| 42 | **不做合并、不排序、不做取舍** | 合并归上层。模块只答"启用了哪几本""每本命中了什么" |
| 43 | **回执只有三样**：`请求` · `书` · `命中`。**没有 `文本`** | 调用方就是发问的那一方，它手里有文本；回一份就是同一份数据两处存 |
| 44 | **`active`（一本）→ `启用`（一串）** | 酒馆本来就允许同时启用多本世界书；主副同构，差别只是列表里有几个元素 |
| 45 | **请求的名字由调用方定，模块不建对照表** | 书的名字就是请求的名字；**有哪几本书由目录回答**，代码里没有清单（R-7） |
| 46 | **不认识的名字不报错，交回空** | 同上；"有没有这份"由目录回答 |
| 47 | **`NO_SUCH_SUB` 删掉** | 模块不再有"只许三个"这条规矩 |
| 48 | **条目加三个字段**：`落点` · `深度` · `角色` | 酒馆的 `position` / `depth` / `role` 一一对得上，**往返一致**因此可验 |
| 49 | **落点只做 `前` / `后` / `按深度`** | `顶部` / `底部` 存下不实现；`EMTop` / `EMBottom` / `outlet` 在 harness 的消息结构里没有落点（U-13） |
| 50 | **`深度` 与 `角色` 只在 `按深度` 时有意义** | 与酒馆一致：那两样本来就只服务 `atDepth` |
| 51 | **"按深度"这个数不由本模块算** | 算它要数对话，对话在上层。**本模块原样交出去** |
| 52 | **只读默认可以导出，导入后就是用户的书** | "是不是默认"看它住在哪，不看叫什么；于是"改一个默认条目"这件事全用已有动作拼出来（U-11） |
