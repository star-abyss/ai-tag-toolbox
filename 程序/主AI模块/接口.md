## 一、装配

```js
const { createMainAiModule } = require('./主AI模块/index.js');
```

两种装配方式，二选一：

| 方式 | 参数 | 说明 |
|---|---|---|
| 递端口 | `{ port }` | 自检走这条 |
| 给位置 | `{ 根目录, 默认目录, 业务工具? }` | 本模块自己装文件适配器 |

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `port` | object | 二选一 | 端口对象，方法见 §三 |
| `根目录` | string | 二选一 | 用户那份的目录。**不能是盘根** |
| `默认目录` | string | 同上 | 只读默认的目录 |
| `业务工具` | function | 否 | 返回 `[{ 名字, 摘要, 参数:{…}, 说明:{…} }]`；AI 可调用能力的唯一来源 |

**装配阶段允许抛错**（除此之外一律不抛）：

| 缺什么 | 抛什么 |
|---|---|
| 既没 `port`，`根目录` / `默认目录` 又有一个不是非空字符串 | `PRESET_BAD_ARGUMENT: 要么递端口…，要么给位置…` |
| `根目录` 是盘根 | `根目录不能是盘根` |
| 端口缺方法 | `端口不合格：端口缺方法：<名字>（要有 …）` |

出口 `Object.freeze`，**不递内部件**。

## 二、对外动作

十个动作。读直接给结果；`存` / `丢` 走端口写。
**失败一律** `{ ok:false, reason:'码: 人话', code }`。

### 2.1 `执行({ 请求?, 预设? })`

上层要的那一个：这次这套预设配置。**读存档。**身份、工作方式与世界书正文由世界书模块提供。

```jsonc
{
  "ok": true,
  "data": {
    "请求": "主AI",
    "预设": { "标识": "$默认:主AI", "名字": "主AI" },
      "工具表": [                        // 已滤掉停用的；文本与schema是副本
      { "名字": "query_tags", "摘要": "查询标签", "参数": { "串": { "type": "string", "description": "…", "required": true } }, "说明": { "串": "…" } }
    ],
      "模型": {},                        // { 走?, 模型? }
      "附加文本": {}                     // 预设 runtime 的副本；默认空对象
  }
}
```

- `请求` 只用来查"这个请求启用了哪几套"；没给就用默认那一套。
- `预设` 指不到 ⇒ `PRESET_NO_SUCH_PRESET`，**不回落**。

### 2.2 `读({ 请求?, 预设? })`

表 + 某请求启用了哪几套 + 那套预设的正文 + 草稿状态。

```jsonc
{
  "ok": true,
  "data": {
    "表": [ /* 见 2.3 */ ],
    "脏": false,
    "请求": "主AI",
    "启用": [ { "标识": "ps1", "名字": "我的主AI", "是本子": false, "存在": true, "读得懂": true } ],
    "预设": { "标识", "名字", "是本子", "工具表": [ { 名字, 摘要, 启用, 参数, 说明, 算得出来 } ], "model", "runtime" },
    "冻结": "读不懂的理由"        // 只在冻结时出现
  }
}
```

`算得出来` 对业务表中的每一行都为真。工具名只作为业务能力标识，不拆分为模块与动作。

### 2.3 `表()**

```jsonc
{
  "ok": true,
  "data": [
    { "标识": "$默认:主AI", "名字": "主AI", "是本子": true,  "存在": true, "工具数": 65 },
    { "标识": "ps1",        "名字": "我的主AI", "是本子": false, "存在": true, "工具数": 65, "读不懂": true }
  ]
}
```

按名字排序。`读不懂: true` 表示那一份在盘上读不出来。

### 2.4 `测({ 请求?, 预设? })`

与 `执行` 同形，**读草稿**。改完不存时，`执行` 拿到旧的、`测` 拿到新的。

### 2.5 `预设({ 动作, … })**

| 动作 | 参数 | 说明 |
|---|---|---|
| `新建` | `名字?`, `源?`, `请求?` | 从 `源` 拷一份；**不给 `源` = 从只读默认抄一份快照** |
| `复制` | `预设`, `名字?` | 从 `预设` 拷一份 |
| `导入` | `内容?` \| `一套?`, `名字?`, `请求?` | 收一份预设对象；**不去模块那头核对** |
| `改名` | `预设`, `名字` | |
| `删` | `预设` | |
| `导出` | `预设` | 给出这一套的文本（可直接再导入） |
| `改` | `预设`, `model?`, `runtime?` | **只改给的那几格**；runtime 按给出的对象原样保存，未给的字段由装配侧决定是否取默认 |
| `换` | `请求`, `启用` | 换某个请求的启用列表；一套都不启用给空数组 |

- 撞名时**自动加号**，绝不覆盖。
- 对只读默认做写动作 ⇒ `PRESET_READONLY_PRESET`。
- `内容` 不是 JSON ⇒ `PRESET_BAD_PRESET`，**状态不动**。
- 导入对象里的身份、流程、世界书字段忽略；世界书内容通过世界书模块导入与编辑。

### 2.6 `工具({ 动作, 预设, … })**

| 动作 | 参数 | 说明 |
|---|---|---|
| `加` | `名字` | 启用已有业务工具；业务表之外的名字失败 |
| `改` | `名字`, `启用?`, `摘要?`, `参数?`, `说明?` | 可改工具摘要及各层级参数 description，空串有效；schema 类型、必填与字段取业务定义 |
| `删` | `名字` | 停用该业务工具 |
| `移` | `名字`, `方向?` \| `到?` | 方向 `上` / `下`；或给目标序号 |
| `重置` | —— | 清掉这一套的工具差异，恢复当前业务定义 |

### 2.7 `存()` · `丢()` · `重读()** · `状态()`

| 动作 | 说明 |
|---|---|
| `存` | 草稿写进端口。冻结时失败 |
| `丢` | 草稿丢回存档，脏变回假 |
| `重读` | 重读端口。自建库与启用列表都不动 |
| `状态` | 体检：几套预设、默认工具表几条、有没有认不出的动作 |

## 三、端口

装配层递进来的对象要有这五个方法。

| 方法 | 返回 |
|---|---|
| `readState()` | `{ state:'ok'\|'missing'\|'unreadable', value?, reason? }` |
| `writeState(value)` | `{ ok, reason? }` |
| `listDefaults()` | `{ ok, items?: [{ 名字, state? }], reason? }` |
| `readDefault(名字)` | `{ state, value?, reason? }` |
| `businessTools()` | `{ ok, 工具表: [{ 名字, 摘要, 参数:{<名>:{type,description,required?}}, 说明 }] }` |

**读的三态**：`ok` 有 / `missing` 确实没有 / `unreadable` 读不懂（带 `reason`）。

`reason` 取值：`权限` · `磁盘满` · `被占用` · `读不懂` · `不存在` · `未知`。

**`businessTools` 是 AI 工具定义的唯一来源。** 它列出经过挑选、可由 AI 调用的业务能力；模块动作不会自动成为 AI 工具。

## 四、盘上的形状

```jsonc
// <根目录>/预设.json —— 用户那份
{
  "format": "主AI预设",
  "version": 1,
  "subs": { "主AI": { "启用": ["ps1"] } },
  "presets": {
    "ps1": {
      "name": "我的主AI",
      "tools": [ { "名字": "query_tags", "启用": false, "摘要": "自定义摘要", "文本覆盖": { "/串": "参数说明", "/对象/properties/名称": "嵌套说明" } } ],
      "toolsOrder": ["query_tags", "draw_image"],
      "model": { "走": "官方", "模型": "deepseek-flash" },
      "runtime": { "图片标题": "" }
    }
  }
}
```

```jsonc
// <默认目录>/主AI.json —— 只读默认（没有 tools：工具表按当前业务契约生成）
{ "name": "主AI" }
```

- 预设 `tools` 只存启用、摘要和以 schema 路径记录的 description 差异，schema 结构始终取当前业务定义。空字符串是有效覆盖；未知或旧工具名读取时不进入工具表；读取不写回原文件，用户保存后只持久化有效差异。
- `runtime` 仅在用户给出时存盘，模块不解释其字段；快照返回 `runtime`，执行返回 `附加文本`，缺省均为空对象。覆盖对象原样保存与返回，空字符串不回落到默认值。
- `tools: []` 表示没有覆盖差异，当前业务工具默认启用；它不是关闭所有工具的开关。
- 旧工具快照只会把名称仍匹配当前业务表的启用与说明迁移为差异；旧身份、流程与世界书字段会忽略，主动保存后只写现行字段。
- `version` 不是 `1`、空文件、数组 ⇒ **都算读不懂**。
- 用户那份读不懂 ⇒ **冻结写**（`测` / `执行` 照常读默认）。
- 只读默认读不懂 ⇒ 那一套在 `表` 里标 `读不懂`，正文按空算，**别的照常**。

## 五、错误码

| 码 | 什么时候 |
|---|---|
| `PRESET_NO_SUCH_PRESET` | 标识指不到（`执行` / `测` / 各写动作） |
| `PRESET_READONLY_PRESET` | 对只读默认做写动作 |
| `PRESET_NO_SUCH_TOOL` | 工具表里没有这个名字 |
| `PRESET_BAD_PRESET` | 导入的内容不是一个能用的预设 |
| `PRESET_STATE_UNREADABLE` | 存档读不懂，写被冻结 |
| `PRESET_WRITE_FAILED` | 写盘失败 |
| `PRESET_BAD_ARGUMENT` | 参数不合格（含没有这个动作名） |

码在 `core.js` 的 `ERR` 里集中定义，`index.js` 的出口也带一份 `ERR`。
**理由里出现码**，便于程序分辨。

## 六、出口

```js
主AI.run(动作, 参数)     // → { ok, data } | { ok:false, reason, code }
主AI.actions            // → ['执行','读','表','测','预设','工具','存','丢','重读','状态']（冻住）
主AI.describe()         // → [{ 动作, 摘要, 参数, 说明 }]
主AI.ERR                // → 错误码表（冻住）

// 直呼式：成功给数据，失败给 null
主AI.执行({ 请求, 预设 })
主AI.读({ 请求, 预设 })
主AI.表()
主AI.测({ 请求, 预设 })
主AI.预设({ 动作, … })
主AI.工具({ 动作, … })
主AI.存() · 主AI.丢() · 主AI.重读() · 主AI.状态()
```

**出口冻住，内部件一个都不递。**
