# 主AI模块设计

## 目标与边界

主AI模块保存模型配置以及用户对当前业务工具的偏好。“这个 AI 是什么”、工作方式与知识正文由世界书模块管理，主 AI 默认书位于 `程序/世界书模块/assets/世界书/主AI.json`。AI 能调用哪些能力由装配层明确交入的业务工具表决定。模块动作、界面管理动作和注册表管理动作不会自动变成 AI 工具。

本模块不执行工具、不认识模块路由，也不把工具名拆解成模块和动作。对接层负责组装当前业务工具对象，并把主AI预设中的启用状态与说明应用到业务声明上。

## 接口与数据流

```text
绘画业务工具定义
        ↓ businessTools() 端口
主AI模块按用户差异生成当前预设工具表
        ↓ 执行({请求})
对接层选出启用工具并登记业务执行器
```

端口由存档读写、只读默认读取与业务工具表组成。主AI模块不会遍历模块动作清单。一个工具条目的结构为：

```js
{
  名字: 'drawing_generate',
  摘要: '根据提示词生成图片',
  参数: {
    正向: { type: 'string', description: '正向提示词', required: true },
    负向: { type: 'string', description: '可选的负向提示词' },
  },
  说明: { 正向: '本次生成使用的正向提示词' },
}
```

业务工具定义拥有工具名、摘要、参数类型、必填项和字段结构。用户预设可启停工具、覆盖摘要与 schema 任意层级的 description 文本、调整顺序；这些操作不改业务 schema 结构。文本覆盖按 schema 路径存储，空串也代表用户明确清空。

## 预设存档

每套用户预设仅保存名字、工具差异、工具顺序、模型配置，以及用户给出的 `runtime` 附加文本对象。`tools` 只记录与业务定义不同的设置；未出现的工具默认启用，`tools: []` 就是无差异。默认预设不落完整工具表，运行时从当前业务定义读取。缺省 `runtime` 为空对象；模块不解释其内容，快照用 `runtime` 暴露、执行用 `附加文本` 返回。

读入旧版完整工具快照时，只对仍存在的同名业务工具保留启用与说明偏好。旧 schema 不参与运行；不认识的旧工具名不会进入当前工具表。身份、流程及世界书字段忽略。读取阶段不改原文件；用户显式保存后，仅写入现行字段。

这个规则让业务定义保持单一来源，同时用户仍可保留预设内容和工具偏好。新业务工具随定义进入当前预设；旧名称不会通过文件快照重新获得执行路由。

## 模块内部分工

| 文件 | 职责 |
|---|---|
| `index.js` | 公开动作、错误信封和装配 |
| `core.js` | 预设草稿、存档、业务工具偏好与执行快照 |
| `preset.js` | 预设字段归一化 |
| `port.js` | 存档与 `businessTools()` 契约 |
| `adapter-file.js` | 用户存档和只读默认文件 |
| `adapter-memory.js` | 内存适配器 |

对接层以工具名查找业务表中的同名定义，并使用业务对象提供的执行函数。注册层不从工具名构造模块调用。

## 验收

- AI 工具表只能来自显式业务工具定义。
- 标准 JSON Schema 中保留正确类型、必填和嵌套字段。
- 修改用户摘要或任意层级 description（含空串）不改变 schema；旧 schema 不能覆盖新定义。
- 用户 `runtime` 覆盖经预设存取、复制、导入导出与执行原样保留；默认文本由对接层一次合并。
- 旧预设中同名工具的启用与说明差异可保留，其他名称不会生成工具。
- 读取不改用户文件；主动保存只写名字、工具差异、工具顺序和模型配置。
- 主 AI 世界书与主AI设置分开；主AI预设不返回、接受或保存身份、流程、世界书正文或引用。
- 空工具差异表使用当前业务工具默认启用。
