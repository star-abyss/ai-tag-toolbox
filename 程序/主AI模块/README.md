# 主AI模块

主AI模块保存模型配置与用户对当前业务工具的偏好。身份、工作方式及知识正文统一由世界书模块管理；主 AI 世界书位于 `程序/世界书模块/assets/世界书/主AI.json`。本模块读取装配层递入的业务工具定义，不从模块动作表生成 AI 工具，也不负责登记或执行工具。

## 业务工具契约

装配层通过端口的 `businessTools()` 递入当前 AI 可以调用的工具：

```js
{
  名字: 'drawing_generate',
  摘要: '根据提示词生成图片',
  参数: {
    正向: { type: 'string', description: '正向提示词', required: true },
    负向: { type: 'string', description: '可选的负向提示词' },
  },
  说明: { 正向: '本次生成使用的正向提示词' },
}
```

条目中的名字、摘要、参数类型、必填项和字段结构来自业务定义。工具名只作为业务能力标识，模块动作名不会从工具名中解析出来。

## 预设中的工具差异

预设不保存完整 schema，只保存用户偏好：停用状态、工具摘要、schema 各层 description 文本覆盖、工具顺序与用户给出的 `runtime` 对象。每次读取预设时，模块以当前业务定义重新生成工具表，只把文本覆盖应用到对应字段；空字符串也会保留。旧预设里名称匹配当前业务工具的偏好可以保留；未知名称不会出现在工具表中。读取不改用户文件；用户主动保存后，文件会写入有效差异。

`tools: []` 表示没有覆盖差异，当前业务工具默认启用。它不表示关闭所有工具；单独停用某个工具时，只保存该工具的停用差异。

只保存 `name`、工具差异、工具顺序和 `model`，以及用户给出的 `runtime`。读取旧存档时身份、流程与世界书字段会被忽略；写入时只输出现行字段。工具 schema 始终取当前业务契约。

## 动作

`createMainAiModule({ port })` 或 `createMainAiModule({ 根目录, 默认目录, 业务工具 })` 创建模块出口。

主要动作：

- `执行` 读取存档，并返回启用的业务工具、模型配置与 `附加文本`（用户 `runtime` 的副本，缺省 `{}`）。
- `读` 查看草稿和预设；`测` 预览草稿；`存` 写入；`丢` 丢弃草稿。
- `预设` 管理用户预设和模型配置。
- `工具` 调整业务工具摘要、参数文本、启用和顺序；不能添加业务契约以外的工具，也不能改 schema 结构、类型或必填字段。

## 文件

- `index.js`：模块门面与公开动作。
- `core.js`：预设草稿、存档与工具差异。
- `preset.js`：预设字段归一化。
- `port.js`：存档与业务工具端口契约。
- `adapter-file.js`、`adapter-memory.js`：文件与内存适配器。
- `test/run.js`、`test/业务工具.js`：模块回归与旧预设迁移验证。

运行检查：

```sh
node test/run.js
node --test test/业务工具.js
```
