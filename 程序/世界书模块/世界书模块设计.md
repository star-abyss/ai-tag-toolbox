# 世界书模块 · 设计规范

> 本文档是重写项目的模块设计之一。框架（三层结构与边界规则）在根 [AGENTS.md](../../AGENTS.md)，上层怎么用它在上层设计里，本文档只写本模块自己。根目录另有一份同名的旧版规划稿（[_旧设计_世界书模块规划稿_已被现行规范取代.md](../../文档/旧设计/_旧设计_世界书模块规划稿_已被现行规范取代.md)，模块还没搬过来时写的）；**现行的是本目录这一份**。
> **自包含**：不引用别的模块的设计。

**一句话**：**管一批世界书，按条件挑出这次要用的条目，连同它的落点交出去。不拼装、不发请求。**

---

# 一、范围

## 1.1 它做

| # | 做什么 |
|---|---|
| 1 | 管书：只读默认 + 用户自己那份（新建 / 导入 / 改名 / 删 / **导出**） |
| 2 | 管启用：一个请求这次用哪几本（0 到多本） |
| 3 | 管条目：加 / 改 / 删 / 移 / 停用 / 条件 / **落点** |
| 4 | 按这次调用的文本筛出命中的条目 |
| 5 | 把命中条目连同**它的落点**交出去 |
| 6 | 导入酒馆世界书（顺序 · 启用情况 · 启用条件 · 落点 · 深度 · 角色） |
| 7 | 草稿与手动保存：改条目即时生效，落下要按保存 |

## 1.2 它不做

| 不做 | 归谁 |
|---|---|
| **不拼装**：不把命中条目接成一段话 | **上层**——它同时握着条目、工具和会话素材 |
| **不排序**：不决定条目之间的先后 | 上层按落点分堆 |
| **不做取舍**：不决定哪本优先、哪条压哪条 | 上层 |
| **不发请求**：不建连接、不收回答 | 上层（模型调用那一小块） |
| 不管理模型与工具配置 | 主 AI 设置模块 |
| 不认识主 AI、不认识副 AI | 它只认"请求"这个名字 |
| 不解析返回内容 | 提问的那个模块 |
| 不管用哪条链路、哪个模型、密钥、超时、重试 | API 路由与上层 |
| **不存参数**（温度、惩罚、输出上限） | 上层与 provider |
| 不管上下文、历史 | 本模块没有上下文 |
| 不做宏替换 | 我们根本没有那个概念 |
| 不管界面怎么画 | 界面是通用面板的事 |
| 不认识对话、图片、标签 | 它只认识自己的世界书 |
| 不做兼容层、不留回退开关 | 要回退用 git |
| 不做酒馆**对话预设**导入 | 那是预设模块的事 |

# 二、术语

| 词 | 意思 |
|---|---|
| **请求** | 调用方交进来的名字（`翻译` / `识图` / `主AI` …）。**一个请求一套书** |
| **书** | 一份世界书：一个名字 + 一串条目 |
| **条目** | 一条：`{ id, label, text, always, keys, enabled, 落点, 深度?, 角色? }` |
| **启用列表** | 这个请求这次用哪几本。没有存档记录时用装配层注入默认；明确保存空列表时保持空 |
| **只读默认** | 随程序走的书，住在 `assets/世界书/`，**一本书一个文件，文件名就是书的名字** |
| **用户那份** | 用户的书，住端口里一个文件；可增删改；可通过 `scope` 归属请求 |
| **命中** | 这次参与的一条条目，连同它的落点 |
| **落点** | 这条要放在哪：`前` / `后` / `顶部` / `底部` / `按深度` / `扩展顶部` / `扩展底部` / `出口` |
| **深度** | 落点是 `按深度` 时才有：距对话末尾第几条 |
| **角色** | 落点是 `按深度` 时才有：`系统` / `用户` / `助手` |
| **草稿 / 存档** | 草稿在内存，改动作用在它上面；存下来才进端口 |
| **冻结** | 存档读不懂时，只挡写盘的那几个入口 |

# 三、约束

## 3.1 继承自框架的边界规则

| # | 规则 | 本模块怎么体现 |
|---|---|---|
| 1 | 一个模块只交出一份清单 | 门面只有 `index.js`；出口冻住 |
| 2 | 能力在谁那儿，工具就在谁那儿 | 端口没递默认目录 = 没有只读默认 |
| 3 | **对外的参数永远是标识** | 参数只有 `请求` / `文本` / `书` / `标识` / `条目`；检验法：看 `describe()` |
| 4 | 决定要在做出这个决定的操作里执行 | 筛选在 `执行` 里做，不靠调用方先滤一遍 |
| 5 | "能不能来"用"东西有没有传进来"表达 | 端口没递默认目录 = 没有默认书 |
| 6 | 不解析不属于自己的东西 | 返回内容不解析；酒馆里我们用不上的字段一概不搬 |
| 7 | "必须和别处保持一致的清单"都不该存在 | **有哪几本书由目录回答**，代码里没有清单 |
| 8 | 多级兜底来源是缺陷 | 不给"没默认就找别处"这种退路 |
| 9 | 依赖由装配层传进来 | 端口与位置都由装配层递；核心不 require fs/path |
| 10 | 不做兼容层，不留回退开关 | 不兼容旧提示词数据 |

## 3.2 本模块自己的硬约束

| # | 约束 |
|---|---|
| 1 | **只读默认没有任何写路径** |
| 2 | **`执行` 只读存档**；`测` 读草稿 |
| 3 | **条目顺序就是数组顺序** |
| 4 | `always` 只有一个来源 |
| 5 | 筛选只有关键词子串命中 |
| 6 | **不拼装、不排序、不做取舍** |
| 7 | 参数不许进本模块的数据 |
| 8 | "读不懂"不许当成"没有" |
| 9 | `always` 决定启用方式；`keys` 独立保存，恒常时不检查 |
| 10 | **落点一律原样带出去**，本模块不解释它 |
| 11 | **导入永不覆盖**：只新增，同一归属范围撞名自动加号 |
| 12 | 默认书归属由注入的 `默认启用` 映射推导；用户书归属记录为 `scope`；无归属旧书不猜测、不迁移 |
| 13 | 同一请求范围内的用户书不撞名；不同请求可同名；用户书与只读默认重名也允许 |
| 14 | 用户书标识使用 `crypto.randomUUID()`，删除后永不复用 |

# 四、架构

## 4.1 形状

```
世界书模块（六边形）
├─ 门面 index.js     十个动作
├─ 核心 core.js      书 · 条目 · 启用列表 · 草稿/存档
├─ worldbook.js      解析 · 归一化 · 筛选（纯函数）
├─ port.js           端口：readState / writeState / listDefaults / readDefault
├─ adapter-file.js   文件适配器。唯一 require fs / path 的地方
├─ adapter-memory.js 内存适配器
└─ assets/世界书/     只读默认：翻译 · 识图 · 文生图
```

## 4.2 一次执行

```
执行({ 请求, 文本 })
  ① 按请求取启用列表      —— 存档有记录用存档，否则用装配层注入默认
  ② 逐本取它当前那份      —— 只读默认读书件；用户书读存档
  ③ 逐本筛条目            —— always 恒进；keys 命中才进
  ④ 交出去：{ 请求, 书, 命中 }
```

**就这四步，没有第五步。** 不接成一段话、不排先后、不决定谁压谁。

## 4.3 对外只有一份清单

门面既给界面用，也给调用点用，**不写第二遍**。模型侧能不能看见本模块，由门面层决定。

## 4.4 依赖方向

```
装配层
  └─ 世界书模块（不认识其他模块）
        ↑ 位置、端口与请求默认列表都由装配层递
```

**没有环。** 本模块不认识任何一个别的模块，也不认识上层。

# 五、需求

## 5.1 请求

| 项 | 规定 |
|---|---|
| 形状 | 一个串，如 `'翻译'` / `'识图'` / `'主AI'` |
| 名字从哪来 | **调用方定的**。它就是"这件事"的名字 |
| 不认识的名字 | **不报"没有这个用途"**——按空启用处理，交回 `书: []`、`命中: []`。**有哪几本书由目录回答** |
| 请求与书的对应 | 用户书 `scope` 记录所属请求；默认书所属请求由注入的默认启用映射推导 |

## 5.2 书

| 项 | 规定 |
|---|---|
| 两份来源 | 只读默认（`assets/世界书/<名字>.json`）· 用户那份（端口里一个文件装全部） |
| 启用几本 | **0 到多本**。一本都没有 ⇒ 交回空 |
| 只读默认能不能删 / 改 | **不能**。它随程序走，用户碰不到。要改就**导出 → 导入 → 启用副本** |
| 只读默认能不能导出 | **能**。导出交回来的是文本，界面拿它存成文件 |
| 用户那份 | 可增删改；一本一本书，各自有名 |
| 导入 | **只新增**。同一请求范围同名就加号（`甲` → `甲 2`）；**没有覆盖这条路** |
| 归属 | 新建 / 导入给了请求时记录 `scope`；不给请求则保持无归属。新建和导入都不自动启用 |
| 可见范围 | `表({请求})` 与 `读({请求}).表` 只列归属该请求的用户书及默认映射到该请求的默认书 |
| 冻结 | 存档读不懂 ⇒ **冻结这个键的写**；默认书照常可用 |

## 5.3 条目

| 项 | 规定 |
|---|---|
| 形状 | `{ id, label, text, always, keys, enabled, 落点, 深度?, 角色? }` |
| `id` 谁发 | **只由程序发**：从 `e1` 起顺着找第一个没被这本书占用的号。给进来的 `id` 不采信 |
| `always` / `keys` | 显式 `always` 决定启用方式，不清空关键词；恒常模式忽略条件。省略 `always` 且只给 `keys` 时，按"词空不空"定 `always`（空 ⇒ `always:true`） |
| 顺序 | **数组顺序就是参与顺序** |
| `enabled` | 停用的条目不参与，但留在书里 |
| 参数 | **一律不存**。温度那类东西本模块一个字段都没有 |

## 5.4 落点

| 落点 | 意思 | 酒馆对应 |
|---|---|---|
| `前` | 投进"前"槽 | `position: 0` |
| `后` | 投进"后"槽 | `position: 1` |
| `顶部` | 投进"顶部"槽 | `position: 2` |
| `底部` | 投进"底部"槽 | `position: 3` |
| `按深度` | 按 `深度` 插在距对话末尾第几条 | `position: 4` |
| `扩展顶部` | 存下、原样带出去 | `position: 5` |
| `扩展底部` | 存下、原样带出去 | `position: 6` |
| `出口` | 存下、原样带出去 | `position: 7` |

| # | 规定 |
|---|---|
| 1 | **本模块只交落点，不解释它**。放哪、怎么排是上层的事；哪几种真能落，也是上层的事 |
| 2 | 落点是 `按深度` 时 `深度` 才有意义；默认 4 |
| 3 | 落点是 `按深度` 时 `角色` 才有意义；默认 `系统` |
| 4 | 落点缺省 = `前`；不认识的值也按 `前` 算 |
| 5 | `深度` 与 `角色` 只在落点是 `按深度` 时进存放形状；换成别的落点就丢掉 |

**为什么本模块不管"按深度"怎么算**：那要数对话，对话在上层。**本模块只把 `深度` 这个数原样交出去**，有对话的那一方自己数。

## 5.5 筛选

| # | 规定 |
|---|---|
| 1 | **`always:true` ⇒ 恒进**，不看文本 |
| 2 | **`keys` 非空 ⇒ 文本里出现任一个 key 才进**（子串命中，两边折小写） |
| 3 | 文本从哪来 | 调用方给的 `文本` |
| 4 | 空正文 / 停用的条目不参与 |
| 5 | 不做正则 / 概率 / 次级逻辑 / 权重 / 递归 / 向量 |
| 6 | 参与与否**必须确定** |

## 5.6 导入酒馆世界书

| 项 | 规定 |
|---|---|
| 读哪些 | 顺序 · 启用情况（`disable`）· 启用条件（`key`）· 落点（`position`）· 深度（`depth`）· 角色（`role`） |
| 不读哪些 | `probability` · `keysecondary` · `selectiveLogic` · 递归那几项 · `group` 那一组 · `scanDepth` · `caseSensitive` · `matchWholeWords` · `sticky` / `cooldown` / `delay` · `automationId` · `vectorized` · `addMemo` |
| 两种形状 | `entries` 是数组就按数组顺序；是对象（`uid` → 条目）就按 key 的先后 |
| 校验 | JSON 语法错 / 没有 `entries` ⇒ `PROMPT_BAD_WORLDBOOK`，**两种情况都不动状态** |
| `id` | 由程序重发，原 `uid` 不沿用 |

## 5.7 导出

| 项 | 规定 |
|---|---|
| 入 | `书({ 动作:'导出', 标识 })` |
| 出 | `{ 名字, 内容 }`；`内容` 是一份能再导入的世界书文本 |
| 形状 | **我们自己的形状**：`{ name, entries: [ { id, label, text, always, keys, enabled, 落点, 深度?, 角色? } ] }` |
| 只读默认 | **能导出**。这是"改一份默认条目"那条三步法的第一步 |

**为什么导出用自己的形状**：导入认自己的字段名（`落点` / `深度` / `角色`）也认酒馆的（`position` / `depth` / `role`）。导出走前者，于是"导出 → 导入"逐字对得上。

## 5.8 草稿与保存

| 项 | 规定 |
|---|---|
| 改条目 / 改书 / 改启用列表 | **即时生效**（作用在草稿上） |
| 落下 | 按 `存` |
| `丢` | 草稿丢回存档 |
| `重读` | 重读端口 |
| 冻结只挡什么 | **只挡写盘的那几个入口**（`书` 的写动作 / `条目` / `存`）；`读` / `表` / `测` / `丢` / `重读` 不写盘，冻结时照常可用 |

## 5.9 出错

一切失败都可分辨（`code` + `reason`）。码表见 §十一。

# 六、交出什么

## 6.1 形状

```js
执行({ 请求, 文本 })
  → {
      请求,                                     // 原样带回，调用方按它原路发回去
      书:   [{ 标识, 名字 }],                    // 这次启用了哪几本，按启用顺序
      命中: [{ 文本, 落点, 深度?, 角色?, 书 }]     // 逐条；`书` 是它来自哪一本
    }
```

| 字段 | 为什么有 |
|---|---|
| `请求` | 调用方要按它把结果发回去 |
| `书` | 界面上要能说出"这次用了哪几本" |
| `命中[].书` | 多本同时启用时，"这条是谁的"必须看得出来 |
| `命中[].文本` | 上层要拼 |
| `命中[].落点` | 上层要按它分堆 |

## 6.2 三条边界

| # | 规定 |
|---|---|
| 1 | **交回的不是"一段提示词"**，是一组带落点的条目。拼装归上层 |
| 2 | **没有 `文本` 这个回程字段**——调用方自己就是发问的那一方，它手里有；回一份就是同一份数据两处存 |
| 3 | **一本书都不启用 ⇒ 交回空**，不是失败 |

## 6.3 上限

| 项 | 规定 |
|---|---|
| 条数 | **不设上限**（可加可不加的限制不加） |
| 单条长度 | **不设上限** |
| 总量 | 超了由上层处理；本模块不截断、不警告 |

# 七、数据

## 7.1 盘上的形状

```
<根目录>/世界书.json                   用户那份（一个文件装全部）
<默认目录>/翻译.json 识图.json 文生图.json   只读默认，一本书一个文件
```

**文件名就是书的名字**，这样"有哪几本书"由目录回答，代码里没有清单。

## 7.2 用户那份

```jsonc
{
  "format": "worldbook", "version": 1,   // format 只是标记；version 不是 1 才算读不懂
  "subs": {
    "翻译": { "启用": ["$default:翻译", "wb<UUID>"] },
    "主AI": { "启用": ["主AI"] },
    "识图": { "启用": [] }
  },
  "books": {
    "wb<UUID>": { "name": "我的翻译", "scope": "翻译", "entries": [ … ] }
  }
}
```

**启用列表是一串标识**，不是一本。主副同构，差别只是列表里有几个元素。
存档 `subs` 中没有请求键表示尚未选择；写入 `启用: []` 表示明确停用。默认列表只由装配层注入，不进入用户存档。

## 7.3 世界书

```jsonc
{
  "name": "翻译",
  "entries": [
    { "id": "e1", "label": "常驻",   "text": "…", "always": true,  "keys": [],           "enabled": true, "落点": "前" },
    { "id": "e2", "label": "中文",   "text": "…", "always": false, "keys": ["中文","zh"], "enabled": true, "落点": "按深度", "深度": 2, "角色": "系统" }
  ]
}
```

## 7.4 标识

| 来源 | 标识 | 谁发 |
|---|---|---|
| 只读默认 | `$default:<名字>` | 由位置算出来，不需要存 |
| 用户那份 | `wb<UUID>` | 程序使用 `crypto.randomUUID()` 发；删除后永不复用 |

**前缀就是"这本书住在哪"**，不另存一个字段。

## 7.5 两个状态

| 状态 | 住哪 | 谁作用在它上面 |
|---|---|---|
| **存档** | 端口里那份 | **`执行` 只用它** |
| **草稿** | 内存里那份 | `读` / `测` 与全部改动 |

## 7.6 两条不变量

| # | 不变量 |
|---|---|
| 1 | 存档读不懂 ⇒ 写被冻结，但默认书照常可用 |
| 2 | 只读默认一个字节都不会被本模块改动 |

# 九、横切

## 9.1 装配

```
createWorldbookModule({ port, 默认启用? })                  端口与请求默认书由装配层递进来
createWorldbookModule({ 根目录, 默认目录, 默认启用? })        内部装文件适配器
```

| # | 规定 |
|---|---|
| 1 | `根目录` / `默认目录` **只认这两个名字**，没有 `root` / `data` 之类的别名 |
| 2 | 两个都不给 ⇒ 装配时抛错 |
| 3 | 给空串 ⇒ 装配时抛错 |
| 4 | 端口缺方法 ⇒ 装配时抛错，并说出缺哪个 |
| 5 | `默认启用` 可由装配层注入 `{ [请求名]: [书标识, …] }`；模块用该映射推导默认书归属 |

## 9.2 依赖从哪来

| 依赖 | 谁给 |
|---|---|
| 用户那份的位置 | 装配层 |
| 只读默认的位置 | 装配层 |
| 请求的默认书列表 | 装配层以 `默认启用` 递入；模块只按请求名查这份数据 |
| 草稿与存档 | 端口 |

## 9.3 端口

四件事：`readState` · `writeState` · `listDefaults` · `readDefault`。形状见 [接口.md](接口.md) §二。

**读的三态**（不是两态）：`ok` 有 / `missing` 确实没有 / `unreadable` 读不懂。
把"读不懂"当成"没有"，下一次写就把用户那份盖掉了；在只读默认上混，用户看到的就是"这份默认没了"，而实际只是文件坏了。

# 十、酒馆兼容

## 10.1 读哪几样

顺序 · 启用情况（`disable`）· 启用条件（`key`）· 落点（`position`）· 深度（`depth`）· 角色（`role`）。

## 10.2 不读哪些（逐条理由）

| 不读 | 为什么 |
|---|---|
| `probability` / `useProbability` | 参与与否必须确定 |
| `keysecondary` / `selectiveLogic` | 次级逻辑，同上 |
| 递归那几项（`excludeRecursion` / `preventRecursion` / `delayUntilRecursion`） | 同上 |
| `group` / `groupWeight` / `groupOverride` / `useGroupScoring` | 同上 |
| `scanDepth` | 扫多深由上层定 |
| `caseSensitive` / `matchWholeWords` | 我们的命中口径是确定的子串 |
| `sticky` / `cooldown` / `delay` | 时间机制，我们没有 |
| `automationId` / `vectorized` / `addMemo` | 酒馆内部的东西 |
| `displayIndex` | 显示顺序由数组顺序回答 |
| 世界书级 `extensions` / 书自身的 `id` | 不是内容 |

**判据一句话**：凡是回答"**什么时候 / 以什么概率**"的字段，一律不要；凡是回答"**是什么内容 / 什么时候算命中 / 放哪儿**"的，才搬。

## 10.3 兼容的判据

```
导入一份带 position / depth / role 的酒馆世界书  →  导出  →  语义相同
```

**有真实数据可依**：酒馆导出的世界书 JSON 就是这一种，拿真文件试。

# 十一、出错

| 码 | 什么时候 | 界面 |
|---|---|---|
| `PROMPT_NO_SUCH_BOOK` | 标识指的书不在 | 刷新表再选 |
| `PROMPT_READONLY_BOOK` | 想改名 / 删 / 加条目 / 改条目，而目标是只读默认 | 提示"默认是只读的"，让他导出再导入 |

# 十四、决定记录

> **作废的留原文不删。** 编号顺延。前 52 条见 [旧设计（已被取代）](../../文档/旧设计/_旧设计_合并决策记录_已被三份新规范取代.md) 的决策记录与它引的讨论记录。

| # | 决定 | 由来说 |
|---|---|---|
| 53 | **`书` 加第四个动作 `导出`** | "改一份默认条目"那条三步法（导出 → 导入 → 启用副本）缺第一步，而顶层动作表里不该为它多开一个动作。导出只读，不受冻结影响 |
| 54 | **`测` 与 `执行` 同形**：都交回 `{ 请求, 书, 命中 }` | 界面直接拿 `命中` 渲染，不必维护第二种形状。差别只有读哪一份 |
| 55 | **`执行` 读存档，`测` 读草稿** | `执行` 是上层要的那一份，必须与"存过的"一致；`测` 是界面预览，用户改了还没存的条目要看得见效果 |
| 56 | **导入永不覆盖**：只有新增，撞名自动加号 | 从"用户操作"出发定的：他递一份文件进来，期望的是"多一本"，不是"顶掉一本"。没有覆盖这条路，就不需要"防替换默认"那条判断 |
| 57 | **`导入` 没有 `标识` 参数** | 没有覆盖目标，这个参数就没有意义。少一个参数少一条歧义 |
| 58 | **归属按位置算**：默认导出再导入 ⇒ 它就是用户的 | 住在默认目录里的是只读默认，住在用户那份里的是用户的。**判断不需要读名字**，于是"改一份默认"全用已有动作拼得出来 |
| 59 | **用户书与只读默认重名是允许的** | 默认那本叫"翻译"是它作者起的名，用户凭什么不能也叫"翻译"？两者标识不同（`$default:翻译` / `wb1`），界面靠"是不是本子"分开。**只在用户书之间不撞名** |
| 60 | **`表` 不报"这本书属于哪个请求"** | 书是共享的；"它属于哪些请求"由启用列表回答（`读` 里给）。表行只报书本身 |
| 61 | **`读` 的启用行带 `读得懂` 一列** | 只读默认文件坏掉时，`存在` 与 `读得懂` 是两件事：前者说"这本书在不在"，后者说"这次读得出来吗"。两者都不报，界面就只会显示一个空壳 |
| 62 | **判断"有没有这本书"与"读不读得出这本书"分开** | 读不懂的默认文件也在清单里（`listDefaults` 收全），所以**启用得了**它，读它才报 `PROMPT_STATE_UNREADABLE`。"读不懂"不许当成"没有"这条，在启用这一层同样成立 |
| 63 | **落点一律原样带出去，模块不解释它** | 模块不做拼装，所以"哪几种落点真能落"是上层的事。八种一律如实交出去，上层按它认识的放 |
| 64 | **删一本书，连带把它从所有请求的启用列表里摘掉** | 留着就是一个指向空处的标识；摘掉是这次操作自己要执行的决定，不靠调用方先清理 |
| 65 | **默认文件名与请求名同名这件事，模块不知道** | 模块只认"书的名字"（= 文件名）与"请求的名字"。**"一个请求默认用哪本"不是模块的规矩**：启用列表空着就是空。把两者绑起来等于在代码里写死一条对照关系 |
| 66 | **默认目录里的 `主AI.json` 是空的壳** | 主 AI 的骨架归预设模块，它的世界书等主 AI 真做的时候写。先留一份空的，界面上看得见这个名字。**（本条的处置已被第 68 条取代，判断本身仍成立）** |
| 67 | **条目里那三个键（`落点` / `深度` / `角色`）用中文** | 盘上形状与酒馆的 `position` / `depth` / `role` 一一对得上，但按项目规矩"给人看的用中文"。导入两边都认 |
| 68 | **删掉默认目录里的 `主AI.json`** | 主 AI 不再要默认世界书（它的内容归预设），那个空壳只暗示了一个不存在的东西。删掉不动模块：默认目录空着时 `listDefaults` 直接回空清单，"零本"是缺省不是能力缺失。判据跟着改：文件适配器那组默认数由 4 改 3（`test/run.js` V-50） |
| 69 | **本模块的定位由上层重定**：一批"按条件进出的正文"，谁的请求都能挂；主 AI 只是使用者 | 主 AI 的身份与流程住预设，只有"随话题进出的知识"归本模块。详见 [上层设计.md](../../文档/上层设计.md) §十一 |
| 70 | **请求默认启用表由装配层注入** | 决定 65 仍然成立：模块不建立默认书名与请求名的映射。装配层把 `{ [请求名]: [书标识, …] }` 递入；模块只在该请求没有存档记录时使用它。显式空列表持续表示停用，并写入原有 `subs` 形状，不迁移存档 |
| 71 | **用户世界书按请求归属** | 取代决定 60 的共享书库方案。新建 / 导入给了请求就存英文键 `scope`；不自动启用；旧书缺少 scope 时不猜测、不迁移。按请求读取表时只返回归属该请求的用户书。 |
| 72 | **默认书归属由默认启用映射推导** | 不再单独维护默认书归属清单；显式启用、执行、测试都必须校验请求归属。跨请求返回 `PROMPT_BOOK_SCOPE_MISMATCH`。 |
| 73 | **用户书标识不复用** | 用 `crypto.randomUUID()` 生成用户书标识；删除后旧预设引用不会指向新书。 |
| 74 | **明确的非恒常空条件保持不命中** | 改条目同时给出 `always:false` 与 `keys:[]` 时保留该状态；不把尚未设置条件的条目误变为常驻。 |

## V1.5.1 决定：本次引用列表

上层预设保存书标识，`执行/测` 可直接接收本次 `启用`。给数组就用该数组，空数组不挂书，省略读取请求存档；不复制正文，不修改请求订阅。用于让预设引用在决定使用它的那次操作中执行。


## V1.5.9 提示词正文统一

决定 74：取代决定 68、69 中主 AI 不提供默认世界书、身份流程保存在预设的安排。主 AI 默认书包含原身份与流程的两条常驻条目，和其他请求共用世界书启用列表。世界书只处理正文、归属和命中，模型和工具配置仍由主 AI 模块管理。显式执行覆盖参数仍为通用门面能力；应用运行与预览统一省略它、读取请求存档。

## V1.5.12 启用方式与条件独立

决定 75：条目切换为一直启用时保留关键词；新增、修改、存档重读与导入导出使用同一语义。一直启用不检查条件，条件启用仍须命中任意关键词；明确条件启用且条件为空时不命中。取代原 `always` 与 `keys` 互斥、切换恒常清空条件的安排。界面采用酒馆的蓝／绿指示灯并独立显示条件区，切换方式后无需重新填写关键词。
