# 世界书模块 · 调用示例

> 字段名与约束以 [接口.md](接口.md) 为准；设计理由在 [世界书模块设计.md](世界书模块设计.md)。

---

## 一、装配

```js
const { createWorldbookModule } = require('./世界书模块/index.js');

const 世界书 = createWorldbookModule({
  根目录: '<userData>/世界书',
  默认目录: '<app>/世界书模块/assets/世界书',
});
```

端口由装配层递（测试、内存、别的存储方案都走这条）：

```js
const { createMemoryAdapter } = require('./世界书模块/adapter-memory.js');
const 世界书 = createWorldbookModule({
  port: createMemoryAdapter({ 默认: { 翻译: { name: '翻译', entries: [] } } }),
});
```

## 二、调用点：上层要的那一份

**这是上层唯一要用到的动作。调用点只写"这是哪件事"与这次的文本。**

```js
const { 请求, 书, 命中 } = 世界书.执行({ 请求: '识图', 文本: 待识别的图 });
// 书   = [{ 标识: '$default:识图', 名字: '识图' }]
// 命中 = [{ 文本: '…', 落点: '前', 书: '$default:识图' }]

// 上层按落点把条目与骨架拼起来，再交给模型调用那一小块
```

**启用了哪几本由启用列表回答。一本都不启用 ⇒ `书: []`、`命中: []`，不是失败。**

**`执行` 读的是存过的那一份。** 改了还没按 `存`，它拿到的还是旧的——这不是缺陷，是"手动保存"的定义。

界面预览要用**没存的**那一份：

```js
const 预览 = 世界书.测({ 请求: '识图', 文本: 待识别的图 });   // 与 执行 同形，读草稿
```

## 三、界面：选书与启用

```js
const 快照 = 世界书.读({ 请求: '翻译' });

快照.表;     // 仅包含翻译归属的书，按名字排序
快照.启用;   // [{ 标识, 名字, 是本子, 存在, 读得懂 }] —— 这个请求这次用哪几本
快照.脏;     // 有没有未保存的改动
```

下拉框直接读 `快照.表`：

```js
for (const 一行 of 快照.表) {
  // 一行.名字      显示名（"翻译" / "我的翻译"）
  // 一行.是本子    是只读默认
  // 一行.存在      那份文件读得出来吗
  // 一行.读不懂    只读默认那个文件坏了（这时 存在 是 false）
  // 一行.条目数
}
```

**启用是"勾选一串"，不是"选一个"**：

```js
世界书.书({ 动作: '换', 请求: '翻译', 启用: ['$default:翻译'] });              // 只用默认那本
世界书.书({ 动作: '换', 请求: '翻译', 启用: ['$default:翻译', 用户书标识] }); // 两本一起
世界书.书({ 动作: '换', 请求: '翻译', 启用: [] });                            // 一本都不用
世界书.存();                                                                // 落下
```

单看某一本：

```js
const 书 = 世界书.读({ 书: 用户书标识 }).书;
书.条目;   // [{ id, label, text, always, keys, enabled, 落点, 深度?, 角色? }]
```

**`读({ 书 })` 找不到就报 `PROMPT_NO_SUCH_BOOK`，不会悄悄换一本。**

## 四、界面：改条目

```js
// 新建一本
const { 标识 } = 世界书.书({ 动作: '新建', 请求: '翻译', 名字: '我的翻译' });

// 加一条（id 由程序发）
const { 条目 } = 世界书.条目({ 动作: '加', 书: 标识, 条目: { label: '常驻规则', text: '只翻译，不解释。' } });

// 改它（只给要改的那几项）
世界书.条目({ 动作: '改', 书: 标识, 标识: 条目.id, 条目: { keys: '中文, zh' } });

// 停用 / 恒常
世界书.条目({ 动作: '改', 书: 标识, 标识: 条目.id, 条目: { enabled: false } });
世界书.条目({ 动作: '改', 书: 标识, 标识: 条目.id, 条目: { always: true } });

// 落点：选了 按深度 才带 深度 与 角色
世界书.条目({ 动作: '改', 书: 标识, 标识: 条目.id, 条目: { 落点: '按深度', 深度: 2, 角色: '系统' } });

// 调顺序
世界书.条目({ 动作: '移', 书: 标识, 标识: 条目.id, 方向: '上' });
世界书.条目({ 动作: '移', 书: 标识, 标识: 条目.id, 到: 0 });

// 删
世界书.条目({ 动作: '删', 书: 标识, 标识: 条目.id });
```

**改条目即时生效**（在草稿上）。要发出去，得按保存：

```js
世界书.存();     // 草稿 → 端口
世界书.丢();     // 草稿 → 丢掉，回到存档
```

切走之前：

```js
if (世界书.读().脏) 问用户('保存 / 丢弃 / 取消');
```

## 五、界面：导入

```js
const 文本 = fs.readFileSync(选中的文件, 'utf8');
const 结果 = 世界书.run('书', { 动作: '导入', 请求: '翻译', 内容: 文本 });
if (!结果.ok) return 提示(结果.reason);   // PROMPT_BAD_WORLDBOOK: 没有 entries —— 这不是一份世界书
// 结果.data = { 标识: 'wb<UUID>', 名字: '某本世界书' }；不会自动启用
世界书.存();                                // 落下
```

**导入只新增，不会顶掉任何一本。** 撞名自动加号：

```
导入「甲」→ wb<UUID>「甲」
同一请求范围再导入「甲」→ 新 wb<UUID>「甲 2」
不同请求范围导入「甲」→ 新 wb<UUID>「甲」
```

给了 `请求` 只记录这本书的归属，不自动启用；启用列表要单独设置：

```js
世界书.书({ 动作: '导入', 请求: '翻译', 内容: 文本 });   // 导入并归属翻译
世界书.书({ 动作: '导入', 内容: 文本 });                  // 只进无归属书库
```

## 六、改一份只读默认的条目：三步，全是已有动作

```js
// ① 导出默认那本
const 导 = 世界书.书({ 动作: '导出', 标识: '$default:翻译' });
fs.writeFileSync('翻译-副本.json', 导.内容, 'utf8');      // 这一步是界面的活

// ② 导入回来（它现在住在用户那份里，算用户的）
const 进 = 世界书.书({ 动作: '导入', 请求: '翻译', 内容: 导.内容 });
// 进 = { 标识: 'wb<UUID>', 名字: '翻译' }

// ③ 启用列表里换过去
世界书.书({ 动作: '换', 请求: '翻译', 启用: [进.标识, '$default:翻译'] });
世界书.存();

// 现在随便改它
世界书.条目({ 动作: '加', 书: 进.标识, 条目: { text: '自己加的' } });
```

**默认那份从来没被改过**，所以没有"恢复出厂"这个动作——启用列表里换回 `$default:翻译` 就行。

**不同请求范围的用户书可以同名**；`$default:翻译` 与用户书也可同名，界面以请求归属和 `是本子` 字段区分。

## 七、酒馆世界书

酒馆的 `worlds/<名字>.json` 直接喂进去就行：

```jsonc
{
  "name": "某本世界书",
  "entries": {
    "0": { "uid": 0, "key": ["龙", "dragon"], "comment": "龙的设定", "content": "……", "constant": false, "disable": false, "position": 4, "depth": 2, "role": "user" },
    "1": { "uid": 1, "key": [],               "comment": "总则",     "content": "……", "constant": true,  "disable": false, "position": 0 }
  }
}
```

搬进来是这样：

| 酒馆 | 我们 |
|---|---|
| `content` | `text` |
| `comment` | `label` |
| `key` | `keys` |
| `constant: true` 或 `key: []` | `always: true` |
| `disable: true` | `enabled: false` |
| 对象里 key 的先后 / 数组顺序 | 条目顺序 |
| `position: 0…7` | `落点`：`前` `后` `顶部` `底部` `按深度` `扩展顶部` `扩展底部` `出口` |
| `depth` | `深度`（只在落点是 `按深度` 时） |
| `role` | `角色`（同上） |
| `probability` / `order` / 次级关键词 / 递归 / `group` … | **一个都不读** |

**导出走我们自己的形状**，所以"导入 → 导出 → 再导入"逐字对得上。

## 八、错误表

`run(...)` 给 `{ ok:false, reason, code }`；`reason` 的写法是 `码: 人话`。直呼式给 `null`。

| 码 | 什么时候 | 怎么办 |
|---|---|---|
| `PROMPT_NO_SUCH_BOOK` | 标识指的书不在；`换` 的启用列表里有不认识的 | 刷新 `读().表` 再选 |
| `PROMPT_BOOK_SCOPE_MISMATCH` | `换` / `执行` / `测` 引用了其他请求归属的书 | 切换到对应请求后选择它 |
| `PROMPT_READONLY_BOOK` | 想改名 / 删 / 加条目 / 改条目，而目标是只读默认 | 提示"默认是只读的"，让他走 §六 那三步 |
| `PROMPT_NO_SUCH_ENTRY` | 条目 id 不在那本书里 | 别用缓存的旧 id |
| `PROMPT_BAD_WORLDBOOK` | 导入的内容 JSON 坏 / 没有 `entries` | 提示"这不是一份世界书"。**状态没动** |
| `PROMPT_STATE_UNREADABLE` | 存档读不懂（写被冻结）· 启用的默认文件读不懂 | 显示横幅；**默认照常能用**；让用户先处理那份文件 |
| `PROMPT_WRITE_FAILED` | 写不进去（磁盘满 / 权限 / 被占用） | 显示端口交回的原因；草稿还在 |
| `PROMPT_BAD_ARGUMENT` | 参数不对 / 没有这个动作 / 移越界 | 检查参数名 |

**冻结的样子**：

```js
const 看 = 世界书.读();
if (看.冻结) {
  // 横幅：存档读不懂（<原因>），已冻结写入
  // 表与只读默认照常可用；丢 / 重读 照常可用
}
```

**一句只读默认文件坏掉的样子**：

```js
const 行 = 世界书.表().find((x) => x.标识 === '$default:翻译');
行.存在;    // false —— 读不出来
行.读不懂;  // true  —— 是文件坏了，不是"没有这份"
行.名字;    // '翻译' —— 名字仍然报得出来（就是文件名）
```

## 九、几个"本模块不负责"的例子

| 想做的事 | 归谁 |
|---|---|
| 把条目拼成一段提示词 | **上层** —— 它手里同时有骨架与条目 |
| 决定哪几条放前面、哪几条放后面 | **上层** —— 按 `命中[].落点` 分堆 |
| 按深度插进对话 | **上层** —— 数对话要对话，模块只给那个数 |
| 把提示词发给模型 | **上层** —— 模块连连接都不建 |
| 温度、惩罚、输出上限 | provider |
| 解析"识图返回的 `tags`" | 识图模块 |
| 在提示词里填入当前时间、模型名 | **不做** —— 本模块不做任何替换 |
| "一个请求默认用哪本" | **装配层与界面** —— 模块的启用列表空着就是空 |
