## 一、它是什么 / 它不是什么

**管一批世界书，按条件挑出这次要用的条目，连同落点交出去。**

| 它做 | 它不做 |
|---|---|
| 管书（只读默认 + 用户那份）与它们的条目 | **不拼装**——不把条目接成一段话 |
| 管"这个请求这次用哪几本"（0 到多本） | **不排序、不做取舍** |
| 按这次调用的文本筛出命中的条目 | **不对模型说话**：谁去发、发到哪、怎么发，全不归它 |
| 把命中条目连同**落点**交出去 | 不认识主 AI、不认识副 AI |
| 答"这次启用了哪几本" | 不读模型的设定（温度那一类，一个字段都没有） |
| 导入酒馆世界书；导出成一份能再导入的文本 | 不管链路、模型、密钥、超时、重试 |
| 存取用户那份（草稿 → 存） | 不做宏替换、不管上下文 |

**它不认识任何别的模块的名字。** 依赖一律由装配层以**端口**形式递进来。

**三句话的边界**：

```
它交出去的  = 一组带落点的条目 + "这次启用了哪几本"
它交不出的  = 一段拼好的文本
它更交不出的 = 任何一次模型调用

身份与工作方式也是常驻条目；模型与工具配置由主 AI 模块管理。
```

**拼装由上层负责**：上层同时握着条目、工具定义和会话素材，按落点生成实际消息。

## 二、东西在哪

```
世界书模块/
├── index.js            门面。**对外只有这一个文件**（出口冻住）
├── port.js             端口契约 + 读的三态约定
├── adapter-file.js     文件适配器。**唯一 require fs / path 的地方**
├── adapter-memory.js   内存适配器。它的用处是**证明核心真的不依赖盘**
├── core.js             核心。纯逻辑，不认识盘
├── worldbook.js        世界书：解析 / 归一化 / 筛选（一组纯函数）
├── assets/世界书/       只读默认，一本书一个文件：主AI.json 翻译.json 识图.json 文生图.json
├── test/run.js         功能自检（65 条）
├── test/默认们.js       内存默认，test 与 tools 共用同一份
├── tools/防改.js        试遍所有能碰只读默认的入口（真目录 + 比哈希）
├── tools/对账默认.js    对账：交出来的正文与文件逐字相同
├── tools/看默认.js      四份默认长什么样 + 试几条文本的命中
├── 接口.md              **契约**：对外操作 / 端口 / 装配的字段名与约束
├── 世界书模块设计.md     设计规范
└── 调用示例.md          调用示例与错误表
```

**契约与实现分开**：`接口.md` 是能独立存在的契约。改实现之前先改契约。

调用链永远是一个方向：

```
装配层 → index.js（门面/动作表） → core.js（纯逻辑） → port → adapter-file.js（盘）
```

**核心不许 require `fs`／`path`。** 它只说"读存档 / 写存档 / 读一份默认"。

## 三、四个词

| 词 | 意思 | 长什么样 |
|---|---|---|
| **请求** | 一件要对模型说的事 | `'主AI'` · `'翻译'` · `'识图'` · `'文生图'` |
| **书** | 一份世界书 | `{ name, entries[] }` |
| **条目** | 书里的一段 | `{ id, label, text, always, keys, enabled, 落点, 深度?, 角色? }` |
| **落点** | 这条要放在哪 | `前` · `后` · `顶部` · `底部` · `按深度` · `扩展顶部` · `扩展底部` · `出口` |

**对外只有标识**；参数里出现路径／地址就是缺陷（看 `describe()` 的参数名即可核对）。

**文件名就是书的名字**（`翻译.json` / `识图.json`）。于是：**有哪几本书由目录回答，代码里没有清单。**

**两种书，同一种东西**：

```
只读默认   随程序走，一本书一个文件，住在 assets/世界书/     标识 $default:<名字>
用户那份   存在端口里，随便建、随便改、随便删                标识 wb<UUID>，带可选 scope
```

**一个请求可以同时启用几本。** 用户书通过 `scope` 独立归属请求；新建或导入给请求只设置归属，不自动启用。未保存过该请求时才使用装配层注入的默认列表；明确保存 `启用: []` 就是停用，不是失败。

**没有"恢复默认"这个动作。** 默认从来没被改过，所以不存在"还"这回事。想改默认的条目？**导出 → 导入 → 启用副本**（见 [调用示例.md](调用示例.md) §六）。

**导入永不覆盖。** 同一请求范围内撞名就加号（`甲` → `甲 2`）；不同请求可以同名。**用户书与只读默认重名是允许的**。

## 四、盘上的形状

```
<根目录>/
└── 世界书.json                    用户那份（一个文件装全部请求）

<默认目录>/
├── 翻译.json                      只读
├── 识图.json                      只读
└── 文生图.json                    只读
```

用户那份：

```jsonc
{
  "format": "worldbook", "version": 1,   // format 只是标记，读的时候不看；version 不是 1 就算读不懂
  "subs": {
    "翻译": { "启用": ["$default:翻译", "wb<UUID>"] },    // ← 一串。一本都不启用就是空数组
    "主AI": { "启用": ["主AI"] }
  },
  "books": {
    "wb<UUID>": { "name": "我的翻译", "scope": "翻译", "entries": [ … ] }
  }
}
```

世界书（我们自己这份形状，只读默认与导出都用它）：

```jsonc
{
  "name": "翻译",
  "entries": [
    { "id": "e1", "label": "常驻", "text": "…", "always": true,  "keys": [],            "enabled": true, "落点": "前" },
    { "id": "e2", "label": "中文", "text": "…", "always": false, "keys": ["中文","zh"], "enabled": true, "落点": "按深度", "深度": 2, "角色": "系统" }
  ]
}
```

**`启用` 是一串，不是一本。** 主 AI 与副 AI 用的是同一个形状，差别只是列表里有几个元素。

## 五、十个动作

| 动作 | 参数 | 说明 |
|---|---|---|
| `执行` | `请求`, `文本` | **上层要的那一个**：交回 `{ 请求, 书, 命中 }`。读存档 |
| `测` | `请求`, `文本` | 同一形状，读草稿（界面预览用） |
| `读` | `请求?`, `书?` | 表 + 请求默认映射副本 + 某个请求启用了哪几本 + 那本书的正文 + 草稿状态 |
| `表` | `请求?` | 全部世界书；给请求时仅列该请求归属的书 |
| `书` | `动作`, … | `换` / `导入` / `新建` / `改名` / `删` / `导出` |
| `条目` | `动作`, `书`, … | `加` / `改` / `删` / `移` |
| `存` · `丢` · `重读` | — | 草稿写进端口 · 草稿丢回存档 · 重读端口 |
| `状态` | — | 体检：默认几份、用户书几本、冻结与脏 |

**两个状态，别混**：

```
存档（端口里那份）  ← 执行只用它 —— 交出去的东西与"存过的"永远一致
草稿（内存里那份）  ← 读 / 测 与全部改动都作用在它上面
```

所以：**改了不存，`执行` 拿到的还是旧的**（但 `测` 看得见）。这不是缺陷，是"手动保存"的定义。

**读与写都直接给结果**（端口是同步的）。

## 六、怎么调

```js
const { createWorldbookModule } = require('./世界书模块/index.js');

const 世界书 = createWorldbookModule({
  根目录: '<userData>/世界书',
  默认目录: '<app>/世界书模块/assets/世界书',
  默认启用: { '绘图任务': ['$default:文生图'] },
});

// 没有存档选择时，绘图任务使用构造时注入的默认书
const { 请求, 书, 命中 } = 世界书.执行({ 请求: '绘图任务', 文本: '一座蓝色城堡' });
// 命中 = [{ 文本, 落点, 深度?, 角色?, 书 }]
// 上层按落点把条目与骨架拼起来，再交给模型调用那一小块
```

界面那几个动作：

```js
const 快照 = 世界书.读({ 请求: '翻译' });        // 表 + 默认映射副本 + 启用那几本 + 脏不脏
世界书.书({ 动作: '换',  请求: '翻译', 启用: ['$default:翻译'] });
const 新书 = 世界书.书({ 动作: '新建', 请求: '翻译', 名字: '我的翻译' }); // 只设归属，不自动启用
世界书.书({ 动作: '导入', 请求: '翻译', 内容: 读进来的文件文本 });
世界书.书({ 动作: '导出', 标识: '$default:翻译' });        // → { 名字, 内容 }
世界书.条目({ 动作: '加', 书: 新书.标识, 条目: { label: '一段', text: '正文', 落点: '后' } });
世界书.条目({ 动作: '改', 书: 新书.标识, 标识: 'e1', 条目: { 落点: '按深度', 深度: 2 } });

世界书.存();                                    // 落下
```

## 七、哪条不能动

1. **只读默认不许有任何写路径。** 程序里没有一处能写到 `<默认目录>`。
2. **`执行` 只读存档，不读草稿。** 破了这条，"上层拿到的和存过的不一致"会变成常态。（`测` 是另一条路，它读草稿。）
3. **不拼装、不排序、不做取舍。** 交回的是带落点的条目，不是一段话。
4. **回执只有 `请求` / `书` / `命中`。** 不回 `文本`——调用方自己手里有。
5. **条目顺序就是数组顺序。** 不许另存 `order` 字段。
6. **`always` 只有一个来源。** `constant: true` 与"没有关键词"都归一成它。
7. **筛选只有关键词子串命中。** 不做概率、不做次级关键词、不做递归、不做向量。
8. **`always` 决定启用方式，`keys` 独立保存。** 恒常时忽略关键词；切换方式不清空条件。
9. **参数（温度、惩罚、上限）不许进本模块的数据。** 一个字段都不留。
10. **"读不懂"不许当成"没有"。** 存档读不懂 → 冻结写、报出来、默认照常可用；默认文件坏掉 → 说它坏，不说它没有。
11. **失败一律 `{ ok:false, reason, code }`，不许抛**（装配阶段除外）。
12. **`深度` 与 `角色` 只在落点是 `按深度` 时有意义**，换成别的落点就丢掉。
13. **"按深度"那个数不由本模块算**——算它要数对话，对话在上层。原样交出去。
14. **落点一律原样带出去，本模块不解释它。** "哪几种真能落"是上层的事。
15. **导入永不覆盖。** 只新增，撞名加号；没有覆盖那条路。
16. **归属按位置算。** 住在默认目录里的是只读默认，住在用户那份里的是用户的——判断不读名字。
17. **用户书与只读默认重名是允许的**；同一请求范围内的用户书之间不撞名。
18. 用户书标识由 `crypto.randomUUID()` 生成，删除后永不复用；旧用户书没有 `scope` 时不猜测归属。
18. **不许 require 别的模块的文件**，也不许被别人 require 内部件（对外只有 `index.js`）。

## 七之二、界面还没写（这一节给写界面的人）

> 本节是早期界面建议。现行界面见 [启用方式与工具条目](../../文档/启用方式与工具条目.md)：蓝灯一直启用、绿灯条件启用，关键词独立保存，修改后显式保存；不展示插入深度和角色控件。下面的输入即切换、互斥及深度控件方案已作废，保留原文用于追溯。

**本模块只到模块层。** 界面属于上层，用的是现有那几个懒加载视图那套做法。
写界面时，条目那几条状态必须一眼能分开：

| 数据 | 列表里显示 |
|---|---|
| `always:true, keys:[]` | `每次` |
| `always:false, keys:['龙','dragon']` | `触发：龙 / dragon` |
| `enabled:false` | 整行淡掉，标`停用` |
| `落点:'按深度', 深度:2, 角色:'系统'` | `@深度 2 · 系统` |
| `always:false, keys:[]` | `未设条件（不会进入）`（只在打字中途出现） |

编辑区一行到位：

```
触发条件  ● 每次参与     ○ 关键词触发 [ 龙, dragon ]
落点      [ 前 ▾ ]        深度 [ 2 ]    角色 [ 系统 ▾ ]
```

**不要另加"确认条件"按钮** —— 在关键词框里打字就切到"关键词触发"，清空就切回"每次参与"，
互斥由模块侧保证，界面不需要自己维护第二份状态。
**落点选到"按深度"时才显示深度与角色**——那两个只有那时有意义。

**"启用哪几本"是一个多选列表**，不是单选。空着是合法的（那就什么都不进）。

**表里可能有两本同名的书**（一本默认、一本用户导入的）。靠 `是本子` 分开，别靠名字。

**只读默认那两行不给编辑按钮**：改名 / 删 / 加条目 / 改条目都会被 `PROMPT_READONLY_BOOK` 拦回来。
界面上该给的是"导出 → 导入 → 启用副本"那条路（[调用示例.md](调用示例.md) §六）。

**`读({ 请求 }).启用` 里那份文件坏掉时**，那一行 `存在:false`、`读得懂:false`——别显示成"这本书没了"，
它还在，只是读不出来。同一件事在表行上写作 `读不懂:true`。

## 八、依赖从哪来

| 依赖 | 递不进来会怎样 |
|---|---|
| `port` 或 `根目录` + `默认目录` | **构造即抛错**（装配阶段允许抛） |
| `默认启用` | 可省略；装配层可注入 `{ [请求名]: [书标识, …] }`，同时据此推导只读默认的请求归属 |
| 只读默认文件 | 那一份不在表里；启用它会被当成不存在的书（`PROMPT_NO_SUCH_BOOK`）；文件在但读不懂 → 报 `PROMPT_STATE_UNREADABLE`，两者不混 |
| 发请求的能力 | **不在本模块里**——上层拿到条目自己去拼、自己去发 |
| 骨架 | **不在本模块里**——预设模块的事 |

**模块自己不找、不猜、不探测路径。** 多级兜底（`a || b || c`）是缺陷。

## 九、改完怎么验

```bash
node test/run.js          # 65 条功能判据 + 内存适配器那条封口证明
node test/run.js 落点      # 只跑名字里含"落点"的
```

或 `npm test`。

判据与设计规范 §十二 的 `V-*` 一一对应。加一条能力就加一条判据，
**判据必须能在不读源码的情况下判真假** —— 判据里出现"大概""应该"就是判据没写清。

拿真 assets 目录跑的（这三个会碰只读默认，所以用真目录 + 比哈希）：

```bash
node tools/防改.js        # 17 条：8 类写入口拦不拦得住 + 同名两本并存 + 哈希不变
node tools/对账默认.js    # 四份默认：命中与文件逐字相同 · 落点对得上 · 条件条目逐条进出 · 转义原样
node tools/看默认.js      # 四份默认长什么样 + 文生图试八条文本的命中
```

新增判据时优先验这些不变量：

| 判据 | 意思 |
|---|---|
| 一本书都不启用 ⇒ 交回空 | 不是失败 |
| 不认识的名字 ⇒ 交回空 | 有哪几本书由目录回答 |
| 默认那本改不动、删不掉、但导得出 | 只读默认没有任何写路径 |
| 导入酒馆形状：读 `key`/`comment`/`content`/`constant`/`disable`/`position`/`depth`/`role` | 其余一概不读 |
| 恒常每次参与，带条件的按文本进 | 筛选确定 |
| **执行只用存过的那一份** | `执行` 只读存档 |
| 无请求记录才使用注入默认 | 显式存档空数组仍保持停用，重启后也不重新启用 |
| **导出 → 导入 → 语义相同** | 酒馆兼容的判据（含 `position` / `depth` / `role`） |
| 导入同名 ⇒ 加号，不覆盖 | 没有覆盖那条路 |
| 存档读不懂 → 冻结写 + 默认照常可用 | "读不懂"不当成"没有" |
| 同一流程在内存适配器上结果一致 | 核心不依赖盘 |
| 动作表里没有路径／地址这类参数 | 对外的参数永远是标识 |

## 十、这一版做到哪了 / 还差什么

**已实现**：书（只读默认 + 用户那份 + 启用列表）、条目的加改删移、恒常与条件筛选、
**落点与深度角色**、酒馆世界书导入、**导出**、草稿与手动保存、读的三态与冻结写、端口 + 两个适配器。
**65 条功能判据全绿**；三个工具用真 assets 目录跑过。

**这一版改掉的（相对旧设计）**：

| 改什么 | 从 | 到 |
|---|---|---|
| 名字 | 提示词模块 | **世界书模块** |
| `执行` 交回什么 | 一段拼好的文本 | **`{ 请求, 书, 命中 }`** |
| 拼装 | 模块做 | **上层做** |
| 段落用词 | 用途 `a1`/`a2`/`a3` | **请求 `主AI`/`翻译`/…** |
| 默认文件名 | `a1.json` | **`翻译.json`**（文件名即书的名字） |
| 启用 | `active` 一本 | **`启用` 一串** |
| 条目字段 | 六个 | **加 `落点` / `深度` / `角色`** |
| 导入 | 可以覆盖 | **只新增，撞名加号** |
| 导出 | 没有 | **`书({ 动作:'导出' })`** |
| `NO_SUCH_SUB` | 用途只许三个 | **删掉**（有哪几本书由目录回答） |

| 项 | 状态 |
|---|---|
| 落点在盘上存**名字还是数字** | **待决**。本设计按名字写 |
| 一本书里条目的**默认落点** | **待决**。现在缺省 `前` |
| 酒馆的**对话预设**导入 | **不做**。那是预设模块的事 |
| 次级关键词 / 概率 / 递归 / 向量 | **一律不读** |
| 正则关键词 | **不做**，全按字面关键词 |
| 条数上限 / 长度上限 | **没有**。用户爱写多长写多长 |
| 索引落盘 | **不落**。书多、条目多到启动慢了再议 |
| `主AI.json` | 默认身份与工作方式作为两条常驻条目，随请求默认启用；复制后可编辑 |
| 本模块接进界面 | **没接**。接线是门面层的活 |

## 本次世界书引用（V1.5.1）

`执行({请求,文本,启用?})` 与 `测` 接收本次的书标识数组；给了就使用该数组（空数组不挂书），省略仍读取请求存档。它只影响本次命中，不修改订阅。主 AI 预设因此可把书标识直接递进来，正文仍只住世界书模块。验证：`node test/预设引用.js`。
