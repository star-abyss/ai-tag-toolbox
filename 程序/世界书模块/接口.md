# 世界书模块 · 接口契约

> **一份能独立于实现存在的契约。** 它不是散文，是可以拿来校验的：字段名、类型、必填、约束、错误码都写死在这里。
>
> 改实现之前先改这里。
>
> 三组接口，边界各不相同：
> - **对外操作**（§一）：门面交出去的那十个。**只认标识，不认路径。**
> - **端口**（§二）：核心要求装配层提供什么。**核心通过它不认识盘。**
> - **装配**（§三）：装配层递什么进来。

---

## 〇、约定

| 记号 | 意思 |
|---|---|
| `必` | 必填 |
| `选` | 可选 |
| `?` | 可能没有（`null`／`undefined`） |
| `串` / `数` / `真伪` / `对象` / `数组` | `string` / `number` / `boolean` / `object` / `Array` |
| `→` | 返回值 |

**两套命名，不许混：**

- **中文键 = 给人的**（动作名、回执字段、输入参数）
- **英文键 = 给程序的**（条目自己的 `id` / `label` / `text` / `always` / `keys` / `enabled`）
- **`落点` / `深度` / `角色` 用中文**（它们是给人看的分类，见设计 §十四 决定 67）

**失败一律 `{ ok:false, reason, code }`**，`reason` 的写法是 `码: 人话`。
直呼式（`世界书.执行(...)`）成功给数据、失败给 `null`。**模块不抛错**（装配阶段除外）。

**两个状态**：`存档`（端口里那份，`执行` 只用它）与 `草稿`（内存里那份，`读` / `测` 与全部改动作用在它上面）。
`存` 把草稿写进存档；`丢` 把草稿丢回存档。

## 一、对外操作

### 1.0 被多个操作共用的形状

```
请求  = 串                            如 '翻译' / '识图' / '主AI'
标识  = 只读默认 '$default:<名字>'      如 '$default:翻译'
      | 用户那份 'wb<UUID>' …
文本  = 串                            这次调用的内容，只用来筛条目

落点  = '前' | '后' | '顶部' | '底部' | '按深度' | '扩展顶部' | '扩展底部' | '出口'
角色  = '系统' | '用户' | '助手'

条目 = {
  id      必串    世界书内唯一，程序分配
  label   必串    显示名
  text    必串    正文
  always  必真伪  恒常：为真时每次参与，keys 不看
  keys    必数组  启用条件；没有恒常时，命中任一项即参与
  enabled 必真伪  假则不参与
  落点    选串    见 §1.0 的落点；缺省 '前'
  深度    选数    只在 落点 === '按深度' 时出现；缺省 4
  角色    选串    只在 落点 === '按深度' 时出现；缺省 '系统'
}

世界书 = { name 必串, entries 必数组[条目] }

启用行 = { 标识 必串, 名字 必串, 是本子 必真伪, 存在 必真伪, 读得懂 必真伪 }
表行   = { 标识 必串, 名字 必串, 是本子 必真伪, 请求 选串, 存在 必真伪, 条目数 必数, 读不懂 选真伪 }
命中   = { 文本 必串, 落点 必串, 深度 选数, 角色 选串, 书 必串 }
```

请求没有对应存档 `subs` 记录时，`读` / `测` / `执行` 使用构造时注入的请求默认列表；存档有记录（包括空数组）时，使用存档或草稿列表。显式 `启用: []` 会覆盖请求默认列表。默认映射同时定义默认书的请求归属。

**约束（不是建议）：**

| # | 约束 | 违反时 |
|---|---|---|
| 1 | 一本书只能由持有它的那一份改：只读默认改不动 | `PROMPT_READONLY_BOOK` |
| 2 | 写操作一律作用在草稿；落下要按 `存` | — |
| 3 | 导入只新增，没有覆盖 | — |
| 4 | **路径与地址不许出现在任何对外参数里** | 缺陷，不是错误码 |

### 1.1 `执行` —— 上层要的那一个

```
入  { 请求 必, 文本 选, 启用 选数组[书标识] }
出  { 请求 必串, 书 必数组[{ 标识 必串, 名字 必串 }], 命中 必数组[命中] }
```

| 项 | 规定 |
|---|---|
| 必做 | 给了 `启用` 就取本次的书标识列表；省略则按请求取存档列表 → 逐本取它当前那份 → 筛 → 交回 |
| 本次引用 | `启用:[]` 表示不挂书；本次列表不改请求存档，用于调用方明确指定本次书籍；应用运行与预览统一读取请求订阅 |
| **只读存档** | **草稿改了不算**（V-46）。交出去的东西与"存过的"永远一致 |
| 省略 `启用` | 有请求存档记录时读取存档列表；没有记录时读取构造依赖中该请求的默认列表 |
| 一本都不启用 / 请求不认识 | `书: []`、`命中: []`，**不是失败** |
| 禁止 | 不许拼装、不许排序、不许带参数（温度、惩罚、上限） |
| 失败 | 启用了某份只读默认而这文件读不懂 → `PROMPT_STATE_UNREADABLE` |
| 同步 | 是 |

### 1.2 `读`

```
入  { 请求 选, 书 选 }
出  {
  表       必数组[表行],
  默认启用 必对象[请求名: 数组[书标识]],
  启用     选数组[启用行],     // 给了 请求 才有
  请求     选串,
  书       选{ 标识 必串, 名字 必串, 是本子 必真伪, 条目 必数组[条目] },
  脏       必真伪,
  冻结     选串
}
```

| 项 | 规定 |
|---|---|
| `书` 给谁 | 给了 `书` 就按它；只给 `请求` 就给那个请求启用了哪几本 |
| `书` 找不到 | `书` 非空而标识不认识 → `PROMPT_NO_SUCH_BOOK`（**不回落、不换一本**） |
| `存在` | 那本书读得出来吗。只读默认文件坏掉 ⇒ `存在:false` |
| `读得懂` | `存在` 的展开：只读默认坏掉时为 `false`，其余为 `true` |
| `读不懂` | 表行上才有：那份只读默认文件读不懂时为真 |
| `冻结` | 存档读不懂时给出原因串 |
| `脏` | 草稿与存档不一致 |
| `默认启用` | 构造时由装配层注入的 `{ [请求名]: [书标识, …] }` 副本；不写入存档 |
| `启用` | 有请求记录时取草稿记录；无记录时取注入的该请求默认列表，没有注入则为空数组 |

### 1.3 `表`

```
入  { 请求 选 }
出  数组[表行]
```

| 项 | 规定 |
|---|---|
| 内容 | 未给请求：全部只读默认 + 全部用户世界书；给请求：该请求归属的用户书 + `默认启用[请求]` 中的默认书 |
| 排序 | **按名字排序；不分组** |
| 归属字段 | 用户书行返回中文 `请求`；无归属的既有书省略该字段 |
| 默认书 | 归属由注入的 `默认启用` 映射推导，不另存归属清单 |

### 1.4 `测`

```
入  { 请求 必, 文本 选, 启用 选数组[书标识] }
出  同 执行：{ 请求 必串, 书 必数组, 命中 必数组[命中] }
```

| 项 | 规定 |
|---|---|
| 用途 | 界面看"这次会命中哪些条目"。**与 `执行` 同形、不同份** |
| 读哪一份 | **草稿**（用户改了还没存的条目要看得见效果）；该请求没有存档记录时使用注入默认列表 |
| 归属 | 显式或选中列表里的每本书必须归属该请求；不属于时返回 `PROMPT_BOOK_SCOPE_MISMATCH` |

### 1.5 `书`

```
入  { 动作 必:'换'|'导入'|'新建'|'改名'|'删'|'导出', … }
```

| 动作 | 入 | 出 | 规定 |
|---|---|---|---|
| `换` | `请求 必, 启用 必数组[标识]` | `{ 请求 必串, 启用 必数组[标识] }` | 设这个请求这次用哪几本。**空数组 = 一本都不用**。去重、保序。有标识不认识 → `PROMPT_NO_SUCH_BOOK`；跨请求书 → `PROMPT_BOOK_SCOPE_MISMATCH`；失败不动状态 |
| `导入` | `请求 选, 名字 选, 内容 选串 \| 书 选对象` | `{ 标识 必串, 名字 必串 }` | **只新增**。条目 `id` 由程序重发。`名字` 缺省用书自己的名字；与同一归属范围的用户书撞名就加号（`甲` → `甲 2`）。与只读默认重名是允许的。给了 `请求` 只设置归属，不自动启用 |
| `新建` | `请求 选, 名字 选` | `{ 标识 必串, 名字 必串 }` | 建一本空的。`名字` 缺省 `新世界书`；同一归属范围撞名加号。给了 `请求` 只设置归属，不自动启用 |
| `改名` | `标识 必, 名字 必` | `{ 标识 必串, 名字 必串 }` | 只改用户那本。空名字 → `PROMPT_BAD_ARGUMENT` |
| `删` | `标识 必` | `{ 删了 必串 }` | 只删用户那本；**连带把它从所有请求的启用列表里摘掉** |
| `导出` | `标识 必` | `{ 名字 必串, 内容 必串 }` | 交回一份能再导入的世界书文本。**只读，不受冻结影响**；只读默认也能导出 |

**导入的校验**：JSON 语法错 → `PROMPT_BAD_WORLDBOOK`；没有 `entries` → `PROMPT_BAD_WORLDBOOK`；
两种情况**都不动状态**。

**导入认两套字段名**：

| 我们的 | 酒馆的 |
|---|---|
| `label` / `text` / `always` / `keys` / `enabled` | `comment` / `content` / `constant` / `key` / `disable`（取反） |
| `落点` | `position`（0…7） |
| `深度` / `角色` | `depth` / `role`（`system` / `user` / `assistant`） |
| 顶层 `name` / `originalData.name` | 同左 |

**导出的形状**：`{ name, entries: [ { id, label, text, always, keys, enabled, 落点, 深度?, 角色? } ] }`
（自己的形状，于是"导出 → 导入"逐字对得上）。

### 1.6 `条目`

```
入  { 动作 必:'加'|'改'|'删'|'移', 书 必, 标识 选, 条目 选, 方向 选, 到 选 }
```

| 动作 | 出 | 规定 |
|---|---|---|
| `加` | `{ 条目 必条目 }` | `id` 由程序分配：从 `e1` 起顺着找第一个没被这本书占用的号。**给进来的 `id` 不采信** |
| `改` | `{ 条目 必条目 }` | 只改给进来的那几项，**`id` 改不动**。显式 `always` 优先，不清空 `keys`，可同时更新关键词；只给 `keys` 则按"词空不空"定 `always`（空 ⇒ `always:true`）。`always:false, keys:[]` 不命中。改了 `落点` 就按新落点整理 `深度` / `角色` |
| `删` | `{ 删了 必串 }` | 删 `标识` 指的那条 |
| `移` | `{ 标识 必串, 到 必数 }` | 给 `方向:'上'\|'下'` 或 `到:序号`；越界 → `PROMPT_BAD_ARGUMENT` |

**`书` 必须是用户那本**；给只读默认 → `PROMPT_READONLY_BOOK`。

### 1.7 `存` · `丢` · `重读`

```
存()    → { 脏 必真伪 }            草稿写进端口
丢()    → { 脏 必真伪 }            草稿丢回存档
重读()  → { 冻结 必真伪, 脏 必真伪 }  重读端口
```

| 项 | 规定 |
|---|---|
| 冻结只挡什么 | **只挡写盘的那几个入口**（`书` 的五个写动作 / `条目` / `存`）。`读` / `表` / `测` / `丢` / `重读` 不写盘，冻结时照常可用 |
| `存` 冻结时 | 拒写 → `PROMPT_STATE_UNREADABLE`，**端口里的原文件不动** |
| `存` 失败 | → `PROMPT_WRITE_FAILED`，草稿保留，不自动重试 |

### 1.8 `状态`

```
入  {}
出  {
  默认   必数      只读默认几份
  用户书 必数
  请求   必数      存档里记了几个请求的启用列表
  存档   必{ 冻结 必真伪, reason? },
  脏     必真伪
}
```

### 1.9 直呼与动作表

| 门面成员 | 说明 |
|---|---|
| `执行` / `读` / `表` / `测` / `书` / `条目` / `存` / `丢` / `重读` / `状态` | 直呼式：成功给数据，失败给 `null` |
| `run(动作, 参数)` | 走动作表，永远给 `{ ok, data }` 或 `{ ok:false, reason, code }` |
| `actions` | 动作名数组（冻住） |
| `describe()` | `[{ 动作, 摘要, 参数, 说明 }]` |
| `ERR` | 错误码字典（冻住） |

**出口冻住**：门面 `Object.freeze`，不递 `core` / `port` / `adapter` / `worldbook`。

## 二、端口

装配层必须交出这四件事。**核心只通过这些方法与外界来往。**

```
readState()          → { state:'ok', value 对象 } | { state:'missing' } | { state:'unreadable', reason 串 }
writeState(value)    → { ok:true } | { ok:false, reason 串 }
listDefaults()       → { ok:true, items 数组[一项] } | { ok:false, reason 串 }
readDefault(名字)    → { state:'ok', value 世界书对象 } | { state:'missing' } | { state:'unreadable', reason 串 }

一项 = { 名字 必串, 条目数 必数, state 选:'unreadable' }
```

**`名字` 就是默认文件名去掉 `.json` 那一段**（`翻译.json` ⇒ `翻译`）。核心拿它当作书的名字，也拿它拼对外标识 `$default:<名字>`。

**`listDefaults` 要收全，不是只收读得懂的**：那份读不懂时，这一项照给（`条目数` 填 `0`）并带 `state:'unreadable'`。
把它从清单里丢掉，核心就永远走不到"读不懂"那一条。

**读的三态（不是两态）：**

| state | 意思 |
|---|---|
| `ok` | 有 |
| `missing` | **确实没有**（文件不存在 / 键没有） |
| `unreadable` | **读不懂**（JSON 坏、形状不对、版本不认、权限不足） |

> **`missing` 和 `unreadable` 绝不能混成一个。**
> 把"读不懂"当成"没有"，下一次写就把用户那份盖掉了；
> 在只读默认上混，用户看到的就是"这份默认没了"，而实际只是文件坏了。

**`reason` 取值**：`权限` / `磁盘满` / `被占用` / `读不懂` / `不存在` / `未知`。

**只读默认没有任何写方法。** 端口契约里不存在"写默认"这件事。

## 三、装配

```
createWorldbookModule({ port, 默认启用? })                  端口与请求默认书由装配层递进来
createWorldbookModule({ 根目录, 默认目录, 默认启用? })        内部装文件适配器
```

`默认启用` 形状为 `{ [请求名]: [书标识, …] }`，例如 `{ '图像任务': ['$default:文生图'] }`。模块不设请求名与书名的映射；省略时等同于 `{}`。该映射同时定义默认书的请求归属；`读({})` 与 `读({ 请求 })` 都返回 `默认启用` 的独立副本。

| 项 | 规定 |
|---|---|
| 两个都不给 | **构造即抛错**（装配阶段允许抛） |
| 端口缺方法 | **构造即抛错**，说明缺哪个 |
| 同时给 `port` 与位置 | 以 `port` 为准 |
| `根目录` | 只有这一个名字；`root` / `data` 之类的别名不存在 |
| `默认目录` | 存只读默认的目录；文件适配器按 `<默认目录>/<名字>.json` 读 |

**文件适配器的两个位置：**

```
<根目录>/世界书.json                 用户那份，可写；原子写（临时文件 + 改名）
<默认目录>/<名字>.json               只读，一本书一个文件
```

**名字能不能当文件名**：不许是空的、`.`、`..`，不许含 `\ / : * ? " < > |` 与控制字符。
不合格的名字在 `listDefaults` 里跳过，在 `readDefault` 里当 `missing`。

**存档文件顶层的两个字段**（`{ "format": "worldbook", "version": 1, "subs": { … }, "books": { … } }`）：

| 字段 | 规定 |
|---|---|
| `version` | **参与判定**：不等于 `1` 就是读不懂，存档按冻结处理 |
| `format` | **只是个标记**：写盘时带上，读的时候**不看**它，不影响任何判定 |

**存档的形状：**

```jsonc
{
  "format": "worldbook", "version": 1,
  "subs":  { "翻译": { "启用": ["$default:翻译", "wb<UUID>"] } },
  "books": { "wb<UUID>": { "name": "我的翻译", "scope": "翻译", "entries": [ … ] } }
}
```

`subs` 没有某请求的键表示尚未作出选择，运行时使用注入默认；`"启用": []` 表示明确停用，优先级高于注入默认。用户书的 `scope` 是请求名；未归属的既有书保留无归属，不推测归属、不迁移。未传请求创建的书同样无归属，只能通过不带请求的全表管理。用户书标识使用 `crypto.randomUUID()`，删除后不会复用。注入配置不写进这个文件。

**核心不许 require `fs` / `path`。** 内存适配器能跑通全部判据，这一条才算事实。

## 四、错误码

| 码 | 什么时候 |
|---|---|
| `PROMPT_NO_SUCH_BOOK` | 标识指的书不在；`读` 里 `书` 非空而找不到；`换` 的启用列表里有不认识的标识 |
| `PROMPT_BOOK_SCOPE_MISMATCH` | `换` / `执行` / `测` 引用了归属其他请求的书 |
| `PROMPT_READONLY_BOOK` | 想改名 / 删 / 加条目 / 改条目 / 移条目，而目标是只读默认 |
| `PROMPT_NO_SUCH_ENTRY` | 条目 id 不在那本书里 |
| `PROMPT_BAD_WORLDBOOK` | 导入的内容 JSON 坏 / 没有 `entries` |
| `PROMPT_STATE_UNREADABLE` | 存档读不懂（写被冻结）；启用的只读默认文件读不懂 |
| `PROMPT_WRITE_FAILED` | 写不进去，或动作本身出错 |
| `PROMPT_BAD_ARGUMENT` | 参数不对 / 没有这个动作 / 缺必填 / 移越界 |

**没有 `PROMPT_NO_SUCH_SUB`**：有哪几本书由目录回答，模块不再有"只许三个用途"这条规矩。
