## 一、它是什么 / 它不是什么

**图片的存放与取回。就这一件事。**

| 它做 | 它不做 |
|---|---|
| 把字节按标识落到磁盘上的确定位置 | 判断"这段对话里哪几张图可见"（对话模块的事） |
| 按标识取回字节或取回地址 | 决定"哪张图该给识图"（识图与界面的事） |
| 列、改显示名、删、清空 | 认识图片内容（**不解析任何格式**） |
| 图库的收藏与分类（表） | 认识对话、识图、AI、出图 |

**它不认识任何别的模块的名字。** 依赖一律由装配层以**函数**形式递进来。

## 二、东西在哪

```
图片模块/
├── index.js            门面。**对外只有这一个文件**（出口冻住）
├── port.js             端口契约 + 读的三态约定
├── adapter-file.js     文件适配器。**唯一 require fs / path 的地方**
├── adapter-memory.js   内存适配器。它的用处是**证明核心真的不依赖盘**（判据 V-31）
├── core.js             核心。纯逻辑，不认识盘
├── test/run.js         功能自检（41 条判据，对应设计 §12.2）
├── test/接口.js         接口校验（27 条，照 接口.md 查形状）
├── 接口.md               **契约**：对外操作 / 端口 / 装配的字段名与约束
├── 图片模块设计.md      设计规范（112 条需求 + 24 条决策）
└── 调用示例.md          调用示例与错误表
```

**契约与实现分开**：`接口.md` 是能独立存在的契约，`test/接口.js` 照它查实现。
改实现之前先改契约；改完契约跑 `node test/接口.js`。

调用链永远是一个方向：

```
装配层 → index.js（门面/动作表） → core.js（纯逻辑） → port → adapter-file.js（盘）
```

**核心不许 require `fs`／`path`。** 它想说"在某个作用域下对某个名字做点什么"，由适配器翻成真实路径。

## 三、五个词

| 词 | 意思 | 长什么样 |
|---|---|---|
| **存放地** | 归属写在路径里的三个目录之一 | `session` / `gallery` / `vision` |
| **作用域** | 存放地 + 归属标识 | `{ 存放地:'session', 会话ID:'A' }` |
| **条目** | 一次落盘产生的一件图片实体 = **一个目录** | `img_xxx/` |
| **标识** | 对外出现的引用，就是条目 ID | `img_muzvylah-9e83qgj8` |
| **引用** | 模块之间传递的定位信息 | `{ 作用域, 条目ID }` |

**对外只有标识；引用只在模块之间流动；模块内只认地址与条目 ID。**
工具参数里出现路径/URL 就是缺陷（看 `describe()` 的参数名即可核对）。

## 四、盘上的形状

```
<根目录>/
├── session/<会话ID>/<条目ID>/     对话图片：对话删了，图就删
├── gallery/
│   ├── <条目ID>/                  图库：只有用户显式删才删
│   ├── 收藏.json                  ["img_…", …]            扁平 ID 集合
│   └── 分类.json                  { 类ID: { 名, 配色?, 成员:[ID] } }   只有一层
├── vision/<条目ID>/               识图工作区：恒 0 或 1 个
├── .staging/<条目ID>/             写入暂存区，仅短暂存在
└── .deleting/<批次>/<条目ID>/      待回收区，仅短暂存在
```

一个条目目录里：

```
img_xxx/
├── original.png     原图，**一个字节不改**
├── preview.png      处理器给的（缺省就没有）
├── thumbnail.png    处理器给的（缺省就没有）
└── meta.json        副档，带 format 版本号
```

图库与识图工作区没有清单或计数器，目录本身就是权威。会话目录只额外保存图号高水位；它不记录图片成员，图片条目仍由目录本身决定。

会话图片有一个独立事实：每张会话图片的 `meta.json` 保存 `sessionNumber`，对应会话目录的 `scope.json` 保存 `highWater`。图号不随删除或清空重排；首次列出旧会话图片时，模块按既有列表顺序补齐缺失图号。

## 五、图片操作

| 操作 | 参数 | 说明 |
|---|---|---|
| `列` | `作用域` | **只读目录，不读任何副档**。给极简条目列表 |
| `列会话图` | 会话 `作用域` | 列出 `{标识,图号}`；首次调用会给未编号的旧素材补号 |
| `按图号取详情` | 会话 `作用域`, `图号` | 按稳定图号读取图片详情 |
| `导入会话图` | 会话 `作用域`, 原图号, 图片数据 | 归档导入时保留原图号 |
| `恢复会话图号` | 会话 `作用域`, 高水位 | 恢复归档时已删除图片留下的高水位 |
| `取详情` | `引用` | 读那一个副档，给完整描述符 |
| `取内容` | `引用`, `变体?` | 给字节（`original` / `preview` / `thumbnail`） |
| `取地址` | `引用`, `变体?` | 给物理绝对路径。**只给面板渲染与模块之间** |
| `存` | `作用域`, `字节`\|`dataUrl`, `文件名`, … | 唯一写入路径 |
| `改` | `引用`, `显示名?`, `元数据?` | 只改副档；**磁盘上的文件名一个字不动** |
| `删` | `引用` | 进系统回收站 |
| `清空` | `作用域` | 删该作用域下全部条目 |

`列` / `取详情` / `取内容` / `取地址` 直接给结果；
`列会话图` / `按图号取详情` / `导入会话图` / `恢复会话图号` 会补齐或恢复图号，和 `存` / `改` / `删` / `清空` / `表` 一样走**单一写队列**，返回 Promise。导入和恢复只供归档适配器使用，不能进入 AI 工具清单。

内部（**不进工具清单**）：`维护({动作:'报告'|'清理'})`、`表({表,动作,…})`、`工作区能力()`。

## 六、怎么调

```js
const { createImageModule } = require('./图片模块/index.js');
const crypto = require('crypto');

const 图片 = createImageModule({
  根目录: '<userData>/image-data',
  处理图片: (字节, 限长) => ({ /* preview:{字节,mime}, thumbnail:{字节,mime} */ }),
  交回收站: (绝对路径) => shell.trashItem(绝对路径),
  校验和: (字节) => `sha256:${crypto.createHash('sha256').update(字节).digest('hex')}`,
});

// 存进当前对话
const 条目 = await 图片.存({ 作用域: { 存放地: 'session', 会话ID: 'A' }, 字节, 文件名: 'a.png' });
条目.标识;   // 交给对话模块登记

// 图库 → 对话（复制，不是搬）
const 源 = 图片.取内容({ 引用: 图库引用 });
await 图片.存({ 作用域: { 存放地: 'session', 会话ID: 'A' }, 字节: 源.字节, 文件名: 源.文件名 });

// 删除对话但保留图片
for (const 一条 of 图片.列({ 作用域: { 存放地: 'session', 会话ID: 'A' } }).条目) {
  const 取 = 图片.取内容({ 引用: 一条.引用 });
  await 图片.存({ 作用域: { 存放地: 'gallery' }, 字节: 取.字节, 文件名: 取.文件名, 来源: 'copy' });
}
await 图片.清空({ 作用域: { 存放地: 'session', 会话ID: 'A' } });
```

**给识图模块的**（它不认识本模块）：

```js
createVisionModule({
  工作区文件夹: '<根目录>/vision/<那个条目>/original.png',   // 只读
  工作区: 图片.工作区能力(),                                // 只有 { 清空 }
});
```

## 七、哪条不能动

1. **不许加清单 / 索引 / 计数器。** 有了它就要维护、要修复、要回滚，那正是被删掉的一整类问题。
2. **不许把路径或地址放进对外参数。** 检验法：看 `describe()` 里每个动作的**参数名**。
3. **`列` 不许读副档。** 上千张时读副档 383 ms，枚举只要 14 ms。要详情就让调用方单独取。
4. **只有一条写队列。** 不许为某个动作另起一条串行链（旧实现里 `visionTail` 就是这么来的）。
5. **条目的字节不许重编码。** `original` 必须一个字节不改。
6. **改名只改 `displayName`。** 磁盘上的文件名、目录名、条目 ID 一个字不动。
7. **元数据是整袋替换**，不许做字段级合并。
8. **"读不懂"不许当成"没有"。** 副档读不懂 → 报 `IMAGE_METADATA_UNREADABLE` 并**冻结该条目的写**（**冻结只挡 `改`**；`删` 照常 —— 删是把整个条目目录交回收站，能在回收站找回）。
9. **删除不回滚。** 改名一完成就算删掉了；回收站失败只如实报告可恢复位置。
10. **表里只装条目 ID。** 一装描述就变成第二份真相。表不是权威，删光表图库照样能用。
11. **不许做兼容层、不留回退开关。** 要回退用 git。
12. **不许 require 别的模块的文件**，也不许被别人 require 内部件（对外只有 `index.js`）。

## 八、依赖从哪来

| 依赖 | 递不进来会怎样 |
|---|---|
| `根目录` 或 `port` | **构造即抛错**（装配阶段允许抛） |
| `处理图片` | 只落原图，取派生变体报 `IMAGE_VARIANT_MISSING` |
| `交回收站` | 条目仍移出可见范围，但停在 `.deleting/`，如实标"未回收" |
| `校验和` | 副档里 `checksum` 为空串（不参与去重，**本模块从不去重**） |
| `新标识` / `现在` | 用内置的随机 ID 与系统时间（测试时可换成可控的） |

**模块自己不找、不猜、不探测路径。** 多级兜底（`a || b || c`）是缺陷。

## 九、改完怎么验

```bash
node test/run.js          # 41 条功能判据 + 内存适配器那条封口证明
node test/接口.js          # 27 条接口形状校验（照 接口.md 查）
node test/session-number.js # 会话图号：并发、删除、清空、重启、导入
node tools/验收.js         # 16 步用户操作场景验收（跑完留数据供查看）
node tools/demo.js        # 端到端演示（用完自清）
node test/run.js 删除      # 只跑名字里含"删除"的
```

或 `npm test` / `npm run test:接口` / `npm run test:all` / `npm run 验收` / `npm run demo`。

判据与设计规范 §12.2 的 `V-*` 一一对应。加一条能力就加一条判据，
**判据必须能在不读源码的情况下判真假** —— 判据里出现"大概""应该"就是判据没写清。

新增判据时优先验这些不变量：

| 判据 | 意思 |
|---|---|
| V-2 | 上位前失败 → 列看不到、暂存不残留 |
| V-4 | 副档读不懂 → 报错 + 冻结写 + 原文件不动 |
| V-8 | 图库与识图工作区没有清单/索引/计数器；会话只存图号高水位 |
| V-9 | 同一份字节存两次 → 两个条目 |
| V-15 | 删掉副档，`列` 照常返回 |
| V-16 | 200 条时 `列` 仍在 150 ms 内 |
| V-17 | 存完立刻列就看得见，没有失效步骤 |
| V-19 | 批量删除部分失败 → 报"已删几个 + 卡在哪个引用" |
| V-27 | 并发存 20 张全部成功、互不覆盖 |
| V-31 | 同一流程在内存适配器上结果一致（核心不依赖盘） |
| V-38 | 字节的四种形状（Buffer / Uint8Array / dataUrl / 过了 JSON 的 Buffer）都收，不像内容的文本要拒 |

## 十、这一版做到哪了 / 还差什么

**已实现**：十二个图片操作、两个维护动作、两张表、工作区能力组、
单一写队列、原子改名上位、两步删除、读的三态与冻结写、端口 + 两个适配器。
**41 条功能判据 + 24 条接口校验 + 16 步场景验收，全绿。**

**已知的缺口**（设计规范里也记着，不许偷偷绕过）：

| 项 | 状态 |
|---|---|
| 导出整个存放地 | **没有**（设计 §13.1 待决 1，等拍板） |
| 跨卷 | 不降级。改名失败就如实报错（设计 §13.1 待决 3） |
| 派生变体的尺寸校验 | 处理器给什么就存什么（设计里没要求校验） |
| 处理器返回的宽高 | 不采信。副档里的宽高取自调用方传的 `宽`/`高` |
| 表的并发 | 与条目共用一条写队列 |
| 「哪些操作对模型可见」 | 归门面层（设计 §13.1 待决 2），本模块不决定 |
| 导入 / 导出整个存放地 | **没做**，等拍板（设计 §13.1 待决 1） |
