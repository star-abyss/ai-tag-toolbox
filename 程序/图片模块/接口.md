# 图片模块 · 接口契约

> **一份能独立于实现存在的契约。** 它不是散文，是可以拿来校验的：字段名、类型、必填、约束、错误码都写死在这里。
>
> 改实现之前先改这里；改完这里，`test/接口.js` 会告诉你实现跟不跟得上。
>
> 三组接口，边界各不相同：
> - **对外操作**（§一）：门面交出去的那几个。**只认标识，不认路径。**
> - **端口**（§二）：核心要求存储层提供什么。**核心通过它不认识盘。**
> - **装配**（§三）：装配层递什么进来。

---

## 〇、约定

| 记号 | 意思 |
|---|---|
| `必` | 必填 |
| `选` | 可选 |
| `?` | 可能没有（`null`／`undefined`） |
| `串` / `数` / `真伪` / `对象` / `数组` / `字节` | `string` / `number` / `boolean` / `object` / `Array` / `Buffer` |
| `→` | 返回值 |

**两套命名，不许混：**

- **中文键 = 给人的**（动作名、回执字段、输入参数）
- **英文键 = 给程序的**（`引用` 里的 `作用域`/`条目ID`，`作用域` 里的 `存放地`/`会话ID`）

**失败一律 `{ ok:false, reason, code }`**，`reason` 的写法是 `码: 人话`。
直呼式（`图片.存(...)`）成功给数据、失败给 `null`。**模块不抛错**（装配阶段除外）。

## 一、对外操作

### 1.0 被三个操作共用的三种形状

```
作用域 = 三者之一：
   { 存放地:'session', 会话ID 必串 }     对话图片
   { 存放地:'gallery' }                  图库
   { 存放地:'vision' }                   识图工作区
   （构造用：{ 暂存:'.staging' } / { 暂存:'.deleting', 批次 串 }）

引用 = { 作用域 必作用域, 条目ID 必串 }    条目ID 形状：/^img_[A-Za-z0-9-]+$/

变体 = 'original' | 'preview' | 'thumbnail'      默认 'original'
```

**约束（不是建议）：**

| # | 约束 | 违反时 |
|---|---|---|
| 1 | `作用域.存放地` 只能是那三个 | `INVALID_SCOPE` |
| 2 | `会话ID` 只对 `session` 有意义；别处给了就拒 | `INVALID_SCOPE` |
| 3 | `会话ID` 缺省 → 落到固定占位段 `_`（**单一规则，不是多级兜底**） | — |
| 4 | `会话ID` 与 `名字` 的每一段都要过安全段校验（拒 `''`、`.`、`..`、含分隔符）；非 `session` 作用域给了 `会话ID` 先按第 2 条判 | `INVALID_IMAGE_PATH` |
| 5 | **路径与地址不许出现在任何对外参数里** | 缺陷，不是错误码 |

### 1.1 `列`

```
入  { 作用域 必 }
出  { 条目 数组[{ 引用 必引用, 标识 必串, 修改时间 必数, 完整 必真伪 }], 总数 必数, 作用域 必作用域 }
```

| 项 | 规定 |
|---|---|
| 必做 | **只做一次目录读取**；**不读任何副档** |
| 禁止 | 不许有查询串 / 排序 / 分页参数（筛选排序归展示方） |
| 顺序 | 按修改时间升序，同一时间按标识排 |
| `完整` | 该条目的 `meta.json` 与原图是否都在（只 stat，不读内容）。不完整的条目照样列出 |
| 边界 | 两个临时位置（`.staging`/`.deleting`）**永不出现**；非 `img_` 目录永不出现 |
| 同步 | 是（直接给结果） |

### 1.2 `取详情`

```
入  { 引用 必 }
出  { 引用, 标识, 文件名, 显示名, mime, 宽, 高, 字节数, 校验和, 来源, 元数据, 变体, 创建时间, 更新时间, 图号? }
```

会话作用域包含稳定 `图号`；图库与识图工作区不包含该字段。

| 项 | 规定 |
|---|---|
| 必做 | **只读它自己那一个副档**，不许为了取一条扫全库 |
| 失败 | 条目不在 → `IMAGE_NOT_FOUND`；副档读不懂 → `IMAGE_METADATA_UNREADABLE`（**并冻结该条目的写：只挡 `改`；`删` 照常**） |
| 同步 | 是 |

### 1.3 `取内容`

```
入  { 引用 必, 变体 选 }
出  { 引用, 变体, 字节 必字节, mime, 文件名 }
```

| 项 | 规定 |
|---|---|
| 必做 | 交**字节**。原图必须与存进去的一模一样（不许重编码） |
| 禁止 | **不许产 URL**；要 `data:` URL 谁自己编码 |
| 失败 | 条目不在 → `IMAGE_NOT_FOUND`；该变体没有 → `IMAGE_VARIANT_MISSING`；变体名不认 → `INVALID_IMAGE_VARIANT` |
| 同步 | 是 |

### 1.4 `取地址`

```
入  { 引用 必, 变体 选 }
出  { 引用, 变体, 地址 必串, mime, 文件名 }
```

| 项 | 规定 |
|---|---|
| 必做 | 交出一个**能直接读**的位置串。文件实现给物理绝对路径；别的实现给自己的方案 |
| 用途 | **只给界面面板渲染与模块之间**。不许进工具参数、不许进模型可见输出 |
| 失败 | 同 `取内容` |
| 同步 | 是 |

### 1.5 `存`

```
入  { 作用域 必
      字节 必字节  或  dataUrl 必串（`data:<mime>;base64,<…>`，与字节等价，二选一）
      文件名 必串      只取末段、限长 180；本模块只存不解释
      mime 选串        不填就从文件名推
      来源 选串        upload | generation | copy | import …
      显示名 选串      不填取文件名，限长 180
      元数据 选对象    不透明袋子：只整体存取，**不许解释、不许合并**
      宽 选数  高 选数  原样记账
    }
出  完整的条目描述符（同 `取详情` 的出参形状）
```

| 项 | 规定 |
|---|---|
| 必做 | 顺序固定：暂存目录 → 原图 → 派生变体 → 副档 → **整目录原子改名上位** |
| 必做 | **返回完整描述符**（含显示名），调用方可以直接并进自己的列表，不必再取详情 |
| 字节形状 | 收四种：`Buffer` / `Uint8Array` / `data:` 串 / 光秃秃的 base64 串；另收 `Buffer` 过一趟 JSON 之后那层包（`{ type:'Buffer', data:[…] }`）。不像内容的文本（例如一个路径）**不当字节**，直接拒 |
| 失败 | 字节为空或不像内容 → `IMAGE_BYTES_REQUIRED`；写盘失败 → `IMAGE_WRITE_FAILED`；处理器报错 → `IMAGE_PROCESSING_FAILED` |
| 边界 | 上位之前失败 ⇒ `列` 看不到任何半成品，暂存不残留 |
| 边界 | 处理器**缺省** → 只落原图（降级）；处理器**报错** → 整体失败（不许说成成功） |
| 异步 | 是（走单一写队列） |
| 禁止 | **不许按字节去重**：同样内容存两次 = 两个独立条目 |
| 禁止 | **不许把条目尺寸设上限**；要限制由调用方在调它之前判 |

### 1.6 `改`

```
入  { 引用 必, 显示名 选串, 元数据 选对象 }       两项至少给一项
出  更新后的条目描述符
```

| 项 | 规定 |
|---|---|
| 必做 | **只改副档** |
| 改名语义 | "改名" = 只改 `显示名`。**磁盘上的文件名、目录名、条目 ID 一个字不动** |
| 元数据语义 | **整袋替换**，不是字段级合并 |
| 失败 | 两项都没给 → `INVALID_ARGUMENT`；副档读不懂 → `IMAGE_METADATA_UNREADABLE`（写被冻结，原文件不动） |
| 异步 | 是 |

### 1.7 `删`

```
入  { 引用 必 }
出  { 已删 必数, 已删除 必数组[引用], 批次 串?, 未回收 必真伪, reason 串? }
```

| 项 | 规定 |
|---|---|
| 必做 | 两步：① 原子改名进 `.deleting/<批次>/` ② 把**那个批次目录整个**交系统回收站 |
| 必做 | 改名一完成就算删掉了：`列` 立刻不再返回它；调用方**不必等**回收站 |
| 幂等 | 条目**不存在** → `{ 已删:0, 已删除:[], 批次:null, 未回收:false }`，**不是失败** |
| 失败边界 | 回收没配 / 回收失败 → `未回收:true` + `reason` 里给可恢复位置。**不回滚** |
| 异步 | 是 |

### 1.8 `清空`

```
入  { 作用域 必 }
出  { 已删 必数, 已删除 必数组[引用], 批次 串?, 未回收 必真伪, reason 串? }
```
（与 1.7 同一个形状；`批次` 在一条都没删掉时是 `null`）

| 项 | 规定 |
|---|---|
| 必做 | 删该作用域下**全部**条目 |
| 禁止 | **禁止假装原子**：部分失败时给 `{ ok:false, code:'IMAGE_REMOVE_FAILED', details:{ 已删 数, 卡在 引用, 批次 串 } }` |
| 禁止 | 不许为它引入事务或两阶段提交 |
| 异步 | 是 |

### 1.9 内部动作（**不进工具清单**）

```
维护.报告  入 {}               出 { 暂存残留, 待回收残留, 临时文件, 不完整条目, 读不懂的副档, 悬空标识, reason? }
维护.清理  入 {}               出 { 已清理, 报告 }
                                  清三样：.staging 残留、适配器临时文件、表里的悬空标识
                                  **不碰 .deleting**
表.收藏    入 { 动作:'读'|'加'|'去', 标识? }              出 数组[串]
表.分类    入 { 动作:'读'|'建类'|'删类'|'加成员'|'去成员', 类?, 标识?, 名?, 配色? }
                                出 字典 或 类 或 新字典
工作区能力 入 {}               出 冻结的 { 清空: () => Promise }   ← **只有一个函数**
```

**`表` 与 `维护` 一律返回 Promise**（它们走同一条写队列）；直呼式给数据，失败给 `null`。

**表的三条硬规矩**：表里**只装条目 ID**；**表不是权威**（删光表图库照样能列能取）；
**建 / 删条目不会自动改表**（悬空 ID 由 `维护.报告` 列出）。

### 1.10 会话图号

```
列会话图  入 { 作用域:{存放地:'session',会话ID} }
          出 Promise<{ 条目:[{引用,标识,图号,文件名,显示名,宽,高,修改时间,完整}], 总数, 作用域, 高水位 }>
按图号取详情 入 { 作用域:{存放地:'session',会话ID}, 图号:正整数 }
             出 Promise<取详情描述符>
导入会话图  入 { 作用域,图号,字节,文件名,mime?,显示名?,元数据?,宽?,高? }
            出 Promise<完整条目描述符>
恢复会话图号 入 { 作用域,高水位:非负整数 }
            出 Promise<{高水位}>
```

会话副档保存 `sessionNumber`，会话目录的 `scope.json` 保存 `{format:1,highWater}`。新存入会话的图片在写入队列中先占用下一个图号；失败可以留下空号，已用图号永不复用。删图与清空不降低高水位。

`列会话图` 是旧会话补齐图号的显式入口：第一次调用时按当前 `列` 的顺序为缺号图片分配并写入图号，后续直接返回已保存图号。图库与识图工作区不能调用这两项操作。归档导入通过 `导入会话图` 创建新标识并保留原图号；复制到另一会话仍走普通 `存` 并分配新图号。公共图片引用仍为 `{type:'session-image',imageId}`。

`导入会话图` 只供归档导入适配器调用，按原图号写入新会话；每个号码必须大于目标当前高水位并按升序导入，已分配过的号码（包含已删除图片的号码）返回 `INVALID_ARGUMENT`。`列会话图` 按图号升序返回，因此可直接用于导出。`恢复会话图号` 在归档素材写入后恢复源会话的高水位，即使源会话已删除最高号图片或当前没有任何图片，也不会复用旧号。两项都不能进入 AI 工具清单。

## 二、端口契约

> **核心通过它不认识盘。** 适配器必须提供下面全部方法。
> 路径一律用「作用域 + 名字」表达：`名字` 是相对该作用域的一段相对路径，`/` 分隔，例如 `img_x/meta.json`。

### 2.0 读的三态（最容易做错的一条）

```
readText / readBinary / stat 一律返回：
  { state:'ok', … }           有
  { state:'missing' }         确实没有
  { state:'unreadable', reason }  读不懂
```

**②③ 绝不能混成一个。** 把"读不懂"当成"没有"，下一次写就把数据盖掉了。

### 2.1 方法表

```
list(作用域, 名字?)            → { ok, dirs 数组[串], files 数组[串], 临时 数组[串] }
                                  名字可给子目录；两个临时位置不进 dirs；
                                  原子写留下的 .tmp-* 不进 dirs / files，只在 临时 里给维护用
stat(作用域, 名字)              → { state, kind?:'dir'|'file', mtime?:数, size?:数, reason? }
readText(作用域, 名字)          → { state, value?:串, reason? }
readBinary(作用域, 名字)        → { state, value?:字节, reason? }
writeText(作用域, 名字, 串)     → { ok, reason? }
writeBinary(作用域, 名字, 字节) → { ok, reason? }
mkdir(作用域, 名字)             → { ok, reason? }
rename(从作用域, 从名字, 到作用域, 到名字) → { ok, reason?, code? }
                                  必须**原子**：要么整棵子树搬过去，要么什么都没动
removeDir(作用域, 名字)         → { ok, reason? }        递归
trash(作用域, 名字)             → { ok, 路径?, 交给? 函数, reason? }  交回收站；拿不到就 reason
全路径(作用域, 名字)            → { ok, 值 串, reason? }  这个名字的实际位置串
```

**写必须原子**（写临时文件再改名）。**`reason` 取值**（与 `port.js` 头部同一套）：`权限` / `磁盘满` / `被占用` / `读不懂` / `不存在` / `未知`。

### 2.2 适配器不许做的事

| # | 不许 | 为什么 |
|---|---|---|
| 1 | 不许认识"条目""变体""存放地"这些领域词 | 那是核心的事。适配器只认"作用域 + 名字" |
| 2 | 不许自己决定回收站怎么回收 | 那是装配层递进来的能力 |
| 3 | 不许拼或猜根目录以外的路径 | 越出根目录一律拒 |
| 4 | 不许把读不懂当没有 | 见 §2.0 |

## 三、装配契约

```js
createImageModule({
  根目录 选串,          // 与 port 二选一；给了它就用内置文件适配器
  port 选对象,          // 与 根目录 二选一；给了它就不再碰盘
  处理图片 选函数,       // (字节, { preview:数, thumbnail:数 }) → { preview:{字节,mime}, thumbnail:{…} }
  交回收站 选函数,       // (位置串) → Promise
  校验和 选函数,         // (字节) → 串
  新标识 选函数,         // () → 串；必须是 /^img_[A-Za-z0-9-]+$/
  现在 选函数,           // () → ISO 串
})
```

| 项 | 规定 |
|---|---|
| 两个都不给 | **抛错** `IMAGE_ROOT_REQUIRED` |
| `port` 缺方法 | **抛错**，并点名缺哪个 |
| `处理图片` 不给 | 只落原图；取派生变体报 `IMAGE_VARIANT_MISSING` |
| `交回收站` 不给 | 条目仍移出可见范围，停在 `.deleting/`，`未回收:true` |
| `校验和` 不给 | 副档里 `checksum` 为空串（**本模块从不去重**，它只记账） |
| 出口 | `Object.freeze`；**只交操作面，不递内部件**（不 export core / port / adapter） |

## 四、错误码

| 码 | 触发 | 可重试 | 冻结写 |
|---|---|---|---|
| `IMAGE_ROOT_REQUIRED` | 根目录无效或没递 | 否 | — |
| `INVALID_SCOPE` | 作用域不是那三类 | 否 | — |
| `INVALID_IMAGE_PATH` | 名字里有危险段 | 否 | — |
| `INVALID_ARGUMENT` | 该给的没给 / 形状不对 | 否 | — |
| `IMAGE_NOT_FOUND` | 条目不存在 | 否 | — |
| `IMAGE_VARIANT_MISSING` | 该变体没有 | 否 | — |
| `INVALID_IMAGE_VARIANT` | 变体名不是那三个 | 否 | — |
| `IMAGE_BYTES_REQUIRED` | 没有可存的内容 | 否 | — |
| `IMAGE_METADATA_UNREADABLE` | 副档读不懂（语法／版本） | 否 | **是** |
| `IMAGE_SESSION_NUMBER_UNREADABLE` | 会话图号副档或高水位读不懂 | 否 | — |
| `IMAGE_WRITE_FAILED` | 写盘失败 | **是** | — |
| `IMAGE_PROCESSING_FAILED` | 处理器报错 | **是** | — |
| `IMAGE_TRASH_REQUIRED` | 回收能力没递 | 否 | — |
| `IMAGE_REMOVE_FAILED` | 回收 / 改名失败 | **是** | — |
| `IMAGE_RESIDUE_PRESENT` | 有未完成的残留 | 否 | — |
| `INVALID_TABLE` | 不是收藏／分类 | 否 | — |

## 五、这份契约怎么被校验

`test/接口.js` 拿这份文档里写死的字段名去问实现：

| 校验 | 判据 |
|---|---|
| 图片操作与内部动作 | 动作清单必须恰好是十二个图片操作与四个维护/表动作 |
| 每个操作的返回字段名与出参**完全一致** | 逐字段比对，多一个少一个都算失败 |
| **对外参数里没有路径 / URL 字段** | 参数名不许匹配 `/path\|url\|地址\|路径/i` |
| 端口缺方法要抛错 | 方法清单按 `port.js` 的 `PORT_METHODS` 逐个查：少一个就装配失败 |
| 内存适配器与文件适配器给出相同结果 | 见 `test/run.js` 的 V-31 |
| 核心不 require fs / path | 静态扫描 `core.js` |

**改实现之前先改这份契约；改完契约，跑 `node test/接口.js`。**

## 接收方与写队列（2026-10-13）

`createImageModule({接收作用域?})` 可注入同步函数 `(规范化作用域) → {ok:true} | 失败信封`；提供时必须是函数。存动作在原写队列回调内、创建 staging 前执行它，失败原样返回且不产生实体；未提供不增加额外作用域所有者。独立宿主的会话接收规则拒绝不存在、读不懂或正在删除的目标。清空在同一原队列回调内列举并删除，包含排在它之前成功写入的图。
