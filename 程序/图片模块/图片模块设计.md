# 1. 范围

## 1.1 目的

规定图片模块的**职责边界、数据布局、接口契约、一致性与失败语义**，作为实现、评审与验收的依据。

## 1.2 范围内

图片的**存放与取回**：把字节按标识落到磁盘上的确定位置，并能在之后按标识取回字节、取回位置、列出、改名、删除。

## 1.3 范围外

| 不做 | 归谁 |
|---|---|
| 判断"哪几张图在对话里可见" | 对话模块 |
| 决定"哪张图该给识图" | 识图模块与展示层 |
| 决定界面怎么画 | 展示层 |
| 生成、编辑、识别图片内容 | 各能力模块 |
| 决定自己存在哪个根目录下 | 装配层 |
| 按语义检索图片（按 tag 找图） | 标签模块 + 展示层 |

## 1.4 读者

模块实现者、装配层接线者、评审者，以及依赖本模块契约的其他模块实现者。

# 2. 术语与约定

## 2.1 术语

| 术语 | 定义 | 不要与它混 |
|---|---|---|
| **存放地** | 条目归属的类别枚举：对话图片 / 图库 / 识图工作区。归属**编码在路径里** | 容器、命名空间 |
| **作用域** | 存放地 + 归属标识。对话图片的作用域标识是**会话 ID** | 路径 |
| **条目** | 一次落盘产生的一件实体 = **一个目录**，自包含 | 文件、记录 |
| **标识** | 对外出现的引用，本模块用**条目 ID**（`img_<…>`） | 地址、路径、序号 |
| **引用** | 模块之间传递的定位信息 = `{ 作用域, 条目ID }` | 标识 |
| **地址** | 文件系统上的位置 | 标识 |
| **变体** | 同一条目的三种规格：`original` / `preview` / `thumbnail` | 格式、编码 |
| **表** | 图库自己的归类数据（收藏 / 分类），只装条目 ID | 清单、索引 |
| **端口** | 核心要求存储层提供的方法集合 | 适配器 |

## 2.2 三层可见性

```
对外（模型 / 界面看到的参数）      →  标识
模块之间传递                     →  引用
模块内                          →  地址、条目 ID
```

**这条不是洁癖，有具体后果：如果模型能填地址，它就能读机器上任何文件。**

## 2.3 命名约定

| 场合 | 用 | 例 |
|---|---|---|
| 模块对外的**动作名** | 中文 | `列` / `存` / `删` / `清空` |
| **回执字段** | 中文 | `总数` / `已删` / `显示名` |
| 模块之间传的形状 | 英文键 | `引用` 的 `作用域` / `条目ID` |
| 失败理由 | `码: 人话` | `IMAGE_NOT_FOUND: 条目不存在` |

## 2.4 规范用语

| 词 | 含义 |
|---|---|
| **必须** | 不可协商。实现与评审按此判定符合性 |
| **禁止** | 出现即为缺陷 |
| **应当** | 偏离须给出理由并记录 |
| **可以** | 自由裁量 |

# 4. 设计约束

约束来自更高层的架构规则，本模块不得偏离。**违反即缺陷，不是取舍。**

| # | 约束 |
|---|---|
| C-1 | 对外参数中**禁止**出现地址、路径、URL |
| C-2 | 一个模块**只交出一份操作面**；不存在"A 面 / B 面" |
| C-3 | 换一个调用方不能改变行为：省略、过滤、包一层、靠调用顺序都**不算执行** |
| C-4 | **不解析不属于自己的东西**。要解析，说明字段定义放错了地方 |
| C-5 | 凡是"**必须和别处保持一致的清单**"都不该存在。它该被算出来，或根本不需要 |
| C-6 | **不做多级兜底来源**。`a \|\| b \|\| c` 找路径、找服务、找配置是缺陷 |
| C-7 | **依赖由装配层递入**。模块自己不找、不猜、不探测路径 |
| C-8 | **不做兼容层、不留回退开关**。要回退用 git |
| C-9 | **一处字段值只存一处**。同一份数据两处各存一份的表都不该存在 |
| C-10 | **出口一律给副本**，不给内部活对象 |

**C-5 与 C-9 派生出本模块最强的一条简化：不持有任何清单、索引或计数器。** 文件系统即权威，条目自包含，因此不存在"索引与本体不一致"这一整类缺陷。

# 5. 架构

## 5.1 上下文

```
        ┌──────────────── 门面层（对外的全部）────────────────┐
        │  工具：参数只收标识                                  │
        │  面板：渲染时向本模块要位置串                          │
        └───────────────────────┬──────────────────────────────┘
                                │ 引用
        ┌───────────────────────▼──────────────────────────────┐
        │                图片模块（本模块）                      │
        │ 列 · 取详情 · 取内容 · 取地址 · 存 · 改 · 删 · 清空     │
        └───────────────────────┬──────────────────────────────┘
                                │ 端口（12 个方法）
                  ┌─────────────┴─────────────┐
          adapter-file.js              adapter-memory.js
          （唯一碰盘的地方）             （不碰盘）
                                │
        ┌───────────────────────▼──────────────────────────────┐
        │ 装配层递入：根目录 · 图片处理器 · 交回收站 · 换标识/时间  │
        └──────────────────────────────────────────────────────┘

  识图模块 ◀── 一个能力组 { 清空 } + 一个只读文件夹路径
```

## 5.2 分解

| 内部部分 | 职责 | 对外 |
|---|---|---|
| `index.js` | 门面：动作表、直呼式、装配。**对外唯一入口** | **是** |
| `core.js` | 纯逻辑：作用域、副档、定位、图片操作、维护、表 | 否 |
| `port.js` | 端口契约、方法清单、三态约定 | 否 |
| `adapter-file.js` | 文件适配器：唯一 `require fs/path` 的地方 | 否 |
| `adapter-memory.js` | 内存适配器：证明核心不依赖盘 | 否 |

**核心不 `require fs` / `path`。** 它只说"在某个作用域下对某个名字做点什么"，由适配器翻成真实路径。

## 5.3 关键设计决定（一句话）

| # | 决定 | 消掉了什么 |
|---|---|---|
| 1 | 归属写在路径里 | 引用计数、孤儿清理 |
| 2 | 跨存放地**复制** | 引用表、"这张图还被谁用着" |
| 3 | 识图工作区是**单张槽位** | "建新的 → 删旧的 → 回滚"整块 |
| 4 | **无清单、无计数器、无索引** | 索引与本体不一致、修复、编号分配 |
| 5 | **没有复制 / 移动操作** | "搬运"这件事本身 —— 复制 = 取内容 + 存 |
| 6 | **枚举与筛选分开** | "为了列表快就得懂筛选"这条连锁 |
| 7 | **表只装 ID、且不是权威** | 表与条目之间的一致性维护 |

## 5.4 部署

单进程。写操作在同一条队列上串行。跨进程单写者由外部保证，本模块不加锁文件。

# 6. 功能需求

## 6.1 职责边界

| 编号 | 需求 |
|---|---|
| R-F-1 | 本模块**必须**只做一件事：图片的存放与取回 |
| R-F-2 | 本模块**禁止**认识对话、识图、AI、出图、提示词、标签——它不认识"图片是什么内容"，只认识"字节与位置" |
| R-F-3 | 本模块**禁止**做"该不该用这张图"这类判断，只回答"能不能取到" |
| R-F-4 | 本模块**禁止**提供"复制""移动"操作。跨存放地搬运由调用方以"取内容 + 存"两步完成（决策 3、11） |
| R-F-5 | 本模块**禁止**对内容做语义判断（不解析元数据含义、不做内容分级、不做相似度） |

## 6.2 三个存放地

| 编号 | 需求 |
|---|---|
| R-F-6 | 存放地**必须**是且仅是三个：`对话图片` / `图库` / `识图工作区`（决策 2） |
| R-F-7 | 存放地**必须**编码在路径里。由路径即可判定一张图属于哪个存放地（决策 4） |
| R-F-8 | 由此**禁止**实现引用计数，**禁止**实现孤儿清理 |
| R-F-9 | 跨存放地搬运**必须**表现为**复制**：源条目原样保留，目标产生新条目 |
| R-F-10 | 任何位置上的条目**禁止**出现"被另一处引用"的状态 |

**存亡归属**：每条规则对应一个用户能理解、能看见的操作。

| 存放地 | 谁决定它的存亡 | 对应的用户操作 |
|---|---|---|
| 对话图片 | 对话删了，图就删 | 「删除对话」 |
| 图库 | 只有用户显式删才删 | 「从图库删除」 |
| 识图工作区 | 下一张进来，上一张就删 | 「上传一张图去识图」 |

**跨存放地搬运的四种情形**（调用方怎么做）：

| 用户操作 | 调用方 | 结果 |
|---|---|---|
| 图库 → 对话 | 取内容（图库引用）→ 存（该对话） | 两份，各自独立——图库那份删了，对话那份还在 |
| 图库 / 对话 → 识图工作区 | 取内容（源引用）→ 清空工作区 → 存（工作区） | 多一个副本 |
| 对话 → 图库（「删除对话但保存图片」） | **逐张**取内容 → 存（图库）；之后清空该会话 | 图库那份留下 |
| 出图产出 | 存（**该对话**） | 跟这段对话走 |

## 6.3 识图工作区：单张槽位

**不是"只放一张的容器"，就是一个单张槽位**（决策 4）。

| 方面 | 规定 |
|---|---|
| 内容 | 当前那一张，**0 或 1 个条目** |
| 写入 | 上传那张就用那张。由本模块的 `存` 落盘 |
| 读 | 识图按装配层递入的**文件夹路径**读，**只读** |
| 换一张 | 旧的没了。由识图调能力组的 `清空`，再 `存` 新的 |

| 编号 | 需求 |
|---|---|
| R-F-11 | 识图工作区**必须**恒定保持 0 或 1 个条目 |
| R-F-12 | 槽位内已有条目时再写入，**必须**由写入方先删除旧条目；本模块**禁止**实现"替换 + 失败回滚" |
| R-F-13 | 识图工作区的图片**禁止**参与对话可见性，**禁止**作为标识出现在任何对外参数或模型可见输出中 |
| R-F-14 | `存` 收字节的四种形状：`Buffer` / `Uint8Array` / `data:<mime>;base64,<…>` 串 / 光秃秃的 base64 串，另收 `Buffer` 过一趟 JSON 之后那层包（`{ type:'Buffer', data:[…] }`）。**禁止**把不像内容的文本（例如一个路径）当字节写盘 |

> **编排归识图，执行归本模块**：识图决定何时换图；删除动作由本模块执行（决策 14）。

# 7. 数据设计

## 7.1 根目录

| 编号 | 需求 |
|---|---|
| R-D-1 | 根目录**必须**由装配层递入，**禁止**探测、**禁止**多级兜底（C-7、C-6） |
| R-D-2 | 根目录无效或为空时，**必须**构造即失败，报 `IMAGE_ROOT_REQUIRED`，**禁止**回退到默认路径 |
| R-D-3 | 本模块**禁止**写根目录以外的任何位置 |

## 7.2 物理布局

```
<根目录>/
├── session/<会话ID>/<条目ID>/     对话图片
├── gallery/
│   ├── <条目ID>/                  图库条目
│   ├── 收藏.json                  ["img_…", …]
│   └── 分类.json                  { 类ID: { 名, 配色?, 成员: [条目ID] } }
├── vision/<条目ID>/               识图工作区，恒 0 或 1 个
├── .staging/<条目ID>/             写入暂存区
└── .deleting/<批次>/<条目ID>/      待回收区
```

一个条目目录：

```
<条目ID>/
├── original.<ext>     原图
├── preview.<ext>      派生（处理器缺省时没有）
├── thumbnail.<ext>    派生（处理器缺省时没有）
└── meta.json          副档
```

| 编号 | 需求 |
|---|---|
| R-D-4 | 布局**必须**如上：`<根>/<存放地>/<作用域>/<条目ID>/`；图库与识图工作区无二级作用域 |
| R-D-4a | 作用域**必须**是且仅是三类：**对话**（存放地=对话图片，标识=会话 ID，**必填**）· **图库**（存放地=图库，无标识）· **识图工作区**（存放地=识图工作区，无标识） |
| R-D-5 | **禁止**图库与识图工作区出现清单文件、索引文件、计数器文件；会话作用域仅允许保存图号高水位，不记录图片成员 |
| R-D-6 | `.staging` / `.deleting` **禁止**出现在任何 `列` 的结果里 |
| R-D-7 | 条目目录**必须**自包含：目录存在且 `meta.json` 与至少 `original.*` 齐全，才算一个可读条目 |

## 7.3 路径语法与命名

```
条目目录名   = img_<…>                         /^img_[A-Za-z0-9-]+$/
变体文件名   = original|preview|thumbnail + '.' + 扩展名
元数据副档   = meta.json
会话作用域状态 = scope.json
作用域段     = 字母数字 . _ - 与汉字；不含分隔符
扩展名       = 由 mime 推；推不出取原文件名扩展名；再取不到用 bin
```

| 编号 | 需求 |
|---|---|
| R-D-8 | 所有路径段**必须**校验为安全段；`''`、`.`、`..`、含路径分隔符者**必须**拒绝，报 `INVALID_IMAGE_PATH` |
| R-D-9 | 对话作用域缺少会话 ID 时，**必须**落到固定占位段 `_`。**这是单一规则，不是多级兜底**（区别于 C-6）。图库与识图工作区没有作用域标识，**禁止**为它们虚构一个 |

## 7.4 标识与引用

```
标识（条目 ID）  img_<…>        对外出现的引用
引用（ref）      { 作用域, 条目ID }   只在模块之间流动
地址（address）  位置串           只给展示层渲染与模块之间
```

| 编号 | 需求 |
|---|---|
| R-D-10 | 条目 ID **必须**在写入时生成，**必须**全局唯一，**一经生成永不变更、永不复用** |
| R-D-11 | 会话图片的稳定图号由图片模块分配并持久化；展示方直接使用该图号，不另算会话图片顺序 |
| R-D-12 | 引用**必须**只由"作用域 + 条目 ID"构成 |
| R-D-13 | 地址**禁止**出现在任何对外参数、任何工具参数、任何模型可见输出中（C-1） |

## 7.5 副档

```jsonc
{
  "format": 1,                  // 整数版本
  "entryId": "img_…",
  "filename": "原名.png",        // 原始文件名
  "displayName": "显示名",        // 用户可改；空则取 filename
  "mime": "image/png",
  "extension": "png",
  "width": 0, "height": 0,
  "fileSize": 0,
  "checksum": "sha256:…",       // 记账用，不参与去重
  "source": "upload",           // upload | generation | copy | import …
  "metadata": {},               // 不透明袋子
  "variants": { "original": "original.png", "preview": "preview.png", "thumbnail": "thumbnail.png" },
  "sessionNumber": 1,            // 仅会话作用域有
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601"
}
```

| 编号 | 需求 |
|---|---|
| R-D-14 | `metadata` **必须**当作**不透明袋子**：本模块只整体存取，**禁止**解释、**禁止**做字段级合并 |
| R-D-15 | 副档**必须**自带整数 `format`；读不懂的版本**必须**报 `IMAGE_METADATA_UNREADABLE` 并**冻结该条目的写**（原文件保持不动；冻结只挡 `改`，`删` 照常 —— 决策 24）（决策 16） |
| R-D-16 | **禁止**按 `checksum` 去重。相同字节重复写入**必须**产生两个独立条目（决策 10） |
| R-D-17 | 清理文件名的规则**必须**唯一：剥掉路径成分、限长 180、空则取约定默认名 |

会话目录的 `scope.json` 只保存 `{format:1,highWater}`。每张会话图片的 `meta.json` 保存其 `sessionNumber`；写入队列先持久化递增的高水位，再提交图片目录。删除与清空不降低高水位，失败可以留下空号。首次列出会话图片时，模块按当前 `列` 顺序给没有 `sessionNumber` 的旧条目补号。图库与识图工作区不创建 `scope.json`。

## 7.6 变体

| 变体 | 语义 | 生成 |
|---|---|---|
| `original` | 存进来的原始字节，**一个字节不改** | 原样落盘 |
| `preview` | 显示用 | 处理器 |
| `thumbnail` | 列表用 | 处理器 |

| 编号 | 需求 |
|---|---|
| R-D-18 | 变体**必须**是且仅是这三个。**禁止**通用变换接口、**禁止**按需尺寸参数 |
| R-D-19 | `original` **必须**原样保存，**禁止**重编码、**禁止**加水印、**禁止**旋转 |
| R-D-20 | 处理器缺省时，**必须**仍然成功落盘，并在元数据中标记派生变体缺失 |
| R-D-21 | 变体缺失**必须**是可分辨的错误（`IMAGE_VARIANT_MISSING`），**禁止**静默回退到其它变体 |

## 7.7 不变量

| 编号 | 不变量 |
|---|---|
| INV-1 | 任一存放地下的条目目录名都是合法且唯一的条目 ID |
| INV-2 | 条目目录存在 ⇒ 其内应有 `meta.json` 与 `original.*`；缺任何一项则该条目**不完整**：仍出现在 `列` 里，但取缺失项报可分辨的错误 |
| INV-3 | `vision` 下的条目目录数 ∈ {0, 1} |
| INV-4 | 根目录下**不存在**清单/索引/计数器文件 |
| INV-5 | 任何时刻读到的条目只有三种状态：**完整 / 不存在 / 被明确标记为不完整** |
| INV-6 | 对外交出的引用里的条目 ID，要么可解析、要么明确报"不存在" |
| INV-7 | 表只描述自己那个作用域；**表里不出现任何别的作用域的事实** |
| INV-8 | 模块内**不存在任何跨会话的缓存文件** |

## 7.8 图库的表

图库的**收藏**与**分类**不进条目副档，另立"表"。

```
<根>/gallery/
├── 收藏.json                  ["img_7f3a…", "img_9c21…"]
├── 分类.json                  { "1": { 名, 配色?, 成员: [ID] } }
└── <条目ID>/                  条目目录
```

| 编号 | 需求 |
|---|---|
| R-G-1 | 收藏**必须**是一个**扁平的条目 ID 集合**（一个数组）。**禁止**给收藏做页、类或任何层级 |
| R-G-2 | 分类**必须**是一层：`分类.json` = `{ 类ID: { 名, 配色?, 成员: [条目ID] } }`。**禁止**页级、**禁止**计数器、**禁止**分片、**禁止**影子层 |
| R-G-3 | 表里**只能装条目 ID**（加分类自己的名字与配色）。**禁止**装路径、文件名、尺寸、来源、"被哪个对话引用"等任何**关于条目**的描述 |
| R-G-4 | 表**只描述图库作用域**。图库的表**禁止**记录会话区、识图工作区或任何对话的事实 |
| R-G-5 | 表与条目**并列存放**，**禁止**写进条目目录内部 |
| R-G-6 | **表不是权威**。删光全部表之后，图库仍然能列、能取、能用；**禁止**让条目的可读性依赖表 |
| R-G-7 | 表**整份读写**，**禁止**字段级合并；写入**必须**走原子写 |
| R-G-8 | 表里**允许**有指向已删条目的悬空 ID。消费方取不到条目就跳过；**禁止**把它当错误 |
| R-G-9 | **禁止**在建 / 删条目时自动改表。表只由用户的显式操作改（决策 20） |
| R-G-10 | 悬空 ID 由**内部维护操作**报告与清理，**禁止**自动级联清理 |
| R-G-11 | 图库**禁止**有"条目概要 / 清单 / 索引"这类**持久化缓存文件**。上千张的性能问题**用加载时机解决，不用机制解决**（§9.5） |

> **R-G-2 只做一层的理由**：分类只会有十几个；两层的架子比装的东西还多。判据：**分类数超过约 50 个时**才考虑引入页级。

# 8. 接口设计

字段名、类型、必填、约束的完整契约见 [接口.md](接口.md)。本章规定操作语义。

## 8.1 操作总览

**十二个图片操作 + 四个维护/表动作。**

| # | 操作 | 输入 | 输出 | 时序 |
|---|---|---|---|---|
| I-1 | **列** | 作用域 | 极简条目描述符列表 | 同步 |
| I-2 | **列会话图** | 会话作用域 | 含稳定图号与高水位的图片列表 | 异步 |
| I-3 | **按图号取详情** | 会话作用域 + 图号 | 完整条目描述符 | 异步 |
| I-4 | **导入会话图** | 会话作用域 + 原图号 + 字节 | 按原图号保存的描述符 | 异步 |
| I-5 | **恢复会话图号** | 会话作用域 + 高水位 | 持久化后的高水位 | 异步 |
| I-6 | **取详情** | 引用 | 完整条目描述符 | 同步 |
| I-7 | **取内容** | 引用 + 变体 | 字节 | 同步 |
| I-8 | **取地址** | 引用 + 变体 | 位置串 | 同步 |
| I-9 | **存** | 作用域 + 字节 + 文件名 + … | 完整条目描述符 | 异步 |
| I-10 | **改** | 引用 + 显示名 / 元数据 | 完整条目描述符 | 异步 |
| I-11 | **删** | 引用 | 删除回执 | 异步 |
| I-12 | **清空** | 作用域 | 删除回执 | 异步 |
| I-13 | 维护.报告 / 维护.清理 | — | 体检结果 | 同步 |
| I-14 | 表.收藏 / 表.分类 | 动作 + 标识 | 表内容 | 异步 |

**结果信封**：

```
成功  { ok: true,  data: … }
失败  { ok: false, reason: '<码>: <人话>', code: '<码>', details?: … }
```

**直呼式**（`图片.存(...)`）成功给数据、失败给 `null`；要拿理由用 `图片.run(动作, 参数)`。

## 8.2 操作契约

### I-1 列

| 项 | 规定 |
|---|---|
| 入 | `作用域` 必填 |
| 出 | `{ 条目: [{ 引用, 标识, 修改时间, 完整 }], 总数, 作用域 }` |
| 必做 | **只做一次目录读取，不读任何副档**（`完整` 只靠 stat 判断） |
| 顺序 | 按修改时间升序，同一时间按标识排 |
| 边界 | 两个临时位置**永不出现**；非条目名的目录**永不出现** |
| 失败 | 作用域非法 → `INVALID_SCOPE` |

### I-2 取详情

| 项 | 规定 |
|---|---|
| 入 | `引用` 必填 |
| 出 | 完整条目描述符（见 §7.5 全部字段 + `引用` `标识` `显示名` 等中文键） |
| 必做 | **只读它自己那一个副档**，禁止为了取一条扫全库 |
| 失败 | 条目不在 → `IMAGE_NOT_FOUND`；副档读不懂 → `IMAGE_METADATA_UNREADABLE`（**并冻结该条目的写：只挡 `改`**） |

### I-3 取内容

| 项 | 规定 |
|---|---|
| 入 | `引用` 必填 · `变体` 选填，默认 `original` |
| 出 | `{ 引用, 变体, 字节, mime, 文件名 }` |
| 必做 | 交**字节**。原图必须与存进去的一模一样 |
| 禁止 | **不许产 URL**；要 `data:` URL 谁自己编码 |
| 失败 | 条目不在 → `IMAGE_NOT_FOUND`；该变体没有 → `IMAGE_VARIANT_MISSING`；变体名不认 → `INVALID_IMAGE_VARIANT` |

### I-4 取地址

| 项 | 规定 |
|---|---|
| 入 | `引用` 必填 · `变体` 选填 |
| 出 | `{ 引用, 变体, 地址, mime, 文件名 }` |
| 必做 | 交出一个**能直接读**的位置串 |
| 用途 | **只给展示层渲染与模块之间**。不许进工具参数、不许进模型可见输出 |
| 失败 | 同 I-3 |

### I-5 存

| 项 | 规定 |
|---|---|
| 入 | `作用域` 必填 · `字节` 或 `dataUrl`（二选一）· `文件名` 必填 · `mime` / `来源` / `显示名` / `元数据` / `宽` / `高` 选填 |
| 出 | **完整条目描述符**（含显示名）——调用方可以直接并进自己的列表，不必再取详情 |
| 必做 | 顺序固定：建暂存目录 → 写原图 → 写派生变体 → 写副档 → **整目录改名上位** |
| 失败 | 字节为空 → `IMAGE_BYTES_REQUIRED`；写盘失败 → `IMAGE_WRITE_FAILED`；处理器报错 → `IMAGE_PROCESSING_FAILED` |
| 禁止 | **不许按字节去重**；**不许设条目尺寸上限** |

### I-6 改

| 项 | 规定 |
|---|---|
| 入 | `引用` 必填 · `显示名` / `元数据`（至少一项） |
| 出 | 更新后的条目描述符 |
| 必做 | **只改副档** |
| 改名语义 | "改名" = 只改 `显示名`。**磁盘上的文件名、目录名、条目 ID 一个字不动** |
| 元数据语义 | **整袋替换**，不是字段级合并 |
| 失败 | 两项都没给 → `INVALID_ARGUMENT`；副档读不懂 → `IMAGE_METADATA_UNREADABLE` |

### I-7 删

| 项 | 规定 |
|---|---|
| 入 | `引用` 必填 |
| 出 | `{ 已删, 已删除, 批次, 未回收, reason? }` |
| 必做 | 两步：① 改名进 `.deleting/<批次>/` ② 把**那个批次目录整个**交系统回收站 |
| 必做 | 改名一完成就算删掉了：`列` 立刻不再返回它 |
| 幂等 | 条目不存在 → `{ 已删: 0 }`，**不是失败** |
| 失败边界 | 回收没配 / 回收失败 → `未回收: true` + 可恢复位置。**不回滚** |

### I-8 清空

| 项 | 规定 |
|---|---|
| 入 | `作用域` 必填 |
| 出 | 同 I-7 |
| 必做 | 删该作用域下**全部**条目 |
| 禁止 | **禁止假装原子**：部分失败时给 `{ ok:false, code:'IMAGE_REMOVE_FAILED', details:{ 已删, 卡在, 批次 } }` |

### I-9 维护（内部）

| 动作 | 出 |
|---|---|
| `报告` | `{ 暂存残留, 待回收残留, 临时文件, 不完整条目, 读不懂的副档, 悬空标识 }`。**不改任何文件** |
| `清理` | `{ 已清理, 报告 }`。清三样：`.staging` 残留、适配器临时文件、表里的悬空标识。**不碰 `.deleting`** |

### I-10 表（内部）

| 动作 | 出 |
|---|---|
| 表.收藏 `读`/`加`/`去` | 条目 ID 数组 |
| 表.分类 `读`/`建类`/`删类`/`加成员`/`去成员` | 字典或类 |

## 8.3 对外禁令（符合性检验用）

| 编号 | 禁止 |
|---|---|
| R-I-1 | 失败**必须**如实报告（`ok:false` + 可分辨的 `code`）；**禁止**抛异常穿透调用方，**禁止**以 `null`/空值表示失败 |
| R-I-2 | 查询类操作**可以**同步返回；写入类操作**必须**返回可等待的结果 |
| R-I-3 | 所有输入**必须**以对象传入；**禁止**位置参数 |
| R-I-4 | 工具声明（`parameters`）中**禁止**出现地址/路径/URL 类字段（C-1 的检验法：看声明里有没有） |
| R-I-5 | 返回给模型的字段中**禁止**含物理路径、`file://` 地址或磁盘布局信息 |
| R-I-6 | **禁止**为只读消费者开一个"只读面"（决策 12）。共用同一份操作面，权限判断在门面层 |
| R-I-7 | **禁止**从本模块导出内部构造器（存储引擎、路径工具、回收站句柄）给调用方使用 |
| R-I-8 | **禁止**在本模块内部做筛选、检索与分页。`列` 只枚举（I-1）；返回顺序是确定的（按修改时间、再按标识），但**禁止**接受排序参数 |
| R-I-9 | 凡**作用于当前对话**的动作，其对外参数中**禁止**出现会话 ID——目标由执行层填。**用户发起的"发送到某个对话"是另一回事**：那是用户在图库面板上显式选的，参数应当显式给 |

## 8.4 典型调用序列

```
① 上传一张图进当前对话
   门面：存({ 存放地:'session', 会话ID:'A' }) → 把返回的标识交给对话模块登记

② 从图库挑一张放进对话（复制）
   门面：取内容(图库引用) → 存({ 存放地:'session', 会话ID:'A' }) → 登记

③ 删除对话但保留图片
   门面：逐张 取内容(对话引用) → 存({ 存放地:'gallery' })；然后 清空(该会话)

④ 用一张图去识图
   门面：取内容(源引用) → 存({ 存放地:'vision' })      ← 覆盖前由识图调「能力组.清空」
   识图：清空()；读固定文件夹里的那一张 → 识别           ← 不取地址、不取引用、不写
```

## 8.5 装配接口

```js
createImageModule({ 根目录 | port, 处理图片?, 交回收站?, 校验和?, 新标识?, 现在? })
  → { 图片操作 + 维护 + 表 + 工作区能力 + actions + describe + ERR + 存放地 + 变体 }
```

**`维护` 与 `表` 一律返回 Promise**（它们走同一条写队列）；直呼式给数据，失败给 `null`。

| 编号 | 需求 |
|---|---|
| R-P-1 | 装配层**必须**递入根目录（或端口）；`处理图片` 与 `交回收站` **可以**缺省 |
| R-P-2 | 模块**禁止**从环境、注册表、用户目录等任何地方自行推导路径（C-7） |
| R-P-3 | 依赖**必须**以**函数**形式递入，**禁止**以模块名或服务名引用 |

**缺省后果**：

| 依赖 | 缺省时 |
|---|---|
| 根目录 / 端口 | **构造即抛错** |
| 处理图片 | 只落原图；取派生变体报 `IMAGE_VARIANT_MISSING` |
| 交回收站 | 条目仍移出可见范围，停在 `.deleting/`，标 `未回收: true` |
| 校验和 | 副档里 `checksum` 为空串（本模块从不去重） |

### 8.5.1 识图工作区的能力组

```js
const 工作区 = 图片.工作区能力();   // Object.freeze({ 清空 })
```

| 编号 | 需求 |
|---|---|
| R-P-4 | 能力组**只给一个操作**：`清空`（决策 19） |
| R-P-5 | 识图**禁止**拿到工作区的绝对路径用于删除或写入；它只用那个路径**读**，且**只读**（决策 19） |
| R-P-6 | 能力组**由本模块交出**（`工作区能力()`），装配层把它递给识图。交出的只有那一个函数，**禁止**连核心或适配器一起给出去；本模块**禁止**认识"识图"这个名字 |
| R-P-7 | 识图**禁止** `require` 本模块的任何文件。要错误形状，由装配层递，或它自己定 |

# 9. 横切关注点

## 9.1 原子性与一致性

| 编号 | 需求 |
|---|---|
| R-X-1 | 条目写入**必须**是"先写暂存目录 → 再原子改名上位"，**禁止**就地逐文件写 |
| R-X-2 | 任何时刻读到的条目只有三种状态：完整 / 不存在 / 被明确标记为不完整（INV-5）。**禁止**"写了一半"的条目以正常面目被读到 |
| R-X-3 | 条目**必须**自包含 ⇒ **禁止**跨条目事务、**禁止**两阶段提交 |

**写入顺序**

```
① 建 <根>/.staging/<条目ID>/
② 写原图字节
③ 调处理器 → 写 preview / thumbnail   （缺省则跳过；处理器报错则整体失败）
④ 写 meta.json
⑤ 整目录改名：.staging/<条目ID> → <存放地>/[<作用域>/]<条目ID>
⑥ 失败：删掉暂存目录，报明细
```

## 9.2 删除

| 编号 | 需求 |
|---|---|
| R-X-4 | 删除**必须**是**两步**：① 把条目目录原子改名进 `<根>/.deleting/<批次>/<条目ID>` ② 把**那个批次目录**整个交给系统回收站。**禁止**就地递归删除。**每一批删除必须有自己的批次名** |
| R-X-5 | 回收失败时**必须**如实报告并交回可恢复的位置，**禁止**静默丢弃 |
| R-X-5a | 删除**禁止**有第二步状态的翻盘：改名成功即视为"已移出可见范围"，此后不再回滚目录 |
| R-X-5b | **改名一完成，该条目就算删掉了**：`列` 立刻不再返回它 |
| R-X-5c | 批量删除**禁止**假装是原子的：**必须**如实报告"已删几个 + 卡在哪个引用上" |

## 9.3 并发

| 编号 | 需求 |
|---|---|
| R-X-6 | 同一进程内，写操作**必须**串行（单一写队列） |
| R-X-7 | 读操作**可以**与写操作并发，但**禁止**读到未上位的暂存条目 |
| R-X-8 | 跨进程的互斥**禁止**由本模块实现（不加锁文件）；**必须**由外部以单实例机制保证 |
| R-X-9 | `清空` 与 `存` 并发时，结果**必须**对应某个确定的串行顺序，**禁止**出现"清空后仍有残留" |

## 9.4 临时空间与残留

| 编号 | 需求 |
|---|---|
| R-X-10 | 启动时**禁止**自动删除 `.staging` / `.deleting` 残留 |
| R-X-11 | 残留**必须**可被观察（`列` 不返回，但 `维护.报告` 必须列出），且只由**显式操作**清理 |
| R-X-12 | 判断"有没有残留"**必须**按两个固定的暂存目录名判定；**禁止**引入第三处临时位置 |

## 9.5 性能

**规模前提按存放地分开：**

| 存放地 | 量级 |
|---|---|
| 会话区 | 几十张 |
| 识图工作区 | 恒 0 或 1 张 |
| 图库 | 只增不减，可能到上千张 |

**实测基线**（1000 个条目，本地盘）：

| 操作 | 耗时 |
|---|---|
| 只枚举目录名 | **14 ms** |
| 逐条读 + 解析 `meta.json` | **383 ms** |

**枚举便宜，读副档才是钱。** 所以优化只有一个方向：少读副档。

| 编号 | 需求 |
|---|---|
| R-X-17 | `列` 的代价**必须**与该作用域的条目总数同阶，且**禁止**随根目录下其他作用域的大小增长 |
| R-X-18 | `列` **禁止**读任何副档。它与条目数的关系就是**一次目录读取** |
| R-X-19 | 单条 `取详情` **必须**只读它自己那一个副档，**禁止**为了取一条而扫全库 |
| R-X-20 | **禁止**用持久化缓存 / 索引 / 清单来解决规模问题 |
| R-X-21 | 会话区与识图工作区**禁止**引入任何缓存或索引 |
| R-X-22 | 本模块**禁止**在构造时或启动时主动枚举任何作用域。它**没有**"预热"这个动作 |
| R-X-23 | **什么时候加载**由调用方决定；本模块只保证**"叫它才做"** |
| R-X-24 | 展示层**应当**只向本模块要**当前可见的那些条目**的详情，**禁止**一次性为全库调 N 次 `取详情` |
| R-X-25 | 调用方**可以**在调用方一侧做会话内缓存；**禁止**把它落盘成第二份真相 |
| R-X-26 | **新存的条目下一次 `列` 必须看得见**，且调用方**不必**做任何"让缓存失效"的动作 |
| R-X-27 | `存` **必须**返回完整的条目描述符（含显示名）。调用方**可以**直接把它并进自己的列表 |

## 9.6 安全

| 编号 | 需求 |
|---|---|
| R-X-13 | 所有进入路径的字符串**必须**经过安全段校验（R-D-8） |

## 10.1 错误码

| 码 | 触发 | 可重试 | 冻结写 |
|---|---|---|---|
| `IMAGE_ROOT_REQUIRED` | 根目录无效或没递 | 否 | — |

| `INVALID_IMAGE_PATH` | 名字里有危险段 | 否 | — |
| `INVALID_ARGUMENT` | 该给的没给 / 形状不对 | 否 | — |
| `IMAGE_NOT_FOUND` | 条目不存在 | 否 | — |
| `IMAGE_VARIANT_MISSING` | 该变体没有 | 否 | — |
| `INVALID_IMAGE_VARIANT` | 变体名不是那三个 | 否 | — |
| `IMAGE_BYTES_REQUIRED` | 没有可存的内容 | 否 | — |
| `IMAGE_METADATA_UNREADABLE` | 副档读不懂（语法／版本） | 否 | **是** |
| `IMAGE_SESSION_NUMBER_UNREADABLE` | 会话图号副档或高水位读不懂 | 否 | — |

| `IMAGE_PROCESSING_FAILED` | 处理器报错 | **是** | — |
| `IMAGE_TRASH_REQUIRED` | 回收能力没递 | 否 | — |
| `IMAGE_REMOVE_FAILED` | 回收 / 改名失败 | **是** | — |

## 10.2 处理原则

| 编号 | 需求 |
|---|---|
| R-E-1 | 失败原因**必须**可分辨：**禁止**只回一个 `false`，**禁止**把"读不懂"与"确实没有"混成一个 |
| R-E-2 | **禁止**用默认值掩盖失败。取不到就报取不到，**禁止**回退到另一个来源（C-6） |
| R-E-3 | 调用方**必须**检查结果信封。这是契约的一部分，不是建议 |
| R-E-4 | **处理器缺省与处理器报错是两回事**：缺省 → 降级，原图照常上位、派生变体标记为缺；报错 → **禁止**上位，报 `IMAGE_PROCESSING_FAILED` |
| R-E-5 | 原子上位点之前失败 ⇒ **禁止**留下可被 `列` 看到的半成品 |
| R-E-6 | 条目不存在与"已经不存在"**必须**给同一个结论（删一个不存在的条目 = "未删除"，不是失败）。**代价是分不清"本来就没有"和"东西没了"**——这是有意的 |
