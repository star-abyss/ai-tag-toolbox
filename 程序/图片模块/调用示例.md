# 图片模块 · 对外接口

> 只写**怎么调**与**会得到什么**。设计理由见 [图片模块设计.md](图片模块设计.md)。
>
> **读同步、写可等待**：读的四个动作直接给结果；写的动作返回 Promise，要 `await`。
> **失败一律 `{ ok:false, reason }`**，`reason` 的写法是 `码: 人话` —— 码给程序分辨，话给人看。
> 直呼式（`图片.存(...)`）成功给数据、失败给 `null`；要拿理由就用 `图片.run(动作, 参数)`。

---

## 一、装配

```js
const { createImageModule } = require('./图片模块/index.js');

const 图片 = createImageModule({
  // 二选一：给端口，或给位置（给了位置就自动装文件适配器）
  根目录: '<userData>/image-data',
  // port: 我自己的适配器,

  处理图片: (字节, { preview, thumbnail }) => ({
    preview:   { 字节, mime },
    thumbnail: { 字节, mime },
  }),
  交回收站: (绝对路径) => shell.trashItem(绝对路径),   // 递不进来就没有删除能力
  校验和: (字节) => `sha256:…`,                       // 可选，只记账，不参与去重
  新标识: () => 'img_…',                              // 可选，测试用
  现在: () => new Date().toISOString(),               // 可选，测试用
});
```

没有根目录也没有端口 → **抛错**。端口缺方法 → **抛错**。装配阶段可以抛，其余一律不抛。

## 二、图片操作

### 1. 列

```js
图片.列({ 作用域: { 存放地: 'gallery' } })
// → { 条目: [ { 引用, 标识, 修改时间 } ], 总数, 作用域 }
```

**只做一次目录读取，不读任何副档。** 所以副档丢了它照样列得出来 ——
要详情就拿去 `取详情`。这里**没有**查询串、排序、分页：筛选与排序归面板。

### 2. 取详情

```js
图片.取详情({ 引用 })
// → { 引用, 标识, 文件名, 显示名, mime, 宽, 高, 字节数, 校验和, 来源, 元数据, 变体, 创建时间, 更新时间 }
```

### 3. 取内容

```js
图片.取内容({ 引用, 变体: 'original' })   // 变体默认 original
// → { 引用, 变体, 字节, mime, 文件名 }
```

**不产 URL。** 谁要 `data:` URL，谁自己把字节编码。

### 列出并按号读取会话图片

```js
const 会话图 = await 图片.列会话图({ 作用域: { 存放地: 'session', 会话ID: 'A' } });
// → { 条目:[{ 标识, 图号, 引用, … }], 总数, 作用域 }
const 图1 = await 图片.按图号取详情({ 作用域: { 存放地: 'session', 会话ID: 'A' }, 图号: 1 });
```

第一次 `列会话图` 会给这个旧会话里尚无图号的图片补号；调用后会话里的图号稳定，删除与清空不重排，也不复用已经占用的号码。

### 4. 取地址

```js
图片.取地址({ 引用, 变体: 'thumbnail' })
// → { 引用, 变体, 地址, mime, 文件名 }     地址是物理绝对路径
```

**只给界面面板渲染与模块之间。** 不许进工具参数、不许进模型可见输出。

### 5. 存

```js
await 图片.存({
  作用域: { 存放地: 'session', 会话ID: 'A' },
  字节,                      // Buffer；或给 dataUrl
  文件名: 'a.png',
  mime: 'image/png',         // 不填就从文件名推
  来源: 'upload',            // upload | generation | copy | import …
  显示名: '我的图',           // 不填取文件名
  元数据: { … },             // 不透明袋子，本模块只整体存取
  宽: 768, 高: 1024,         // 可选，原样记账
});
// → 完整的条目描述符（含显示名）—— 调用方可以直接并进自己的列表，不必再取详情
```

无论图从哪来，**只有这一条写入路径**。顺序是：暂存目录 → 原图 → 派生变体 → 副档 → **整目录原子改名上位**。
上位之前失败，`列` 看不到任何半成品。

### 6. 改

```js
await 图片.改({ 引用, 显示名: '新名字' });
await 图片.改({ 引用, 元数据: { … } });     // **整袋替换**，不是字段级合并
// → 更新后的条目描述符
```

- 改名 = **只改 `displayName`**；磁盘上的文件名、目录名、条目 ID 一个字不动。
- 两项至少要给一项，空调用报 `INVALID_ARGUMENT`。

### 7. 删

```js
await 图片.删({ 引用 });
// → { 已删: 1, 已删除: [引用], 批次, 未回收: false }
```

条目**不存在**时给 `{ 已删: 0 }`，**不是失败**（幂等）。
回收站没配或回收失败 → `未回收: true` 并在 `reason` 里给可恢复的位置。**不回滚。**

### 8. 清空

```js
await 图片.清空({ 作用域: { 存放地: 'session', 会话ID: 'A' } });
// → { 已删, 已删除: [引用…], 批次, 未回收 }
```

「删除对话」= 清空该会话；「清空图库」= 清空图库。
**部分失败会如实报**：失败时 `details` 里给 `{ 已删, 卡在, 批次 }`。

## 三、给识图模块的：工作区能力

```js
const 工作区 = 图片.工作区能力();   // Object.freeze({ 清空 })
await 工作区.清空();                // 换图前把工作区腾空
```

**只有一个函数。** 工作区恒为 0 或 1 张，识图不需要"挑着删"。
识图拿到的只是这几个函数 —— 它既不知道本模块的名字，也拿不到任何路径去删。

## 四、内部：维护与表（不进工具清单）

### 维护

```js
图片.维护({ 动作: '报告' });
// → { 暂存残留, 待回收残留, 不完整条目, 读不懂的副档, 悬空标识, reason? }

图片.维护({ 动作: '清理' });     // 只清 .staging；**不碰 .deleting**（那可能是唯一副本）
// → { 已清理, 报告 }
```

`报告` **不改任何文件**。残留只由显式调用清理，启动时绝不自动删。

### 表（只给图库）

```js
// 收藏：一个扁平的条目 ID 集合，不分页不分层
await 图片.表({ 表: '收藏', 动作: '读' });                    // → ["img_…", …]
await 图片.表({ 表: '收藏', 动作: '加', 标识 });              // → 新集合
await 图片.表({ 表: '收藏', 动作: '去', 标识 });              // → 新集合

// 分类：只有一层
await 图片.表({ 表: '分类', 动作: '读' });                    // → { 类ID: { 名, 配色?, 成员 } }
await 图片.表({ 表: '分类', 动作: '建类', 名: '人物' });        // → 新类
await 图片.表({ 表: '分类', 动作: '删类', 类: 类ID });
await 图片.表({ 表: '分类', 动作: '加成员', 类: 类ID, 标识 });
await 图片.表({ 表: '分类', 动作: '去成员', 类: 类ID, 标识 });
```

三条硬规矩：**表里只装条目 ID**；**表不是权威**（删光表图库照样能列能取）；
**建 / 删条目不会自动改表**（系统不给删除擦屁股，悬空 ID 由维护报告列出）。

## 五、动作清单（给门面层用）

```js
图片.actions;    // 含列会话图与按图号取详情
图片.describe(); // [{ 动作, 摘要, 参数, 说明 }, …]
```

**模型侧与界面侧读的是同一份**，不写第二遍。给模型看的那几条从这份里挑，
挑的时候看**参数名**里有没有路径类字样 —— 有就是缺陷。

## 六、错误表

| 码 | 什么时候 | 可重试 | 给人的意思 |
|---|---|---|---|
| `IMAGE_ROOT_REQUIRED` | 根目录无效或没递 | 否 | 图片功能不可用（**装配时抛错**） |
| `INVALID_SCOPE` | 作用域不是那三类 | 否 | 参数问题 |
| `INVALID_IMAGE_PATH` | 名字里有危险段（`..`、分隔符、空） | 否 | 参数问题 |
| `INVALID_ARGUMENT` | 该给的没给、给错了形状 | 否 | 参数问题 |
| `IMAGE_NOT_FOUND` | 条目不存在 | 否 | 图已经不在了 |
| `IMAGE_VARIANT_MISSING` | 该变体没有（没处理器／文件掉了） | 否 | 该规格的图不存在 |
| `INVALID_IMAGE_VARIANT` | 变体名不是那三个 | 否 | 参数问题 |
| `IMAGE_BYTES_REQUIRED` | 没有可存的内容 | 否 | 空 |
| `IMAGE_METADATA_UNREADABLE` | 副档读不懂（语法／版本） | 否 | 该图读不出来，**其写被冻结**（只挡 `改`；`删` 照常） |
| `IMAGE_WRITE_FAILED` | 写盘失败 | **是** | 没存下来 |
| `IMAGE_PROCESSING_FAILED` | 处理器报错 | **是** | 派生图没生成，条目**没上位** |
| `IMAGE_TRASH_REQUIRED` | 回收能力没递 | 否 | 条目已移出可见范围，文件在 `.deleting/` |
| `IMAGE_REMOVE_FAILED` | 回收失败／改名失败 | **是** | 没删干净，`details` 里给卡在哪 |
| `IMAGE_RESIDUE_PRESENT` | 有未完成操作的残留 | 否 | 需要先处理残留 |
| `INVALID_TABLE` | 不是收藏／分类 | 否 | 参数问题 |

一句话：**能分辨才叫失败。** 返回 `false` 而不说为什么，等于没报。

## 七、三条最容易踩的

1. **写操作忘了 `await`** —— `存`/`改`/`删`/`清空`/`表` 都返回 Promise。
   直呼式忘了 await 会拿到 `null`，看着像"存失败"，其实只是没等。
2. **以为 `列` 会给显示名** —— 它只给 `{ 引用, 标识, 修改时间 }`。
   显示名在 `取详情` 里。这是刻意的：上千张时逐条读副档要 383 ms，枚举只要 14 ms。
3. **以为删了就能原地找回** —— 改名一完成条目就算没了；回收站失败时文件停在
   `.deleting/<批次>/` 里，要恢复得自己从那儿拿。
