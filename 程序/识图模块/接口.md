# 识图模块 · 接口

> **这是契约。改实现之前先改它；改完跑 `node test/run.js`。**
> 设计理由在 [识图模块设计.md](识图模块设计.md)；上手指南在 [README.md](README.md)。

**一句话**：**一张图进来，要么本地模型给它打标，要么把图里藏着的提示词读出来，要么交给模型看。**

**几条路是分开的**（用户自己挑）：

| 路 | 什么时候用 | 要不要模型 |
|---|---|---|
| `读元数据` | 图是 AI 画的，PNG 里就藏着提示词与工作流 | **不要**，纯解析 |
| `认图` | 想要"这张图画了什么"，离线也要能用 | 要**本地**打标模型 |
| `看图` | 本地打标不够细，或要一段描述 | 要**一条能看图的链路** |

---

## 一、对外操作

### 1.0 被多个操作共用的形状

```
引用 = { 作用域 必作用域, 条目ID 必串 }     作用域形状见 图片模块/接口.md

**引用参数是扁平的**（存放地 / 条目ID / 会话ID）：
   存放地  必串   session / gallery / vision
   条目ID  必串   img_…
   会话ID  选串   只在 存放地 是 session 时给；不给算占位段 _

`读元数据` 另可接原始 PNG 字节；参数里不出现文件路径或地址。

标签 = {
  词      必串    模型给的英文词（标签圈的写法）
  中文名  必串|null  库里的中文名；没给查词或库里没有 = null
  概率    必数|null  0~1，四位小数
  分类号  必数
  分类    必串    普通 / 画师 / 作品 / 角色 / 元数据 / 分级
}
```

**约束（不是建议）：**

| # | 约束 | 违反时 |
|---|---|---|
| 1 | 引用参数是扁平标识；只有 `读元数据.字节` 接收原始图片字节。**不许出现文件路径 / 地址** | 缺陷，不是错误码 |
| 4 | 也认已经收好的 `{ 作用域, 条目ID }`（界面与别的模块这么给） | —— |
| 2 | 位图从哪来是装配层的事：本模块只说"把这张图给我" | —— |
| 3 | 阈值与上限都只是"这次怎么筛"，缺省有缺省的样子 | —— |

### 1.1 `认图`（本地打标）

```
入  { 存放地 必, 条目ID 必, 会话ID 选, 阈值 选, 上限 选 }
出  { ok:true, data:{ 引用, 标签 数组, 总数, 阈值, 尺寸, 模型 } }
```

| 项 | 规定 |
|---|---|
| 必做 | 取字节 → 交给本地打标引擎 → 过阈值 → 按概率从高到低排 → 配中文名 |
| 阈值 | 给了就用给的（只认 0~1 的数）；没给用**模型自带的**；都没有用 `0.35` |
| `上限` | 给了就只要前几个；没给全要 |
| 中文名 | 有查词就配，查不到给 `null`；**没给查词一律 `null`**（形状稳定） |
| 查词抛错 | 不带崩整件事：中文名全给 `null`，标签照给 |
| 异步 | 是（要跑模型） |
| 失败 | `VISION_BAD_REF` · `VISION_NO_BYTES` · `VISION_NO_ENGINE` · `VISION_ENGINE_FAILED` |

### 1.2 `读元数据`

```
入  { 存放地 选, 条目ID 选, 会话ID 选, 字节 选 }
出  { ok:true, data:{ 引用|null, 有, 提示词, 负向提示词, 工作流, 参数, 全部, 尺寸 } }
```

| 项 | 规定 |
|---|---|
| 输入来源 | 给 `字节` 时直接解析；没给时按 `存放地 / 条目ID / 会话ID` 经 `取图字节` 取图 |
| 字节 | PNG 原始字节；经 JSON 调用时为整数数组 |
| 必做 | 只读 PNG 的 `tEXt` / `iTXt` / `zTXt` 块；**不解析 EXIF** |
| 正负向 | 识别 `parameters` 中的 `Negative prompt:`；识别 ComfyUI `prompt` API graph 与 `workflow` 节点图时，沿采样器的正 / 负连接提取文本 |
| 原始字段 | `全部` 保留 PNG 文字块原文；`工作流` 保留 `workflow` 原文；未知 JSON 图不会作为提示词返回 |
| `有` | 有没有读到任何文字块 |
| 不是 PNG | `VISION_BAD_METADATA`（不抛错） |
| 没给这一支 | 同样 `VISION_BAD_METADATA`——不静默给空 |

### 1.3 `看图`

```
入  { 存放地 必, 条目ID 必, 会话ID 选, 提示 选串, 参考标签 选数组 }
出  { ok:true, data:{ 引用, 标签, 描述, 模型, 用量 } }
```

| 项 | 规定 |
|---|---|
| 必做 | 取字节 → 连提示与参考标签一起交给递进来的看图函数 |
| `参考标签` | 通常就是 `认图` 出来的那批，给模型当参考；不给也行 |
| 回来的标签 | 也配中文名（与 `认图` 同一套） |
| 失败 | `VISION_NO_VIEWER` · `VISION_VIEW_FAILED`（理由里带链路报的原话） |

### 1.4 `看模型`

```
出  { ok:true, data:{ 可用, 缺, 能本地打标, 能读元数据, 能看图, 有查词, 模型 } }
```

**它只报端口齐不齐**，不探盘上有没有模型文件——"有没有"是装配层与界面的事。

### 1.5 直呼与动作表

| 门面成员 | 说明 |
|---|---|
| `认图({ 存放地, 条目ID, 阈值? })` | 回执本身（异步） |
| `标签({ 存放地, 条目ID, 阈值? })` | 只要标签数组；失败给 `[]` |
| `读元数据({ 存放地, 条目ID })` · `看图({ 存放地, 条目ID, 提示? })` | 回执本身 |
| `run(动作, 参数)` · `actions` · `describe()` | 走动作表 / 动作名（冻住）/ 清单 |
| `ERR` · `SAY` · `分类名` · `端口` | 都冻住 |

**出口冻住**：不递 `core` / `port` / 适配器。

## 二、端口（装配层递什么进来）

| 名 | 形状 | 必给 | 不给会怎样 |
|---|---|---|---|
| `取图字节` | `(引用) → { 字节, mime? }`（引用是模块收好之后的对象） | 按引用读图时 | 无此端口时引用输入报 `VISION_NO_BYTES`；若提供 `读元数据` 端口，可省略 |
| `查词` | `(词列表) → 中文名 或 null 的数组` | 否 | 中文名一律 `null` |
| `tagger` | `{ 打标(字节, {阈值,上限}) → { 标签, 尺寸? } }` | 否 | `认图` 报 `VISION_NO_ENGINE` |
| `看图` | `({ 字节, mime, 提示, 参考标签 }) → { 标签, 描述, 模型?, 用量? }` | 否 | `看图` 报 `VISION_NO_VIEWER` |
| `读元数据` | `(字节) → { 提示词, … }` | 否 | `读元数据` 报 `VISION_BAD_METADATA` |
| `引擎` | `{ id, 名字, 阈值 }` | 否 | 阈值退回 `0.35`，"看模型"不报模型名 |

直接传 `读元数据({ 字节 })` 只需要 `读元数据` 端口；`认图`、`看图` 与按引用读元数据仍需要 `取图字节`。

## 三、错误码

| 码 | 什么时候 |
|---|---|
| `VISION_BAD_REF` | 存放地 缺了 / 不在那三个里，或 条目ID 是空的 |
| `VISION_NO_BYTES` | 取不到字节（图不在、取图那一支抛错、没给取图端口） |
| `VISION_NO_ENGINE` | 要用本地打标而没递进来 |
| `VISION_ENGINE_FAILED` | 打标引擎抛错 |
| `VISION_NO_VIEWER` | 要用看图而没递进来 |
| `VISION_VIEW_FAILED` | 看图那条链路抛错 |
| `VISION_BAD_METADATA` | 不是 PNG / 没给读元数据那一支 |
| `VISION_BAD_ARGUMENT` | 动作名不对，或动作自己抛错 |
