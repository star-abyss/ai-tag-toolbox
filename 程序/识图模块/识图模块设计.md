# 识图模块 · 设计规范

> **自包含。** 不引用别的模块的设计。三层结构与边界规则在根 [AGENTS.md](../../AGENTS.md)。
> 上手指南在 [README.md](README.md)；字段名与错误码在 [接口.md](接口.md)。

**一句话**：**一张图进来，要么本地模型给它打标，要么把图里藏着的提示词读出来，要么交给模型看。**

---

## 一、范围

### 1.1 它做

| # | 做什么 |
|---|---|
| 1 | `认图`：把图交给递进来的本地打标引擎，过阈值、按概率排、配中文名 |
| 2 | `读元数据`：读 PNG 的文字块，抠出提示词 / 负向 / 工作流 / 参数 |
| 3 | `看图`：把图、提示、参考标签交给递进来的看图函数，收标签与描述 |
| 4 | `看模型`：只说端口齐不齐（不探盘） |

### 1.2 它不做

| 不做 | 归谁 |
|---|---|
| 不认识模型文件、不读盘、不探测路径 | 打标引擎（装配层递进来） |
| 不认识标签库、不解析它的字段 | 查词函数（标签模块的 `认词`） |
| 不认识 AI 链路（发请求 / 选模型 / 密钥 / 重试） | 看图函数（装配层用调度造） |
| 不解析 EXIF | 等有需要再加 |
| 不编译图、不做缩放 / 归一化 | 打标引擎那一层（它知道模型要什么形状） |
| 不决定"该走哪条路" | 调用方（模型或界面） |
| 不落盘、不保存任何东西 | 无存储 |

### 1.3 为什么三条路是分开的

| 路 | 要什么 | 什么时候用 |
|---|---|---|
| `读元数据` | 什么都不要（纯解析） | 图是 AI 画的：提示词本来就在文件里，**比任何模型都准** |
| `认图` | 本地模型 | 离线也要能用；要"这张图画了什么" |
| `看图` | 一条能看图的链路 | 要描述、要更细的判断，或本地模型拿不准 |

**合成一个动作再给个模式参数是不行的**：三样的输入不一样（元数据不要模型、看图要提示），
失败表现也不一样（一个是"文件里没有"、一个是"模型没装"、一个是"链路不通"）。
**拆成三个动作，调用方一眼看得出自己要走哪条。**

## 二、术语

| 词 | 意思 |
|---|---|
| **引用** | `{ 作用域, 条目ID }`，与图片模块同一套 |
| **字节** | 图片的原始字节；本模块只搬不解析（元数据那条除外） |
| **标签** | `{ 词, 中文名, 概率, 分类号, 分类 }` |
| **打标引擎** | 递进来的 `{ 打标(字节, 选项) }`，里面是 ONNX 会话与预处理 |
| **看图函数** | 递进来的 `({ 字节, mime, 提示, 参考标签 })`，里面是 AI 链路 |
| **阈值** | 概率过这一条线才算一个标签 |

---

## 三、约束

| # | 约束 |
|---|---|
| 1 | 对外参数只有 引用 / 阈值 / 上限 / 提示 / 参考标签；**没有路径、没有字节** |
| 2 | 核心不 `require fs` / `path`，不 `require` 别的模块（`元数据.js` 是纯函数，同目录） |
| 3 | 一个模块只交出一份清单：`describe()` |
| 4 | 失败一律 `{ ok:false, reason, code }`，不抛错（装配阶段除外） |
| 5 | 出口 `Object.freeze`，不递内部件 |

## 四、需求

| 编号 | 需求 |
|---|---|
| R-1 | 认图：取字节 → 引擎打标 → 过阈值 → 按概率降序 |
| R-2 | 阈值三档：调用方给的 > 模型自带的 > `0.35`；给的必须落在 0~1，否则退回 |
| R-3 | 上限：给了就截前几个，没给全要 |
| R-4 | 中文名：有查词就配，查不到与没给都 `null`（形状稳定） |
| R-5 | 查词抛错不带崩：标签照给，中文名全 `null` |
| R-6 | 读元数据：认 `tEXt` / `iTXt` / `zTXt`；正负向写在一段里时按 `Negative prompt:` 劈开 |
| R-7 | 看图：把提示与参考标签原样带过去；回来的标签也配中文名 |
| R-8 | 引用不对（缺作用域 / 缺条目ID / 不是对象）一律 `VISION_BAD_REF` |
| R-9 | 引擎 / 看图函数抛错：接住，换成带原话的失败回执 |
| R-10 | 看模型：只报端口齐不齐 |
| R-11 | 读 ComfyUI PNG：从 `prompt` API graph 或 `workflow` 界面图沿采样器正 / 负 condition 连线取提示词；无法识别图时不把 JSON 当成正向提示词 |

## 五、架构

```
装配层
  ├── 取图字节（图片模块的 取内容）
  ├── 查词（标签模块的 认词）
  ├── tagger（模型引擎：ONNX 会话 + sharp 预处理）
  ├── 看图（调度：请求名 识图 + 世界书的提示词）
  └── 读元数据（本模块的 元数据.js）
        ↓
index.js（门面：动作表 · 直呼式 · describe）
        ↓
core.js（四条路的编排）
```

**核心是纯逻辑**：只调递进来的函数。

`读元数据` 可直接收 PNG 字节，经现有 `读元数据` 端口解析；没有直接字节时仍按引用调用 `取图字节`。界面导入 PNG 走这一个动作，不先把临时图写进存放地。

## 六、一次认图的编排

```
① 收引用（不合法 ⇒ BAD_REF）
② 取字节（取不到 ⇒ NO_BYTES）
③ 定阈值（给的 → 模型的 → 0.35）
④ 交给引擎（抛错 ⇒ ENGINE_FAILED）
⑤ 收标签：词 / 概率 / 分类号 → 分类名
⑥ 配中文名（查词抛错就全 null）
⑦ 按概率降序、截上限
```

## 九、决策记录

| # | 决定 | 由来说 |
|---|---|---|
| 1 | **三条路拆成三个动作** | 三样的输入与失败表现都不一样；合成一个再给模式参数，调用方看不出自己要走哪条（判据②） |
| 2 | **位图由装配层取，模块只收字节** | 引用是标识；模型能填地址就能读机器上任何文件（规则 3） |
| 3 | **模型与推理引擎由装配层递** | 模块自己不找、不猜、不探测路径（规则 9）；模型可选可换，位置只有配置一处 |
| 4 | **阈值与上限都是"这次怎么筛"** | 阈值必须能在界面上看到（判据②），所以它是动作参数，不是藏起来的常量 |
| 5 | **查词抛错不带崩整件事** | 中文名只是锦上添花；标签本身（模型给的）比中文名重要 |
| 6 | **中文名形状稳定：没有就是 `null`，不是缺字段** | 界面拿它渲染，缺字段与 `null` 是两种写法 |
| 7 | **不解析 EXIF** | 要另一个解析器；本机要处理的图基本都是 PNG |
| 8 | **缩放 / 归一化归引擎** | 那是"模型要什么形状"的知识，属于引擎那一层，不属于编排 |
| 9 | **引用参数是扁平标识**（存放地 / 条目ID / 会话ID） | 模块内部收成 `{ 作用域, 条目ID }` 再交给端口；`读元数据.字节` 是原始图片数据，不是路径 |
| 10 | **模块的 reason 已经带码时，装配层不再套一层** | 真机实测到过 `INVALID_SCOPE: INVALID_SCOPE: …`——码写两遍，谁都不好读 |
| 11 | **ComfyUI 图语义在本模块的纯函数元数据解析器里集中处理** | 真 PNG 的 `prompt` 是节点图 JSON；把它当普通提示词会产生一条整图 JSON 假标签。识图模块保留原始元数据，并只从已识别的采样器正 / 负分支提取文本；未知图不冒充提示词。Tag 的切分与既有浏览器桥接继续走 `装订.切分`，不增加动作或跨模块依赖 |
| 12 | **识图标签展示复用标签模块的一次批量 `render.sort`** | 已知词需要沿用库里的中文名与页分类；查询在装配桥接层批量完成，rawText仍保留权重、转义等原文。未命中时不伪造中文名或库分类 |
| 13 | **读元数据既可按引用取图，也可直接传 PNG 字节** | 界面上传图不需要为了读文字块先保存一份图片；两条输入都进现有解析器，不新增解析实现 |

## 十、本次实施范围与验收

本次处理 ComfyUI PNG 的内置提示词。`元数据.js` 解析 API prompt graph 与 workflow 节点 / 连线，按 sampler 的 positive、negative 输入及上游输出槽位分别抽取文本；覆盖真实样本中的 `easy fullLoader`，也覆盖标准 `CLIPTextEncode`。原始 `全部`、`工作流`、`参数` 与现有 A1111 `parameters` 拆分行为保留。未识别的图只保留在原始字段，不产出 JSON 提示词。

主页面 `/` 已有 `vision → binding.切分 → builtinTags → #tpModes` 链路；装配桥接以切分单元的纯词一次调用 `tag.render.sort`，将命中记录的中文名与当前页分类补给展示行，chip 的 `rawText` 仍使用 `前+词+后`。模型词也复用这一批量映射，保留概率；库命中时由当前标签库分类替换引擎分类，库未命中时保留引擎分类；没有中文名的词只显示原文，不重复伪装中文名。metadata未知词没有引擎分类时显示待分类。不得增加识图→标签内部依赖、第二份分类表、全量标签库下载或逐词HTTP查询。验收使用 `<桌面>/ComfyUI_09900_.png`：正负文本分别匹配图中 sampler 分支；正向 Tag 逐项显示；权重括号、转义标点、换行和重复项保持既有 `装订.切分` 形状；已知词用库中文名/分类，未命中词保留引擎分类或不加分类；不得出现整段 JSON 假 Tag。测试还覆盖未知图不冒充提示词与既有 A1111 输入。相关命令：`node test/run.js`、`node 程序/对接层/界面/试/识图界面.js`，并在主页面对真实样本做端到端验收。
