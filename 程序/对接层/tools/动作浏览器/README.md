## 怎么起

```bash
node 程序/对接层/tools/动作浏览器/服务.js
```

打开控制台打出来的那个地址。**要令牌**——令牌每次启动现生成，只有拿到那份页面的人能调，页面自己带着。

换端口 / 指定项目根：

```bash
node 程序/对接层/tools/动作浏览器/服务.js --端口 8800 --项目根 <仓库>
```

## 它是什么

**是界面，不是中间层。** 中间层是那条 `POST /toolbox/调`——服务收到 `{ 模块, 动作, 参数 }`，转手调 `门面[模块].run(动作, 参数)`，回执原样吐回。这个页面只是那条路的第一个使用者，跟以后按用途设计的用户界面**平级**。

它跟 `tools/` 下那些脚本是同一类东西，区别只在一条：**那些脚本走的是进程内直调，它走的是浏览器 → HTTP → 宿主 → 门面**。所以它补的正是别人验不到的那一段。

| 谁验过 | 走哪条路 | 没验到的 |
|---|---|---|
| `各模块/test/run.js` | 直接 require，进程内 | 一切 |
| `对接层/tools/接口实测.mjs` | 真装配，进程内 | **HTTP 这一层** |
| **动作浏览器** | 浏览器 → HTTP → 宿主 → 门面 | ← 就是它 |

**用户界面做完之后它也不删。** 某块界面还没做，从这儿先用；某块界面做坏了，从这儿对照看原始回执。

## 四条路由

| 路 | 方法 | 收 | 回 |
|---|---|---|---|
| `/` | GET | — | 页面（令牌注在里面） |
| `/页.js` · `/页.css` | GET | — | 页面要的那两份 |
| `/toolbox/桌` | POST | `{}` | `{ 动作表, 装不上, 项目根, 模型 }` |
| `/toolbox/调` | POST | `{ 模块, 动作, 参数 }` | 那个动作的回执 |
| `/toolbox/模型` | POST | `{}` 看 / `{ 换: { 类别, id } }` 换 | `{ ok, data: 模型那一份 }` |

三条 POST 都要 `x-toolbox-token` 头。服务只绑 `127.0.0.1`。

**回执的拆法**与登记工具那一条相同：模块给 `{ ok:false, reason, code }` ⇒ **原样交回**；给 `{ ok:true, data }` ⇒ 交 `data`；其余原样。

## 本地模型：这一格由谁在跑

页面上那条**模型条**管的就是这件事——**跑着换，不用重起**。

```
识图模型  [ WD EVA02 Tagger（wd-eva02） ▾ ]   在用 wd-eva02    模型目录 …
翻译模型  [ Opus-MT 英中互译（opus-mt） ▾ ]   在用 opus-mt
```

| 它显示 | 从哪来 |
|---|---|
| 有哪几格 | 扫项目根 `模型/识图/` 与 `模型/翻译/`，**没有第二份清单** |
| 显示名 | 每格自己那份 `模型.json` 的 `名字` |
| 装好了没有 | `模型.json` 点名的文件都在才算装好；缺什么就写什么 |
| 这次用哪个 | 配置里那一格值；留空就是"目录里第一格装好的" |

**换得了是因为模块拿到的是"转交对象"**：门面装配时拿到的是 `{ 打标, id, 名字, 阈值 }`，
这里每次调用现查"现在用哪一格"（`模型可选.js`）。所以换模型只是改这里的答案，**模块那边一个字不用动**。

换不了的情况都如实说：这一格不存在 ⇒ `HOST_NO_MODEL`；没装好 ⇒ `HOST_MODEL_INCOMPLETE`（还会说缺哪个文件）。
**被拒绝时不会换掉现在用的那一格。**

## 参数怎么填

**只有一条规矩**：先按 JSON 解，解不出来就是字符串。

| 参数 | 怎么填 |
|---|---|
| 文本（`串` · `文本` · `名字`） | 直接写字 |
| 数字 / 真伪（`上限` · `启用`） | `30` · `true` |
| 数组（`词` · `标识列表`） | `["1girl","hatsune_miku"]` |
| 对象（`作用域` · `条目` · `图`） | `{"存放地":"gallery"}` |
| 可选参数 | 留空 = 不传，模块用自己的默认值 |
| 必填参数 | 留空照传空串，模块自己拒绝并给码 |

**这条规矩让界面不必知道类型。** 参数该长什么样，页面不去猜——猜错了就是"界面替用户决定事情"。

## 回执怎么显示

原样 JSON。一处例外，为了看得见：

| 情形 | 页面怎么处理 |
|---|---|
| 回执里带**原始字节**（`image.取内容` · `comfy.取图`） | 画成图；那串数字从 JSON 里换成一句 `<原始字节：N 字节>` |
| 字节串的形态 | 宿主是 Node，Buffer 过 JSON 会变成 `{ type:'Buffer', data:[…] }`。页面认这一种，也认 `Uint8Array` 与带 `length` 的数字键对象 |

**字节的识别只看形状，不看是谁给的**——所以以后哪个模块新出一个回字节的动作，这里不用改。

**这个台子没有字节上限。** `image.取内容` 与 `comfy.取图` 回到页面上的是真字节，多大都画得出来；
工具那条路（模型那侧）另有一条：回执里的字节超过 1 MB 就报 `TOOL_TOO_MANY_BYTES`，
因为那份 base64 文本要进模型的上下文。要看大图就用这个页面。

## 装了什么、没装什么

**装了的**：七个能力模块 + 主AI，走的是 `对接层/模块清单.js` 与 `cordis.patch.yml` 那一份配置，不另写一份。

**没装的（如实报缺，不假装）**：

| 缺什么 | 为什么 | 表现 |
|---|---|---|
| 看图那条链路 | 要走 DSH 的模型调用；这个台子没有 `ctx.llm` | `vision.看图` 报缺 |
| 装订的 AI 翻译 | 同上 | `binding.装订` 报缺（`切分` 照常可用，它是纯函数） |

**本地模型是装上的**（目录从配置来，第一次用到才加载）—— 所以 `translate.本地译` 与 `vision.认图` 都是真的。

**也就是说：除那两条要 DSH 的，其余动作全部真读写本机数据。**

要看那两条真链路，走 `对接层/tools/真模型实测.mjs`、`出图实测.mjs` 那类脚本，或者把界面接进 DSH。

## 哪条不能动

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | **页面不认识任何模块** | 动作名、摘要、参数名、说明全部来自宿主。页面上没有一处写死"有哪些动作" |
| 2 | **参数值的读法只有一条**：先 JSON、后字符串 | 页面推断类型就是在替用户决定 |
| 3 | **回执原样显示**，不加工、不改字段名 | 它就是给人看的；加工过就看不到模块真正交出来什么 |
| 4 | **不替用户拦** | 画不出来的参数给文本框，必填留空照传；拒绝是模块的事 |
| 5 | **模型换得动靠"转交对象"，不靠重装** | 门面拿到的是每次现查的那一份；换模型不动模块一个字 |
| 6 | **换不了就说清哪一步不行** | 不存在 / 没装好（说缺哪个文件）/ 拒绝了就不动现在用的那一个 |

## 自检

```bash
node 程序/对接层/tools/动作浏览器/test/run.js     # 27 条：路由 · 动作表 · 模型列与换 · 调动作 · 失败分辨 · 真写再删
node 程序/对接层/tools/动作浏览器/test/页面.js     # 20 条：真服务 + jsdom，验渲染出来的 DOM
```

**页面那份要 jsdom**，本仓库不带它（运行时零依赖）。指一个装了它的地方就能跑：

```bash
JSDOM_DIR=<某个 node_modules 的上一层>  node 程序/对接层/tools/动作浏览器/test/页面.js
```

指不到时那份自检会打印"跳过"并零退出。

两份都**自建数据、自清数据**：世界书那段建一本、启用、执行、再删干净；模型那段造一格不完整的假模型、验完删掉。
