## 一、装进一个 profile

```bash
# 1) 本层自己的依赖（只有一个 devDependency）
cd 程序/对接层
pnpm install

# 2) 装进某个 profile（本机开发用 link）
dsh plugin --profile <profile> add link:<本仓库>/对接层

# 3) 重启那个 profile
dsh web
```

**profile 里不要再单独装 DSH 的包。** 同一个 profile 出现两份 `@deepseek-ai/*` 时，
工具一调用就报 `Cannot read properties of undefined (reading 'prepare')`。

### 1.1 一个不碰 GUI 的测试 profile

```bash
export DSH_HOME=~/dsh-test          # 或 $env:DSH_HOME = "$env:TEMP\dsh-test"
dsh plugin --profile <profile> add link:<本仓库>/对接层
dsh plugin --profile <profile> add "@deepseek-ai/dsh-headless@0.2.0-rc.2"   # 要它，才有"跑一轮就退出"的应用壳
dsh --profile <profile> headless "用 tag_status 查标签库体检，把「记录」的数字念给我。"
```

**`@deepseek-ai/dsh-headless` 不能少**：它是那个"答一个任务、打印结果、退出"的应用壳。
少了它，`headless` 只是个普通参数，进程不会自己结束。

## 二、配置长什么样

`cordis.patch.yml` 里三段：

```yaml
# ① 让开位置：身份与工作方式归世界书，不放环境事实
- id: system-prompt
  config:
    includeHarnessIdentity: false
    personaPrefix: ''
    personaSuffix: ''

# ② 计划模式那段正文（机制是 DSH 的）
- id: plan-mode
  config:
    section: |
      你在计划模式里。这个模式只有一条规矩：**先给方案，等人点头，再动手。**
      …

# ③ 我们自己这一层
- insert:
    - id: toolbox
      name: dsh-toolbox
      config:
        项目根: '<仓库绝对路径>'
        用户目录: '工具箱数据/主AI'
        默认目录: '主AI模块/assets/预设'
        图片目录: '工具箱数据/图片'
        世界书用户目录: '工具箱数据/世界书'
        世界书默认目录: '世界书模块/assets/世界书'
        模型目录: '模型'
        翻译模型: 'opus-mt'
        识图模型: 'wd-eva02'
        翻译方向: 'auto'
        comfyUI地址: 'http://127.0.0.1:8188'
        comfyUI工作流存档: '工具箱数据/comfyUI/工作流.json'
        请求: 主AI
        装订请求: 翻译
        池:
          官方: { 路由: deepseek-official, 模型: [deepseek-flash] }
          本地: { 路由: local, 模型: [qwen-vl] }
        路由:
          主AI: {}
          翻译: {}
          识图: { 走: 本地, 模型: qwen-vl }
          文生图: {}
```

**池里只写路由名与模型候选。** 地址与密钥住 DSH 那边的 provider 配置与凭据存储。

## 三、`apply` 交回来的东西

```js
import { apply } from './对接层/index.js';

const 出 = apply(ctx, config);
出.主AI.执行({ 请求: '主AI' });     // 这次这套预设
出.门面.tag.describe();            // 标签模块的动作表
出.预设.工具表.length;              // 74
出.工具;                          // ['tag_query', 'tag_record_get', …]
出.调度.查路由('识图');             // { 跟随:false, provider:'local', model:'qwen-vl', 用的谁:{…} }
出.本轮文本(agent);                // 本步批次的文本
```

## 四、只验装配（不启 DSH）

```js
import fs from 'node:fs';
import yaml from 'js-yaml';
import { apply } from '../index.js';

const 配置 = yaml.load(fs.readFileSync('cordis.patch.yml', 'utf8'))
  .find((一) => 一.insert).insert.find((一) => 一.id === 'toolbox').config;

const ctx = {
  systemPrompt: { section: () => () => {} },
  tools: { register: () => () => {} },
  llm: { stream: async function* () {} },
  on: () => () => {},
  effect: () => () => {},
};

const 出 = apply(ctx, 配置);
出.工具.length;      // 74
```

**契约替身只要这五样**：`systemPrompt.section` / `tools.register` / `llm.stream` / `on` / `effect`。
`test/run.js` 就是这么跑的。

## 五、错误表

| 码 | 什么时候 | 怎么办 |
|---|---|---|
| `TOOL_BAD_TOOL_NAME` | 工具名拆不成 `<模块>_<动作>` | 看预设工具表的 `名字` |
| `TOOL_NO_SUCH_MODULE` | 名字前半段没有对应模块 | 只有 `tag` / `image` / `worldbook` / `binding` / `translate` / `comfy` / `vision` |
| `TOOL_MODULE_FAILED` | 模块没给码就失败了 | 看模块自己的理由 |
| `DISPATCH_NO_SUCH_POOL` | 路由指向池里没有的条目 | 对齐 `池` 与 `路由` 的键 |
| `DISPATCH_NO_SUCH_ROUTE` | 池条目没写路由名 / 没模型 | 补上 |
| `DISPATCH_MODEL_NOT_IN_POOL` | 要的模型不在池的候选里 | 改池的 `模型` 或路由那一行的模型 |
| `DISPATCH_NO_TEXT` | 模型那边出错 | 理由里带 `用的谁`，照着查那条链路 |
| `DISPATCH_BAD_ANSWER` | 装订的翻译没回一个 JSON 对象 | 换条模型，或看那段报文 |

## 六、装的时候常见的三件事

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 请求被 400 打回，日志里问 `Invalid 'tools[0].function.name'` | 工具名里有中文或 `.` | 模块键用英文；动作名里的 `.` 换成 `_` |
| 工具一被调用就报 `Cannot read properties of undefined (reading 'prepare')` | 同一个 profile 里有两份 `@deepseek-ai/dsh-tools` | 卸掉 profile 里那份；本层不带 DSH 的包 |
| `dsh --profile <profile> headless "…"` 跑完不退出、也不输出 | 那个 profile 的 bundles 里没有 headless 应用壳 | 装上 `@deepseek-ai/dsh-headless` |
