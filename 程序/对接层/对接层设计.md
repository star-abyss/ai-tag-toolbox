## 一、范围

**本层做四件事**（上层设计 §13.2）：

| # | 做什么 |
|---|---|
| 1 | 按配置装模块（位置从配置来；工具参数里永远不出现地址） |
| 2 | 按预设的工具表**登记工具**（`ctx.tools.register`） |
| 3 | 注册世界书提示词段：《前》（5110）与《后》（5120）；计划模式正文写在补丁里 |
| 4 | 挂插手点：`agent/inbox/claimed`（记住本轮文本）· 段 provider（现算）· 调度那一小块 |

## 1.1 它不做什么

| 不做 | 归谁 |
|---|---|
| 解析模块内部结构 | 模块只给工厂、动作表与回执 |
| 改 DSH 的包 / 打源码补丁 | 借它的库与服务，装配代码全是我们自己的 |
| 接管会话与循环 | DSH |
| 存凭据、管 provider 列表 | DSH 的凭据存储与 provider 配置 |
| 写身份与工作方式的正文 | 世界书条目 |
| 挑世界书条目 | 世界书模块 |

## 1.2 三条定性

| # | 定性 | 体现 |
|---|---|---|
| 1 | **彻（彻）底放开** | 用户预设的工具表不校验；指不到的动作在调用时失败，错交回给 AI |
| 2 | **不做安全边界** | 本层没有能落到系统上的动作；工具要么调模块，要么不发请求 |
| 3 | **缺省是缺省，错是错** | 路由没写 = 跟随主 AI；写了指不到 = 失败，不回落 |

## 二、为什么是一个包，而不是改 DSH

**DSH 的装配方式（profile + patch 层）是为"改它自己"设计的。** 我们要的是在自己的装配代码里
把数据摆出来，所以本层做成一个**自成一个体的包目录**，带一份自己的 `cordis.patch.yml`：

| 借 | 自己写 |
|---|---|
| `dsh-llm`（模型调用）· `dsh-session` · `dsh-tools`（工具注册）· `dsh-agent-loop` · `dsh-system-prompt` · `dsh-web-app` | 本层的全部 |

**做成包的好处**：它能被装进任何一个 profile，也能被卸掉；而它的装配代码一行都不在 DSH 的包里。

**代价**：profile 里出现两份 `@deepseek-ai/*` 会破坏单例。所以本层**不自带任何 DSH 的包**（决定 3）。

## 三、模块键与工具名

### 3.1 为什么模块键是英文

提供方对工具名有硬约束：

```
Invalid 'tools[0].function.name': string does not match pattern.
Expected a string that matches the pattern '^[a-zA-Z0-9_-]+$'
```

原来的 `标签.query` 一个都不合法，整轮请求被 400 打回。所以**模块键改英文**：

| 模块键 | 模块 |
|---|---|
| `tag` | 标签模块 |
| `image` | 图片模块 |
| `worldbook` | 世界书模块 |
| `binding` | 装订模块 |
| `comfy` | comfyUI 模块 |

### 3.2 中文动作名一个字不动

模块层的中文动作名（`列` · `取详情` · `装订` · `出图` · …）属于模块自己的设计，
**本层不碰它们**。翻译发生在 `模块清单.js` 的 `动作名` 那张对照表里：

```js
动作名: { 列: 'list', 取详情: 'detail', …, 'record.get': 'record_get' }
```

表里没有的动作名原样用（`query` 本来就合法）。

### 3.3 名字的拼法归主 AI 模块

`<模块键>_<动作名>` 这个拼法是**预设的形状**，所以它在 `主AI模块/preset.js` 的 `工具名()` 里。
本层只把模块侧的名字翻成模型侧的名字递进去，不自己拼。

## 四、装模块

```
配置（项目根 + 各目录 + 地址）
   ↓
模块清单.js：[{ 名字, 门面, 工厂, 选项, 动作名 }]
   ↓ createRequire 按路径取 index.js，调工厂
门面 = { tag, image, worldbook, binding, comfy }
```

**递给模块的只有两样东西**：位置（从配置来）与函数（本层造的，比如装订的 `AI翻译`）。

**本层不认识模块的内部结构**：只用 `index.js` 交出来的工厂、`describe()` 与 `run()`。

## 五、登记工具

```
预设的工具表（主 AI 模块给）
   ↓ 拆名字：<模块键>_<动作名>
查模块清单 → 找门面 → 翻回模块自己那层的动作名
   ↓ 造定义（name / description / parameters / output / execute）
ctx.tools.register(定义)
```

**工具定义由本层自己写**，不引 DSH 的 `dsh-tools` 包：

- 那个包用 `Symbol()`（不是 `Symbol.for`）把调度器挂在 `ToolRuntime` 上；
- 插件目录里再装一份 = 两份副本 = 两个 symbol；
- 结果：工具一被调用就报 `Cannot read properties of undefined (reading 'prepare')`。

**参数进预设**：`parameters.properties` 直接来自预设工具表的 `参数`，用户改参数就是改
"模型填什么"；改错就是调用失败。本层不维护"预设参数 ↔ 模块参数"的对照表。

**失败交回给 AI**：模块给 `{ ok:false, reason, code }` ⇒ `execute` 抛错，错误信息就是那条
`码: 人话`。模型看得见，用户查得着。

## 六、提示词段

| 段名 | order | 正文 | 记什么 |
|---|---|---|---|
| `toolbox:世界书前` | `5110` | 当前请求启用世界书的《前》命中 | 世界书模块计算正文 |
| `toolbox:世界书后` | `5120` | 当前请求启用世界书的《后》命中 | 世界书模块计算正文 |

**纯函数纪律**：段 provider 每步同步调用一次，**不许 await、不许发请求、不许改状态**。
它读取本轮文本，由世界书模块计算当前请求启用书籍的命中，把对应落点的文本交出去。

**让开位置**：`includeHarnessIdentity: false` + 两个 persona 都留空——身份正文归世界书，
不注册 harness 写死的那一行，也不放环境事实（AI 没有能用到它们的手段，写进去还会每轮都变）。

**计划模式**：机制是 DSH 的（状态 / 出口工具 / 评审弹窗），**那段正文是我们的**，
写在 `cordis.patch.yml` 的 `- id: plan-mode` 里。它不由本插件注册。

## 七、本轮文本与插手点

```
agent/inbox/claimed   ← 本步批次被领走（早于组装）
        ↓ 把这几条拼起来，按 agent 分桶
   WeakMap<agent, string>
        ↓ 段 provider 组装时读它
世界书命中扫描用这段文本
```

**为什么挂这里**：组装那一刻本步消息还没落盘（P1），而 `claimed` 早于组装（P2）。
取本轮批次正好落在两者之间，不需要"滞后一步"那条退路。

**按 agent 分桶**：一个进程里可能同时跑几个 agent，各记各的。
`agent/inbox/inserted` 来了就清掉——新的一批进来，上一批不再代表"本轮"。

## 八、调度那一小块

```
请求({ 请求, messages, … })
  ① 查路由：没写 → 跟随主 AI；写了 → 池里那一条 + 模型
  ② ctx.llm.stream({ provider, model, messages, signal })
  ③ 失败 → 归成中文可分辨的码
  ④ 交回 { 正文, 用量, 用的谁: { provider, model }, 停在哪 }
```

**回执带 `用的谁`**：用户随时看得出这次到底发去本地了没有（判据②）。

**"没写"与"写错"必须分开**：混在一起，一个拼错的名字会让识图静悄悄地走错链路而无人知晓。

**池里只写路由名与模型候选**，地址与密钥住 DSH——一处字段值只存一处。

## 九、不做什么（逐条留档）

| 不做 | 为什么 |
|---|---|
| 自带 DSH 的包 | 两份副本 = 两个 `Symbol()`，工具调用会炸 |
| 在插件里读盘找位置 | 位置从配置来；模块自己不找、不猜、不探测路径 |
| 校验用户预设 | 缺了就是缺功能，写错了就是调用失败 |
| 多级回落 | 规则 8 |
| 兼容层 / 回退开关 | 要回退用 git |
| 挂 MCP | 会让"模型能用哪些工具"多出第二个来源 |
| `complete: true` | 会吃掉 DSH 自己的工具指导；要做就得改宿主 |
| 改 DSH 的源码 | 与"模块层一个字不动"同源：不撬别人的房子 |
| 自己声明一条网关路由 | 路由名被占用会让插件加载失败；这一版只做"池条目 = 一个已注册的路由名" |

## 十一、决策记录

> **作废的留原文不删。** 编号顺延。
> 与整层有关的决定（16–42）在 [上层设计.md](../../文档/上层设计.md) §十七；这里只记**对接层自己**的。

| # | 决定 | 由来说 |
|---|---|---|
| 1 | **本层是一个自成一体的包目录**（`对接层/`），带自己的 `cordis.patch.yml` | DSH 的装配是为"改它自己"设计的；我们要在自己的装配代码里把数据摆出来 |
| 2 | **模块键改英文、工具名 `<模块键>_<动作名>`** | 提供方对 `tools[].function.name` 有 `^[a-zA-Z0-9_-]+$` 的硬约束；原来的 `标签.query` 会被 400 打回 |
| 3 | **模块层的中文动作名一个字不动**，对照表住本层的 `模块清单.js` | 那些中文动作名是模块自己的设计；改它们要动七个模块，而改一张表只动一处 |
| 4 | **本层不自带任何 DSH 的包** | 两份 `@deepseek-ai/*` 会让内部的 `Symbol()` 单例错位，工具一调用就报 `reading 'prepare'`。只依赖注入进来的服务 |
| 5 | **工具定义由本层自己写**（不引 `defineTool`） | 同上一条；省掉的那个包只是造对象的语法糖，形状我们自己写得起 |
| 6 | **计划模式那段正文写在补丁文件里** | `!!js` 的求值作用域里没有 `require`、没有 `import`，读不了文件；而 DSH 的 `plan-mode` 配置只接受一段字符串 |
| 7 | **名下的那份 `assets/计划模式.txt` 删掉** | 一处字段值只存一处：正文在补丁里，再留一份就是第二份真相 |
| 8 | **`onnxruntime-node` 与 `sharp` 按 `@huggingface/transformers` 要的那两个版本钉死**（`1.21.0` / `^0.34.1`） | 它们是原生模块，JS 那一半与原生那一半必须是同一版。`transformers` 把 `onnxruntime-node` 钉在 `1.21.0`（napi-v3）；本层自己再装一个 `1.30.0`（napi-v6），根 `node_modules` 里那一份会盖住它要的那一份，装模型时报 `The requested API version [30] is not available, only API versions [1, 21] are supported`。`sharp` 同理（`Could not load the "sharp" module`） |
