# 对接层 · 接口

> 工具登记现行契约（2026-10-17）：`登记工具({ctx,业务:{工具表,执行},处理回执,上下文?})`。业务执行收到工具名、参数和原始运行上下文，失败保留原业务字段；工具名不再拆为模块动作。详见 [绘画业务接口](../../文档/绘画业务接口.md)。下文旧登记参数与模块动作生成规则不再适用。

> **这是契约。改实现之前先改它；改完跑 `node test/run.js`。**
> 设计理由在 [对接层设计.md](对接层设计.md)；上手指南在 [README.md](README.md)。

这一层不是模块：它没有 `run()` / `describe()`，对外面就是 **DSH 的插件约定**加一份配置。

---

## 一、插件出口

```js
// 对接层/index.js
export const name = 'toolbox';
export const inject = ['systemPrompt', 'tools', 'llm'];
export function apply(ctx, config) { … }
```

| 导出 | 类型 | 说明 |
|---|---|---|
| `name` | string | 恒为 `'toolbox'` |
| `inject` | string[] | 要用到的服务；缺一个插件就不激活 |
| `apply` | function | 装配。收 `(ctx, config)`，交回装出来的东西 |

### 1.1 `apply` 的返回值

DSH 不用这个返回值；自检与诊断脚本用它。

```js
{
  主AI,        // 主 AI 模块的门面（预设的家）
  门面,        // { tag, image, worldbook, binding, translate, comfy, vision } —— 七个模块的门面
  预设,        // 这次这套预设（执行 交出来的那一份）
  工具,        // ['tag_query', 'tag_record_get', …] —— 登记成功的工具名
  调度,        // { 请求, 查路由 }
  本轮文本     // (agent) => string
}
```

### 1.2 `apply` 抛错的时机

**装配阶段允许抛错**（只有这里抛）：

| 缺什么 | 抛什么 |
|---|---|
| `config.项目根` 不是非空字符串 | `对接层要一个 项目根（配置里的那个位置）` |
| 某个模块的 `index.js` 里没有那个工厂 | `<文件> 里没有 <工厂>` |
| 主 AI 模块装配失败（缺 `用户目录` / `默认目录`） | 模块自己抛 |
| 预设里有工具指向不存在的模块 | `TOOL_NO_SUCH_MODULE: 预设里有工具「x_y」，可是没有「x」这个模块` |
| 工具名拆不成两段 | `TOOL_BAD_TOOL_NAME: 工具名要是「<模块>_<动作>」，这个是「…」` |

**为什么这几条要抛**：它们都是"这一层装不起来"，静默少一半工具比炸掉更难查。

## 二、配置项（`cordis.patch.yml` 里 `toolbox` 那一段）

| 键 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `项目根` | string | **是** | 唯一一个位置。七个模块与主 AI 模块都在它下面 |
| `用户目录` | string | 是 | 主 AI 的用户那份放哪（相对 `项目根`） |
| `默认目录` | string | 是 | 只读默认预设目录（相对 `项目根`） |
| `图片目录` | string | 是 | 图片模块的根目录 |
| `世界书用户目录` | string | 是 | 世界书模块的用户那份 |
| `世界书默认目录` | string | 是 | 世界书模块的只读默认 |
| `模型目录` | string | 否 | 本地模型那一层（相对 `项目根`，见 `模型/说明.md`）；不给就不装本地模型 |
| `翻译模型` | string | 否 | 这次用哪一格翻译模型；空 = 用第一格装好的 |
| `识图模型` | string | 否 | 这次用哪一格识图模型；空 = 用第一格装好的 |
| `翻译方向` | string | 否 | `auto` / `en-zh` / `zh-en` |
| `comfyUI地址` | string | 是 | 哪台 ComfyUI。**只有装配层能填地址** |
| `comfyUI工作流存档` | string | 是 | 存着的那张工作流放哪（相对 `项目根`） |
| `请求` | string | 否 | 这次的请求叫什么，缺省 `主AI` |
| `装订请求` | string | 否 | 装订模块的 AI 翻译走哪个请求；缺省跟随 `请求` |
| `池` | object | 否 | `{ <池条目名>: { 路由, 模型: [名…] } }` |
| `路由` | object | 否 | `{ <请求名>: { 走?, 模型? } }`；空 = 跟随主 AI |

**配置里的路径只出现在这一层**：工具参数里永远没有路径 / 地址。

## 三、工具名

```
<模块键>_<动作名>
```

| 模块键 | 对应的模块 |
|---|---|
| `tag` | 标签模块 |
| `image` | 图片模块 |
| `worldbook` | 世界书模块 |
| `binding` | 装订模块 |
| `translate` | 翻译模块 |
| `comfy` | comfyUI 模块 |
| `vision` | 识图模块 |

**约束**：`^[a-zA-Z0-9_-]+$`。名字里的 `.` 换成 `_`（`record.get` → `record_get`）。

**动作名对照**住在 `模块清单.js` 的 `动作名` 里：键是模型侧的名字，值是模块自己那层的名字。
表里没有的原样用（`query` 这一类本来就合法）。对不上时模块自己报"没有这个动作"，错交回给 AI。

## 四、登记进 DSH 的工具定义

本层自己写这条定义（不引 DSH 的 `dsh-tools`，见 [README.md](README.md) §七 第 1 条）：

```js
{
  name: 'tag_query',
  description: '工具箱的「tag_query」。参数与模块动作 1:1，成功给这个动作的回执，失败给「码: 人话」。\n串：要查的词，逗号分隔',
  parameters: {
    type: 'object',
    properties: { 串: { type: 'string', description: '要查的词，逗号分隔' }, 上限: { type: 'string' } },
    additionalProperties: true,
  },
  output: {
    schema: { type: 'object', additionalProperties: true },   // 交回的是模块自己的回执
    render: (_参数, 值) => [{ type: 'text', text: JSON.stringify(值, null, 2) }],
  },
  execute: async (参数) => { … },   // 调模块的动作；失败抛错
}
```

| 字段 | 从哪来 |
|---|---|
| `name` | 预设工具表的 `名字` |
| `description` | 预设工具表的 `说明` 逐项 |
| `parameters.properties` | 预设工具表的 `参数`（`{ type, oneOf?, description?, enum?, required? }`） |
| `output.schema` | 固定：任意 JSON 对象 |
| `execute` | 调 `模块.run(动作, 参数)`，把信封拆开 |

**`execute` 的四条约定**：

1. 参数原样递给模块（`门.run(动作, 参数)`）。
2. 模块给 `{ ok:true, data }` ⇒ 交回 `data`；给回执本身 ⇒ 原样交回。
3. 模块给 `{ ok:false, reason, code }` ⇒ **抛错**，错误信息就是那条 `码: 人话`。
4. 交回去之前，回执里携带的**原始字节编成 `dataUrl`**（模型那侧只能收无损 JSON，Buffer 过不去）。
   键名与位置一点不动：`字节` 键还是 `字节` 键。超过 `1024 × 1024` 字节 ⇒ 抛 `TOOL_TOO_MANY_BYTES`。

**参数类型在模型这一侧补**：模块的动作表只给参数名与说明，所以 `模块清单.js` 里另有一张
`参数类型` 表（只列不是字符串的那些），按 `模块键.动作名` 分层、按参数名兜底；
`index.js` 装配时用 `取参数类型(模块键, 动作名, 参数名)` 查它，随动作一起交进预设的工具表。
查不到的按 `string`。

## 五、提示词段

| 段名 | order | 正文来自 | 约束 |
|---|---|---|---|
| `toolbox:世界书前` | `5110` | 请求启用的世界书中落点《前》的命中，含常驻身份和工作方式 | 同步 provider，不能 await |
| `toolbox:世界书后` | `5120` | 落点《后》的命中 | 同上 |

两段都 `interpolate: false`（原样保留文本）。**空文本的段不贡献 token。**

计划模式那段正文**不由本插件注册**：它写在 `cordis.patch.yml` 的 `- id: plan-mode` 里，
机制归 DSH。

## 六、`agent/inbox/claimed`

```js
const 本轮文本 = 造本轮文本(ctx);
本轮文本(agent);   // → string，没说过话时是空串
```

| 事件 | 干什么 |
|---|---|
| `agent/inbox/claimed` | 把这一步批次里的文本拼起来（同一个 agent 的多条用 `\n` 接） |
| `agent/inbox/inserted` | 新一批进来 ⇒ 清掉这个 agent 的桶 |

**按 agent 分桶**（`WeakMap`）：一个进程里可能同时跑几个 agent。

**为什么挂这里**：`claim` 早于组装，组装早于消息落盘（[上层设计.md](../../文档/上层设计.md) §5.5 的 P1 / P2）。
所以这里记下来的文本，正好是"组装那一刻已经确定、但还没落盘"的那一批。

## 七、调度

```js
const 调度 = createDispatcher({ ctx, 池, 路由, 主AI请求 });
调度.查路由('识图');   // → { 请求, 跟随, provider, model, 用的谁 }
await 调度.请求({ 请求, messages, 温度?, 上限?, 信号? });
// → { 正文, 用量, 用的谁: { provider, model }, 停在哪 }
```

| 情形 | 处理 |
|---|---|
| 路由表那一行**没写** | **跟随主 AI**（provider 留空，`用的谁.provider` 是 `(跟随主 AI)`） |
| 写了，池里没这一条 | `DISPATCH_NO_SUCH_POOL`，**不回落** |
| 池条目没写路由名 | `DISPATCH_NO_SUCH_ROUTE` |
| 写了模型，但不在池的候选里 | `DISPATCH_MODEL_NOT_IN_POOL` |
| 池与路由都没写模型 | `DISPATCH_NO_SUCH_ROUTE` |
| 模型那边出错 | `DISPATCH_NO_TEXT`，理由里带 `用的谁` |

**装订模块的 AI 翻译端口**：`造翻译({ 调度, 请求名 })` 给一个 `async (报文) => 键值对`，
报文形状见 `装订模块/port.js`（`{ source, words, from, to }`）。模型没回 JSON ⇒ `DISPATCH_BAD_ANSWER`。

## 八、错误码

| 码 | 什么时候 |
|---|---|
| `TOOL_BAD_TOOL_NAME` | 工具名拆不成 `<模块>_<动作>` |
| `TOOL_NO_SUCH_MODULE` | 工具名前半段没有对应的模块 |
| `TOOL_MODULE_FAILED` | 模块没给码就失败了 |
| `TOOL_TOO_MANY_BYTES` | 回执里带的原始字节超过 1 MB（编成 base64 之后更大） |
| `DISPATCH_NO_SUCH_POOL` | 路由指向池里没有的条目 |
| `DISPATCH_NO_SUCH_ROUTE` | 池条目没写路由名 / 没模型 |
| `DISPATCH_MODEL_NOT_IN_POOL` | 要的模型不在池的候选里 |
| `DISPATCH_NO_TEXT` | 模型那边出错，没拿到正文 |
| `DISPATCH_BAD_ANSWER` | 装订的翻译没回一个 JSON 对象 |

模块自己的码原样带出来（`PRESET_*` / `IMAGE_*` / `PROMPT_*` / `BIND_*` / `TEXT_*` / `COMFY_*` / `VISION_*` / `TAG_*`）。
