## 一、它是什么 / 它不是什么

**它是本项目的装配层，同时是 DSH 的一个 Host 插件。** 它把"这个 AI 是什么"接到运行时上。

| 它做 | 它不做 |
|---|---|
| 按配置装七个能力模块与主 AI 模块 | 提供能力（能力在那些模块里） |
| 按预设的工具表**登记工具** | 执行工具（模块自己执行） |
| 注册提示词段：世界书前（5110）· 世界书后（5120） | 写正文（由世界书管理） |
| 记住本轮文本（挂 `agent/inbox/claimed`） | 挑世界书条目（那是世界书模块） |
| 查路由 → 调模型 → 交回带 `用的谁` 的回执 | 存凭据、管 provider 列表（那是 DSH） |

**它不认识模块的内部结构，也不改 DSH 的包。** 它只认两样东西：模块交出来的 `index.js`
（工厂 + 动作表）与 DSH 交出来的服务（`ctx.systemPrompt` / `ctx.tools` / `ctx.llm`）。

## 二、东西在哪

```
对接层/
├── index.js            插件入口：apply(ctx, config) 做那四件事（§一）
├── 模块清单.js         七个模块怎么装 · 模块键与动作名的对照
├── 登记工具.js         预设的工具表 → DSH 的工具注册表
├── 工具定义.js         工具说明与参数转换；运行登记、模型发送、界面预览共用
├── 调度.js             查路由 → 调模型 → 归类失败
├── 本轮文本.js         记住本步批次（挂 agent/inbox/claimed）
├── 世界书.js           请求 + 文本 → 带落点的条目，按落点分堆
├── 存档.js             一个小文件的读写（comfyUI 模块的 `存档`）
├── cordis.patch.yml    挂载声明：system-prompt · plan-mode · 插入本插件 + 全部配置
├── 模型引擎/            本地模型那一套：目录扫面 · 翻译 · 识图 · 看图
├── test/run.js         自检（33 条判据）：装配 · 登记 · 段 · 调度 · 工具执行 · 模型
├── tools/              真装配的实测脚本：接口实测 · 真模型实测 · 出图实测 · 看计划模式
├── tools/动作浏览器/     调试台：本地 HTTP 服务 + 一个页面，八个模块的动作点着调
├── README.md           本文件
├── 对接层设计.md         设计规范
├── 接口.md              契约：apply 的配置项 · 工具名 · 错误码
└── 调用示例.md           调用示例与错误表
```

**它没有 `core.js` / `port.js` / 适配器**——它不是模块，是装配层。这一层的"纯逻辑"就是
模块清单、名字对照、路由查表这三样，它们各自成文件，都不碰盘、不发请求。

```
DSH（profile + patch 层）
   └─ cordis.patch.yml ──→ index.js: apply(ctx, config)
                                ├─ 装模块（位置从配置来）
                                ├─ 装主AI模块（预设的家）
                                ├─ 登记工具（ctx.tools.register）
                                ├─ 注册段（ctx.systemPrompt.section）
                                └─ 挂插手点（ctx.on / 调度）
```

## 三、几个词

| 词 | 意思 | 长什么样 |
|---|---|---|
| **模块键** | 装配层给模块起的名字，也是工具名的前半段 | `tag` / `image` / `worldbook` / `binding` / `translate` / `comfy` / `vision` |
| **动作名** | 模型侧那一套动作标识 | `query` · `record_get` · `save` · `generate` |
| **工具名** | `<模块键>_<动作名>`，**登记进 DSH 的就是它** | `tag_query` · `comfy_generate` |
| **本轮文本** | 本步批次拼起来的文本，世界书命中用它扫 | 一步里几条消息拼成一段 |
| **池** | 用户配的多套 API：只写**路由名**与模型候选 | `{ 官方: { 路由: 'deepseek-official', 模型: ['deepseek-flash'] } }` |
| **路由** | `{ 请求名 → 池里哪一条 + 哪个模型 }`；空 = 跟随主 AI | `{ 识图: { 走: '本地', 模型: 'qwen-vl' } }` |

**工具名只能有 ASCII 字母、数字、下划线、连字符。** 这是提供方的硬约束
（`^[a-zA-Z0-9_-]+$`），中文或用点会在请求那一步被 400 打回。

**模块自己那层的中文动作名一个字不动。** 装配层用 `模块清单.js` 里的一张对照表把它翻成
模型侧的名字；表里没有的就原样用（比如 `query` 本来就合法）。

## 四、装起来之后长什么样

在 profile 的插件树里，它是一条：

```yaml
- id: toolbox
  name: dsh-toolbox
  config: { 项目根: …, 用户目录: …, 池: {…}, 路由: {…} }
```

装起来之后，运行时有这些变化：

| 变化 | 数量（默认那份） |
|---|---|
| 系统提示词多两段 | 世界书前（5110）· 世界书后（5120），主 AI 基础正文也是书内常驻条目 |
| 工具注册表多 N 条 | **74 条**（七个模块的动作总数） |
| 干涉点 | 三个监听：`agent/inbox/claimed` · `agent/inbox/inserted` · `agent/pre-step` |
| harness 自己的身份与口吻 | **不注册**（`includeHarnessIdentity: false`） |

## 五、四个动作（它没有对外动作表）

本层不是模块，没有 `describe()` 也没有 `run()`。它的对外面就是 **DSH 的插件约定**：

```js
export const name = 'toolbox';
export const inject = ['systemPrompt', 'tools', 'llm'];
export function apply(ctx, config) { … }
```

`apply` 收配置、装东西，把装出来的东西交回给调用方（自检用它；DSH 不用返回值）：

```js
{ 主AI, 门面, 预设, 工具: ['tag_query', …], 调度, 本轮文本 }
```

## 六、怎么装

```bash
# 1) 对接层依赖（运行界面服务与对账补丁自检）
cd 程序/对接层 && pnpm install

# 2) 装进某个 profile（本机开发用 link）
dsh plugin --profile <profile> add link:<本仓库>/对接层

# 3) 重启那个 profile
dsh web
```

**profile 里不要再单独装 DSH 的包**（比如 `@deepseek-ai/dsh-tools`）。同一个 profile 里出现
两份 `@deepseek-ai/*`，会让它们内部的 `Symbol()` 单例错位，工具一调用就报
`Cannot read properties of undefined (reading 'prepare')`。见决定 44 / 45。

配置全在 `cordis.patch.yml` 里，一处改完重启即可。它同时做三件事：

| 段 | 干什么 |
|---|---|
| `- id: system-prompt` | 让开位置：不注册 harness 的身份，不放环境事实 |
| `- id: plan-mode` | 计划模式那段正文（机制是 DSH 的，正文是我们的） |
| `- insert: toolbox` | 插入本插件 + 它的全部配置 |

## 七、哪条不能动

1. **不许自带 DSH 的包。** 两份副本 = 两个 `Symbol()` = 工具调用炸。只依赖注入进来的服务。
2. **不许把地址 / 路径放进工具参数。** 位置从 `cordis.patch.yml` 来；检验法看 `接口.md` 的工具参数名。
3. **模块键与工具名只能是 ASCII**（`^[a-zA-Z0-9_-]+$`）。要加模块就加英文键。
4. **模块层的中文动作名不许改。** 翻译发生在装配层这张对照表里，不在模块里。
5. **不许解析模块内部结构。** 只认 `index.js` 交出来的工厂与 `describe()` / `run()`。
6. **路由"没写"跟随主 AI，"写错"明确失败**，不许回落。
7. **池里只写路由名与模型候选**，地址与密钥住 DSH。
8. **段 provider 必须同步。** 它每步被调一次，不许 await、不许发请求。
9. **不改 DSH 的包、不打源码补丁。** 借它的库与服务，装配代码全是我们自己的。
10. **不挂 MCP、不做 `complete: true`、不放环境事实。**

## 八、依赖从哪来

| 依赖 | 递不进来会怎样 |
|---|---|
| `项目根`（配置） | **装配时抛错**——它是唯一一个位置 |
| `用户目录` / `默认目录`（配置） | 主 AI 模块装配时抛错 |
| `ctx.systemPrompt` / `ctx.tools` / `ctx.llm` | `inject` 声明的，缺了插件不激活 |
| `ctx.tools` 这个服务 | 工具登记不了，插件抛错（宁可炸，也不静默少一半工具） |
| 某一个模块的 `index.js` 里没有那个工厂 | 装配时抛错，指明是哪个文件少了哪个名字 |

**本层自己不找、不猜、不探测路径。** 多级兜底（`a || b || c`）是缺陷。

## 九、改完怎么验

```bash
cd 程序/对接层 && node test/run.js        # 33 条
node test/run.js 工具                # 只跑名字里含"工具"的
node tools/看计划模式.cjs             # 把补丁里那段计划模式正文原样打出来
```

**三个真装配的脚本**（都用 `cordis.patch.yml` 里那份配置真装一遍，走工具接口调）：

```bash
node tools/接口实测.mjs      # 七个模块逐个动作走一遍（25 条）；会真读真库
node tools/真模型实测.mjs    # 本地翻译 + 本地识图 + 读元数据（要那两格模型在）
node tools/出图实测.mjs      # 真出一张图：存工作流 → 认口 → 出图 → 取图（要 ComfyUI 开着）
```

**调试台**（浏览器里点着调；它补的是 HTTP 那一层，`test/run.js` 与上面三个脚本都验不到）：

```bash
node 程序/对接层/tools/动作浏览器/服务.js
node 程序/对接层/tools/动作浏览器/test/run.js     # 27 条：四条路由 · 动作表 · 模型列与换 · 调动作
node 程序/对接层/tools/动作浏览器/test/页面.js     # 20 条：真服务 + jsdom（要 JSDOM_DIR）
```

**自检查什么**：装配装出了什么（七个模块 + 主 AI）· 段注册的 order · 工具名合法性与数量 ·
工具**真的能调用到模块并出真回执** · 调度的三种情形（跟随 / 指不到 / 模型不在池里）·
本轮文本的记与清 · 参数里有没有路径 / 地址。

**自检不查什么**：DSH 那边的装载。那只能真机联调。

**真机怎么跑**（headless，不碰正在用的 GUI）：

```bash
dsh plugin --profile <测试 profile> add "@deepseek-ai/dsh-headless@0.2.0-rc.2"
dsh --profile <测试 profile> headless "用 tag_status 查标签库体检，把「记录」的数字念给我。"
```

## 十、这一版做到哪了 / 还差什么

**已实现**：那四件事（装模块 · 登记工具 · 注册段 · 挂插手点）· 调度那一小块（池 + 路由 + `用的谁`）·
装订的 AI 翻译端口 · **本地模型那一套**（目录扫面 + 翻译 / 识图 / 看图）· 默认工具表 **74 条** ·
参数类型表（模型那侧按 JSON Schema 填 `作用域` / `引用` / `词` 这类非字符串参数）·
计划模式正文（写在补丁里）· **动作浏览器**（本地调试台，补 HTTP 那一层）。

**验过的**：

| 项 | 结果 |
|---|---|
| 对接层自检 | **33 过 / 0 失败** |
| 七个能力模块自检 | 全部仍然全绿（66 · 41 · 59 · 61 · 134 · 43 · 37） |
| 主 AI 模块自检 | **62 过 / 0 失败** |
| 接口实测（真装配，从工具接口进） | **25 过 / 0 失败**：七个模块逐个动作走一遍 |
| 动作浏览器自检 | **27 过 / 0 失败**（HTTP 那一层）；页面那份 20 过（要 jsdom） |
| 真机联调（工具那条） | 用默认那份跑通一轮，模型真调 `tag_status`，拿到 52246 条的真回执 |
| 本地翻译（真模型） | `translate_local` 走 `模型/translation/opus-mt`：一段自由文本 → 中文，1.3 秒 |
| 本地识图（真模型） | `模型/vision/wd-eva02`：1.9 秒装模型、0.9 秒出标，64×64 图 @0.6 → `no_humans 90.1% · explicit 76.3%` |

**已知的缺口**：

| 项 | 状态 |
|---|---|
| 界面 | **没有**。预设的编辑、启用、看回执都要界面。现在能点着调的是调试台（动作浏览器），它跟以后按用途设计的用户界面**平级** |
| 「自己声明一条网关」 | **这一版不做**（[上层设计.md](../../文档/上层设计.md) §十六 待定 7） |
| `tools.execute` 的 PTC 内层调用 | 没验过；默认那份走 native，用不上 |
| 命中扫描的文本范围 | 现在**只扫本轮**（决定 42）；"最近 N 条"没做（§十六 待定 2） |
| 用 DeepSeek key 的真机联调 | **跑成了**（隔离 profile，模型 deepseek-flash）。三轮：<br>① `tag_status` → `主库 52246 · 自建库 0 · 索引 51442`，**4.8 秒**；<br>② `translate_local` 翻一段自由文本 + `vision_models` 查那一格 → 整段译文 `日出时清晨的山湖 水上喷雾 摄影现实`，7.3 秒；<br>③ `vision_detect` + `vision_metadata` 打真图 → 5 个标签带中文名（`no_humans 93.6%` …），元数据读出 `a cat, sitting` / `blurry` / 512×512 |
