# 装订模块

装订模块执行 AI 翻译，并提供翻译模块共用的纯文本切分与拼装端口。字段契约见 [接口.md](接口.md)，设计与取代决定见 [装订模块设计.md](装订模块设计.md)，示例见 [调用示例.md](调用示例.md)。

## 职责

| 它做 | 依赖来自 |
|---|---|
| 切分并记录唯一标识、壳和 UTF-16 范围 | 本模块纯逻辑 |
| 按方向查词和投影待译原词 | 装配层的查词函数 |
| 调用 AI 并按原词结果归位 | 装配层的提示词及请求适配器 |
| 从原文词范围替换并生成范围表 | 本模块的共用拼装函数 |
| 为本地翻译提供文本处理 | 冻结的 `装订.文本处理` 对象 |

本模块不加载模型、不读配置、不直接访问标签或页面。翻译模块从装配层接收文本处理对象，不 require 装订模块。

## 对外入口

```js
const 装订 = createBindingModule({ 查词, AI翻译 });
const 切分结果 = 装订.切分({ 文本 });
const 回执 = await 装订.装订(文本, { 方向: 'en-zh' });
const 文本处理 = 装订.文本处理;
```

装订方向默认为 `en-zh`，也支持 `zh-en`。动作参数、回执字段和错误码见接口文档。

## 纯文本端口

`装订.文本处理` 有 `切分`、`拼装`、`猜方向`、`需翻译` 四个纯函数。它保留输入格式，以原始 UTF-16 范围替换词段；表中的范围可用于双向对照。UI 和翻译模块共享这份行为，不自行重切文本。

## AI 报文与失败

AI 仍接收 `{ source, words, from, to }`，返回原词键值对象。缺少个别键或值非法时该单元保留原词，其他项照常使用。端口抛错时装订返回明确失败及本次原文。单次在飞闸门由模块持有，界面输入快照调度由界面负责。

## 旧规则取代说明

旧设计中的全角规整、空项收掉、统一重建分隔符和两边重新切分后按序号配对，已由范围切分和同次拼装结果表取代。被取代的原文及原因保留在 [装订模块设计.md](装订模块设计.md) §五。
