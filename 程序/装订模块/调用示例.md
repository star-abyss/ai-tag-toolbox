# 装订模块 · 调用示例

契约见 [接口.md](接口.md)，决策理由见 [装订模块设计.md](装订模块设计.md)。

## 装配

```js
const 端口 = createRealAdapter({
  认词: (words) => 标签.recognize(words),
  取提示词: (report) => 提示词.提示词('翻译', report.source),
  发请求: ({ 用途, system, user }) => AI调用.发({ 用途, system, user }),
  用途: '翻译',
});
const 装订 = createBindingModule(端口);

const 翻译 = createTranslateModule({
  文本处理: 装订.文本处理,
  查词: (words) => 标签.recognize(words),
  译: 本地模型.译,
});
```

两模块共用同一个文本处理对象，由装配层传递。

## 切分与位置

```js
const 切分 = 装订.切分({ 文本: '(1girl:1.2), long hair, long hair' });
// 切分是单元数组；每项含唯一标识、前/词/后、原文范围、词范围。
// 范围使用 UTF-16 下标、左闭右开；重复词有不同标识和位置。
const 原始文本处理结果 = 装订.文本处理.切分('(1girl:1.2), long hair');
// 共用纯文本端口另返回 { 文本, 单元, 退化 }。
```

### 拼装

UI 无需对原文与译文分别重新切分。装订动作成功回执的表在同次拼装中生成：

```js
const 回执 = await 装订.装订('(1girl:1.2), long hair', { 方向: 'en-zh' });
if (回执.ok) {
  显示(回执.译文);
  // 回执.表内含原文范围、词范围、译文范围和每项来源。
} else {
  显示(回执.原文);
  显示错误(回执.reason);
}
```

括号、权重、外围空白、分隔符及空项从本次原文保留。词范围内的译文由 AI 返回。译文范围包含完整对应项的壳，不含外围空白与分隔符。

## AI 报文

```js
// 例如对未命中的单元，AI 端口收到：
{
  source: '(red hair:1.3), blue eyes',
  words: ['blue eyes'],
  from: '英文',
  to: '中文',
}

// AI 端口返回原词键值对象：
{ 'blue eyes': '蓝眼' }
```

本地模型端口格式不同，使用 `{id,text}`；两种报文各自保留，均由文本处理端口拼装出范围表。

## 方向与错误

```js
await 装订.装订('猫坐在垫子上', { 方向: 'zh-en' });
// 成功回执.方向为 zh-en；查词中文名不会覆盖英文翻译。
```

方向缺省为 `en-zh`。装订失败回执始终包含本次原文。常见错误：`TEXT_BUSY`（已有请求）、`TEXT_NO_TRANSLATOR`（缺少 AI 端口）、`TEXT_TRANSLATOR_FAILED`（端口失败）、`TEXT_BAD_ANSWER`（响应格式不符）、`TEXT_LOOKUP_FAILED`（查词失败）。
