# 渲染顺序 · 两张表

> **这份是设计稿。** 它定义"出词按什么顺序吐"，也就是两张渲染表。
> 设计全貌见 [../work/角色与作品_设计稿.md](../../临时/work/角色与作品_设计稿.md)；定稿后并入 [标签模块设计.md](标签模块设计.md)。
>
> **它只回答一件事：词按什么顺序出来。** 它不管"哪些词被选中"（那是用户与界面的事），也不管"提示词怎么拼成一段文本"（那是界面与装配层的事）。

---

# 一、两张表，一份页序

```
表一 · tag 页渲染顺序    谁用：标签面板拼提示词 · 识图模块给打出来的标签排序
表二 · 角色渲染顺序      谁用：角色库导出一个角色

两份表共用同一份页序（§三）。表二 = 一个作品槽 + 这份页序。
```

**为什么共用一份**：页序改了要改两处，就是"必须和别处保持一致的清单"（边界规则 7）。两张表的差别只在"哪些页进、哪些页不进"，那是两条**规则**，不是两份表。

# 二、表一 · tag 页渲染顺序

**输入**：一批自由文本，或显式的 `{标识}` 对象。**输出**：自由文本原样保留；只有显式标识用记录规范名称输出，再按下面的顺序排好。

```
按 页序 → 类序 → 格内序 排

页序    这张表里页的先后（§三）
类序    页.json 里 `类列表` 数组的顺序（**类 ID 从小到大**）
格内序  类格文件数组的顺序（199 个格全是 ID 升序，实测无例外）
```

> **这三层在盘上都是现成的**，只有页序不在盘上：端口读页时按页 ID 升序排，那是给人看的排列。
> 所以页序是**代码里的一条常量**（`render-order.js` 顶部的 `页序` 数组），改它一处就够。

| 规则 | |
|---|---|
| **在表里的页 → 出**，按表里的先后 | |
| **不在表里的页 → 不出** | 页「角色组」与它底下的全部类一律不出 |
| **没有页可归的词 → 排最后** | 识图打出来而库里没有的、以及散落的词 |
| **库里查不到的词 → 排最后** | 查不到就没有页，不报错 |
| **同一批词里重复的 → 都留着** | 不去重（与"类格里重复 ID 都留着"同一条规矩） |
| **不许在这里改词本身** | 它只排序，不改写法（与"归一化只产出比对键"同源） |

# 四、表二 · 角色渲染顺序

**输入**：一个角色（或一批角色）。**输出**：三段，按这个先后。

```
① 角色名    角色记录的名称主值
② 作品      从"这个角色在哪个类里"读 —— 是类名，不是它成员里的那条 tag
③ 特征      成员里除作品外的那些，按 表一 排
```

| 规则 | |
|---|---|
| **② 从类读，不从成员第 0 位读** | 第 0 位与类名是同一件事的两种写法；以类为准，成员第 0 位只是它的索引 |
| **② 那一段若角色属于「未分类」→ 空着** | 不写"未分类"三个字进提示词 |
| **③ 里页「角色组」不出** | 也就是角色不会把别的角色带出来 |
| **① 不给中文名** | 出的是规范写法（`hakurei_reimu`）；中文名是给人看的，不进提示词 |

**例**（真实数据排出来的）：

```
【hakurei_reimu】博丽灵梦
 ① 角色名     hakurei_reimu
 ② 作品       touhou
 ③ [眼睛]      brown_eyes · red_eyes
    [头发]      long_hair(长度) · hair_tubes(默认) · black_hair(发色) · brown_hair(发色)
    [服装]      detached_sleeves
    [道具与装饰] hair_bow · red_bow
    （1girl 落在「人物与角色」页 —— 那页在表里，所以它**会**出，排在 ③ 的开头）
```

> 上一版设计里"人物与角色页不进表"，此处按"表里列了它 → 就出"处理。**要它不出，就把它从 §三 的表里拿掉**（一整页不出，比在页里挑词清楚）。

# 五、谁实现、谁是唯一入口

```
tag 模块：一份页序（常量）+ 一个动作「按渲染顺序排」
   ├─ 标签面板：已选的词走它
   ├─ 角色库：一个角色的整套词走它（并用动作「一个角色的词」拿 ①②③）
   └─ 识图模块：它打出来的标签走它     ← 装配层把这个动作递进去，识图不存表
```

**识图模块不认识 tag 模块**（它自己的规矩 3：核心不许 require 别的模块）。所以它**不存表**，靠装配层把"排序"这一个动作递进来 —— 与 [上层设计.md](../../文档/上层设计.md) 决定 47「切分只有一份，由装配层把装订模块的那一份递给翻译模块」同一条做法。

**排序递不进来时**：识图照常给标签，只是不排序（与"查词递不进来，中文名一律 null"同一条规矩）。
