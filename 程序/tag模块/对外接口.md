# 标签模块 · 对外接口

> 这份只写**怎么调**。设计（为什么是这样）见 [标签模块设计.md](标签模块设计.md)。

# 一、装配：这是一个六边形

```
        ┌─────────────── 门面（index.js）────────────────┐
界面 ──▶│  run(动作, 参数)  ·  actions  ·  describe()      │
─ 功能 ▶│  候选查询 / 唯一解析 / 认词                     │
        │  出词顺序：render.pages / sort / words           │
        └───────────────────┬───────────────────────────┘
                            │ 只认这套
                    ┌───────▼────────┐
                    │  核心 core.js  │  不认识盘、不认识文件
                    └───────┬────────┘
                            │ 端口（port.js）
                 ┌──────────┴──────────┐
         adapter-file.js        adapter-memory.js
             （盘上）                （内存）
```

**三条铁律**

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | **对外不管功能还是界面，都走同一套动作表** | 界面不 require 核心里的任何文件，它只认动作名 |
| 2 | **面子上不递内部件** | 出口冻住的，没有 `store` / `library` / `search` 这些口子 |
| 3 | **核心不认识存储** | 换个适配器，核心一行都不用改；测试用内存端口跑，证明得了 |

## 1.1 怎么装起来

```js
// 正规写法：装配层把端口递进来
const { createFilePort } = require('./adapter-file.js');
const { createTagModule } = require('./index.js');

const tags = createTagModule({ port: createFilePort({ root: '…/tag模块/data' }) });

// 便利写法：给个位置，内部自己装文件适配器
const tags = createTagModule({ data: '…/tag模块/data' });
```

| 参数 | 说明 |
|---|---|
| `port` | 一个端口：`read / set / remove / list / scan / status` 六件。缺一件当场拒绝装配 |
| `data` | 便利写法，等价于内部 `createFilePort({ root: data })`。**只有这一个名字，没有别名** |

**位置由装配层给，模块自己不找、不猜、不探测。**

## 1.2 端口长什么样

```js
read(key)        → { state: 'ok'|'missing'|'unreadable', value?, reason? }
set(key, value)  → { ok, reason? }
remove(key)      → { ok, reason? }
list(prefix?)    → [键名]
scan()           → { keys, temp, external }     // 磁盘上都有什么（体检用）
status(key)      → { key, state, reason?, frozen }
```

**三态读是硬要求，不是建议。** `missing`（确实没有）和 `unreadable`（读不懂）绝不能混成一个 ——
混了就会出现"坏文件被当成空、下一次写把它清光"。读不懂的键会被**冻结写**。

# 二、调用：两条等价的路

```js
// 路一：动作表（界面和功能都从这里进）
const r = tags.run('query', { 串: 'miku' });
if (r.ok) console.log(r.data);              // 成功：data
else console.log(r.code, r.reason);         // 失败：程序看 code，人看 reason

// 路二：直呼（写起来短一点，等价）
tags.query('miku');                 // 成功给数据，失败给 null（要理由就走 run）
tags.recognize(['hatsune_miku']);   // ['初音未来']
tags.positions('收藏').attach(1, 2, 'u1');
```

**每个动作的返回都是 `{ ok: true, data }` 或 `{ ok: false, reason, code }`。** 全模块**同步**、**不抛错**。

**失败要按 `code` 分支，不要按 `reason` 的文字猜**——`reason` 是给人看的话，改一个字不该让调用方断掉。全部码与理由原文的对应表在 [README.md](README.md) §4.3，码本身在 `error.js`，门面用 `tags.ERR` 交出来。

`tags.actions` 是全部动作名；`tags.describe()` 把整张表交出来：

```js
[{ 动作: 'query', 摘要: '查库：给一个查询串，出一组候选', 参数: ['串', '上限?'], 说明: { 串: '…', 上限: '…' } }, …]
```

**界面照着 `describe()` 就能画出该有的东西**，不必自己另写一份清单。

# 三、查询、唯一解析与认词

| 动作 | 输入 | 输出 |
|---|---|---|
| **`query`** | 一个查询串（+ 可选上限） | 一组候选：**记录**或**类** + 档位、字段、命中类型和命中词；带"还有更多" |
| **`resolve`** | 一个 tag 写法 | 唯一精确命中的 `{标识, 记录}`；歧义、近似或无匹配给 `null` |
| **`recognize`** | 一个词，或一批词 | 从 `resolve` 的同一条记录取主中文名；不能唯一解析给 `null` |

`query` 为近似检索保留候选；`resolve` 只按精确记录身份解析，不把连写近似候选当成用户选择。规范名称优先于别的记录里同写法的别名；其余名称别名与主中文名合并检查唯一性。别名及中文名的其余多值仍可用于 `query`，不会自动成为认词关系。

**候选有两种**（决定 121）：`类型:'记录'`（库里那一条，能选进提示词）与 `类型:'类'`（页底下的一个类，
点开 = 列它的成员）。搜 `touhou` 时两种并列都出 —— 它既是库里的一条 tag，也是页「角色组」底下的一个类
（那个类装着 311 个角色）。**类只索引 `类名`**，走同一套 5 档；同档内记录排在类前面。

```js
tags.run('query', { 串: 'miku', 上限: 30 });
// { ok:true, data:{ 候选:[
//     { 类型:'记录', 档:2, 命中:'名称', 命中类型:'近似', 命中词:'hatsune_miku', 记录:{…} },
//     { 类型:'类',   档:1, 类:{ ID, 类名, 页ID, 页名 } },
//   …], 还有更多:true, 合计:155 } }

tags.run('recognize', { 词: ['hatsune_miku', '1girl', 'zzz_没有这个词'] });
// { ok:true, data:['初音未来', '双马尾', null] }

tags.run('resolve', { 词: 'wrist_band' });
// { ok:true, data:{ 标识:1574, 记录:{…} } }，歧义与近似匹配返回 data:null
```

记录候选的 `命中` 保持现有字段，供界面继续使用。`命中类型` 为 `规范名`、`确认别名`、`主中文名`、`其他检索写法`、`近似` 之一；`命中词` 是词库里实际匹配的原写法。档位只表示文本匹配强度，不代表两个 tag 在绘画语义上等价。

**查库的 5 档**（序号越小越靠前，同档内比常用词 → 长度 → 主库优先 → ID）：

| 档 | 条件 | 例（查 `miku`） |
|---|---|---|
| 1 | **全等**：规范名称 / 主中文名 / 名称字段中的别名 / 其余中文写法完全相等；规范名称优先 | `miku` 这条记录自己 |
| 2 | **切词命中，且命中的是第一个词** | `miku_day` |
| 3 | **切词命中，且命中的是最后一个词或夹在中间** | `hatsune_miku`、`my_cat_ears` |
| 4 | **连写相等**：分隔符可以省（`fuhua` → `fu_hua`） | `hatsunemiku` |
| 5 | **兜底**：名称或中文名里含这个串（前缀、包含都在这档） | `mikusa`、`catapult`、`bobcat` |

> 切词命中排在兜底之前，否则 `mikusa` 这些会把 `hatsune_miku` 挤出前 30。

**查库最多 30 条**，多的用 `还有更多` 表示，**不分页**。**空查询给零结果**，不倒 30 条出来。
**认词只解析唯一身份**：规范名优先；其余只接受唯一名称别名或主中文名。近似连写只进候选，不用于自动认词。空输入给 `null`。
**认词一个字都不许崩**：给 `null`、数字、对象、空串、超长串，一律给 `null`。

# 五、记录长什么样

```
记录 = { ID, 名称, 中文名, 成员?, 成人?, 回显? }
```

| 字段 | 形状 | 说明 |
|---|---|---|
| `ID` | 数字 或 `u` + 数字 | 主库数字，自建库带 `u`。**永不改、不复用** |
| `名称` | 逗号分隔的字符串 | **第一个是规范写法**，其余是同一个词的别的写法 |
| `中文名` | 逗号分隔的字符串 | **第一个是主名**，其余是别称。可以是空串 |
| `成员` | ID 数组 | **只有组有这个字段**。可以是空数组 —— 空组也是组 |
| `成人` | `true` | 只有是的时候才有 |
| `回显` | `false` | 只有"不参与检索"的时候才有 |

**判据**

- **能删的只有自建库里的**（ID 带 `u`）。原有记录只能隐藏。
- **`edit` 是直接改库**，不是"存一份差异"。第一次改之前，模块自己把改之前的原文抄一份进修改库。
- **ID 由模块分配**，调用方不许自己造 ID。
- **"是不是组"看 `成员`**：带这个字段（空数组也算）就是组。**是哪种组由身份表回答**：
  在角色表里 = 角色组（`identity.isRole`），在系列表里 = 系列组（`identity.isSeries`），
  两张表都不在 = 用户自己建的组。`record.groups` 会把两条标记一起带上。

# 六、位置与渲染

**格里只有 ID 和顺序**。真正的数据在库里那一条记录上。

```
position.attach('收藏', 页ID, 类ID, 记录ID)      // 摆进去
position.members('收藏', 页ID, 类ID)            // → ['1', 'u3', …]
position.whereIs('收藏', 记录ID)                // → [{ 页, 页名, 类, 类名 }]
```

**悬空 ID 不在这儿处理**：成员被删了、被隐藏了，格里那个 ID 还在，**渲染时读一次、取不到就跳过**。
组、页、类三处同理，模块里只写这一条判断。

# 七、这一类错误长什么样

| `code` | `reason` 原文 | 什么时候 | 调用方怎么办 |
|---|---|---|---|
| `TAG_RECORD_MISSING` | `记录不存在` | 取/改/隐藏时 ID 不在库里 | 跳过 |
| `TAG_RECORD_READONLY` | `原有的记录不能删，只能隐藏` | 删主库里的记录 | 改成 `hidden.hide` |
| `TAG_NOT_MODIFIED` | `它没有被改过` | 还原一条没改过的 | 忽略 |
| `TAG_NOT_HIDDEN` | `它不在隐藏库里` | 恢复一条没隐藏的 | 忽略 |
| `TAG_ID_TAKEN` | `来源库里已经有这个 ID 了` | 还原时撞号 | 报给人看 |
| `TAG_NAME_REQUIRED` · `TAG_PAGE_NAME_REQUIRED` · `TAG_CLASS_NAME_REQUIRED` | `名称不能为空` / `页名不能为空` / `类名不能为空` | 新建时没给名字 | 让用户填 |
| `TAG_PAGE_MISSING` · `TAG_CLASS_MISSING` · `TAG_PAGE_OR_CLASS_MISSING` · `TAG_CLASS_NOT_IN_PAGE` | `页不存在` / `类不存在` / `页或类不存在` / `这个类不在这页底下` | 位置树对不上 | 刷新位置表 |
| `TAG_BAD_POSITION_ROOT` · `TAG_NEED_ID_LIST` | `位置只有这两种：分类 / 收藏` / `要一个 ID 列表` | 参数形状不对 | 改代码 |
| `TAG_NO_SUCH_ACTION` | `没有这个动作：xxx` | 动作名写错了 | 改代码 |
| `TAG_ACTION_FAILED` | 抛错那句话，或 `读不懂` / `权限` / `磁盘满` / `被占用` / `未知` | 动作自己抛错；或理由不在码表里 | 看 `reason`；**只有 `未知` 值得重试** |

**`读不懂` 意味着那一格坏了、写被冻结，重试永远失败，要报出来给人看。** 它的码是 `TAG_ACTION_FAILED`。

`status` 能看见坏键：`status.data.坏的键`、`status.data.野键`、`status.data.写剩的临时文件`。

# 八、一次完整调用

```js
const { createTagModule } = require('./index.js');
const tags = createTagModule({ data: '…/data' });

// 认词：给一段切好的词，拿中文名
tags.recognize(['hatsune_miku', 'twintails']);        // ['初音未来', '双马尾']

// 查库：用户敲字，出候选
const r = tags.run('query', { 串: 'miku' });
for (const row of r.data.候选) console.log(row.记录.ID, row.记录.中文名, `第${row.档}档`);

// 新建自己的词，摆进收藏
const made = tags.run('record.create', { 名称: 'my_oc', 中文名: '我的原创角色' }).data;
const 收藏 = tags.positions('收藏');
const 页 = 收藏.createPage({ 页名: '我的' });
const 类 = 收藏.createClass(页.ID, { 类名: '常用' });
收藏.attach(页.ID, 类.ID, made.ID);

// 改一条（原文自动进修改库），随时还原
tags.run('record.edit', { 标识: made.ID, 名称: 'my_oc', 中文名: '改过的名字' });
tags.run('modified.restore', { 标识: made.ID });      // 回到 '我的原创角色'

// 隐藏不需要的东西，随时扔回来
tags.run('hidden.hide', { 标识: 1 });
tags.run('hidden.unhide', { 标识: 1 });
```

# 九、这一版没对外的东西

| 没给 | 为什么 |
|---|---|
| 分页 | 30 条截断就够，分页要状态 |
| 匹配位置 / 高亮下标 | 位置是比对键上的，拿去高亮会对不齐；渲染层自己在原串上找 |
| 拼音、错字容错、打分模型 | 只做分档，不做调参 |
| 认词顺带返回 ID / 类目 | 认词只回答"这个写法有没有收录、中文叫什么" |
| 内部件（`store` / `library` / `search`） | 出口不漏内部件；要什么能力就加动作 |
