## 1. 一分钟认识这个模块

本地 JSON 文件库，管 AI 绘画标签（tag 与"组"）。

- **纯 Node、零依赖、全同步、对外不抛错**（失败一律 `{ ok:false, reason, code }`）
- **六边形架构**：门面只给一套动作表，核心不认识磁盘，存储靠端口注入
- **数据在盘上分三处**：`data/记录/` · `data/位置/` · `data/表/`，**记录按 ID 分片**
- **两组能力**：`query`（用户敲字出候选）/ `recognize`（机器给的词要中文名）

```
装配层 / 界面 / 测试
        │  只认这一套
        ▼
   index.js  ← 门面：run(动作,参数) · actions · describe() · query · recognize · positions · KEYS
        │
   core.js    ← 核心：不认识盘、不认识文件、不认识 node fs
        │  端口 port.js：read / set / remove / list / scan / status
   ┌────┴─────┐
adapter-file.js        adapter-memory.js
   │                        （测试用，可注入损坏值）
   ├── layout.js   逻辑键 ↔ 盘上路径
   └── file-io.js  读写一个文件（原子写、三态读、冻结）
        │
data/记录 · data/位置 · data/表 · data/index.json
```

**盘上长什么样**

```
data/
  index.json                 { 格式, 版本, 分片:1000, 计数器 }
  记录/主库/000.jsonl         1 – 1000 号，一行一条
  记录/主库/001.jsonl         1001 – 2000 号
  …                          共 53 片
  记录/自建库.jsonl  隐藏库.jsonl  修改库.jsonl
  位置/分类/<页ID>/页.json     页名、配色、类列表
  位置/分类/<页ID>/<类ID>.json [成员 ID]
  表/成人.json  角色.json  系列.json  注释.json  常用词.json
```

**分片是这笔设计的核心**：一条记录住哪一片由 `ID ÷ 1000` 算出来，
所以**改一条只重写它所在的那一片**（约 100 KB），删一条也不会让别的记录换片。

**改代码前先记住三条边界（设计决定 94 / 95 / 99）**

| # | 规矩 | 违反的后果 |
|---|---|---|
| 1 | 界面与测试**只从 `index.js` 进**，不许 require `core.js` / `library.js` 内部件 | 测试里有一条用例专门断言出口不漏内部件 |
| 2 | **出口不递内部件**：门面上没有 `store`/`library`/`search`/`port` | 同上，`tags` 是 `Object.freeze` 的 |
| 3 | **核心不许 require `fs`/`path`**，只能通过端口拿数据 | 换内存适配器就跑不动了 = 六边形破了 |

**已核对：`core.js` / `library.js` / `search.js` / `position.js` / `shadow.js` / `layout.js` 里没有任何 `fs` / `path` / `os`。**
只有 `file-io.js`（唯一碰文件的地方）、`port.js` 的布局分支、适配器、`tools/*`、`test/run.js` 碰得到文件系统——**这是设计意图，不是遗漏**。

### 1.1 它在整个项目里的位置（框架：三层结构）

本项目是**重写**：只认本仓库的代码，旧目录（`工具箱\`）里的任何实现与文档都不作参考。

```
① 模块层    ← ★ 就是这个模块。提供能力，互不认识，也不认识模型/界面/Agent 框架
② 门面层      工具清单（给模型）· 通用面板（给人）
③ 执行层      归一化参数 → 向模块要东西 → 调模块 → 整形结果
```

**由此推出两条最容易搞错的事：**

| 事 | 说明 |
|---|---|
| **本模块里没有"工具清单"** | 那是**门面层**的东西。`index.js` 的 `actions` / `describe()` 是模块自己的能力清单，**不是给模型的工具声明**，不要在这一层加工具元数据 |
| **一个工具可以用多个模块** | 工具数量由"要给模型几件事做"决定，不由模块数量决定；**不要为这个模块造一个壳** |

**框架十条边界规则里，与本模块直接相关的五条：**

| 规则 | 在本模块的体现 |
|---|---|
| 1 · 只交出一份清单 | `describe()` 算出来的，**没有第二份手写清单**（规则 7：要与别处对齐的清单不该存在） |
| 3 · 对外参数永远是**标识** | `position.attach` 收的是记录 ID，不是路径；**模块对外没有收路径的参数** |
| 6 · 不解析不属于自己的东西 | 库外数据的解析归产生它的模块；本模块只收"单个词" |
| 9 · 依赖由装配层传进来 | 位置的 `port` 也是外面递的；模块自己不找、不猜、不探测路径 |
| 10 · 不做兼容层、不留回退开关 | 重建就是重来，旧 ID 一律不沿用 |

> ⚠️ **框架文档本身还没有重写。** 上表这五条是从本模块的设计与代码里读出来的事实，**不是从某份文档抄的**。
> 哪天要立框架文档，应当**按新代码重新写**，而不是搬旧目录那份。

**依赖方向是单向的，不许出现反向 require：**

```
index.js → core.js → library.js → normalize.js
              │  ↘ search.js  ↗
              │  ↘ position.js
              │  ↘ shadow.js
              ↘ error.js        （门面自己用它把 reason 翻成 code）
              ↘ port.js → layout.js
                   │    ↘ file-io.js
                   ↘(只被 index / adapter 用)

adapter-file.js / adapter-memory.js → port.js     （适配器只实现端口）

normalize.js 是零依赖的纯函数叶子：core.js 与 port.js 都从它取 deepCopy。
error.js 也是零依赖的叶子，而且**只被门面用**：内部件照旧只报理由原文。
```

**存储这一层是三段，各管一件事**（别把职责混回去）：

| 文件 | 只管 |
|---|---|
| `file-io.js` | 一个文件怎么读写。**不知道数据是什么** |
| `layout.js` | 逻辑键对应哪个路径、怎么分片。**不碰文件系统** |
| `port.js` | 端口六个方法 + 合并写、按片写。**不知道业务** |

### 4.3 失败怎么分辨：按 `code` 分支，`reason` 只给人看

失败信封是两个字段：

```js
{ ok: false, reason: '页不存在', code: 'TAG_PAGE_MISSING' }
```

- **`reason`** 是理由原文，**一个字都不改**，给人和界面看
- **`code`** 是给程序分支用的，**全部定义在 `error.js`**，门面用 `tags.ERR` 交出来
- **表里查不到的理由落回 `TAG_ACTION_FAILED`**：内部件报的读写失败（`权限` / `磁盘满` / `被占用` / `未知`）、冻结键（`读不懂`）、以及任何没走到这里的抛错

| `code` | 什么时候 | `reason` 原文 | 调用方怎么办 |
|---|---|---|---|
| `TAG_NO_SUCH_ACTION` | 动作名不在动作表里 | `没有这个动作：<名字>` | 改代码 |
| `TAG_ACTION_FAILED` | 动作自己抛错；或理由不在表里 | 抛错那句话 / 见上 | 看 `reason` |
| `TAG_RECORD_MISSING` | 记录不存在，或它不在那个库里 | `记录不存在` | 刷新列表 |
| `TAG_NAME_REQUIRED` | 名称给了空的 | `名称不能为空` | 让用户填 |
| `TAG_RECORD_READONLY` | 想删原有记录 | `原有的记录不能删，只能隐藏` | 改走隐藏 |
| `TAG_NOT_HIDDEN` | 想还原一条没藏过的 | `它不在隐藏库里` | 刷新列表 |
| `TAG_NOT_MODIFIED` | 想还原一条没改过的 | `它没有被改过` | 刷新列表 |
| `TAG_ID_TAKEN` | 还原时来源库已经有这个 ID | `来源库里已经有这个 ID 了` | 报给人看 |
| `TAG_PAGE_MISSING` | 页不存在 | `页不存在` | 刷新位置表 |
| `TAG_CLASS_MISSING` | 类不存在 | `类不存在` | 刷新位置表 |
| `TAG_PAGE_OR_CLASS_MISSING` | 页与类至少缺一个 | `页或类不存在` | 刷新位置表 |
| `TAG_CLASS_NOT_IN_PAGE` | 这个类挂在别的页底下 | `这个类不在这页底下` | 刷新位置表 |
| `TAG_PAGE_NAME_REQUIRED` | 页名给了空的 | `页名不能为空` | 让用户填 |
| `TAG_CLASS_NAME_REQUIRED` | 类名给了空的 | `类名不能为空` | 让用户填 |
| `TAG_BAD_POSITION_ROOT` | 位置不是分类 / 收藏 | `位置只有这两种：分类 / 收藏` | 改代码 |
| `TAG_NEED_ID_LIST` | 重排没给数组 | `要一个 ID 列表` | 改代码 |

**只有 `TAG_ACTION_FAILED` 值得重试。`读不懂` 意味着该键被冻结，重试永远失败，要报出来给人看。**

**两条不算失败的**（有意如此，别去"修"）：

- `record.batch` 取不到的**静默跳过**，不报错
- `position.detach` 拿掉一个不存在的东西**算成功**（给回原样的表），和"删一个不存在的条目 = 未删除"同一条规矩

`ERR.理由` 是"理由原文 → 码"那张表；**同一句原文只出现在一处**，所以它可以直接当键。

**三处落点不能混**（这是"写一格不影响别的格"和"改一条只写一片"的实现方式）：

| 落点 | 粒度 | 为什么 |
|---|---|---|
| **位置** | 一个类 = 一个文件 | 改一个类不碰其他 198 个 |
| **记录** | 一片 = 1000 条 | 改一条只重写它那片约 100 KB |
| **表** | 一张表 = 一个文件 | 本来就小（成人 5.7 KB / 角色 366 KB / 系列 43 KB / 注释通常空） |

**分片怎么定位**（`layout.js`）：

```
记录住哪一片 = floor(ID ÷ 分片大小)      分片大小写在 index.json，现为 1000
第 9539 号   → floor(9539 / 1000) = 9   → 记录/主库/009.jsonl（9000–9999 号）
```

**这就是"删一条不会让别的记录换片"的原因**——片号由 ID 算出来，跟它在数组里的位置无关。

**记录的形状**

```
{ ID, 名称, 中文名, 成员?, 成人?, 回显? }
```

| 字段 | 形状 | 要点 |
|---|---|---|
| `ID` | 数字 或 `u`+数字 | **永不变、不复用**。`isOwnId()` [21](#L21) 判"能不能删" |
| `名称` | **逗号分隔**的字符串 | 第一个是规范写法（小写 + 下划线）；其余是同词别的写法 |
| `中文名` | 逗号分隔的字符串 | 第一个是主名；可在库里为空串 |
| `成员` | ID 字符串数组 | **只有组有这个字段**（`Array.isArray(record.成员)` 就是"是不是组"） |
| `成人` | `true` | 只有是的时候才出现 |
| `回显` | `false` | 只有"不参与检索"时才出现；`search.build()` 会跳过 [48](#L48) |

**字段顺序是固定的**（`layout.js` 的 `记录字段序`）：`ID, 名称, 中文名, 成员, 成人, 回显`。
一行一条的 diff 要稳，就靠这个顺序——**加字段请加在末尾**。

> ⚠️ **曾经有个 `子分类` 字段**（52,246 条全带一个 `sub:<64位哈希>`），
> 它只是 `tools/refactor.js` 建位置时的中间变量，**运行时没有任何代码读它**，
> 而且和"位置"里的归属重复。**已经丢掉**——主库从 10.31 MB 降到 6.44 MB。

**索引的三张表**（都在 `search.js` 的 `build()` 里建，全部可从记录重建）

| 表 | 键 | 用途 |
|---|---|---|
| `byKey` | 比对键 | 档 1 全等 |
| `byFlat` | 连写键（去掉分隔符） | 档 4 连写相等 |
| `segments` | 按 `_` 切开的段 | 档 2 / 3 切词命中 |

> `head`（首字符池）与 `byLength`（长度表）**已经删掉**：它们是给原 13 档的前缀分层用的，
> 砍成 5 档后没人读。同档内的名次由 `rankCompare` 在最后统一排，

### 5.1 盘上为什么这么排（给 AI 读、给 git 管）

**这是这份布局存在的理由，改布局前先读这一段。**

| 目标 | 做法 |
|---|---|
| **AI 能顺着路径找到东西** | 位置是**真目录**：`位置/分类/7/8.json` = 第 7 页第 8 类，看一眼就知道在哪个分类底下 |
| **改一个东西只产生一行的 diff** | 一行一条记录（`.jsonl`）。改一个字段 → **diff 加 1 行删 1 行**，AI 直接看出"第 9539 号的中文名变了" |
| **git 里每次提交只长一点点** | 分片。改一条只重写一片（约 100 KB），git 只存这一片的新 blob |
| **不重复存归属** | 记录上不带"我在哪个类"。归属从位置推出来（决定 108） |
| **名字不占路径** | 路径用 **ID**（`默认` 在 8 个页里重名、`视图/特效` 带斜杠，名字当不了路径）；**名字放文件内容里** |

**实测数字**（改一条记录）：

| | 旧布局 | 新布局 |
|---|---|---|
| 写入 | 9.95 MB | **111 KB** |
| 隐藏一条记录 | 9.95 MB | **0.1 KB** |
| git 每次提交 `.git` 增长 | 4.9 MB | **44 KB** |
| git diff | 加 1 行删 1 行 | 加 1 行删 1 行（只涉及那一片 + 修改库） |
| 数据总体积 | 10.31 MB / 210 文件 | **6.45 MB / 283 文件** |

**git 上真正贵的是 blob，不是 diff**：改一条记录，diff 只要 1 行，
但 git 每次提交都把**整个改动过的文件**存一份新 blob——所以旧布局每次提交要长 4.9 MB，
新布局只长 44 KB（只重写了那一片）。

**索引不进 git**：它是算出来的（决定 110），也不该占仓库。**`.gitignore` 里应当排除任何索引缓存文件。**

**账本在这儿**：`data/重构报告.json` 是 `tools/refactor.js` 的**构建产物**——记录源数据到库的每一步计数与对账。
**它不是运行时数据**（不在 `KEYS` 里，模块不读它），是给人核对用的。
**它不进 git**：`tag模块/data/` 已在 `.gitignore` 里，这份报告与库数据一样**只放在本机**。

## 6. 不许动的结构不变量

这十条是设计里定死的。**改代码时如果撞上它们，先回去问人，不要"顺手"改。**

| # | 不变量 | 落在哪 |
|---|---|---|
| 1 | **一处字段值只存一处**。类格里只有 ID 和顺序，不许加"这个 tag 属于哪些类"的反向表 | `position.js` |
| 2 | **ID 永不变、不复用、不补位**；两套 ID 空间（数字 / `u` 前缀）永不撞号 | `library.js` |
| 3 | **计数器随库同一次写落盘，只增不减，永不看库里的最大值** | `library.js` `create` [99](#L99) |
| 4 | **原有的记录不许删，只能隐藏**（判据是 ID 前缀，不是别的标记） | `library.js` `remove` [163](#L163) |
| 5 | **隐藏 = 剪切**（从来源库移出，整条进隐藏库）；**修改 = 复制**（原文抄一份，再直接改来源库） | `shadow.js` |
| 6 | **每条 ID 只抄一次原文**；还原之后删掉那份，再改会重新抄 | `shadow.js` `markOriginal` [144](#L144) |
| 7 | **隐藏库 / 修改库不被检索碰**：`search.build()` 用 `hidden.listHidden()` 排掉 [47](#L47) | `search.js` |
| 8 | **悬空 ID 读的时候跳过，写的时候不清理**（组员 / 页下类 / 类下成员三处共用一条规则） | `core.js`、`position.js` |
| 9 | **出口一律给副本**，不给库里的活对象 | `normalize.js` 的 `deepCopy` [121](#L121) |
| 10 | **归一化只产出比对键，永不替换真实文本**；不做连写拆词、不做错字容错 | `normalize.js`、`search.js` |

## 7. 会咬人的地方（读代码时最容易被绕进去的）

**① `core.js` 与 `index.js` 是两套字段名。** `core.js` 内部用 `page` / `pages` / `类`，`index.js` 转成对外的 `页` / `页列表`：

```js
// core.js L183 / L196  —— 这里就是转换点
return result.page ? { ok:true, 页:result.page } : { ok:true, 页列表:result.pages };
```

改返回字段名时**两处都要看**，否则会出现 `undefined` 而不报错。`tools/probe-shell.js` 就是专门探这个的。

**② 只有装配是"抛错"的。** `createTagModule` 参数不对会 `throw`（[363](#L363) / [367](#L367)）；**其余一切失败都走 `{ok:false,reason,code}`**。文档里的"全模块不抛错"指的是装配之后。

**②b 失败理由的原文改不得，码要跟着改。** `reason` 是那张表（`error.js` 的 `理由`）的**键**，同时 `test/run.js` 里有判据按子串认它。改一句人话要同时动：`error.js` 的键、`test/run.js` 的断言、`tools/probe-*` 里的子串。码本身只是 `ERR` 里的一个值，加一个码要在 `理由` 里配一句原文——判据会挡住"配了两句"和"配了不存在的码"。

**③ `library.update` 的 `onFirstEdit` 回调在写盘成功之后才调用**（[156](#L156)）。所以 `core.edit` 拿到的是"库已改、原文已抄"的次序，回滚点在这之前。

**④ 改一条记录是"整条覆盖"，不是逐字段合并。** 没给的 `成员` 会从原记录继承（[141](#L141)），没给的 `中文名` 会变成空。

**⑤ 写失败都做了回滚**：`create` / `update` / `remove` / `hide` / `unhide` 在 `set` 失败时把内存数组恢复原状。**改这些函数时要保持这个模式**，否则内存与盘会不一致。

**⑥ 索引失效靠四处 `invalidate()`**：`library.onChange`（[49](#L49)）、`hide` / `unhide`（[114](#L114) / [121](#L121)）、`rebuild`（[129](#L129)）、`positions.invalidate`。新增写路径时**别忘了挂上**，否则查库返回旧数据。

**⑦ ⚠️ 写主库要带提示：`set('主库', shell, { 记录: [...] })` 或 `{ 删掉: [id] }`。**
带了提示，端口按 ID 找到那几片重写；不带提示时端口只能拿盘上整库和传入的整库逐条比出改了哪些，再逐片写
（`port.js` 里那个兜底分支），写盘量大得多。`library.js` 与 `shadow.js` 的写路径都带了，新增的要跟上。

**⑧ 主库的"整库读"发生在装配时。** `library.load()` 读完整库（53 片）才交出门面，
之后 `record.get` 与认词都走内存里的索引，不再读盘。所以"读盘多少"看的是装配，不是单次 `record.get`。

**⑨ `position.js` 删页是遍历字典逐个删格**（`layout.js` 没有"按前缀列键"这个能力）。
删格失败会带 `还有格没删掉` 回来（例如那一格读不懂，删不动）——**别忽略这个字段**，它意味着盘上留了孤儿格。

**⑩ 空值不落盘。** 空数组发给 `set` 会转成删文件——
所以盘上不会有 `[]` 这种 0 字节文件，读回来是 `missing` 而不是 `unreadable`。
**"空类" = 字典里有、盘上没有那个格**，这不是丢数据（`position.members` 对取不到的格返回 `[]`）。

**⑪ 空查询的守卫是 `isSymbolOnlyKey`。** `toKey(';)')` = `')'`（`;` 折成下划线又被当首尾下划线剪掉），
`')'` 是限定词括号的一部分、库里到处都是 —— 所以折完只剩结构符号的查询直接给零结果。
**有实词字符的照旧放行**（`:3` 是库里真有的 tag，366 条）。

**⑫ 临时文件放在目标所在目录、名字以 `.tmp-` 开头**（`file-io.js` 的 `写文本`）。
早先的写法是 `<目标>.tmp-xxx`，当目标是**目录**（`记录/主库`）时改名会 EPERM —— **这个坑踩过一次**。
改原子写的时候注意别退回去。

**⑬ 读了文件之后立刻改名，在 Windows 上可能 EPERM。** 端口里凡"读一片 → 改 → 写回同一片"的地方
都靠 `file-io.js` 的缓存把读结果留在内存，写的时候不再读盘。**新增这类读改写要照做。**

**⑭ ⚠️ 写完盘必须 `library.重读(库)`。** 主库是按片写的，**只动被改的那一片**——
`library.main` 这份 shell 不会跟着变。拿它继续算（例如接着隐藏一条记录）就会**把别的改动覆盖掉、丢记录**。
`library.create` / `update` / `remove` 与 `shadow.hide` / `unhide` 都调了它。**这个 bug 踩过一次。**

**⑮ 空的页目录要删掉。** 删页不只是删 `页.json` 和格文件——目录留着会变成"盘上有、字典里没有"的野目录。
`port.js` 写位置树时用 `file-io.js` 的 `删空目录` 收尾。

**⑯ 一片读不懂 ≠ 整库不能用。** 端口遇到坏分片会：**能读的照读**（查询照常）、
把那个库标成只读（**拒写**，因为写下去会把读不出来的那片盖掉）。
别改成"一片坏了整库报废"——那等于一个文件损坏就丢掉 5 万条。

**⑰ 身份表是**两张**：`表/角色.json`（角色组 34115）与 `表/系列.json`（**作品** 4049）。**
`record.groups` 上那两个标记各查一张表 —— **两张都不认的才是用户自己建的组**（自建库里的组不在任何一张表里）。
存量库里 `表/角色.json` 曾经装的是系列组（来历见 [标签模块设计.md](标签模块设计.md) §七 决定 118），
补法是 `tools/拆两张表.js`（拆过之后再跑就是只核对不写）。

> ⚠️ **作品退回 tag 之后（决定 120、第八轮）**：`identity.isSeries` 答的是"**这条是不是作品**"，
> 不是"这条是不是组" —— 那 4049 条作品**没有 `成员` 字段**，`record.groups` 里一条都不出现。
> 谁再拿"是不是组"去推"是不是作品"，就是把两种意思搅在一起。

**⑱ 位置与检索是连着的：一改位置，两张索引都要作废。** 检索里有"类"这一种候选
（`search.js` 的 `queryWithClasses`，索引的是 `类名`），渲染顺序索引的是"谁在哪一页哪一类"。
所以 `core.js` 里凡改动位置的路径都走同一个 `位置改过了()`（作废渲染索引 + 作废检索索引），
**新增写位置的路径要挂上它**，否则搜出来的类与出词顺序都是旧的。

**⑲ 写主库有一道闸（`查片`）：一片里混进不属于它的 ID 就拒写。**
片号由 ID 算出来（`floor(ID ÷ 分片大小)`），所以"第 1 片里出现 2000 号"一定是写错了。
`改主库` 合并时**只并"属于这一片"的那几条改动**（`本片`），拿整批改动去并会把别片的记录推进来 ——
2026-10-12 踩过一次，主库从 5.2 万条涨到 20 万条，靠备份回滚。**这道闸与那个过滤都别删。**

## 8. 检索语义（最常被改、最容易改坏）

**两个入口不共用取数方式，共用数据来源与失效时机。**

- `query(串, {limit})`：默认 30 条，出 `还有更多`，**不分页**；空串给零结果（[128](#L128)）
- `recognizeOne(词)`：**一个字都不许崩**，任何异常给 `null`（[182](#L182)）；查 `byKey` 优先，再查 `byFlat`

**候选有两种（决定 121）**：`类型:'记录'`（那条 tag，能选进提示词）与 `类型:'类'`（那个类，点开列成员）。
搜作品时两种并列都出 —— `touhou` 既是库里的一条 tag，也是页「角色组」底下的一个类。
类只索引 `类名`（页名不进检索），走同一套 5 档；同档内**记录排在类前面**，截断在合并之后的 30 条上。

**5 档**（`search.js` 的 `query`；档位号只有 1–5，没有别的）

| 档 | 条件 | 例（查 `miku`） |
|---|---|---|
| **1** | **全等**：与 `名称` 主值 / `中文名` 主值 / 任一别称 / 其余中文名完全相等 | `miku` 这条记录自己 |
| **2** | **切词命中，且命中的是第一个词** | `miku_day` |
| **3** | **切词命中，命中的是最后一个词或夹在中间** | `hatsune_miku`、`my_cat_ears` |
| **4** | **连写相等**：下划线可以省 | `hatsunemiku` → `hatsune_miku` |
| **5** | **兜底**：名称或中文名里含这个串（前缀、"陷在词里"、包含都在这档） | `mikusa`、`catapult`、`bobcat` |

**同档内的名次：常用词表 → 长度短者优先 → 主库优先 → ID 升序**（`rankCompare`）。

> ⚠️ **常用词必须排在长度前面。** 反过来会把"名字短"当成"更相关"：
> 搜 `miku` 时 `hatsune_miku`（**常用词表第 0 名**）会被二十多条不出名的 `xxx_miku`
> 挤到二十名开外 —— 而它正是用户最常搜的那一个。
>
> **前缀与"陷在词里"不再分档**（原设计分 9/10 两档）：都落兜底档，同档内按常用词与长度分先后，
> `cat_ears` / `catapult` / `bobcat` 的相对次序不变。
>
> **空组、空类不是特殊档**：兜底档只在前面几档凑不够 30 条时才有内容。
>
> **档位号是搜索的一部分**：前端拿 `档` 决定要不要标"精确命中"，**改档位号就是改对外行为**，
> 要同步改 `test/run.js` 的断言与本节。
