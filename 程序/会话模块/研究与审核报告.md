# 会话模块架构研究与设计审核报告

日期：2026-10-13。结论：采用本仓库现有六边形做法，以会话为保存和执行归属单位；保留图片模块的独立物理归属；执行器与界面通过端口和唯一门面对接。规范见本目录设计、接口与对接实施，本报告不重复定义字段。

## 1. 研究范围与证据

只研究本仓库，未参考同级旧项目或 work 中的历史实现。重点阅读了以下代码与对应设计/接口：

| 模块/位置 | 架构级事实 | 会话设计采用的部分 |
|---|---|---|
| 图片模块 index/core/port/两个 adapter | 一份动作表；核心说作用域与 ID，适配器落盘；单写队列；目录是素材权威 | 单门面、函数端口、图片按会话归属、不建资产清单 |
| 图片模块设计 §6—§9、接口 §1.7—§1.8 | 跨存放地复制；没有引用计数/去重；删除允许部分结果，移出可见范围后不回滚 | 删除保图通过复制；跨资源失败报告真实阶段，不做假事务 |
| 主AI模块 core/preset/port/index | 默认工具表从模块动作现算；自己的草稿与存档分开；读不懂冻结写；内存适配可替换 | 派生数据不落第二份；草稿与已受理消息区别；三态读取和副本出口 |
| 世界书模块 core/worldbook/port/index | 自己解释世界书字段，对外交公开命中形状；装配提供依赖；存档/草稿含义明确 | 会话不解析世界书结构，由执行器保存本轮参考正文 |
| 装订模块 core/port/index | 核心编排真实业务；只收两个所需函数；在 finally 放闸门；失败交回输入 | 生命周期规则留核心，实际执行通过小端口，不把宿主对象塞进去 |
| 翻译、识图 port/core/README | 输入/模型/字节能力均注入，核心不找模型或路径；使用既有公共能力 | 执行函数与图片函数注入，缺执行明确报错，不探测其他模块 |
| ComfyUI core/port/index | 外部 HTTP 在适配器；核心出图有信号与任务标识；业务参数和运行控制目前部分混用 | 会话停止只要求取消可取消请求，不回滚外部任务；补门面信号接缝 |
| 对接层 宿主/模块清单/登记工具/主AI装配 | 模块清单造实例，describe 形成交付面；统一门面 run；主AI是单独装配的应用模块 | 会话应用模块按同样方式接入，保留原成功解包协议 |
| 对话管理模块/界面助手/页面接缝 | 已集中文字状态，但全文替换、全库快照、图片空实现与旧管理通道仍在 | 保留必要行为，重建契约并替换运行入口 |

研究中没有把现有模块的每个实现细节当成必须照抄的规范。例如标签模块的分片布局服务其大词库，会话不需要分片；主AI/世界书的只读默认库不适用于聊天；图片内存适配器现有文件帮助依赖也不要求新会话照搬。会话内存适配器只依赖数据纯函数。

## 2. 现有问题的实证位置

| 位置 | 触发情形与后果 |
|---|---|
| 对话管理模块/core.js `historyFrom`、页面 `assistant.run` | 输入带图，发送只交文字；纯图被当空输入 |
| 页/我们的模块.js `listSessionImages/resolveSessionImage/clearConversationImages` | 返回空或固定成功，没有真实素材操作 |
| 同文件 `deleteSession`、core 删动作 | 保图布尔没有进入真实删除；图片作用域未清 |
| 对话管理模块/adapter-file.js | 每次写整个会话数组，切换也重写正文；直接覆盖正式文件 |
| core `run/update/finally` | 进度通常到整轮结束才落盘；执行器可替换整份历史 |
| 登记工具.js 的 `编字节` 与界面助手 stringify | 图像 base64 进入轨迹；固定 1 MB 限制与图片模块无上限冲突 |
| 图片模块/core.js `清空` | 列发生在排队前；队列中较早的存图可能不在清空快照中 |
| comfyUI模块/index.js 与 core 的信号参数 | 核心有取消能力，但经统一动作门面调用没有完整转交 |
| 页/对话管理.js accept | 只比较单个进程版本号，新进程较小版本不能覆盖旧缓存 |

这些是源码确定的行为缺口；本轮没有启动真实浏览器重现全部情形，也没有把旧测试通过当作新联动已验证。

## 3. 简单方案的选择

| 问题 | 最终选择 | 删除/不采用的成本 |
|---|---|---|
| 单会话保存 | 平铺 ID.json 快照 | 额外空目录、全库重写、事件重放和压缩 |
| 文件可靠写入 | 同目录临时文件后改名 | 数据库、WAL、多级备份来源、跨模块事务 |
| 记录形状 | 有序图文 parts + 轮次 + 工具记录 | 展示表/history 表/图片发送表的人工同步 |
| 当前选择 | 现有界面 preferences | 服务端当前选择文件与默认目标猜测 |
| 素材归属 | 保留图片 session/gallery/vision；跨作用域复制 | 共享资源图、引用计数、孤儿清理 |
| 模型执行 | 一个执行函数和三种固定事实提交 | 新调度框架、通用事件总线、整份历史覆盖 |
| 保存失败 | 管理修改保原状，外部事实留内存并可存 | 自动重试或重跑副作用、伪装成功 |
| 归档 | 自包含 JSON，显式 base64 | ZIP 依赖、压缩适配层、归档文件缓存服务 |
| 导入失败 | 先有可见空会话承接素材 | 隐藏发布事务、孤立临时素材、自动补偿清理 |
| 发送唯一性 | 一条页面提交链 + 本会话运行位 | 自动请求重发、提交 ID 去重账本 |
| 历史配置 | 保存真实消息/工具/参考正文和实际模型信息 | 每轮完整 system/tools 快照与精确请求回放 |
| 框架连接 | 宿主直接装配，三个有实际职责的接入文件 | 只转发工厂参数的额外装配模块 |

该方案仍有明确成本：启动读全部会话文件；每个提交写该会话全文；完整归档在内存中构造，base64 增大归档体积。它适合当前本地个人项目，未声称解决海量历史、跨进程多写者或零丢失流式增量。只有实际需求出现时再调整保存方式。

默认主 AI 仍使用七个业务模块工具，会话与主AI属于应用模块；这保持现有框架分类，不新增 AI 自主管理会话功能。会话仍只定义一份完整动作清单，宿主装载即存在，没有基于“模型/界面”的两套动作实现或运行时可用性过滤。后续手工登记会话工具也必须使用同门面与声明。

## 4. 写入后的审核

审核基线：本轮新建的会话目录文档及本轮修改的旧文档入口/归档说明。工作区既有大量代码修改不属于本轮设计变更。按 code-review 的需求轴、仓库标准轴顺序自查；未使用子代理。

### 4.1 已修正的问题

| # | 轴 | 初稿问题 | 修正结果 |
|---|---|---|---|
| A01 | 标准 | 先前草案继续把模块管理动作放 `/对话/*` | 明确全部会话动作经宿主与 `/toolbox/调`，SSE 仅通知 |
| A02 | 标准 | 删除/归档的先后决定散在装配层 | 会话核心掌握生命周期，图片执行经端口，HTTP 只转交 |
| A03 | 标准/简洁 | 只含一个 JSON 的额外会话子目录、ZIP、服务端选择、提交去重库 | 改平铺文件、自包含 JSON、界面选择、单提交链与运行闸门 |
| A04 | 标准/简洁 | 新增仅转发参数的会话装配文件 | 删除该层，宿主直接构造；保留图片适配/执行/投影的真实职责 |
| A05 | 需求 | 停只取消模型下一步，实际可取消工具没有接到信号 | 明确运行上下文到 ComfyUI 已有 core 的转交与独立验收 |
| A06 | 需求 | 删除时排队上传可能重新产生无归属图 | 图片存动作内部执行接收函数；清空在原队列内枚举 |
| A07 | 需求 | 全局同一个响应版本会让其他会话更新压掉当前详情 | 列表/详情分开比较；实例和选择代次挡迟到响应；刷新合并不丢通知 |
| A08 | 需求 | close 拒绝全部提交会挡住自己的收口保存 | 只拒外部新写，内部 commit/finally 持续到收口结束 |
| A09 | 简洁 | 强行增加完整请求预览，实际页面无法直接复用 Node 字节投影 | 保留现有预设预览，格式说明与缺图状态可见；不加预览动作或准备端口 |
| A10 | 需求/简洁 | 提交真实工具事实时再次读图检查，用户删图会使已发生结果丢失 | 写事实只检查自身形状；保存时保证归属，后续缺失在读端表达 |
| A11 | 需求 | context 空串无法证明是否已提交一次 | 只允许非空参考提交，用原字段判重复，无额外状态表 |
| A12 | 需求 | 导入缺失图片仍可能沿用源活动 ID | 明确 null/missing 历史说明，不分配假图片实体，不建旧 ID 别名 |
| A13 | 文档 | 两个独立 Part 对象放在同一个 JSON 示例块，无法直接解析 | 改成合法 Part 数组，重新检查所有 JSON 示例 |
| A14 | 需求 | 工具图像入档失败可能被当作无副作用的普通工具失败 | 明确阶段、非字节原回执、已存部分与原错误的转交；不自动重取 |
| A15 | 需求 | 页面旧草稿请求可能晚于发送到达，使已发内容重新变成待发 | 同会话草稿与受理使用短提交链，新编辑排在受理之后；不引入多轮输入队列 |

### 4.2 仓库边界逐项检查

| 根规则 | 本设计对应位置 |
|---|---|
| 一份清单 | index 唯一动作表生成 run/actions/describe；宿主读同源 |
| 能力归属 | 图片 CRUD 在图片；会话生命周期在会话；模型协议/工具循环在执行适配 |
| 外部参数为标识 | 会话、图片都是 ID；导入给内容，根目录只在构造传入 |
| 决定在操作里执行 | 会话删动作保图/清图/删记录；图片存动作队列内执行接收决定 |
| 依赖传入而非判断模块装没装 | 三类端口显式注入，执行函数缺失有确定失败 |
| 只解析自己的数据 | 会话只解释 Session/归档/图片标记；图片业务字段翻译在装配适配 |
| 不维护重复清单 | 摘要、已发送、素材列表、history 现算；无资产索引 |
| 单一来源、无多级兜底 | 唯一会话目录、明确目标、正式文件读取、明确输出适配器 |
| 装配层递依赖 | 核心不找图片、模型、配置路径 |
| 无兼容和迁移 | 新实例与归档新 ID，旧运行代码接通后移除，旧本机数据不读不删 |

### 4.3 需求覆盖与余项

详细字段、默认值、错误码、工具状态推进、端口同步性、导入映射、缺图处理、部分失败及现有文件接入位置已确定。README 给出执行顺序，接口提供唯一数据契约，对接实施提供 30 个模块场景与 17 个集成场景。

没有留下“实现时选择 JSON 或 JSONL”“可以再决定放哪里”“是否兼容旧格式”等架构分叉。源码函数内部的普通算法写法由实施者按约定选择，不额外制定逐行代码模板。

本轮审核没有剩余需要用户裁决的架构冲突。尚未验证的是实现后的运行正确性、浏览器布局与真机模型/ComfyUI 联动；这些必须由下一对话按验收执行，不能用本报告替代。
