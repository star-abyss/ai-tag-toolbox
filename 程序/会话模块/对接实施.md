# 会话模块对接与实施

本文件规定独立宿主、执行器、图片及页面怎样接入。[接口.md](接口.md) 是数据契约，[设计.md](设计.md) 是生命周期规范。以下接入已实施；实际命令、结果与验证边界见 [实施验收.md](实施验收.md)。

## 1. 独立宿主装配

### 1.1 位置和实例

在 `对接层/cordis.patch.yml` 的 toolbox 配置增加唯一 `会话目录: '工具箱数据/会话'`。`读配置` 已按现有方式读取，宿主用 `path.resolve(项目根, 配置.会话目录)` 解析。缺配置是装配失败，不探测 `%APPDATA%/API/会话` 或旧目录。API、图片、世界书等现有位置保持原配置。

`对接层/模块清单.js` 仿照现有 `主AI` 导出会话应用模块描述：

```text
名字: 'session'
门面: '会话模块/index.js'
工厂: 'createSessionModule'
动作名:
  list:列, read:读, create:新, rename:改名,
  pendingQuestion:待答问题, answerQuestion:回答问题, cancelQuestion:取消问题,
  draft:草稿, send:发, stop:停, clear:清空,
  remove:删, save:存, export:导出, import:导入
```

它不加入七个能力模块数组。独立 `宿主.js` 在图片和主 AI 造好后装一次会话模块；会话的 describe/actions 加入宿主动作交付面和反查表。给 AI 的绘画业务工具由对接层单独定义，不从会话模块动作或七个模块动作自动生成。会话管理动作只给界面使用，不进入 AI 的业务工具表。

直接在 `宿主.js` 的装配位置从新模块 index 取工厂与文件适配器，调用会话图片适配与执行器工厂。不另建只转发构造参数的装配文件，不再次创建宿主、服务商、主 AI 或图片实例。

`宿主.js` 交出同一个 `门面.session`；`ready` Promise 供服务启动等待；close 供关闭时取消本轮。返回的 `宿主.清单` 从七个描述加会话描述现算，供动作翻译/登记使用；主AI的默认业务工具来源仍使用原七个描述，不复制会话动作定义。会话装不上记录在现有“装不上”列表，不返回伪造空会话或备用旧助手。

`对接层/index.js` 的 DSH apply 继续装七个能力模块与主 AI，继续用 DSH 会话；不装新会话文件适配器，不读取新独立会话根。两种模式不会对同一会话文件形成双写者。

### 1.2 参数类型和控件

类型在现有 `模块清单.js` 的 `参数类型` 按动作补充：

| 动作键 | 参数 | JSON Schema |
|---|---|---|
| session.draft / session.send | 内容 | array，元素为接口中的 Part |
| session.remove | 保留图片 | boolean |
| session.export | 会话列表 | array of string |
| session.import | 内容 | string，完整归档 JSON |
| session.待答问题 | 会话 | string |
| session.回答问题 | 会话、问题ID、答案 | string |
| session.取消问题 | 会话、问题ID | string |
| 其他会话参数 | 会话 / 标题 | string |

Part schema 明确 type、text、imageId；导入缺图形状只供历史/草稿恢复，send 的 schema 不接受空 imageId。接口运行检查仍处理错误输入，避免 schema 与实际类型不一致。

`界面字段` 为会话参数提供上下文控件，标题为文本，内容为结构化内容/文件输入适配所用字段。既有通用动作浏览器可以用 JSON 编辑数组，不能将 Part 数组误当普通字符串。默认值与说明读取 describe，不在页面复制动作参数清单。

## 2. 图片生命周期适配

新增 `对接层/会话图片.js`，`造会话图片({图片门面})` 返回接口中的五函数。只调用图片 `index.js` 公开 `run`；禁止引用图片 core/adapter 文件。

作用域唯一转换：`{存放地:'session',会话ID:sessionId}`；引用唯一转换：`{作用域,条目ID:imageId}`。sessionId 始终存在，不能落图片模块的 `_` 占位。

| 会话图片函数 | 现有图片动作及映射 |
|---|---|
| list | `run('列',{作用域})`；取 data.条目[].标识 为 ids |
| read | `取详情` + `取内容(original)`；字段映射为 ImagePayload，元数据原袋转交 |
| write | `存` 到目标会话；bytes→字节、filename→文件名、displayName→显示名、mime、width→宽、height→高、metadata→元数据，来源=import；取 data.标识 为 id |
| copyToGallery | read 源图后 `存` 到 gallery，来源=copy；返回 data.引用，不解释它 |
| clear | `清空` 该会话作用域；保留成功数据、失败 code/reason/details 和未回收警告 |

read/list 必须同步。直接使用模块 run，不经过异步的 `宿主.调` 包一层，否则同步导出契约会失效。write/copy/clear 等待原 Promise。

### 2.1 两个必要的图片模块修改

**A. 存图由接收方确认作用域。** 在 `createImageModule` 增加注入函数 `接收作用域?`，签名 `(规范化作用域) → {ok:true} | 失败信封`，同步。未提供表示调用方没有额外作用域所有者；图片模块仍按自身格式规则存放。提供的项必须是函数。

核心 `存` 在原有写队列的回调里、创建 staging 前调用它。失败原样返回，不产生实体。不能只在排队前检查，也不能在宿主外包拦截后宣称操作内部已执行决定。

独立宿主在造图片时传入闭包。对于 gallery/vision 返回 ok；对于 session，读取同实例会话列表摘要：目标不存在返回 `SESSION_NO_SUCH_SESSION`，读不懂返回 `SESSION_STORE_UNREADABLE`，删除中返回 `SESSION_BUSY`，其余接收。会话造好前不会调用写动作；闭包从同一装配对象取后来赋值的会话门面，不另找模块。

接口说明和图片 `存` 摘要说明这个已装配的接收规则，图片区显示返回理由。只检查目标归属状态，不判断模型想用哪张图片。

**B. 清空在队列内枚举。** 当前图片 core 的 `清空` 在排队前调用列；将这次列和删一批放在同一个原写队列回调内。这样排在清空前的已成功存图会被枚举，排在删除会话开始后的新存图会因 A 被拒绝。保持单一图片写队列，不另建闸门或事务。

这两处是本任务需要的现有模块改动；同步更新图片接口、设计与测试。图片模块不认识会话模块名字，不自行检查模块是否安装；它只执行传入函数。

## 3. AI 执行端口

将现有 `对接层/界面/助手.js` 中模型部分重构为 `对接层/会话执行.js` 的 `造会话执行({门面,清单,服务商})`，返回接口规定的执行函数。它不创建会话，不保存文件，不负责 SSE。旧助手文件在接通后移除。

### 3.1 一轮请求

1. signal 已停止则立即返回停止结果，尚未发 API。
2. 从主 AI 门面 `run('执行',{请求:'主AI'})` 取 preset；本轮用户 parts 中的 text 按顺序以换行连接，供世界书匹配。调用 `worldbook.run('执行',{请求:'主AI',文本,启用:preset.世界书})`，使用本轮预设的明确引用，保留已有身份/流程/前/后及按深度语义。会话没有私有预设或私有模型设置，继续读取现有主AI请求配置。
3. 从业务工具表筛出预设启用项，固定本轮工具、链路/模型设置。按深度正文通过 commit(context) 保存一次，等待成功。每次模型请求前重新读取会话图号；system 只列当前对话的图号与名称，不介绍图库或内部模块。
4. 从 read() 的唯一消息记录生成本次 messages；不是从页面快照取 history。每张当前会话图片按已有图号投影为原生图像块。按第 4 节转换。
5. 调用服务商.请求，传 signal。保存整条 assistant 消息和 pending 调用声明；等成功后逐个提交 running、执行工具、提交结果。
6. 工具回执已保存后再请求模型；没有工具调用则返回 ok。没有代码预置流程、自动识图或循环次数上限。

会话图片图号由图片模块持有；模型与界面读取同一图号。模型不接触图册标识；需要图像时用图号查询，并由请求投影把真实字节作为视觉内容交给模型。系统提示词不注入图库或模块说明。

独立执行端口始终使用新会话 ID，禁止从全局“当前会话”取目标。主 AI、世界书或工具原错误保持结构化 code/reason；无结构化异常才由核心转 EXECUTION_FAILED。

工具参数 args 原样记录；执行时 JSON.parse，必须得到对象。解析失败/非对象使用登记工具 ERR 新增的 `BAD_ARGUMENT:'TOOL_BAD_ARGUMENT'`；不存在的工具使用既有 `TOOL_BAD_TOOL_NAME`；执行异常已有 code/reason/details 则保持，没有则用既有 `TOOL_MODULE_FAILED` 配人话。这些都是已保存的工具 error 回执，交回模型，不把它们当成会话存储失败。空参数调用由模型给 `{}`，不从别处猜参数。

### 3.2 工具结果的图片格式

执行器用 `造绘画业务({门面,sessionId,提问,signal})` 取得业务工具表与执行器。工具定义由该表唯一提供；预设只决定启用项与参数说明，不覆盖业务参数类型或必填规则。执行不按模块名拆工具名，不登记七个模块动作。

生图业务工具通过图片模块保存输出，返回严格 `{type:'session-image',imageId}` 引用；执行器保存引用，不保存字节或 base64。失败 envelope 原样保存，保留 code、reason、details 及其他 JSON 字段。

每次模型请求把业务工具回执中的严格 session-image 标记解析成当前会话图片字节，在配对 tool result 之后追加含原生 image 块的用户视觉消息。工具 JSON 中只描述图号，不泄漏图片标识；请求投影不持久化 base64。有效业务回执不按长度隐藏或截断。

历史中不再属于业务工具表的旧模块调用及其配对 tool result 只从模型请求投影中省略，持久记录保留。当前业务工具与回执按完整顺序投影。用户取消 `ask_user` 时先保存取消回执，再结束本轮；同一 assistant 消息剩余待执行的调用由会话核心收口为已取消，不会继续发图。

### 3.3 停止信号的具体接线

绘画业务工厂接收本轮 `signal`，将其传入可取消的长操作。提问通过会话核心内的当前会话提问端口 await；界面经会话模块动作读取、回答或取消问题。signal 与业务参数分开传递，不进入模型 schema。

ComfyUI 已有 core 信号支持，但 index 尚未完整转交。修改 ComfyUI 门面的 run 及直呼接缝，使第三运行上下文（直呼时第二参数）的 `signal` 转交探活、看队列、看节点定义、出图和取图对应 core；出图由门面转成 core 现有的 `输入.信号`，其他方法转入其现有信号实参。取消对外从业务参数袋读取信号的另一来源，更新本仓库相应调用及接口回归。其他不使用该运行上下文的模块按 JavaScript 调用规则忽略第三实参，不扩展它们的业务参数。

服务商请求直接传本轮 signal。不能取消的短本地/图片操作实际返回后，仍先保存已经获得的结果，再检查停止并结束本轮；界面显示停止中直至收口。只有尚未得到结果的运行工具才标结果未确认。停止不回滚已经提交的 ComfyUI 外部任务，不自动执行清队列。

## 4. 请求与界面投影

新增 `对接层/会话投影.js`，仅使用会话公开记录与注入的取图函数，输出当前服务商使用的消息形状。它不引入会话内部 data.js。

| 记录 | 请求投影 |
|---|---|
| user.context 非空 | 在该 user 消息之前插一条 user 参考正文；历史只插一次 |
| user.parts text | `{type:'text',text}` |
| user.parts 正常 image | 按所属会话读取 original，附共享图号并转 `{type:'image',data:base64,mimeType}`；由现有服务商再转 image_url |
| user.parts 缺图/读取失败 | 文字块说明图片不可用与原 reason，不暴露图片存放标识；界面历史显示同一原因 |
| assistant.parts | 文字原样，图像引用转图号文字（缺图附原因），按原顺序拼正文；reasoning 交 reasoning_content |
| assistant 工具声明 | tool_calls；调用 id/name/args 原值，导入后用新 id |
| 已结束工具 | 声明后按原调用顺序追加 role=tool/tool_call_id/content=JSON.stringify(result) |
| 工具结果含图片标记 | tool JSON 以图号描述，配对结果后追加原生 image block 消息供模型视觉读取 |

pending/running 工具不进入下一次请求；执行器必须等本条声明的全部调用有结果才进行下一步。恢复/停止时核心会给出 cancelled/interrupted 结果，因此后续正常发送能得到闭合协议。

已撤销的非业务工具调用及其配对回执从模型历史投影中移除。当前业务工具调用与正常回执保留完整，不按回执长度隐藏或截断。助手图片仍在界面显示为产物；图像标记在每次模型请求时解引用为图像块。

此投影函数只供实际执行与协议回归复用，不新增完整请求预览接口。现有提示词页继续预览预设/世界书正文；会话区和工具轨迹显示模块交付面的格式说明。历史图文不自动裁剪、概括、去重或降级模型。服务商拒绝能力/大小，原样显示错误。

浏览器 `view-bridge.js` 按 Session.parts 生成既有 DSH 组件的 text/image/reasoning/tool-call 块，严格图片标记生成工具产图块；这是组件适配，不修改存档字段。组件只保留一个消息渲染器。停止、失败和未保存由轮次状态/保存状态展示，不造 assistant 文本消息。

## 5. HTTP 与 SSE

所有新会话动作：

```text
POST /toolbox/调
{模块:'session',动作:'发',参数:{会话:'s_…',内容:[…]}}
```

宿主现有 `调` 会解包成功 data，失败保持 `{ok:false,…}`。会话浏览器客户端明确按这个协议转换为自身调用结果；不能继续要求 HTTP 成功对象一定有 `ok:true`，也不能拿受理回执覆盖消息缓存。

移除独立界面的 `POST /对话/状态、新、换、发、停、改名、清空、删、导入、导出`，以及全部泛化 POST `/对话/*` 分支。只保留 `GET /对话/流` 作为通知传输端点，内部订阅门面。它不执行管理动作，也不发所有会话全文。

`/toolbox/调` 取消现有 96 MB 请求体限制，以接受自包含归档与图片；读完整请求体后按模块解析。其他链路/服务商端点的现有限制不在本次修改范围。上传会话图片也走 image/存 的同一 `/toolbox/调`，不新增上传路径或复用 `/存图` 另做会话能力。

服务监听前等待宿主会话 ready。若模块正常且列为空，宿主启动流程只调用一次新建；有坏文件时按有会话处理，页面显示问题，仍允许用户主动新建。

SSE 沿用同源令牌与既有页面生命周期管理，15 秒心跳等已有传输行为保持。不重新实现令牌或服务商配置。

### 5.1 客户端同步算法

重构 `页/对话管理.js` 为读取交付面并调用宿主的缓存适配器，保留现有平铺侧栏组件。缓存内容为 Summary 列表、当前 Session 副本、实例与通知版本；列表和当前详情分别记录已应用版本，不能共用一个响应版本闸门。当前 ID 由现有 preferences 保存。

1. 启动读取列表，恢复已保存且还存在的 ID；没有则选排序后的第一项。列表为空则明确调用新建，并选中返回 ID。
2. 打开 SSE。收到新实例就清掉旧缓存版本，重新读列表与当前详情；同实例只处理更高版本通知。
3. 通知后刷新列表；当前 ID 在变更中则读取它。列表响应只与列表已应用版本比较，详情响应只与该目标详情已应用版本比较。响应还必须匹配发请求时捕获的实例代次与选择代次；回执目标 ID 必须仍为当前选择。旧实例/旧选择的响应不能切回缓存。实例只由初次列表或 SSE 新实例通知切换，迟到读响应不能重置实例。
4. 切换只改变本地选择并读取该 ID，不执行后端换动作，不取消其他会话运行。
5. 当前被删除时选最新列表的第一项；删除其他会话保持选择；确实空列表时新建一次。对同一客户端合并正在进行的列表刷新/自动新建 Promise；刷新进行中到达的新通知积累待刷新标志与变更 ID，完成后继续读取，不丢弃通知。

写动作回执用于表示成功/失败及新 ID；真实列表和消息由同一门面读取刷新。浏览器刷新没有任何自动发送路径。网络失败没有自动重发。

## 6. 既有助手页与素材区

`我们的模块.js` 的 assistant 是 UI 适配器，接缓存和宿主动作，不继续保存一套会话。旧英文方法只在既有 UI 组件接缝处转换，不成为模块或 HTTP 兼容入口。同步读方法读缓存；需要动作的写方法等待 Promise。

必要映射：

| 现有 UI 方法/流程 | 新接法 |
|---|---|
| sessions/currentSession/currentId | 新客户端缓存投影；选择属于 UI |
| run({text,imageIds}) | 点击时固定会话及输入，转 Part[]，调用 session/发；支持纯图 |
| cancel | 固定当前目标 ID 调 session/停 |
| new/rename/clear/delete | 只调对应 session 动作；delete 透传保留图片布尔 |
| switchSession | 本地选择 + 读目标，不调用换接口 |
| exportSessions/importSessions | session 导出/导入；下载/读取 `.toolbox-session.json` |
| flushPersistence | 调 session/存 并返回真实结果，不能固定 true |
| listSessionImages | 调 image/列 的明确 session 作用域，缓存在页面；不能固定空 |
| resolveSessionImage | 由完整会话引用取图片详情/字节地址，缓存读取；不能返回 null 占位 |
| uploadSessionImage | 文件经 image/存；图库源先 image/取内容再 image/存到目标会话；成功后按用户意图加入草稿 |
| removeSessionImage | image/删；保留历史/草稿引用，由缺图状态显示 |
| saveSessionImage | image/取内容 + image/存到 gallery |
| clearConversationImages | image/清空当前明确作用域，返回真实回执；不同时清空消息或输入 |

所有图片动作仍经同一宿主 facade。素材列表的详情按需加载，无持久化镜像。对话区资产 URL/cache key 使用 `(sessionId,imageId,variant)`，不得从“当前会话、图库”等多级来源试探。

草稿 text/附件的权威由模块 draft 保存，页面只保留编辑中的副本。输入编辑在 change/blur 时保存。页面对同会话的草稿写与发送使用一条短 HTTP 提交链：点击时固定输入，在该链里先保存这份草稿（与最后成功保存内容相同则省略），再调用发；此后编辑的草稿排在这次受理之后。切换前等待当前草稿链保存成功；失败保留编辑副本、显示理由并保持当前会话。这只保证短写请求顺序，不排队多轮模型输入。页面刷新恢复最后一次成功保存的草稿，不承诺恢复尚未提交的每个按键。

受理前保留输入；受理成功后，仅当编辑副本仍等于这次提交内容才清除。失败保留文字和附件。输入组件、ui.sendDrafts、pendingDrafts 只作这个草稿的投影，移除各自独立变更并互相猜同步的路径。消息气泡按服务端消息 ID 唯一更新。

删除/导入中会话的素材操作按钮显示处理中，普通界面不同时发起相冲突的操作。图片“存”的接收决定仍由第 2.1 节在实际写入时执行，防止排队上传越过删除生命周期。

删图提示写明历史引用将不可用；清空记录提示写明保留图片；导入未完成与未保存状态可见。去掉现有“共享图片”统计与从图库删图会破坏会话的提示，因为跨作用域已经复制。

移除助手页关于排队、steer、autoLocalVision、旧任务提问等当前链路没有实现的分支与文案；不改这些控件在其他独立业务面板中的用途。保留 Enter 与按钮的一条提交链，运行中显示 busy/停止，不伪装已排队。
