# 会话模块接口契约

本文件是字段、动作、端口的唯一规范。状态转换和失败策略见 [设计.md](设计.md)，实际框架适配见 [对接实施.md](对接实施.md)。

## 1. 工厂和门面

CommonJS 入口仅 `index.js`。导出冻结对象：

```text
createSessionModule({ port, 图片, 执行?, 新标识?, 现在? }) → 冻结门面
createFileAdapter({ 根目录 }) → 存储端口
createMemoryAdapter({ sessions? }) → 存储端口
ERR → 冻结的错误码表
```

`port`、`图片` 必填；其方法在第 5 节定义。`执行` 未提供时管理动作仍存在，发返回 `SESSION_NO_EXECUTOR`；提供时必须是函数。`新标识()` 默认 `crypto.randomUUID()`，返回无前缀的字母数字/连字符串；核心为会话、消息、轮次分别加 `s_ / m_ / t_`。默认 `现在()` 为 `Date.now()`。传入项形状不符时工厂抛错，属于装配错误；运行期动作返回失败信封。

门面：

| 项 | 契约 |
|---|---|
| `run(动作, 参数={})` | 只执行第 4 节动作。同步读返回信封，写返回 Promise 信封 |
| `actions` | 冻结的动作名数组，由唯一动作表生成 |
| `describe()` | 副本数组，每项 `{动作,摘要,参数,说明}`；参数为中文名数组，可选项以 `?` 结尾 |
| `subscribe(fn)` | 订阅第 7 节通知，返回退订函数；观察者异常不改变操作结果 |
| `ready` | `Promise<{ok:true,问题:[…]}>`，启动加载与中断整理结束；整体目录读取失败返回失败信封 |
| `close()` | Promise；拒绝后续外部写动作，请求所有执行停止，内部 commit/finally 仍可保存，等待执行收口。不是动作表项目 |

不增加另一套直呼动作、`调` 别名或旧动作翻译。构造/订阅/关闭属于宿主生命周期接口；用户能力仅有一份动作表。

成功统一 `{ok:true,data:<该动作的数据>}`，失败统一 `{ok:false,code,reason,details?}`。`reason` 必含 `码: 人话`。公共回执外层字段中文；会话与端口数据作为程序结构使用下述英文键。所有输入先复制，所有读出口返回副本，不返回 Map 或内部对象。

ready 未结束时，读返回已加载且标 `就绪:false` 的数据，写返回 `SESSION_NOT_READY`；ready 整体失败后管理写返回原初始化失败。宿主必须等 ready 后提供服务。

## 2. 持久化形状

### 2.1 Session

```json
{
  "format": "toolbox-session",
  "version": 1,
  "id": "s_demo",
  "title": "新对话",
  "titleManual": false,
  "createdAt": 0,
  "updatedAt": 0,
  "messages": [],
  "turns": [],
  "draft": []
}
```

所有列出的字段必填。时间为非负整数毫秒；数组顺序就是记录顺序。会话/消息/轮次 ID 分别匹配 `^s_[A-Za-z0-9-]+$ / ^m_[A-Za-z0-9-]+$ / ^t_[A-Za-z0-9-]+$`。默认随机生成，重名或注入生成器返回非法 ID 报 `SESSION_BAD_ID`，不循环寻找兜底 ID。文件里的 id 必须等于文件名 ID，否则该文件读不懂。

`updatedAt` 在受理用户消息、追加助手消息、工具状态提交、改名、清空、最终收口、导入完成时更新。单独编辑草稿或重试保存不改变它。列表按 updatedAt 降序、ID 升序稳定排序。

运行位、AbortController、Promise 队列、未保存标记、最近保存错误、实例标识和通知版本只在内存，不进 Session 文件。

### 2.2 Part

正常内容仅两种：

```json
[
  {"type":"text","text":"原文"},
  {"type":"image","imageId":"img_demo"}
]
```

text 保留原始空格和换行；图片 ID 使用图片模块现有 `^img_[A-Za-z0-9-]+$`。消息图片所属会话来自外层 Session.id，不另存作用域。输入草稿和发送都使用 Part 数组，保留顺序，不按图片内容去重。

历史导入缺图的特殊记录：

```json
{"type":"image","imageId":null,"missing":{"originalId":"img_old","reason":"IMAGE_NOT_FOUND: 图片已删除"}}
```

这是历史缺失说明，originalId 只是原文，不是可定位标识。只由导入/读历史使用；`发` 接到此类待发块返回 `SESSION_IMAGE_MISSING` 并保留草稿。草稿可以保存这种历史块，便于导入后用户看见并移除。普通新引用被外部删图时不改写文件，解析时报告缺失。

### 2.3 Message

```text
{
  id: MessageID,
  turnId: TurnID,
  role: 'user'|'assistant',
  parts: Part[],
  reasoning: string,
  context: string,
  toolCalls: ToolCall[],
  createdAt: number,
  model: null | {provider:string, model:string}
}
```

全部字段必填。user 的 reasoning/context 初始为空、toolCalls 为空、model 为 null；context 可由本轮执行器提交一次参考正文。assistant 的 context 必为空。模型空正文但有工具调用时 parts 可以为空；纯推理回复也可记录。没有正文、推理、工具的空 assistant 消息视为执行端口错误。

消息 ID 由核心生成；执行器不能指定或覆盖。关联的 turnId 必存在。每轮恰有一条触发 user 消息，其 ID 等于 Turn.inputMessageId。后续消息属于该轮。

### 2.4 Turn

```text
{
  id: TurnID,
  inputMessageId: MessageID,
  status: 'running'|'complete'|'stopped'|'failed'|'interrupted',
  startedAt: number,
  endedAt: null|number,
  error: null|{code:string,reason:string}
}
```

running 的 endedAt 为 null；终态有结束时间，所属工具不能遗留 pending/running。failed 保存实际失败；interrupted 保存 `SESSION_INTERRUPTED`；stopped 保存 `SESSION_STOPPED`；complete 的 error 为 null。停止中是运行位的内存状态，不额外落一份轮次状态。

### 2.5 ToolCall

```text
{
  id: string,
  name: string,
  args: string,
  status: 'pending'|'running'|'complete'|'error'|'cancelled'|'interrupted',
  result: null|JSONValue
}
```

id/name 是模型工具声明的非空串；args 原样保存模型给的 JSON 文本，解析属于执行器。一个 assistant 消息内调用 ID 唯一；不同消息可以出现相同提供方 ID，定位必须同时给 messageId/callId。

pending/running 的 result 为 null。其他状态必须包含 result 字段，工具真实返回的 JSON null 也原样保存；cancelled/interrupted 的 result 是明确的停止/中断失败信封。complete/error 保存工具真实结果，不能被收口覆盖。

工具 JSON 值内部的图片标记：

```json
{"type":"session-image","imageId":"img_demo"}
```

导入的历史缺图可为 `{type:'session-image',imageId:null,missing:{originalId,reason}}`。只识别恰含这些字段的标记；普通业务对象即便有名为 type 的字段也不被当作图片。标记必须由装配层回执格式化产生，不能包含原图 base64。其余 JSON 作为不透明业务值保存。

## 3. 运行读取回执

以下字段用于动作回执，不是 Session 文件结构：

- `实例`：本门面实例创建时生成的标识；同一实例不变，重建实例改变。
- `版本`：内存非负整数，初值 0；每次可见状态变化加一，包括停止请求、未保存事实、写入成功、导入过程会话加入/完成及删除。失败且没有状态变化不加。
- `就绪`：启动恢复是否结束。
- `运行状态`：`空闲 | 运行中 | 停止中 | 删除中 | 导入中`。已经结束轮次的结果读 turns。
- `未保存`：内存有尚未成功写入的事实；`保存错误` 为 null 或失败信封。

对一个读不懂文件，列表项仍保留标识，标题为标识，消息数/更新时间为 null，`读不懂` 为原因串，`冻结:true`。不把它计为零消息的普通会话。

## 4. 唯一动作表

`会话` 参数为会话 ID 串，始终显式传入；没有“当前”的替代参数。未列出的参数没有额外意义。所有动作摘要和参数说明由 index.js 同一动作表提供。

| 动作 | 参数（? 可选） | 同步性 | 成功 data |
|---|---|---|---|
| 列 | 无 | 同步 | `{会话:Summary[],总数,实例,版本,就绪,问题:[]}` |
| 读 | 会话 | 同步 | `{会话:Session,待答问题:null|Question,运行状态,未保存,保存错误,实例,版本,就绪}` |
| 待答问题 | 会话 | 同步 | `{会话ID,问题:null|Question}` |
| 回答问题 | 会话、问题ID、答案 | Promise | `{会话ID,问题ID,已回答:true}` |
| 取消问题 | 会话、问题ID | Promise | `{会话ID,问题ID,已取消:true}` |
| 新 | 无 | Promise | `{会话:Session}` |
| 改名 | 会话、标题 | Promise | `{会话ID,标题}` |
| 草稿 | 会话、内容 | Promise | `{会话ID,草稿:Part[]}` |
| 改消息 | 会话、消息ID、文本 | Promise | `{会话ID,消息ID}` |
| 发 | 会话、内容 | Promise | `{会话ID,轮次ID,消息ID}`，表示已保存并受理 |
| 重新生成 | 会话、轮次ID | Promise | `{会话ID,轮次ID,消息ID}`，表示已保存并受理 |
| 停 | 会话 | Promise | `{会话ID,已请求:boolean}` |
| 清空 | 会话 | Promise | `{会话ID,已清空:number}`，数字为清空前消息条数 |
| 删 | 会话、保留图片? | Promise | `{会话ID,已删:true,已保留:JSONValue[],图片回执:JSONValue}` |
| 存 | 会话 | Promise | `{会话ID,已保存:true}` |
| 导出 | 会话列表 | Promise | `{内容:string,会话数:number,图片数:number}` |
| 导入 | 内容 | Promise | `{会话ID列表:string[],已导入:number}` |

Summary 的普通项为 `{标识,标题,消息数,更新时间,运行状态,未保存,冻结:false,读不懂:null}`；冻结项按第 3 节。`问题` 列出当前未解决的 `{会话ID,code,reason}`，从冻结条目和当前未保存错误计算，不维护另一张历史问题表；成功保存后相应保存问题消失。ready.问题 是启动结束时的这份快照。根目录失败直接返回失败，不返回假空列表。

Question 为运行态 `{问题ID,问题,选项}`，只保存在当前进程，不写入会话文件或导出归档。问题通知经会话版本变化发送；界面用同一会话的显式 ID 读取与回答，切换会话不会转移问题。取消问题使等待中的 `ask_user` 工具收到 `BUSINESS_CANCELLED`，工具回执保存后当前轮停止，未执行的后续工具不运行。停止或关闭会话也会结束等待。

### 4.1 参数与行为

- **新**：创建 title=`新对话`、titleManual=false，时间为现在，messages/turns/draft 为空；先存成功才进入列表。
- **改名**：标题必须是有非空白内容的字符串；保存 trim 后的全文，titleManual=true，不截断标题。
- **草稿**：内容必须为 Part 数组；整袋替换。可以为空。成功后保存副本；不读取图片检查存在性，不改变历史。
- **改消息**：文本必须是字符串，原样保留空格与换行。目标必须是用户或助手消息；将文本写到首个 text part 的位置并移除其余 text part，若没有 text part 则追加一块。其他 part、消息字段、ID、轮次、上下文及后续消息不变。空助手正文仍须有图片、推理或工具内容使其符合消息形状。执行中返回 `SESSION_BUSY`；不触发模型。
- **发**：内容必须有一张正常图片或一段非空白文字；每个普通图片块在本会话图片端口读取成功才受理。相同图片出现两次保留两次。只有 title=`新对话` 且 titleManual=false 时自动标题：首个非空白文字的首行 trim 全文，纯图使用 `图片对话`。
- **重新生成**：目标轮次必须存在且已结束，可以没有助手输出。保存重新执行状态时清空原用户消息上的旧参考正文，使用当前用户 parts 重新执行；执行器读取到目标轮之前的消息、目标用户消息和本次新助手消息，不读取目标旧助手回复与后续轮次。新助手消息插在原用户消息之后、后续对话之前；不新增用户消息，不修改草稿及后续消息。首条新助手消息写盘成功时替换目标轮已有的助手消息；此前失败保留旧回复，替换后工具提交失败则保留已经发生的新事实。提交形状沿用 `发` 的受理回执。
- **停**：不存在会话报错；没有本轮执行返回已请求=false；已有停止请求仍返回 true。直接 abort，随后发布停止中状态；不等待本轮完成，不操作删除/导入任务。
- **待答问题**：读取目标会话当前的运行态问题；没有问题返回 null。
- **回答问题**：问题 ID 必须匹配目标会话当前问题；答案为非空字符串。回答只唤醒该问题对应的本轮。
- **取消问题**：问题 ID 必须匹配目标会话当前问题；取消后 `ask_user` 保存失败回执并停止本轮。
- **清空**：保留会话身份和标题，messages/turns/draft 同时清空；素材不动。
- **删**：保留图片缺省 false，必须是布尔；允许删除读不懂的文件。保留图片的结果引用由图片端口给出，核心不解析。无回收站的警告保持在图片回执内。
- **存**：把本会话当前内存快照写入端口；用于未保存内容重试。会话运行中也可用，不能重启执行。
- **导出**：会话列表是非空且无重复的 ID 数组，按输入顺序导出；不隐式导出全部。读不懂、删除中、导入中的目标返回失败/busy；正常运行中可以导出当时快照。图片图号与高水位由图片模块列出后写入归档。
- **导入**：内容是第 6 节 JSON 文本，不接受路径或其他旧格式。多项顺序导入，遇到失败即停止；已完成项与当前可见的部分会话在 details 中返回。

发/清空/删遇到本会话在执行或管理中的重入返回 `SESSION_BUSY`，不排队成第二轮；不同会话可独立执行。删除/导入占用该会话管理位，其他写动作返回 busy；普通短提交按顺序等待。读一直可用，显示真实运行状态。

### 4.2 错误码

| ERR 键 | code | 使用场景 |
|---|---|---|
| BAD_ACTION | SESSION_BAD_ACTION | 动作不在唯一动作表 |
| BAD_ARGUMENT | SESSION_BAD_ARGUMENT | 必填/字段类型/归档结构不符 |
| BAD_ID | SESSION_BAD_ID | 自己生成的 ID 非法或重名 |
| NO_SESSION | SESSION_NO_SUCH_SESSION | 目标不存在 |
| NOT_READY | SESSION_NOT_READY | 初始化未结束 |
| CLOSED | SESSION_CLOSED | 关闭后的写动作 |
| BUSY | SESSION_BUSY | 同会话重入或管理中 |
| NO_EXECUTOR | SESSION_NO_EXECUTOR | 没有传执行函数 |
| EMPTY_INPUT | SESSION_EMPTY_INPUT | 本次内容没有文字或图片 |
| UNREADABLE | SESSION_STORE_UNREADABLE | 会话目录/文件不可读或格式版本不符 |
| WRITE_FAILED | SESSION_WRITE_FAILED | 会话快照写入失败 |
| REMOVE_FAILED | SESSION_REMOVE_FAILED | 会话文件删除失败 |
| BAD_UPDATE | SESSION_BAD_UPDATE | 本轮提交目标、字段或状态顺序错误 |
| EXECUTION_FAILED | SESSION_EXECUTION_FAILED | 执行端口抛出未结构化异常或正常返回却遗留工具 |
| STOPPED | SESSION_STOPPED | 用户/宿主停止，及尚未开始工具的回执 |
| INTERRUPTED | SESSION_INTERRUPTED | 重启中断，或已开始工具结果未确认 |
| IMAGE_MISSING | SESSION_IMAGE_MISSING | 导入的缺图块进入本次待发内容 |

图片端口返回的失败 code/reason 原样向外转交，保留其 details；会话模块可在外层 details 加阶段、已完成项及目标。不能把所有图片错误都吞成一个通用错误。

## 5. 注入端口

### 5.1 存储 port

| 方法 | 返回 | 同步性 |
|---|---|---|
| `list()` | `{ok:true,ids:string[]}` 或 `{ok:false,reason}` | 同步 |
| `read(id)` | `{state:'ok',value:Session}` / `{state:'missing'}` / `{state:'unreadable',reason}` | 同步 |
| `write(id,value)` | `{ok:true}` / `{ok:false,reason}` | Promise |
| `remove(id)` | `{ok:true}` / `{ok:false,reason}` | Promise |

适配器只管理自己的 Session 文件，不管理图片、草稿偏好文件或历史 API 目录。read 的 JSON 编解码在适配器，字段格式检查在 data.js。缺文件与读不懂不同。remove 缺文件视为已不存在；其他 I/O 失败明确报告。

文件与内存实现都复制 value，遵循相同返回形状。内存工厂 sessions 缺省为 []，可以注入初始 Session 数组；坏读/坏写测试通过包装端口方法模拟，不为生产接口增加故障开关。

### 5.2 图片生命周期端口 图片

这些是会话需要的五个函数，不是另一份图片动作表。实际适配放 `对接层/会话图片.js`，调用图片模块公开门面。

| 方法 | 成功 data | 同步性 |
|---|---|---|
| `list(sessionId)` | `{ids:string[]}` | 同步 |
| `listNumbered(sessionId)` | `{images:[{id,number,displayName,filename}],highWater:number}` | Promise |
| `read(sessionId,imageId)` | ImagePayload | 同步 |
| `write(sessionId,payload)` | `{id:string}` | Promise；归档 payload 含 number 时按原号导入 |
| `restoreNumbering(sessionId,{highWater})` | `{highWater:number}` | Promise；恢复已删除图号留下的编号空位 |
| `copyToGallery(sessionId,imageId)` | 不透明的图库引用 JSON | Promise |
| `clear(sessionId)` | 图片模块清空回执原数据 | Promise |

所有返回采用 `{ok:true,data}` 或原失败信封。`list` 顺序采用图片模块现有列顺序。read 只读 original，并组合公开详情；write 产生新图片 ID，原字节不变。clear 的部分失败与未回收语义原样保留。

ImagePayload 的字段：`bytes:Uint8Array`、`filename:string`、`displayName:string`、`mime:string`、`width:number`、`height:number`、`metadata:JSONValueObject`；`read` 另带当前 `number:number`。metadata 只整体传递；会话不解析它。source 在实际 write 时由适配器固定为 import，copyToGallery 固定为 copy。图片的 checksum、内部 format、variants、旧 entryId 不从归档覆写。

图号与 `highWater` 由图片模块持有。归档导入通过图片模块的专用写入口按原号写入，再调用 `restoreNumbering` 恢复最高已分配号。已删除图号不回收，归档不会重新编号。

### 5.3 执行函数

```text
执行({sessionId,turnId,inputMessageId,signal,read,commit,notify,提问})
  → Promise<{ok:true} | {ok:false,code,reason}>

read() → Session 副本
commit(event) → Promise<{ok:true,data} | 失败信封>
notify() → void
提问.ask({问题,选项},signal) → Promise<{ok:true,data:{答案}} | 失败信封>
提问.read() → null | {问题ID,问题,选项}
```

read/commit 已绑定本轮，不接受另一个会话/轮次目标。执行函数不保存盘、不改会话文件。收到 commit 失败立即返回该失败；关闭/停止时遵循 signal。执行函数抛错由核心收成 EXECUTION_FAILED，实际结构化 API 错误应返回原 code/reason。

`notify()` 发布本会话的运行时变化通知并递增版本，不写入消息或会话文件。执行器先更新自己拥有的运行时进度，再通知界面重新读取；已结束轮次的迟到通知忽略。会话模块不解析业务进度内容。

commit 仅三种确定事件：

| kind | 输入 | 成功 data | 限定 |
|---|---|---|---|
| context | `{kind:'context',text:非空string}` | `{消息ID:inputMessageId}` | 只写触发 user 的 context；原字段非空时拒绝再次写，且在任何 assistant 提交之前；空参考不提交 |
| message | `{kind:'message',parts:Part[],reasoning:string,toolCalls:[{id,name,args}],model:null或模型对象}` | `{消息ID:新ID}` | 核心补 role/turnId/time/context，工具统一初始 pending/result=null |
| tool | `{kind:'tool',messageId,callId,status,result?}` | `{消息ID:messageId,调用ID:callId}` | pending→running，无 result；running→complete/error，必须有 JSON result |

message 中的图片来自本会话落盘返回的引用，不接受任意 Buffer。核心检查自己的字段与标记形状，不再通过重新取图否认已经发生的事实；图片保存时的归属由执行器输出适配保证。若用户此后明确删图，引用允许悬空，在读取/显示时报告缺失。工具结果的其他 JSON 字段不由核心解释。

迟到提交、上一轮提交、终态工具再改、在其他消息里找相同 callId 都返回 BAD_UPDATE；不会改过去的事实。

## 6. 完整归档格式

导出返回 JSON 文本：

```text
{
  format:'toolbox-session-archive', version:2,
  sessions:[
    {
      session:Session,
      imageNumberHighWater:number,
      images:[
        {
          id:源图片ID,
          number:number,
          filename,displayName,mime,width,height,metadata,
          base64:原图字节的base64
        }
      ],
      missing:[{id:源图片ID,reason:读取失败理由}]
    }
  ]
}
```

sessions 非空；每项字段必填。images 是图片端口列出的全部现存素材。missing 是 messages.parts、toolCalls.result 的图片标记及 draft 中引用但不存在于素材列表的正常图片 ID，去重后按 ID 排序；之前已经导入为 null/missing 的块原样保留，不再分配活动图片 ID。

对列出的现存图片，read 失败就导出失败。仅“引用本来就不在素材列表”记录 missing。归档无路径、派生变体、API 密钥或实例运行对象；base64 只属于这个显式归档格式。

导入只接收 version 2；旧版归档没有原图号与已删图高水位，不执行猜测式重编号。导入先检查 version/字段形状/自身 ID 关联/图片映射完整性/非空标准 base64 解码，再发生副作用；base64 要求解码后再标准编码与原串相同，不接另一套转义格式。不校验图片像素内容、不设数量或文件大小限制。每个正常图片引用必须在 images 或 missing 中；同项图片源 ID 不重复，images 与 missing 不重叠。Session 内消息/轮次 ID 唯一，关联闭合。归档中的会话 ID 在包内唯一。

重建位置只有以下五处：

1. Session.id；Message.id；Turn.id；Turn.inputMessageId；Message.turnId。
2. 每项 ToolCall.id，分配 `tc_<新标识>`；在模型请求投影中声明/回执使用同一新值。
3. Message.parts 的 imageId。
4. draft 的 imageId。
5. ToolCall.result 内严格匹配的 session-image 标记。

导入图片仍重建活动 ID，但保留每张原图的 number，并通过图片模块恢复 imageNumberHighWater。因此历史文本中的“图5”仍指向原来的图5；已删图片留下的空号不被复用。

正常源图通过图片端口 write 得到新 ID；missing 源图变成第 2 节 null/missing 记录，保留原始缺失理由。其余正文、context、reasoning、args 和不透明业务结果保持原文，不搜索替换字符串。新会话的 createdAt/updatedAt 为本次导入时间；历史消息、轮次的时间保持原值。进行中的轮次按启动恢复规则转中断；已结束状态保持。

导入失败 details 统一为：

```text
{
  阶段:'新建'|'图片'|'记录',
  已导入:string[],
  部分会话:null|string,
  已存图片:string[],
  来源会话:string
}
```

结构检查失败没有任何新会话或图片。处理某项期间失败，则已完成项不回滚，当前“导入未完成”会话与素材保留可见。先创建空会话失败时部分会话为 null，已存图片为空。

删除失败 details 至少为 `{阶段:'列图片'|'保图'|'清图'|'删记录',会话ID,已保留:[],图片回执:null|JSONValue}`；保留原失败 details 时放入 `来源详情`。无关错误不强塞这些字段。

## 7. 变化通知

```text
{实例:string,版本:number,变更:string[],已删:string[],待答问题变更?:[{会话ID:string,问题:null|Question}]}
```

一个状态提交对应一个通知；数组中的 ID 去重。仅改名/草稿/执行进度也发变更；删除发已删。subscribe 本身不立即回调，SSE 建连适配器订阅后立即发送 `{实例,版本,变更:当前列表所有ID,已删:[]}` 初始通知。版本只用于同实例排序，不能跨重启比较。

提问出现或关闭时通知额外带 `待答问题变更`；关闭用 `问题:null`。其他状态更新不带该字段。通知没有消息正文、当前选择或图片字节。页面从同一门面读取列表和当前目标会话；具体 HTTP 外形沿用宿主现有解包行为。
