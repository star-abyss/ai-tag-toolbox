# 翻译模块 · 设计

> 字段和动作形状见 [接口.md](接口.md)。设计理由在这里；实现代码注释只描述程序行为。

## 一、职责

翻译模块编排本地翻译：从装配层注入的文本处理端口切分输入，按方向查词或调用本地模型，再调用共用拼装生成译文和对应表。模块不认识同级模块名称，不访问路径，不拥有模型加载与页面输入状态。

装订模块和翻译模块共用同一份文本处理能力。装订把待译项交给 AI 并沿用 AI 的原词键值报文；翻译模块把待译项交给本地模型，以独立 `id` 收发，避免重复词混淆。界面通过各自动作取得回执。

## 二、数据流

```text
装配层
  ├── 装订门面的文本处理
  ├── 标签查词（可选）
  └── 本地模型端口（可选）
          ↓ 注入
翻译门面 → 方向与来源判断 → 待译单元 → 按 id 归位 → 共用拼装
                                            └→ 译文、表、统计
```

纯文本端口是一个依赖注入接缝：模块通过四个函数完成切分、拼装、方向推断和是否需要翻译的判断。核心不自行 require 同级模块，也不维护第二套切分逻辑。

## 三、单元与范围

共用切分扫描原文并记录每个单元的标识、壳、词、原文范围及词范围。`标识` 在一次结果中唯一；重复词各自有独立标识。位置是原文 UTF-16 下标，左闭右开。

原文范围包含完整 tag 或短语的壳，不含外围空白和项间分隔符；词范围只覆盖会被替换的内容。拼装按词范围替换，其他字符直接从原文保留，包括壳、分隔符、空项、外围空白及外围换行。词范围内的文本由对应译文替换。退化状态由切分结果明确返回。

装订 AI 端口当前使用原词键值表，保持模型提示词报文形状；其结果与本地结果都必须由同一次拼装生成回执及范围表。AI 缺少个别键或值非字符串时按现有策略保留该原词。本地端口使用 `{id,text}`，任何待译单元缺失或返回空译文均失败并携带输入原文。

## 四、方向与选词

`auto` 对完整输入进行方向判定，实际方向写入回执；用户明确指定方向时使用指定值。

- `en-zh`：精确查词命中时使用标签中文名。未命中的英文片段交英中模型；混合单元中的已有中文片段保留。
- `zh-en`：中文片段交中英模型；混合单元中的已有英文片段保留。中文词库只提供中文名，不作为英文译文。

模型适配器在混合单元内部按语言片段翻译来源语言文字，保留已有目标语言片段及外围格式，并对整个单元按其 ID 返回一条译文。纯英文或纯中文句子作为整体翻译，不逐词碎片化；模型输出内部的数字或标点由模型决定。统计反映实际库译、模型译和原样保留来源。

## 五、UI 对照与任务调度

UI 读取表内范围进行双向高亮。鼠标悬停或选择原文项时，高亮该项及其译文范围；在译文侧执行相反映射。tag 按项对应，普通句子按整单元对应。页面不再重切文本、以词名查找重复项或按数组位置猜配。复制内容直接取最终译文。

自动本地翻译在输入停止约 500 ms 后触发。页面同一时刻只运行一次本地调用，并保留一个最新待处理快照；后续输入覆盖待处理快照。清空、方向变化、离开页面或更新输入会使旧响应失效，不能回填当前结果。失败后可重新执行；移除译文结果缓存，模型加载缓存仍保留。

## 七、被取代的决定

旧决定 #2 原文：**“切分不复制，由装配层递装订模块那一份”**。共用同一份切分仍然有效；其“递切分函数”的接口形状已由决定 20261017-1 更新为注入装订门面的完整纯文本处理对象。旧决定 #1“本地翻译是独立的一个模块，不是装订模块的一个模式”继续有效。

旧需求 R-6 及旧接口 §1.1 原文：**“目标语言是中文时，已经是中文的格不必交出去”**。这一整格规则由决定 20261017-5 更新为混合单元按语言片段判断；旧决定 #5“已经是目标语言按方向判”仍然有效，判断粒度更新为片段。此前实现中额外整段译文覆盖逐项结果的做法，由决定 20261017-3 取代。
