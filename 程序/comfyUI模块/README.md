## 一、它是什么 / 它不是什么

**把一张 ComfyUI 工作流读进来，让它变成能填的参数，填完去跑，把图取回来。就这一件事。**

| 它做 | 它不做 |
|---|---|
| 认出一张图里正 / 负 / 图各接在哪 | 替 AI 决定提示词写什么 |
| 把正向、负向、图片填进去 | 改采样参数（steps / cfg / denoise / 模型 / 尺寸） |
| 提交、盯到完成、报产出 | 管队列、取消别人的任务、管 ComfyUI 的启动与安装 |
| 取回产出文件的字节 | 解析图片内容（那是识图的事）、存图（那是图片模块的事） |
| 记一张"当前用的工作流" | 决定工作流从哪来（桌面？网络？别人给的？） |

**它不认识任何别的模块。** 通信与存档一律由装配层递进来（端口 + 存档）。

## 二、东西在哪

```
comfyUI模块/
├── index.js            门面 + 动作表（十三个动作）。**对外只有这一个文件**（出口冻住）
├── core.js             核心：连接 / 存档 / 认口 / 出图编排。不 require fs / path / http
├── graph.js            图：两种形态互转 · 认口 · 填口。纯函数
├── port.js             端口契约（七个方法）+ 异常归类的词
├── adapter-http.js     HTTP 适配器。**本模块唯一发请求的地方**
├── adapter-memory.js   内存适配器。证明核心不依赖真网络
├── test/run.js         功能自检（185 条）
├── test/接口.js         接口校验（34 条，照 接口.md 查形状）
├── test/客户端隔离.js    真实 HTTP 提交的客户端标识与显式标识回归
├── test/自定义控件.js   自定义控件保存名称、连线与提交输入回归
├── tools/              探针与实测脚本（见 §九）
├── 接口.md              **契约**：十三个动作 / 端口 / 装配的字段名与错误码
├── comfyUI模块设计.md   设计规范：范围 / 需求 / 架构 / 横切 / 决策记录
└── 调用示例.md          调用示例与错误表
```

调用链永远是一个方向：

```
装配层 → index.js（门面/动作表） → core.js（纯逻辑） → port → adapter-http.js（真网络）
                                                     └─ graph.js（纯函数）
```

**契约与实现分开**：`接口.md` 是能独立存在的契约，`test/接口.js` 照它查实现。
改实现之前先改契约；改完契约跑 `node test/接口.js`。

## 三、六个词

| 词 | 意思 | 长什么样 |
|---|---|---|
| **界面图** | ComfyUI 里"另存为"出来的那份工作流 | `{ id, nodes, links, … }` |
| **接口图** | 提交给 ComfyUI 的那份 | `{ 节点id: { class_type, inputs } }` |
| **口** | 一处可以填的地方：正向 / 负向 / 图片 | `{ nodeId, classType, input, 文本 }` |
| **产出** | 一次出图落下的文件 | `{ 节点, 种类, 文件名, 子目录, 类型 }` |
| **存档** | 装配层提供当前工作流、绘图开关与生成设置的记录 | `{ 读(), 写(记录), 清() }`；顶层 `启用` 缺省 `false`，`生成设置` 缺省 `{ 每轮张数:1, 最多轮数:3, 自动迭代:true }` |
| **节点定义** | 这一台 ComfyUI 的 `/object_info` | `{ 节点类名: { input, output_node, … } }` |

**对外只有工作流、提示词与图片；地址在装配层，路径在装配层。**

## 四、认口与填口

**认口**：先找采样器（类名像 `Sampler` / `Guider`，或者同时吃 `positive` / `negative` / `latent_image` 里至少两项），
从它的 `positive` / `negative` 沿输入连线往上游走，收角色相符的文本节点。
采样器上没挂正负时，按角色在全图里找文本节点。
图口认 `LoadImage` 这一类的节点。

**填口**：正向接在几个节点上就往几个里写同一段字；图上没有负向口时负向忽略；图片只写进图片口。
**填口给的是新图，入参一个字不动。**

**转图时丢掉这几类节点**：标注、静音（`mode: 2`）、旁路（`mode: 4`）、中转（`Reroute`）。
旁路与中转的输出按类型接到上游；`PrimitiveNode` 的值当成控件值写进下游那一格。

规则细节与边界在 [comfyUI模块设计.md](comfyUI模块设计.md)。

---

主采样器的 `latent_image` 上游若连到已知且能落实绝对张数的 latent 批量节点，`认` / `认图` 会在 `张数` 中报告其可填写输入。已识别 `EmptyLatentImage`、`EmptySD3LatentImage`、`EmptyFluxLatentImage`、`EmptyFlux2LatentImage` 的 `batch_size`，以及 `RepeatLatentBatch`：它只支持直接接上述空 latent（同时把原始批量设为 1），或接单图 `LoadImage → VAEEncode`。显式传 `张数` 时只写入这类已确认的入口；找不到时返回错误，不重复提交凑数。张数控制主采样器的批量；输出节点产出的附加文件照常保留，不按请求数字截断。

## 五、十三个动作

| 动作 | 参数 | 说明 |
|---|---|---|
| `探活` | —— | 版本 / 设备 / 显存 |
| `看队列` | —— | 正在跑几个、排队几个 |
| `看节点定义` | —— | 这台 ComfyUI 装了哪些节点（结果缓存） |
| `存工作流` | `图` | 界面图或接口图都收；先认口，认得出才存 |
| `取工作流` | —— | 取存档里那一张 |
| `清工作流` | —— | 清工作流，保留绘图开关 |
| `绘图开关` | `启用?` | 读取或设置是否接受新的出图请求；缺省关闭 |
| `生成设置` | `每轮张数?` `最多轮数?` `自动迭代?` | 读取或更新生成设置；缺省 1 张、最多 3 轮、允许自动迭代 |
| `参数` | `节点?` `参数?` `值?` | 读取或编辑工作流实际节点控件值，写入后用于生成 |
| `认` | —— | 读存档里那一张：正 / 负 / 图各接在哪、可填哪三项 |
| `认图` | `图` | 读递进来的那一张 |
| `出图` | `正向?` `负向?` `图片?` `张数?` | 填 → 提交 → 盯到完成 → 报产出；显式张数覆盖已识别的批量入口 |
| `取图` | `产出` | 取一个产出文件的字节 |

**十三个动作一律返回 Promise。** 直呼成功给数据、失败给 `null`；要理由就用 `run`，拿 `{ ok, data }` 信封。

`绘图开关` 不传参数只读取，传布尔值写入存档顶层 `启用`；关闭时新出图在任何网络请求前以 `COMFY_DISABLED` 失败。关闭不会取消在飞任务。

`生成设置` 不传参数读取完整设置；传入一个或多个字段只更新对应项。张数与轮数必须为正整数，不设置隐藏上限。`存工作流` 与 `清工作流` 保留该设置。

`参数` 不传 `节点` 读取所有节点的参数与实际控件值；只传节点编号时返回该节点。传入节点、参数名和值会直接改存档中的原工作流控件，保留界面图布局与连线；已接线的输入只读。控件类型、选项和范围从当前 ComfyUI 节点定义读取，seed 后的 `control_after_generate` 与 LoraManager 对象控件也使用各自在原图中的值。

`出图` 还接 `onEvent`（看进度）与 `间隔毫秒`（轮询间隔）。取消来自 `run` 第三参数或直呼第二参数的 `{signal}` 运行上下文。

## 六、怎么调

```js
const { createComfyModule } = require('./comfyUI模块/index.js');

let 档 = null;
const comfy = createComfyModule({
  地址: 'http://127.0.0.1:8188',
  存档: { 读: () => 档, 写: (v) => { 档 = v; return true; }, 清: () => { 档 = null; } },
});

await comfy.工作流(JSON.parse(工作流文本));       // 存工作流
await comfy.绘图开关(true);                        // 显式允许出图
await comfy.生成设置({ 每轮张数: 2, 最多轮数: 3, 自动迭代: true });
const 口 = await comfy.认();                     // 认口
const 跑 = await comfy.出图({ 正向: '1girl, solo', 负向: 'worst quality', 张数: 2 });
const 图 = await comfy.取图(跑.产出[0]);          // { 字节, mime, … }
```

更多（事件、取消、图生图、错误处理）在 [调用示例.md](调用示例.md)。

## 七、哪条不能动

1. **对外参数里不许出现地址或路径。** 检验法：看 `describe()` 里每个动作的参数名。
2. **核心不许 `require fs` / `path` / `http`，也不许自己发请求。** 内存适配器要能跑通同一套判据。
3. **一个模块对外只有 `index.js`**，出口 `Object.freeze`，不递内部件。
4. **地址只能由装配层递进来。** 模块不读环境变量、不探测、没有默认地址；工具脚本从命令行或 `tools/.实测/设置.json` 取。
5. **一次出图同时只有一次在飞**（`COMFY_BUSY`），闸门走 `finally`。
6. **采样参数不由模块填。** steps / cfg / denoise / 模型 / 尺寸都写在图里；图生图的降噪是工作流的一部分。
7. **不许 require 别的模块**，也不许被别人 require 内部件。
8. **失败一律 `{ ok:false, reason, code }`，不抛错**（装配阶段除外）。
9. **不做兼容层、不留回退开关。** 要回退用 git。
10. **不加隐藏上限、不加没要求的校验。** 模型与界面能看到的约束才算约束。

## 八、依赖从哪来

| 依赖 | 递不进来会怎样 |
|---|---|
| `port` 或 `地址` | **构造即抛错**（装配阶段允许抛） |
| `存档` | 存 / 取 / 清工作流报 `COMFY_STORE_REQUIRED` |
| `clientId` | 提交不带（出图照常，ComfyUI 页面不认这个任务） |
| `等待` / `现在` | 用内置的 `setTimeout` 与 `Date.now`（自检可换） |
| `上限毫秒` | 默认 30 分钟 |
| `新UUID` | 用内置的 UUID v4 形状 |

**模块自己不找、不猜、不探测。** 多级兜底（`a || b || c`）是缺陷。

## 九、改完怎么验

```bash
cd 程序/comfyUI模块

node test/run.js            # 185 条功能判据（含假取回跑的 HTTP 适配器那一套）
node test/接口.js            # 34 条接口形状校验（照 接口.md 查）
node test/run.js 出图        # 只跑名字里含"出图"的

# 对真机（会真的出一张图）
node tools/造工作流.cjs http://127.0.0.1:8188 0.55   # 按真机节点定义造两张工作流
node tools/连真机.cjs   http://127.0.0.1:8188         # 端口七法 + 存 + 认 + 出一张 + 取图
node tools/验进度条.cjs <client_id>                    # 核对提交带没带 client_id
node tools/扫真实工作流.js <工作流目录> [节点定义.json]   # 拿一批真实工作流扫认口成功率

# 两个子代理的多轮联调（用户 / AI 各一个）
node tools/联调.cjs 起 http://127.0.0.1:8188 文生图
node tools/联调.cjs 说 '@要求.txt'                    # 说 / 交 / 出图的参数写成 @文件
node tools/联调.cjs 问
node tools/联调.cjs 出图 '@参数.json'
node tools/联调.cjs 取图 '<文件名>'
```

`tools/.工作流/` 与 `tools/.实测/` 是脚本自己的产物目录，`.gitignore` 里一条一个（`**/tools/.工作流/` · `**/tools/.实测/`）忽略掉了。
**其它位置不留产物**：`tools/` 下只有脚本。

**自检都自建数据、自清数据**，不碰真机、不留残留；失败非零退出。

## 十、这一版做到哪了 / 还差什么

**已实现**：十三个动作、端口七个方法、HTTP 适配器与内存适配器、界面图↔接口图互转
（标注 / 静音 / 旁路 / 中转 / 原型五类节点各有处置）、认口（采样器优先 + 全图兜底）、填口（正向多口同写）、
图片上传与回填、事件与取消、单一在飞闸门、超时、节点定义缓存、界面图随 `extra_data` 一起提交（PNG 里留着工作流）。

**验过**：185 条功能判据、34 条接口形状校验全绿；32 张真实工作流扫过（28 张认得出正向口）；
本机 ComfyUI 上真跑过文生图与图生图（两轮文生图由两个子代理各跑一轮，图生图三次的降噪是 0.35 / 0.5 / 0.55），
明细与判据编号见 [comfyUI模块设计.md](comfyUI模块设计.md) §12。

**已知的缺口**（不许偷偷绕过）：

| 项 | 状态 |
|---|---|
| 界面 | **没有**。模块层已闭合，接线是门面层的活 |
| 工作流从哪来 | 不由本模块决定：存档里那一张由调用方给 |
| 采样参数填写 | **故意不做**：steps / cfg / denoise / 模型 / 尺寸属于工作流 |
| 队列管理 | 不做：只看，不删、不清、不插队 |
| 产出只取不存 | 取回来的是字节，存哪儿是图片模块的事 |
| 视频 / 3D / 音频产出 | 只在 `产出` 里如实标出 `种类`，不解析、不转码 |
| 多个采样器的图 | **只填主采样器那一组口**（`认` 里的 `采样器不唯一` 会报出来），其余采样器的文本节点不动 |
| 认口认不出的图 | 如实报 `认不出的`，不去猜 |
