# 1. 范围

## 1.1 目的

规定 comfyUI 模块的**职责边界、工作流的两种形态、口的识别与填写规则、任务的生命周期、失败语义**，作为实现、评审与验收的依据。

## 1.2 范围内

**一次出图的全部搬运**：

```
一张 ComfyUI 工作流读进来 → 认出正 / 负 / 图三个口 → 把三项填进去
→ 提交给 ComfyUI → 盯到跑完 → 把产出的图取回来
```

具体包括：两种形态的工作流互认与转换、口的识别、口的填写、任务提交、状态轮询、产出清单、产出字节的取回、取消与超时、图片上传、节点定义缓存、事件回调。

## 1.3 范围外

| 不做 | 归谁 |
|---|---|
| 决定界面怎么画、工具怎么列 | 展示层 |
| 写、改、翻译、过滤提示词 | AI 与用户 |
| 决定 steps / cfg / denoise / 采样器 / 种子 | 工作流文件 |
| 决定用哪个模型、出多大尺寸 | 工作流文件 |
| 管理 ComfyUI 的队列（删任务、清队列、插队、中断） | ComfyUI 与用户 |
| 安装、启动、停止 ComfyUI，装自定义节点，下模型 | 用户 |
| 从哪弄来工作流文件（扫目录、下载、生成） | 调用方与工具脚本 |
| 产出图之后怎么存、怎么给别的模块用 | 调用方 |
| 判断"这张图好不好看"、"该不该出" | AI 与用户 |

## 1.4 读者

模块实现者、装配层接线者、评审者，以及依赖本模块契约的调用方实现者。

# 2. 术语与约定

## 2.1 术语

| 术语 | 定义 | 不要与它混 |
|---|---|---|
| **界面图** | ComfyUI 里"另存为"出来的那份工作流：`{ id?, nodes 数组, links 数组, … }` | 接口图 |
| **接口图** | 提交用的那份：`{ 节点id: { class_type, inputs, _meta? } }` | 界面图 |
| **口** | 图上某一处**可填的位置**：正向提示词口 / 负向提示词口 / 图片口。记成「哪个节点、哪个输入」 | 参数、字段 |
| **产出** | ComfyUI 跑完交回的文件项：`{ 节点, 种类, 文件名, 子目录, 类型 }` | 本地文件、路径 |
| **存档** | 当前工作流记录与绘图开关；工作流字段为 `{ format, 存于, 界面图, 口 }`，开关单独在顶层 `启用` | 数据库、清单 |
| **节点定义** | ComfyUI 的 `/object_info`：这台机器装了哪些节点、每个节点要什么参数 | 工作流、模板 |
| **client_id** | 提交时带的一个串，ComfyUI 页面按它认出"这个任务是这个页面发的" | 会话、身份 |
| **端口** | 核心要求通信层提供的七个方法 | 适配器、TCP 端口 |
| **任务号** | ComfyUI 给这次提交的编号（`prompt_id`），盯任务与取历史都用它 | 文件名 |

## 2.2 三层可见性

```
对外（模型 / 界面看到的参数）      →  出图参数：正向 / 负向 / 图片 / 张数；设置动作：每轮张数 / 最多轮数 / 自动迭代
模块之间传递                     →  口、产出项、事件
模块内                          →  接口图、节点定义、节点 id、任务号
```

**这条不是洁癖，有具体后果：地址一旦能由对外参数填，填地址的人就能让本模块去连任何地方。**

## 2.3 命名约定

| 场合 | 用 | 例 |
|---|---|---|
| 模块对外的**动作名** | 中文 | `认` / `出图` / `取图` |
| **回执字段** | 中文 | `任务号` / `产出` / `填了的` |
| 工作流里的结构 | 英文键（ComfyUI 自己的写法） | `class_type` / `inputs` / `nodes` |
| 端口方法名 | 中文 | `探活` / `看任务` / `送图片` |
| 失败理由 | `码: 人话` | `GRAPH_NO_PROMPT: 这张图上认不出正向提示词的口…` |

## 2.4 规范用语

| 词 | 含义 |
|---|---|
| **必须** | 不可协商。实现与评审按此判定符合性 |
| **禁止** | 出现即为缺陷 |
| **应当** | 偏离须给出理由并记录 |
| **可以** | 自由裁量 |

# 4. 设计约束

约束来自更高层的架构规则，本模块不得偏离。**违反即缺陷，不是取舍。**

| # | 约束 |
|---|---|
| C-1 | 对外参数中**禁止**出现地址、路径、URL |
| C-2 | 一个模块**只交出一份操作面**；不存在"A 面 / B 面" |
| C-3 | 换一个调用方不能改变行为：省略、过滤、包一层、靠调用顺序都**不算执行** |
| C-4 | **不解析不属于自己的东西**。要解析，说明字段定义放错了地方 |
| C-5 | 凡是"**必须和别处保持一致的清单**"都不该存在。它该被算出来，或根本不需要 |
| C-6 | **不做多级兜底来源**。`a \|\| b \|\| c` 找地址、找服务、找配置是缺陷 |
| C-7 | **依赖由装配层递入**。模块自己不找、不猜、不探测地址 |
| C-8 | **不做兼容层、不留回退开关**。要回退用 git |
| C-9 | **一处字段值只存一处**。同一份数据两处各存一份的表都不该存在 |
| C-10 | **出口一律给副本**，不给内部活对象 |

**C-6 与 C-9 派生出本模块最强的一条简化：地址只有一个来源（装配层），工作流只有一处（存档）。** 因此不存在"连错了机器"、"用的是哪一张图"这两整类缺陷。

**C-8 在本模块的具体含义**：这一轮删掉的三条约束（占位符拦截、安全整数校验、图片节点数上限）**不留开关、不留注释掉的代码**，只在决策记录里留原文（决策 3、4、5）。

# 5. 架构

## 5.1 上下文

```
        ┌──────────────── 调用方（AI / 界面 / 工具脚本）────────────────┐
        │  出图参数：正向 · 负向 · 图片 · 张数；另有生成设置动作         │
        │  拿回产出项，靠它取字节；要进度就读事件                        │
        └───────────────────────┬──────────────────────────────────────┘
                                │ 十二个动作 { ok, data } / 直呼
        ┌───────────────────────▼──────────────────────────────────────┐
        │                  index.js（门面，对外唯一入口）               │
        │  动作表 + 直呼式 + describe() + ERR 合并                      │
        └───────────────────────┬──────────────────────────────────────┘
                                │
        ┌───────────────────────▼──────────────────────────────────────┐
        │                        core.js（纯逻辑）                      │
        │  探活 · 看队列 · 看节点定义 · 存/取/清工作流 · 认 · 出图 · 取图 │
        │  闸门（一次在飞）· 定义缓存 · 事件 · 取消 · 超时               │
        └───────────┬───────────────────────────────────┬──────────────┘
                    │ graph.js（纯函数）                 │ 端口（七个方法）
                    │  认形态 · 界面图转接口图            │
                    │  读口 · 填口 · 补图id              │
                    │                    ┌──────────────┴───────────────┐
                    │                    │                              │
                    │            adapter-http.js               adapter-memory.js
                    │          （唯一发请求的地方）              （假 ComfyUI，自检用）
                    │                    │
        ┌───────────▼────────────────────▼──────────────────────────────┐
        │ 装配层递入：{ 地址 } 或 { port } · 存档 · clientId · 等待       │
        │             · 现在 · 上限毫秒 · 新UUID · 取回 · 超时毫秒        │
        └───────────────────────────────────────────────────────────────┘
```

## 5.2 分解

| 内部部分 | 职责 | 对外 |
|---|---|---|
| `index.js` | 门面：动作表、直呼式、装配、三个错误码表合并。**对外唯一入口** | **是** |
| `core.js` | 纯逻辑：连接、存档、认口、出图、取图、闸门、定义缓存、事件 | 否 |
| `graph.js` | 图：两种形态互认与转换、读口、填口、补图 id。**全是纯函数** | 否 |
| `port.js` | 端口契约：七个方法名、校验、把异常归成 reason 词 | 否 |
| `adapter-http.js` | HTTP 适配器：**本模块唯一发请求的地方** | 否 |
| `adapter-memory.js` | 内存适配器：假 ComfyUI，证明核心不依赖真机 | 否 |

**核心不认识 HTTP。** `core.js` / `graph.js` / `port.js` 里没有 `http`、`fetch`、`fs`、`path`；`core.js` 只说"提交这张图"、"看一眼这个任务号"，由适配器翻成真实请求。

**`index.js` / `core.js` / `graph.js` / `port.js` / 两个适配器都不 `require` 本模块以外的文件**（决策 11）。

## 5.3 关键设计决定（一句话）

| # | 决定 | 消掉了什么 |
|---|---|---|
| 1 | **工作流只有一份**，存在存档里 | 工作流清单、选择逻辑、"当前用的是哪张" |
| 2 | **口是算出来的**，不另存一张映射表 | 口与图不一致、改图层要同步改口 |
| 3 | **出图只接受正向 / 负向 / 图片 / 张数；生成设置单独读写** | steps / cfg / denoise / 模型 / 尺寸的映射表与参数面板 |
| 4 | **端口只七个方法** | 核心里的 HTTP 细节、URL 拼装、协议分支 |
| 5 | **一次只有一个在飞** | 任务表、队列、并发控制、结果归属判断 |
| 6 | **产出只给文件名三件套** | 产出索引、本地落盘、路径管理 |
| 7 | **认口只有三条规则 + 一条兜底** | 提示词语义解析、模板语法 |
| 8 | **错误交给 ComfyUI 自己报** | 数值范围校验、占位符检查、节点数上限（决策 3、4、5） |

## 5.4 部署

单进程。一个模块实例 = 一张工作流 + 一次在飞的出图。模块**不碰盘**：工作流存在装配层给的存档里，产出字节由调用方决定怎么处置。HTTP 适配器用全局 `fetch`（可以换掉），每次请求自带超时（`AbortController`）并可被出图的 `信号` 中断。**地址只出现在装配层与适配器里，不出现在任何对外参数中。**

# 6. 功能需求

## 6.1 职责边界

| 编号 | 需求 |
|---|---|
| R-F-1 | 本模块**必须**只做一件事：把一张工作流读进来 → 认出三个口 → 填进去 → 提交 → 盯到跑完 → 报产出 |
| R-F-2 | 本模块**禁止**认识别的模块，**禁止** `require` 本模块以外的文件（决策 11） |
| R-F-3 | 本模块**禁止**管界面：不给界面定形状、不渲染、不排布、不决定"哪个动作给模型看" |
| R-F-4 | 本模块**禁止**替 AI 写提示词：给什么写什么，不拼词、不过滤、不去重、不翻译、不加权重语法 |
| R-F-5 | 本模块**禁止**碰采样与模型：`steps` / `cfg` / `denoise` / `sampler_name` / `scheduler` / `seed` / 模型名 / 尺寸一律由工作流自己带（决策 1） |
| R-F-6 | 本模块**禁止**管 ComfyUI 本身：不装、不启、不停、不装节点、不删任务、不清队列、不中断正在跑的 |

## 6.2 工作流的两种形态

| 编号 | 需求 |
|---|---|
| R-F-7 | 收且仅收两种形态：**界面图**（有 `nodes` / `links`）与**接口图**（每个值都有 `class_type` 与 `inputs`）。这两种的 JSON 字符串也收（`认形态`） |
| R-F-8 | 界面图 → 接口图：**已连线的输入**取 `[源节点, 源槽]`；**没连线的输入**从 `widgets_values` 取。没有节点定义时按控件声明的顺序逐位取值 |
| R-F-9 | 界面图里**没声明的控件**，按节点定义补回参数名；定义里说某个参数后面跟开关位（`control_after_generate`）时，值按**两位**走 |
| R-F-9a | **控件已经被转成连线输入时不占 `widgets_values` 的位**：逐位取值时跳过它，后面的控件照原位对（决策 24） |
| R-F-10 | 节点定义缺省时**只按文件里有的算**；一个控件声明都没有的节点，把标量值按位置塞进 `w0` / `w1`… |
| R-F-11 | 转不动的图**必须**拒收：不是图 → `GRAPH_INVALID`；图里没有节点 → `GRAPH_EMPTY`；没有可执行的节点 → `GRAPH_EMPTY` |
| R-F-12 | 界面图的 `id` **必须**是 UUID 形状；不是就补一个，**补 id 不改入参**（决策 6） |
| R-F-12a | 转图时**不进接口图**的节点：标注（`Note` / `MarkdownNote`）、静音（`mode: 2`）、旁路（`mode: 4`）、中转（`Reroute`）、原型（`PrimitiveNode`）。**穿透规则**：旁路与中转的连线**按类型接到它的上游**；原型节点的第一个值**当成控件值写进下游那一格**；接不上时那一条输入不落（决策 23） |

## 6.3 认口

| 编号 | 需求 |
|---|---|
| R-F-13 | **采样器**的认法：类名像 `Sampler` / `Guider`，**或者**同时吃 `positive` / `negative` / `latent_image` 里至少两项 |
| R-F-14 | **主采样器**取评分最高者；有 `positive` 键的优先；平手按节点 id 排。图上有多个采样器时**必须**报 `采样器不唯一`，但仍只用主采样器那一组口（决策 17） |
| R-F-15 | **正向口**：从主采样器的 `positive` 沿输入连线往上游找文本节点；**负向口**：从 `negative` 同理 |
| R-F-16 | 往上游走时**只沿输入连线**走；`model` / `clip` / `vae` / `latent` / `image` / `mask` / `width` / `height` / `batch_size` / `seed` / `steps` / `cfg` 这些键**不去解析** |
| R-F-17 | 同一个节点的同一个输入**只算一个口**（去重）；一个节点不妨碍它上游还有别的文本节点 |
| R-F-18 | **兜底**：主采样器上没挂正负时，在全图范围里挑——先挑显式标了本侧字段（`positive` / `negative`）的，再挑当场空着的，正向最后取字最多的，负向不给 |
| R-F-18a | 兜底时的**排除按「这个角色下要填的键」算，不按节点算**：同一个节点同时带 `positive` 与 `negative` 两个文本字段时（加载器自带的两个文本框），两边的口**各认各的**（决策 21） |
| R-F-18b | **图片口要真的能装文件名**：类名像 `LoadImage` / `ImageLoader` / `LoadImageMask` / `LoadImageOutput`，**并且**节点上确实有一个装文件名的键（`image` / `image_name` / `filename` / `file`）才算口；**认不出这个键就不算口**，**禁止**硬猜一个 `image` 出来（决策 25） |
| R-F-19 | **图片口**：类名像 `LoadImage` / `ImageLoader` / `LoadImageMask` / `LoadImageOutput` 的节点；输入名取 `image` / `image_name` / `filename` / `file`（原为"都没有就用 `image`"，已改：认不出就不算口，见 R-F-18b）；`当前值` 是图里现在那个字符串 |
| R-F-20 | **输出节点**：类名以 `Save` / `Preview` 开头，**或者**节点定义里 `output_node === true`；种类归到 `image` / `video` / `audio` / `3d` |
| R-F-21 | `认得的` / `认不出的` **必须**按正 / 负 / 图三项算。**没有正向口时出图必须拒**（`GRAPH_NO_PROMPT`）；没有负向口**不算错**（决策 17） |

**提示词字段怎么挑**（`挑提示词字段`）：先看字段名在候选表 `text` / `text_g` / `text_l` / `prompt` / `positive` / `negative` / `string` / `value` / `populated_text` / `wildcard_text` 里的位置，再看谁的字多，最后按声明顺序。给了角色（正 / 负）时，把本侧的字段名排在最前。

## 6.4 填口

| 编号 | 需求 |
|---|---|
| R-F-22 | **正向**写进图里**全部**正向口。一个口写一次，同一个节点不重复写 |
| R-F-23 | **负向**只在图上有负向口时写；没有就**跳过**，不报错 |
| R-F-24 | **图片**写进全部图片口。图上没有图片口而给了图片 → **拒**（`INVALID_ARGUMENT`）（决策 15） |
| R-F-25 | 没给的项**一个字不动**（不给负向就不碰负向那个口头上的值） |
| R-F-26 | 口上是**连线**（还没落到控件上）时报 `INVALID_ARGUMENT`，**禁止**改成插节点、**禁止**改成写上游 |
| R-F-26a | **图片口上是连线时同样报 `INVALID_ARGUMENT`**（与正 / 负向一致），**禁止**静默跳过、**禁止**照旧报成功（决策 25） |
| R-F-27 | 填口**必须**交出新图，**入参一个字节不动**（深拷贝） |

`张数` 是可选的批量输入。仅当主采样器 `latent_image` 上游有明确且当前可直接填写的批量节点时才识别和写入。支持 `EmptyLatentImage`、`EmptySD3LatentImage`、`EmptyFluxLatentImage`、`EmptyFlux2LatentImage` 的 `batch_size`；`RepeatLatentBatch.amount` 是倍数，只在它直接接上述空 latent（同时将原始批量设为 1）或单图 `LoadImage → VAEEncode` 时支持。其它输入链无法确认绝对批量时不报可写入口。显式请求张数而没有可写入口时返回 `INVALID_ARGUMENT`，不重复提交任务。该值控制主采样器批量；多输出节点产出的附加文件照常保留，不按该值截断。

## 6.5 一次出图

| 编号 | 需求 |
|---|---|
| R-F-28 | 顺序**必须**固定：检查绘图开关 → 读存档 → 取节点定义 → 认口 → 送图片（有的话）→ 填口 → 提交 → 盯到完成（§9.1） |
| R-F-29 | 还没存过工作流就出图 → `COMFY_NO_WORKFLOW`；这张图上认不出正向口 → `GRAPH_NO_PROMPT` |
| R-F-30 | 提交**必须**带上：填好的接口图、配了就给 `client_id`、**界面图**（决策 16） |
| R-F-31 | 盯：每 `间隔毫秒`（默认 1200）看一次任务；状态一变报一次事件；状态里带 `error` 就报 `COMFY_FAILED`，`reason` 里是 ComfyUI 的原文 |
| R-F-32 | 跑完交 `{ 任务号, 状态, 产出, 填了的 }`；`填了的` 每项写成 `节点id.输入名` |
| R-F-33 | 取图**必须**只靠产出项里的 `文件名` / `子目录` / `类型` 三件套去取字节，回 `{ …产出项, 字节, mime }` |
| R-F-34 | `绘图开关` **必须**读写存档顶层 `启用`；缺省 `false`，无工作流也可读写 |
| R-F-35 | `启用` 为 `false` 时，新出图**必须**在任何端口请求前回 `COMFY_DISABLED`；关闭不取消在飞任务 |
| R-F-36 | 设置 `每轮张数`、`最多轮数`、`自动迭代` 由 `生成设置` 读写；默认 `{ 每轮张数:1, 最多轮数:3, 自动迭代:true }`，正整数不设隐藏上限 |
| R-F-37 | `出图` 只有显式收到 `张数` 时才覆盖工作流批量入口；无可写入口时失败，不重复提交凑数、不丢弃产出 |
| R-F-38 | `提交中` 事件在调用端口提交前发出；信号已取消时不得调用端口提交 |

# 7. 数据设计

## 7.1 存档

```jsonc
{
  "启用": false,                     // 新存档缺省关闭；独立控制是否接受新出图
  "生成设置": { "每轮张数": 1, "最多轮数": 3, "自动迭代": true },
  "format": 1,                        // 整数版本，现为 1
  "存于": <毫秒数>,                    // 存下来的时刻
  "界面图": { "id": "…", "nodes": [], "links": [] },   // 存下来的那张（深拷贝）
  "口": { "format": 1, "节点数": 7, "正向": [], "负向": [], "图片": [], "输出": [], … }
}
```

| 编号 | 需求 |
|---|---|
| R-D-1 | 工作流记录字段为 `format` / `存于` / `界面图` / `口`；存档顶层另有独立的 `启用` 布尔值和 `生成设置` 对象 |
| R-D-2 | `format` **必须**是整数版本；现为 `1` |
| R-D-3 | 存档由装配层以 `{ 读(), 写(记录), 清() }` 递入；**模块自己不碰盘**（决策 14） |
| R-D-4 | 存档**只有一份**：没有清单、没有多张、没有"当前指针"、没有产出缓存（C-5、C-9） |

## 7.2 口

```
口 = {
  format 数,                 图版本，现为 1
  节点数 数,
  采样器们 数组[{ nodeId, classType, 评分 }],
  主采样器 串 | null,
  采样器不唯一 真伪,           图里不止一个采样器；认口只认主采样器那一组
  正向 数组[口项],            口项 = { nodeId, classType, title, input, 文本 }
  负向 数组[口项],
  图片 数组[图片口项],         图片口项 = { nodeId, classType, input, 当前值 }
  张数 数组[张数口项],         张数口项 = { nodeId, classType, input, 当前值 }
  输出 数组[{ nodeId, classType, 类型 }],
  认得的 数组[串],            ['正向提示词','负向提示词','图片'] 里认得的那几个
  认不出的 数组[串],
  接口图 对象                 提交用的那份
}

填了的 = { 正向 数组[串], 负向 数组[串], 图片 数组[串], 张数 数组[串] }   每项 '节点id.输入名'
```

| 编号 | 需求 |
|---|---|
| R-D-5 | 口**必须**是且仅是上面十三个字段 |
| R-D-5a | 图里不止一个采样器时 `采样器不唯一` 为真；**认口只认主采样器那一组口**，其余采样器的文本节点不填（决策 22） |
| R-D-6 | 口项与图片口项的字段**必须**如上；口项里的 `文本` 是那个输入现在的值 |
| R-D-7 | 口是**算出来的**，**禁止**另存第二份（存档里那份是"存的那一刻"的结论，出图时按当时的图重算）（C-9） |
| R-D-8 | `接口图` 留在口里，提交用的就是它；产出、事件、回执里的图**禁止**再包一层 |

## 7.3 产出

```
产出项 = { 节点 串, 种类 串, 文件名 串, 子目录 串, 类型 串 }
```

| 编号 | 需求 |
|---|---|
| R-D-9 | 产出项的字段**必须**如上。`种类` 由 ComfyUI 的输出来源名换算：`images` → `image`、`gifs` → `video`、其余用原名 |
| R-D-10 | 产出项里**禁止**出现本地路径、绝对路径、`file://`（C-1）；只有 ComfyUI 那边的三件套 |
| R-D-11 | 产出清单**只由 ComfyUI 的历史给**；模块**禁止**保存产出、**禁止**建产出索引（C-5） |

## 7.4 事件

| 编号 | 需求 |
|---|---|
| R-D-12 | 事件**必须**是且仅是六种：`已送图片` / `提交中` / `已提交` / `状态` / `已取消` / `完成`（字段见 §9.2） |
| R-D-13 | 事件是 `onEvent` 的入参，**不是**返回值；模块**禁止**攒事件、**禁止**给事件队列、**禁止**让调用方"回头取" |

## 7.5 端口

| 编号 | 需求 |
|---|---|
| R-D-14 | 端口**必须**有且仅有七个方法：`探活` / `看队列` / `看节点定义` / `提交` / `看任务` / `取结果文件` / `送图片`（决策 13） |
| R-D-15 | 每个方法**必须**给 `{ ok:true, data }` 或 `{ ok:false, reason, code }`，**禁止**抛错穿透 |
| R-D-16 | 端口失败时 `reason` 用固定词表：`连不上` / `超时` / `权限` / `读不懂` / `不存在` / `未知`；由异常归类时给四个：`连不上` / `超时` / `权限` / `未知` |
| R-D-17 | `看节点定义` **可以**给 `{ nodes: {…} }` 包一层，也**可以**直接给节点表；核心两种都收 |

**HTTP 适配器对的那几条路径**（端口的参考实现，不是对外接口）：

| 端口方法 | 路径 |
|---|---|
| `探活` | `GET /system_stats` → `{ 版本, 设备, 显存总量, 显存可用 }` |
| `看队列` | `GET /queue` → `{ 运行中, 排队中 }` |
| `看节点定义` | `GET /object_info` → 节点表原样 |
| `提交` | `POST /prompt`，体 `{ prompt, client_id?, extra_data }` → `{ 任务号 }` |
| `看任务` | `GET /history/<任务号>` → `{ 状态, 完成, 产出, 错误 }`；404 → 状态 `unknown` |
| `取结果文件` | `GET /view?filename=&subfolder=&type=` → `{ 字节, mime }` |
| `送图片` | `POST /upload/image`（表单：`image` / `type=input` / `overwrite=true`）→ `{ 文件名, 子目录, 类型 }` |

## 7.6 内存适配器的开关

```js
createMemoryAdapter({
  节点定义,      // 默认一套常用的八类节点
  产出,          // 跑完给这些文件，默认一项
  状态序列,      // 每次看任务前进一格，默认 ['running','success']
  提交失败,      // 提交时返回的失败话，默认 null
  执行失败话,    // 状态里带 error 时给的错误原文
  探活失败,      // 默认 null
  文件,          // { '文件名': 字节 }，取结果文件用
})
→ { 探活, 看队列, 看节点定义, 提交, 看任务, 取结果文件, 送图片, 记 }
```

| 编号 | 需求 |
|---|---|
| R-D-18 | 开关**必须**是且仅是上面七个；**不给开关就用内置的那一套** |
| R-D-19 | `记` 里**必须**有：`提交过的` / `送过的` / `取过的` / `看任务次数`——给自检看"到底发了什么" |
| R-D-20 | 内存适配器**禁止**碰网络、**禁止**碰盘；它只是把端口的七种回答摆出来 |

## 7.7 不变量

| 编号 | 不变量 |
|---|---|
| INV-1 | 存档里的 `口` 与 `界面图` 是同一张图算出来的 |
| INV-2 | 任一时刻，在飞的出图至多一次 |
| INV-3 | 填口交出的接口图与存档里的界面图不是同一个对象；出图不改存档 |
| INV-4 | 模块发出的请求只有端口的那七个方法；没有第八条路 |
| INV-5 | 该发生的那个事件报一次，且只报一次（有 `onEvent` 时）；`状态` 只在状态串变化时报 |

| INV-7 | 产出项里的三件套足以取回字节：`取图` 不再问别的东西 |

# 8. 接口设计

字段名、类型、必填、约束的完整契约见 [接口.md](接口.md)。本章规定操作语义。

## 8.1 操作总览

**十二个对外动作。**

| # | 动作 | 直呼名 | 输入 | 输出 | 时序 |
|---|---|---|---|---|---|
| I-1 | `探活` | `探活()` | — | `{ 版本, 设备, 显存总量, 显存可用 }` | 异步 |
| I-2 | `看队列` | `看队列()` | — | `{ 运行中, 排队中 }` | 异步 |
| I-3 | `看节点定义` | `看节点定义()` | — | 节点表（结果缓存进核心） | 异步 |
| I-4 | `存工作流` | `工作流(图)` | `图` 必填 | `{ 启用, format, 存于, 界面图, 口 }` | 异步 |
| I-5 | `取工作流` | `取工作流()` | — | 同 I-4 | 异步 |
| I-6 | `清工作流` | `清工作流()` | — | `null` | 异步 |
| I-7 | `绘图开关` | `绘图开关(启用?)` | `启用` 可选 | `{ 启用 }` | 异步 |
| I-8 | `生成设置` | `生成设置(设置?)` | 三字段可选 | `{ 每轮张数, 最多轮数, 自动迭代 }` | 异步 |
| I-9 | `认` | `认()` | — | 认得的三项 + `张数` / `输出` / `节点数` / `采样器` / `采样器不唯一` + `可填`（读存档里的那张） | 异步 |
| I-10 | `认图` | `认图(图)` | `图` 必填 | 同 I-9（读递进来的那张，不碰存档） | 异步 |
| I-11 | `出图` | `出图({ 正向?, 负向?, 图片?, 张数? })` | 四项选填 | `{ 任务号, 状态, 产出, 填了的 }` | 异步 |
| I-12 | `取图` | `取图(产出项)` | `产出` 必填 | `{ …产出项, 字节, mime }` | 异步 |

**结果信封**：

```
成功  { ok: true,  data: … }
失败  { ok: false, reason: '<码>: <人话>', code: '<码>', details?: … }
```

**直呼式**（`comfy.认()`）成功给数据、失败给 `null`；要拿理由用 `comfy.run(动作, 参数)`。

**`认` / `认图` 的十一个字段**：`认得的` · `认不出的` · `正向` · `负向` · `图片` · `张数` · `输出` · `节点数` · `采样器` · `采样器不唯一` · `可填`。

其中 `采样器不唯一` 是**必须让调用方看得见的那条约束**：本模块只填主采样器那一组口，图上还有别的采样器时如实报出来（决策 22）。

**参数解包**（`存工作流` / `认图`）：先把递进来的这个值**本身**认一次形态——它本身是一张工作流就直接用；不是才取 `参数.图`。所以接口图 / 界面图**直接给也对**，包一层 `{ 图 }` 也对；给一段不是图的东西**如实报错**（`GRAPH_INVALID` / `GRAPH_EMPTY`），**禁止**悄悄去读存档里那一张。

**`取图` 的两种给法**：直呼时给产出项本身（`取图(产出项)`）；走动作表时给 `{ 产出: 产出项 }`。参数里有 `产出` 且参数自己不像一个产出项（没有 `文件名`）时取 `参数.产出`，否则把参数当成产出项本身。

## 8.2 对外禁令（符合性检验用）

| 编号 | 规定 |
|---|---|
| R-I-1 | 对外**只有**这十二个动作；`actions` 与 `describe()` **必须**与它一致，一个不多一个不少 |
| R-I-2 | 十二个动作**必须**一律返回 Promise——同步动作也包成 Promise，免得同步与异步两套规矩 |
| R-I-3 | `run` **必须**一律给信封；`reason` **必须**写成 `码: 人话`；没有这个动作时报 `INVALID_ARGUMENT` |
| R-I-4 | 直呼成功给数据、失败给 `null`；**禁止**直呼时抛错穿透调用方（装配阶段除外） |
| R-I-5 | 对外参数里**禁止**出现地址、路径、URL、目录、文件名（C-1 的检验法：看 `describe()` 的 `参数` 里有没有） |
| R-I-6 | `出图` 的对外参数**必须**只有 `正向` / `负向` / `图片` / `张数` 四项（加选填的 `onEvent` / `间隔毫秒` / `clientId`；取消从单独的 `{signal}` 运行上下文传入）；**禁止**出现 steps / cfg / denoise / 模型 / 尺寸（决策 1） |
| R-I-7 | 所有输入**必须**以对象传入；**禁止**位置参数。`存工作流` / `认图` / `取图` **可以**直接给那一件东西（直呼时少包一层） |
| R-I-8 | 出口**必须**冻住，**禁止**把核心、图、端口、适配器递给调用方 |
| R-I-9 | `在跑吗()` **必须**是同步的真伪，给"现在忙不忙" |
| R-I-10 | `ERR` **必须**是三个错误码表合并的结果（`core.js` + `graph.js` + `adapter-http.js`），且冻住 |

## 8.3 典型调用序列

```
① 装一张工作流
   门面：run('存工作流', { 图 }) → 存进存档；返回的 口.认得的 告诉调用方认出了什么

② 出图（文生图）
   门面：run('出图', { 正向, 负向 }) → 内部：认口 → 填口 → 提交 → 盯 → 报产出

③ 出图（图生图）
   门面：run('出图', { 正向, 负向, 图片: { 字节, 文件名, mime } })
   ∟ 内部先把字节送进 ComfyUI 输入区，拿回文件名，再写进图片口

④ 取图
   门面：run('取图', { 产出: 跑.data.产出[0] }) → 字节交给调用方处置

⑤ 换一张工作流
   门面：run('清工作流') → run('存工作流', { 图: 新图 })
```

## 8.4 装配接口

```js
const { createComfyModule } = require('./comfyUI模块/index.js');

// 地址由装配层给，形如 http://127.0.0.1:8188（不带尾斜杠；带了也会被去掉）
const comfy = createComfyModule({ 地址: 'http://127.0.0.1:8188', 存档 });

createComfyModule({ port | 地址, 存档?, clientId?, 等待?, 现在?, 上限毫秒?, 新UUID?, 取回?, 超时毫秒? })
  → { 十二个直呼函数, run, actions, describe, ERR, 端口方法, 在跑吗 }
```

| 编号 | 需求 |
|---|---|
| R-P-1 | **必须**给 `port` 或 `地址` 二者之一；**`port` 是 `undefined` 时才回落到 `地址`**；两者都没有 → **构造时抛错**（`COMFY_PORT_REQUIRED`） |
| R-P-2 | 给了 `port` 时**必须**校验七个方法齐全；缺方法 → **构造时抛错并点名缺哪个**（决策 13）。**显式给了一个不合格的端口就走这条，不回落到地址** |
| R-P-3 | `存档` **可以**缺省；缺省时存 / 取工作流报 `COMFY_STORE_REQUIRED`（决策 14） |
| R-P-4 | `clientId` / `等待` / `现在` / `上限毫秒` / `新UUID` / `取回` / `超时毫秒` **可以**缺省，由装配层递入 |
| R-P-5 | 缺省时的行为**必须**是：`等待` → `setTimeout`、`现在` → `Date.now`、`上限毫秒` → 30 分钟、`新UUID` → 内置的 UUID v4 形状、`超时毫秒` → 30 秒、`取回` → 全局 `fetch` |
| R-P-6 | `地址` **只能**由装配层给；模块**禁止**读环境变量、**禁止**探测、**禁止**回退到默认地址（决策 9、C-6） |
| R-P-7 | 端口**必须**是一个对象；方法名照 §7.5 写死，**禁止**改名、**禁止**别名 |
| R-P-8 | **装配阶段的错误是抛错**（错就是装不起来），运行阶段一律走失败信封（§8.1） |

**缺省后果**：

| 依赖 | 缺省时 |
|---|---|
| 端口 / 地址 | 构造即抛错 |
| 存档 | 没有存工作流的能力；`认` / `出图` 报 `COMFY_STORE_REQUIRED` |
| clientId | 提交不带 `client_id` 字段 |
| 等待 / 现在 | 真等、真取时间 |
| 新UUID | 用内置的 UUID v4 形状 |

# 9. 横切关注点

## 9.1 一次出图的顺序

```
⓪ 检查开关      false → COMFY_DISABLED（不请求端口）
① 读存档        没有工作流 → COMFY_NO_WORKFLOW
② 取节点定义    缓存里有就用，没有就取一次；取不到就停在这（连不上 / 不是 JSON）
③ 认口          转不动 → GRAPH_INVALID / GRAPH_EMPTY；没正向口 → GRAPH_NO_PROMPT
④ 送图片        有图片才做：字节 → 输入区 → 回文件名 → 拼子目录
⑤ 填口          正负 / 图片 / 可选张数 → 新的接口图；口是连线 / 不收图片 / 没有张数入口 → INVALID_ARGUMENT
⑥ 提交          取消检查 → `提交中` 事件 → 接口图 + client_id + 界面图 → 任务号
⑦ 盯            每 间隔毫秒 看一次；状态一变报一次；error → COMFY_FAILED
⑧ 报产出        完成 → { 任务号, 状态, 产出, 填了的 }
```

| 编号 | 需求 |
|---|---|
| R-X-1 | 顺序**必须**如上；先检查开关，`取节点定义` 在 `认口` 之前，`送图片` 在 `填口` 之前 |
| R-X-2 | 任一步失败就**停在那一步**，后面的步骤不执行；把那一步的理由**原样**交回去 |
| R-X-3 | 提交之前的失败**不带**任务号；提交之后由本模块自己判定的失败（执行失败 / 超时 / 取消）**必须**带 `details.任务号`；盯的途中端口自己失败时，把端口给的理由**原样**交回 |
| R-X-3a | **端口回了 `ok` 却没给 `data` 时**（提交没给任务号、送图片没给文件名、取结果文件没给字节，三处）→ 报 `COMFY_UNREACHABLE`（话里写清缺什么），**不抛错**、**不拿 `undefined` 往下走**（决策 26） |

## 9.2 事件

```
{ 类型: '已送图片', 文件名: '子目录/文件名' }
{ 类型: '提交中',   填了的: { 正向, 负向, 图片, 张数 } }
{ 类型: '已提交',   任务号, 填了的: { 正向, 负向, 图片, 张数 } }
{ 类型: '状态',     任务号, 状态 }
{ 类型: '已取消',   任务号 }
{ 类型: '完成',     任务号, 状态, 产出, 填了的 }
```

| 编号 | 需求 |
|---|---|
| R-X-4 | 事件**必须**按发生顺序报；`状态` 只在状态串变化时报一次，同状态不重复报 |
| R-X-5 | `已送图片` 在提交之前报；`提交中` 在调用提交端口前报；`已提交` **必须**带任务号与 `填了的`；`完成` **必须**带状态与产出 |
| R-X-6 | 取消时**必须**报 `已取消`（拿得到任务号时带着它） |
| R-X-7 | **观察者抛错不影响出图**（决策 20）：`onEvent` 里抛出来的错被吞掉，出图照走 |

## 9.3 并发闸门

| 编号 | 需求 |
|---|---|
| R-X-8 | **一次出图同时只有一次在飞**；上一次没结束就再叫一次 → `COMFY_BUSY`（决策 7） |
| R-X-9 | 闸门**必须**在 `finally` 里放下：成功、失败、取消、超时都一样放 |
| R-X-10 | 除 `出图` 外的动作**不设**闸门：看、认、存取工作流随便叫 |

## 9.4 取消

| 编号 | 需求 |
|---|---|
| R-X-11 | `信号` 一断**必须**报 `COMFY_CANCELLED`；拿得到任务号时带 `details.任务号` |
| R-X-12 | 取消在盯的每一圈开头判一次；送图片、提交、看任务回来时再判一次——**取消优先于端口给的理由** |
| R-X-13 | 取消**不撤回**已经提交的任务：模块**禁止**删 ComfyUI 队列里的东西，也**禁止**假装撤回了 |

## 9.5 超时与轮询

| 编号 | 需求 |
|---|---|
| R-X-14 | 一次出图最多盯 `上限毫秒`（默认 30 分钟）；超过报 `COMFY_TIMEOUT` 并带任务号 |
| R-X-15 | 两次 `看任务` 之间等 `间隔毫秒`（默认 1200 ms）；出图时**可以**按次换 |
| R-X-16 | 判断"超了没有"**必须**用递入的 `现在()`，用它的差算，不看墙上时间 |

## 9.6 图片上传

| 编号 | 需求 |
|---|---|
| R-X-17 | 图片**必须**先送进 ComfyUI 的输入区，拿回文件名（有子目录就拼成 `子目录/文件名`）**再**填口（决策 15） |
| R-X-18 | 字节**可以**是 `Buffer` / `Uint8Array` / `ArrayBuffer`；没有字节时**不发请求**，报 `COMFY_BYTES_REQUIRED` |
| R-X-19 | 文件名**必须**只取最后一段（去掉路径成分）；没给文件名时用约定的默认名；`mime` 不是 `image/*` 时按 `image/png` 送 |
| R-X-19a | 送上去用 `type=input` 与 `overwrite=true`：同名重送就是覆盖，**禁止**攒一堆同名副本 |

## 9.7 节点定义缓存

| 编号 | 需求 |
|---|---|
| R-X-20 | 节点定义**只取一次**，取回后缓存进核心；之后的 `认口` / `出图` 都用它（决策 18） |
| R-X-21 | `存工作流` **用手上已有的定义**，不为了存一张图去取一次定义；没取过就按文件里有的算（R-F-10） |

## 9.8 client_id

| 编号 | 需求 |
|---|---|
| R-X-22 | 提交时带 `clientId`：装配层给了就带，**出图时给的优先**；都没给就不带这个字段（不是空串） |

## 9.9 界面图随 extra_data 提交

| 编号 | 需求 |
|---|---|
| R-X-23 | 提交时**必须**把**界面图**放进 `extra_data.extra_pnginfo.workflow`，让 ComfyUI 页面能显示这张图的原始样子（决策 16） |

## 9.10 安全与边界

| 编号 | 需求 |
|---|---|
| R-X-24 | `地址` **只能**由装配层递入（`{ 地址 }` 或 `{ port }`）；模块**禁止**读环境变量、**禁止**探测、**禁止**有默认地址（决策 9） |
| R-X-25 | 本模块**只**对递进来的那一个地址发请求；**禁止**发别的网络请求、**禁止**执行外部命令、**禁止**碰盘（决策 13、14） |

## 9.11 明确不保证

| 项 | 规定 |
|---|---|
| **产出的保留时间** | **不保证**。ComfyUI 那边清掉了，取图就报 `COMFY_FILE_MISSING` |
| **任务号的持久性** | **不保证**。ComfyUI 重启后历史里没有了，`看任务` 给状态 `unknown`，**不报错** |
| **出图进度百分比** | **不保证**。只有状态串（`running` / `success` / `error` …），没有第几步 |
| **队列位置与预计时间** | **不保证**。要看只看得到"运行中几个、排队中几个" |
| **进程崩溃后的恢复** | **不保证**。在飞的那次出图随进程一起没了，任务还在 ComfyUI 那边跑 |
| **跨进程互斥** | **不保证**。闸门是**本进程内**的；别的进程 / 另一个界面同时提交，本模块不管 |
| **工作流能不能跑通** | **不保证**。认得出三个口不等于这张图在 ComfyUI 上跑得起来；跑不起来由 ComfyUI 报错，原文交回 |

# 10. 错误模型

## 10.1 错误码

**三处 `ERR` 一共 23 个键、21 个码**（`INVALID_ARGUMENT` 与 `COMFY_UNREACHABLE` 各在两处定义，取值相同）。

| 码 | 出处文件 | 什么情况 | 调用方该做什么 |
|---|---|---|---|
| `COMFY_PORT_REQUIRED` | `core.js` | 装配时既没端口也没地址 | 改装配：给 `port` 或 `地址` |
| `COMFY_ADDRESS_REQUIRED` | `adapter-http.js` | 给了 HTTP 适配器但地址是空的 | 改装配：给一个地址 |
| `COMFY_STORE_REQUIRED` | `core.js` | 没递存档却要存 / 取 / 清工作流 | 补 `存档` |
| `COMFY_NO_WORKFLOW` | `core.js` | 还没存过工作流 | 先 `存工作流` |
| `COMFY_DISABLED` | `core.js` | 绘图开关关闭 | 勾选“启用绘图” |
| `COMFY_GRAPH_REQUIRED` | `adapter-http.js` | 要提交的图是空的 | 先 `认口`，或换一张图 |
| `GRAPH_INVALID` | `graph.js` | 既不是界面图也不是接口图（含 JSON 解析失败） | 换一张图 |
| `GRAPH_EMPTY` | `graph.js` | 图里没有节点 / 没有可执行的节点 | 换一张图 |
| `GRAPH_NO_PROMPT` | `graph.js` | 认不出正向提示词的口 | 到 ComfyUI 里确认这张图后重新导入 |
| `INVALID_ARGUMENT` | `core.js` · `graph.js` | 参数形状不对（如图片给错、没给产出项、要填的口是连线、存档没写进去） | 改参数 |
| `COMFY_UNREACHABLE` | `core.js` · `adapter-http.js` | 连不上 ComfyUI | 看 ComfyUI 起没起、地址对不对 |
| `COMFY_NOT_JSON` | `adapter-http.js` | 那个地址返回的不是 JSON，或不是 ComfyUI 的服务信息 | 看地址是不是指到别处了 |
| `COMFY_PROMPT_REJECTED` | `adapter-http.js` | 提交被拒（4xx），一般是节点参数不合规 | 看 `reason` 里的逐条节点报错与可选值 |
| `COMFY_SUBMIT_UNKNOWN` | `adapter-http.js` | 5xx，或 200 却没给任务号 | 到 ComfyUI 队列里看有没有这张图 |
| `COMFY_TASK_REQUIRED` | `adapter-http.js` | 看任务没给任务号 | 改参数 |
| `COMFY_FILE_MISSING` | `adapter-http.js` · `adapter-memory.js` | 产出文件不在，或取到的是空文件 | 看那次任务真出了图没 |
| `COMFY_BYTES_REQUIRED` | `adapter-http.js` | 送图片没给字节 | 改参数：给字节 |
| `COMFY_HTTP_ERROR` | `adapter-http.js` | 送图片 / 取文件的其它 HTTP 错 | 看 `details.状态码` |
| `COMFY_FAILED` | `core.js` | ComfyUI 报告执行失败，或动作里抛了错 | 看 `reason` 里 ComfyUI 的原文 |
| `COMFY_CANCELLED` | `core.js` | `信号` 断了 | 用户自己取消的；要确认就去 ComfyUI 看任务号 |
| `COMFY_TIMEOUT` | `core.js` | 超过 `上限毫秒` 还没跑完 | 大图 / 视频就把 `上限毫秒` 调大；看 ComfyUI 卡在哪 |
| `COMFY_BUSY` | `core.js` | 上一次出图还没结束 | 等它回来，或看 `在跑吗()` |

## 10.2 处理原则

| 编号 | 需求 |
|---|---|
| R-E-1 | 失败**必须**可分辨：**禁止**只回一个 `false`，**禁止**把"认不出"与"图上就没有"混成一个 |
| R-E-2 | 端口给了什么理由就报什么理由，**禁止**换成自己的话（**唯一的例外是取消**：取消优先于端口给的理由）（R-X-12） |
| R-E-3 | 执行失败时 `reason` 里**必须**是 ComfyUI 的原文（`COMFY_FAILED`），**禁止**改写成自己的概括 |
| R-E-4 | 提交被拒时**必须**把节点错误逐条交回（节点 id、类名、输入名、可选值），调用方不必去翻 ComfyUI 的日志 |
| R-E-5 | **参数被拒**（4xx）与**提交结果未知**（5xx / 没任务号）**必须**分成两个码（决策 8） |
| R-E-6 | 失败**不吞**：端口失败与执行失败一律上交；**只有观察者抛错被吞**（R-X-7） |
| R-E-7 | **端口不守约**（回 `{ ok:true }` 却没给 `data`）**必须**报 `COMFY_UNREACHABLE`，**禁止**抛错、**禁止**把 `undefined` 当成结果往下传（R-X-3a、决策 26） |

# 11. 明确不做

| 编号 | 不做 | 归谁 |
|---|---|---|
| R-N-1 | 不管界面怎么画、工具怎么列、进度条怎么显示 | 展示层 |

| R-N-4 | 不管模型选择与出图尺寸 | 工作流文件 |
| R-N-5 | 不管队列：不删任务、不清队列、不排优先级、不中断正在跑的 | ComfyUI 与用户 |
| R-N-6 | 不管 ComfyUI 的安装、启动、停止、装节点、下模型 | 用户 |
| R-N-7 | 不管工作流文件从哪来：不扫目录、不下载、不生成。文件由调用方给 | 调用方与 `tools/` 脚本 |
| R-N-8 | 不管产出图之后的事：不给本地路径、不落盘、不进任何图库 | 调用方 |
| R-N-9 | **不做占位符替换，也不做占位符拦截**（决策 3） | — |
| R-N-10 | **不做数值范围与安全整数校验**：填不进去时由 ComfyUI 自己报（决策 4） | ComfyUI |
| R-N-11 | **不设"最多几个图片节点"这类隐藏上限**（决策 5） | — |
| R-N-12 | **不做兼容层、不留回退开关**；作废的约束只记在决策记录里，不在代码里留分支（C-8） | — |

**一处必须说清的边界**：本模块**不是**"工作流管理器"。它不保存工作流库、不比对两张图的差别、不追踪"这张图是谁改的"。要管理多张工作流，由调用方自己决定给哪一张。
